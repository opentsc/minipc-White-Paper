# 05　案例一：模型摘要

## 这一章的任务

把[第 4 章](04-案例一-抓网页.md)抓到的那一堆原始文字，交给这台机器上的模型，**变成每篇一段、一眼扫得完的中文摘要。**

做完之后，点一下执行，屏幕上是几条这样的东西：

```text
标题：某某新版本发布
摘要：这个版本换了默认的网络配置工具，旧的配置文件需要手工迁移，官方给了一个转换脚本。
链接：https://……
```

**这一章有两件容易出错的事**，各占一节：提示词写不好，它就开始自己发挥；内容太长，它只看了个开头。

## 开始前

- [第 4 章](04-案例一-抓网页.md)做完，那条叫“日报-案例一”的工作流里已经有手动触发加 RSS Read 两个节点，执行一次能看到一批条目；
- **[第 4 章](04-案例一-抓网页.md)最后让你抄下来的那几个字段名在手边**，这一章要用；
- [第 3 章](03-第一个工作流.md)那个 HTTP Request 节点配过一次。**参数怎么填不重讲**，这一章只说不一样的地方；
- [第 6 卷第 1 章](../06-本地模型/01-模型与量化.md)读过，知道 token 是怎么回事。**本章最后一节要用那一章的估算办法**；
- [第 6 卷第 7 章](../06-本地模型/07-多模型切换.md)那张常备模型表看一眼，**这一章要挑一个**；
- 60 分钟。

## 新词

**提示词**（prompt）：你发给模型的那段话。**它决定模型答成什么样**，是这一章的主角。

**系统提示**（system）：`messages` 里角色写 `system` 的那一条，放在最前面。**规矩写在这里**——“只根据给的内容说”“不要写开场白”“控制在多少字”。[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)讲过三种角色，这一章第一次真的用上 `system`。

**逐条执行**：一个节点收到十条数据，它就跑十遍，一条一遍。**这是 n8n 的默认行为**，本章要用到它，也要知道什么时候不该用它。

**截断**：送进去的内容超过模型这次能看的长度，超出的部分被丢掉。**它不报错**，所以最难发现。

## 第一步：先把素材收拾干净

**别拿抓下来的原样去喂模型。** 三件事先做掉。

### 一、只留最近几条

[第 4 章](04-案例一-抓网页.md)结尾留的那个问题。订阅源一次给你十几条，**你每天要看的是新出来的那几条**。

在 RSS Read 后面加一个 **Limit** 节点，**Max Items** 填 5。

**这个节点在不同版本里的名字和参数名可能不一样，需要核验**，认意思——就是那个“只留前几条”的节点。RSS 的条目一般是新的在前面，所以留前 5 条就是最近 5 条。

> **想按时间卡而不是按条数卡**，用 Filter 那类节点，条件写成发布时间在最近一天之内，字段名用[第 4 章](04-案例一-抓网页.md)抄下来的那个（`pubDate` 或者 `isoDate`）。**本案例按条数卡就够**，简单、可预测，而且不会因为某天人家没发新文章就交出一份空日报。

### 二、把标题和正文拼成一段话

再加一个 **Edit Fields (Set)** 节点（[第 3 章](03-第一个工作流.md)用过），**右键把它改名叫“整理素材”**。加两个字段。

**第一个字段，名字填 `系统提示`，类型字符串，值用固定值（不是表达式），把下一节那段提示词整段贴进去。**

**第二个字段，名字填 `用户内容`，类型字符串，值切到表达式那一边**，填：

```text
标题：{{ $json.title }}

正文：
{{ ($json.content || $json.contentSnippet || $json.description || "").slice(0, 3000) }}
```

**这一段有三处要说明：**

- **`{{ }}` 外面的字是原样保留的。** `标题：` 这三个字符不是表达式，会照样出现在最后拼出来的那段话里。**表达式和固定文字可以混着写**，这是 n8n 里很常用的一招；
- **`||` 是“前面那个没有就用后面那个”。** [第 4 章](04-案例一-抓网页.md)说过各家站点的 RSS 字段名有出入，有的给 `content`，有的只给 `description`。这么写三个都试一遍，**三个都没有就用最后那个空字符串，不至于整条炸掉**。**把这三个名字换成你自己抄下来的那几个**；
- **`.slice(0, 3000)` 是只取前 3000 个字符。** 这是本章最后一节那件事的第一道防线，**理由到那一节说**。

**填完看输入框下面。** n8n 一般会把这个表达式当场算出来给你看——**那一小块预览就是模型将要收到的东西**，标题在不在、正文是不是空的、有没有一堆尖括号，当场就看得见。**这一步不要跳过**，它比执行一次再回头查快得多。

### 三、正文里那些标签怎么办

[第 4 章](04-案例一-抓网页.md)提过，RSS 的正文字段常带着 `<p>`、`<a href=...>` 这类东西。

**本案例的做法是不清，在提示词里让模型忽略它们。** 理由是：清标签要么多加一个节点，要么写一段代码，**而这些标签对摘要质量的影响，比它们占掉的那点 token 更小**。下面那段提示词里有专门的一条管这件事。

**真要清干净**，n8n 里有把 HTML 转成纯文本或者 Markdown 的现成节点，加在这一步前面。**节点名和参数需要核验**，本章不写死。

## 第二步：提示词

**下面这段可以直接抄，抄完再按你自己的需要改。**

```text
你是一个只做摘要的助手。你的全部工作是把用户给你的一篇文章压成一段中文摘要。

规矩：
1. 只根据用户给出的内容写，原文没有提到的东西一个字都不要补；
2. 用中文，平铺直叙，不评价，不猜作者的意图；
3. 摘要控制在 100 字以内；
4. 内容里可能夹着 HTML 标签，忽略它们，只看文字；
5. 内容太短或者看不出讲了什么，就只回四个字：内容不足；
6. 只输出摘要本身。不要写“摘要如下”这类开场白，不要用 Markdown 标记，不要把标题再重复一遍。
```

**六条不是凑数的，一条一条说它防的是什么：**

**第 1 条防瞎编。** 这是[第 7 卷第 5 章](../07-RAG/05-阻止瞎编.md)那一整章的核心那句话，**放进自动流程里更要紧**——那一卷里是你坐在屏幕前看着它答，编了你当场就看出来；这里没人看着，编出来的东西直接进日报。

**第 2 条防它替你下判断。** 不加这一条，模型很爱写“这是一个重要的更新”“值得关注”。**日报要的是它讲了什么，不是它值不值得关注**——后面那个判断你自己来。

**第 3 条给长度。** 不给的话它有时候写三行有时候写三十行，**一份日报里长短不一，扫起来很累。**

**第 4 条处理上一节没清的标签。**

**第 5 条给一条退路。** 有的条目抓下来只有一个标题，正文是空的（[第 4 章](04-案例一-抓网页.md)最后让你看的第三样东西）。**不给退路，模型会对着空内容编一段**；给了退路，日报里就是一行“内容不足”，你一眼看见，知道那条要自己点开看。

**第 6 条管格式。** 不管的话它会给你加“## 摘要”这类标记，还爱把标题重复一遍。**下一章要把这些摘要拼成一份日报，格式脏了那一步就难做。**

> **改提示词的时候，一次只改一条，改完执行一次看效果。** 一口气改三条，效果变了你不知道是哪一条起的作用。**这和[第 3 章](03-第一个工作流.md)那条“改一处执行一次”是同一条规矩。**

## 第三步：调模型的那个节点

从“整理素材”拖一条线出去，加一个 **HTTP Request**，**改名叫“问模型”**。

参数和[第 3 章](03-第一个工作流.md)那次几乎一样：

- **Method** 选 **POST**；
- **URL** 填 `http://host.docker.internal:11434/v1/chat/completions`；
- **Send Body** 打开，**Body Content Type** 选 **JSON**，**Specify Body** 选用 JSON 写；
- **选项里的超时调大**，理由[第 3 章](03-第一个工作流.md)说过。

**请求体这次不一样**：

```json
{
  "model": "qwen3.6-35b",
  "messages": [
    {"role": "system", "content": {{ JSON.stringify($json.系统提示) }}},
    {"role": "user", "content": {{ JSON.stringify($json.用户内容) }}}
  ],
  "stream": false,
  "temperature": 0.2
}
```

**四处要说明。**

**一、`JSON.stringify(...)` 不能省，这是本章最容易栽的跟头。**

抓下来的正文里一定有双引号、换行、反斜杠这些字符。**直接写 `"content": "{{ $json.用户内容 }}"` 的话**，正文里那个双引号会把这段 JSON 从中间截断，**节点当场报一个看不懂的格式错误**，而你盯着提示词找半天。

`JSON.stringify(...)` 干的事是把一段文字转成一个合法的 JSON 字符串，**该转义的转义，而且它自己会带上外面那对引号**——所以上面那行 `{{ }}` 外面没有引号，**不要自己再加一对**。

**二、`temperature` 填一个小数。** [第 6 卷第 8 章](../06-本地模型/08-局域网API.md)那张参数表里的那一项——**小了更稳更死板，大了更活也更容易跑偏。** 做摘要要的是稳，`0.2` 是一个能用的起点。**这不是实测出来的最优值**，觉得太死板就往上调一点。

**三、`stream` 还是 `false`**，理由[第 3 章](03-第一个工作流.md)说过。

**四、模型挑哪个。** [第 6 卷第 7 章](../06-本地模型/07-多模型切换.md)那张常备组合表里，**日常对话那一档就够做摘要**。摘要这件事不难，**难的是它稳不稳定听话**，不是它聪不聪明。

> **想省一点等待，可以换那张表里更轻的那个模型试试。** 换完把同一批文章跑一遍，两边的摘要摆在一起看，**自己判断值不值**。[第 6 卷第 16 章](../06-本地模型/16-模型测试表.md)那张测试表就是记这种对比的。

### 最后一个节点：把摘要挑出来

再加一个 **Edit Fields (Set)**，加三个字段，全部用表达式：

| 字段名 | 值 |
| --- | --- |
| `标题` | `{{ $('整理素材').item.json.title }}` |
| `摘要` | `{{ $json.choices[0].message.content }}` |
| `链接` | `{{ $('整理素材').item.json.link }}` |

**`摘要` 那一行[第 3 章](03-第一个工作流.md)见过**，就是那条路径。

**另外两行是新东西——`$('节点名')` 是去别的节点的数据里取。** 到了这一步，流转的数据已经变成模型的返回了，**标题和链接不在里面**，得回头找。**这就是[第 3 章](03-第一个工作流.md)那条“把节点改个名字”的用处**，改成了中文名，这里引用起来一目了然。

**`.item` 的意思是“和当前这条对得上的那一条”。** 五篇文章逐条走，第三篇算摘要的时候，它取的是第三篇的标题。**节点名换成你自己起的那个，字段名换成你抄下来的那个。**

执行一次。**输出面板上应该是五条，每条三个字段。**

## 多条内容：一条条来还是合成一批

**上面这条流程是一条条来的**——五篇文章，HTTP Request 那个节点被执行五次，每次问一篇，回来五段摘要。**这是 n8n 的默认行为，你什么都没做它就是这样。**

另一条路是把五篇拼成一大段，**一次问完**。两条路各有各的用处：

| | 一条条来（本案例用这个） | 合成一批 |
| --- | --- | --- |
| 调模型几次 | 五次 | 一次 |
| 一篇内容坏了 | **只坏那一条**，别的照常 | **整批一起坏** |
| 每次送进去多长 | 短，不容易被截断 | 长，**很容易撞上下一节那件事** |
| 输出格式好不好控 | 好控，一次就要一段话 | 难控，要它按顺序输出五段，它可能少一段、并两段 |
| 能不能横向比较 | **不能**，它一次只看得见一篇 | **能**，可以让它“从这五篇里挑最值得看的三篇” |
| 快慢 | 五次请求 | 一次请求 |

**本案例走一条条来这条路，理由是最后那份日报本来就是一篇一行。** 而且它有一个很实在的好处——**一篇抓坏了只坏那一行，别的四行照常送到你手上。**

> **什么时候值得合成一批**：你要的不是“每篇讲了什么”，而是“今天这十条里哪几条值得看”。那种日报模型必须同时看见全部十条才判断得了。**做法是在中间加一个把多条并成一条的节点**（这类节点一般叫 Aggregate 或者类似的名字，**需要核验**），然后提示词换成“下面是今天的十条，挑出最值得看的三条，每条一句话说明理由”。**这条路本卷不展开**，知道它存在、知道代价在哪儿就够了。

## 内容太长怎么办

**这一节讲的是本章最难发现的一种错。**

### 先说它长什么样

**它不报错。** 你收到的摘要读起来通顺、像模像样，**只是内容只覆盖了原文的开头一小段**，后面的全没提。**你不去核原文，永远不会发现。**

原因是模型这次能看的长度是有上限的，**超出的部分被悄悄丢掉**。

### 怎么估

[第 6 卷第 1 章](../06-本地模型/01-模型与量化.md)那条：**一个汉字常算一到两个 token。** 所以一篇 3000 字的中文文章，大概是 3000 到 6000 个 token，加上提示词那几行，**七千上下**。

**这个估算够粗，但方向是对的**——你要知道的不是精确值，是“我送进去的东西大概是几千还是几万”。

**要精确值有个现成的办法**：[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)讲过，返回里的 `usage.prompt_tokens` 就是这次实际送进去了多少。**点开“问模型”那个节点的输出，翻到 `usage` 那一块，看一眼那个数。** 这是实测，不是估算。

### 上限是多少

**这一条要自己确认。** 模型本身支持的上下文长度（[第 6 卷第 1 章](../06-本地模型/01-模型与量化.md)那张表里各个模型标的那个数）是一回事，**Ollama 实际给这次对话开了多长，是另一回事**——它有一个自己的默认值，**这个默认值随版本变化，需要核验**。

**表现前面说过了：不报错，只是后面的内容它没看见。**

### 两条应对

**一、截断。本案例用这个。**

就是上面“整理素材”那个字段里的 `.slice(0, 3000)`——**只取正文前 3000 个字符。**

**为什么截断在日报这个场景里够用**：一篇文章的开头通常已经交代了它要讲什么，**而日报的目的是让你判断要不要点开看全文**，不是替代全文。**3000 这个数是本教材挑的起点，不是实测出来的最优值**，觉得摘得太浅就往上调，调到 `usage.prompt_tokens` 开始逼近上限为止。

**二、分批。本案例不用。**

长文切成几段，每段各摘一次，最后把几段摘要合起来再摘一次。**它能覆盖全文，代价是一篇文章要调好几次模型，还多一层出错的地方。** 要处理的是几万字的报告、不是博客文章的时候才值得这么做。

> **无论用哪条，都记得看一眼 `finish_reason`。** [第 6 卷第 8 章](../06-本地模型/08-局域网API.md)讲过：`stop` 是正常说完，**`length` 是它的回答被长度上限截断了**，那说明摘要本身是半截的——这跟上面说的输入被截断是两回事，**一个是它没看全，一个是它没说完。**
