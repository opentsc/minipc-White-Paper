# 04　装机镜像

## 这一章的任务

把配好的这台机器做成一个母盘，下一台照着写回去，半天装完。

**先把这一章和[第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)的分工说清楚，因为它们用的是同一个工具、同一套操作。**

| | [第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)的恢复镜像 | 这一章的母盘 |
| --- | --- | --- |
| 做给谁用 | **你自己这台机器** | **下一台要交出去的机器** |
| 什么时候做 | 装完系统越早越好 | **配置稳定、不再天天改的时候** |
| 里面有什么 | **你现在的全部东西**，密钥、测试数据、历史记录都在 | **清理过的，一样私人东西都没有** |
| 写回哪儿 | 写回原来那一台 | **写到新买的那一台** |
| 写回之后 | **什么都不用改**，回到做镜像那一刻 | **必须改一串东西**，见本章第四节 |
| 用几次 | 一台一次 | **一份用很多次** |

**一句话：那一章的镜像是你的退路，这一章的母盘是你的产线。**

**做法本身不重抄。** 怎么从 Live 模式启动、怎么用“磁盘”程序创建和恢复磁盘映像、写错盘会怎样——[第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)写全了。**这一章写的是它前后那两段：做之前清理什么，写回之后必须改什么。**

## 开始前

- [第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)做过一遍。**没做过就先去做那一章**，这一章假设你会用那个“磁盘”程序；
- **一台配置已经稳定的机器。** 判断标准是这一周你没有再改过任何配置——**还在天天调的东西不该做成母盘**；
- 一块移动硬盘，可用空间不小于内置 SSD 的标称容量（[第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)那条规矩）；
- 那个恢复 U 盘；
- **一段不用这台机器的时间。** 做镜像那一步要连续几个小时，中途不能拔线；
- **清理那一段单独留一个小时**，别赶。

## 新词

**母盘**：**从一台配置好、清理干净的机器上做出来的镜像文件**，用来装下一台。它和[第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)那个备份镜像是同一种文件，**区别全在里面装了什么。**

**清理**：**把母盘里属于你个人和上一个客户的东西删掉。** 这一章第一节的全部内容。

**机器唯一标识**：**系统装好时生成的一串编号，用来在网络上区分不同的机器。** 整盘复制会把它一起复制过去，**两台机器带着同一个编号上同一个网络，会出各种说不清的毛病。** 第四节处理它。

**出厂检查**：**新装好一台机器，交出去之前逐项确认一遍。** 本章第五节那张单子。

## 一、做镜像之前先清理

**这一节是本章最要紧的一节。**

**跳过它的后果是具体的**：你的 SSH 私钥、上一个客户的合同、你自己的命令历史，**随着这块母盘装进了下一个客户的机器。** 而母盘会被反复使用——**清一次，管很多台；漏一样，也漏很多台。**

### 清理清单

**四组。打印出来，一项一项划掉。**

```text
========== 母盘清理清单 ==========
清理人：　　　　　　　日期：

---------- 第一组　钥匙 ----------
□ SSH 私钥和公钥（~/.ssh/ 整个目录）
□ ~/.ssh/authorized_keys（放进来的别人的公钥）
□ 各种 API 密钥、令牌、.env 文件
□ n8n 里存的凭据（SMTP、邮箱、别的系统）
□ Open WebUI 里建的账户，尤其是管理员账户
□ 浏览器里保存的密码和登录状态
□ 已保存的 Wi-Fi 网络和密码
□ Tailscale 的登录状态（退出登录，不是只断开）
□ Git 里配置的远程地址和凭据

---------- 第二组　数据 ----------
□ 测试数据和样例文件
□ 上一个客户的任何文件（原件、跑出来的结果、台账、日报）
□ 知识库里已经建好的库和上传的原件
□ 跑出来的中间文件（out/、failed/、done/、各种 .csv）
□ 下载目录、文档目录、桌面上的东西
□ 回收站

---------- 第三组　痕迹 ----------
□ 命令历史（~/.bash_history）
□ 浏览器历史记录
□ 应用的执行记录与运行日志（n8n 的执行记录、系统日志）
□ 最近打开的文件列表

---------- 第四组　身份 ----------
□ 主机名改成一个中性的（例如 minipc-base）
□ 固定 IP 改回自动获取（不改的话新机器和母机会撞地址）
□ 定时任务里的收件人邮箱，换成占位或者删掉
□ 你自己那个个人账户删掉，只留一个交付用的初始账户
□ 那个初始账户的密码设成一个已知的初始密码，交付时必改
==================================
```

**四组里最容易漏的是第三组。** 钥匙和数据你会想起来，**命令历史不会**——而它里面有你敲过的路径、地址，有时候还有密码。

**第四组那两条“身份”单独说：**

- **主机名不改**，装出来的每一台都叫同一个名字。**同一个局域网里两台重名的机器，谁也说不清哪台是哪台**；
- **固定 IP 不改回自动获取**，新机器一插上客户的网，**它和母机（或者上一台）用同一个地址**，两台一起打不开。

### 清理完先重启一次

**这一步不能省。**

清理是删东西，**删东西容易删坏**。删完立刻做镜像，坏的那一份会被复制到每一台机器上。

**重启之后确认三件事：**

```text
□ 能正常开机、能登录那个初始账户
□ 该起来的服务都起来了
□ 模型还在，问一句有回应
```

**三件事都对，才动手做镜像。**

## 二、做镜像

**做法照[第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)第三步，本章不重抄。** 关机、插恢复 U 盘、选“试用 Ubuntu”、打开“磁盘”程序、选中内置 SSD、创建磁盘映像、存到移动硬盘上。

**这一章要补的只有三条。**

**一、文件名带日期和版本号。**

```text
base-2026-08-20-v1.img
```

**理由和[第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)那条一样**——**你会有好几份，而它们看起来一模一样。**

**二、一份母盘配一份说明，放在同一个目录里。**

```text
========== 母盘说明 ==========
镜像文件名：
做的日期：　　　　版本：
从哪台机器上做的：
里面装了什么（服务、应用、模型，一行一个）：

初始账户名：　　　初始密码：
主机名（母盘里的）：
IP 获取方式：自动

哪些东西是空的（清理清单第几组已执行）：
开机后必改清单在哪儿：（本章第四节）
上一次用它装机是什么时候、装了哪台：
==============================
```

**填好的样子（虚构示例，客户与编号全部虚构）：**

```text
========== 母盘说明 ==========
镜像文件名：base-2026-08-20-v1.img
做的日期：2026-08-20　　版本：v1
从哪台机器上做的：样机 MP-BASE-01（这台不交付）
里面装了什么：
　Ubuntu（版本见开机后 cat /etc/os-release）
　Docker
　llama.cpp，读单据那个服务
　Ollama，一个向量模型
　发票台账那三个脚本

初始账户名：ops　　初始密码：（写在移动硬盘里那份密码本上，不写这张纸）
主机名（母盘里的）：minipc-base
IP 获取方式：自动

哪些东西是空的：清理清单四组全部执行，2026-08-20 由李工执行并签字
开机后必改清单在哪儿：和本文件同目录，必改清单.md
上一次用它装机是什么时候、装了哪台：2026-08-22，装了 MP-2026-003
==============================
```

**这份说明的作用在三个月之后才显出来**——那时候你会有两三份母盘，**记不清哪一份里有什么。**

**三、母盘只从你自己那台干净的样机上做。**

**不要在客户机器上装完、用一阵子、再做一份母盘。** 那台机器上已经有客户的数据和配置，**清理一遍也未必清得干净。**

**规矩是：一台样机专门用来生母盘，它不交付、不接客户的数据。** 没有条件专门留一台的话，**至少在做母盘之前把清理清单完整跑一遍，一条不跳。**

## 三、写回新机器

**做法照[第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)“把镜像写回硬盘”那一节，本章不重抄。** 确认设备名那几步一步都不能跳，**写错盘没有恢复办法**，那一章写清了三种写错的后果。

**这一章补两条。**

**一、新机器的 SSD 容量不能小于母机的。**

镜像是整块盘的原样复制。**母机 2 TB，新机器 1 TB，写不进去**——[第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)提过这一条，程序会报错拒绝执行。

**采购的时候要注意这件事**：**几台机器的 SSD 容量最好一致**，不一致的话母盘要从容量最小的那一台上做。

**二、写回之后第一次开机，不要接客户的网络。**

**理由是第四节那张必改清单**：这时候这台机器的主机名、机器唯一标识、初始密码，**和母机以及之前装的每一台都是一样的。**

**一插上客户的网就可能出事**——两台机器抢同一个地址、内部服务连到了错的那一台。**先不接网，或者接你自己带的路由器，把必改清单做完再上他们的网。**

## 四、开机后必改清单

**这一节是母盘这条路唯一的代价：每装一台，下面这些必须改一遍。**

**照这张单子走，一项一项划掉。**

```text
========== 开机后必改清单 ==========
这台机器给谁：　　　　装机日期：
机器编号（你自己编的）：

---------- 必改，一项都不能跳 ----------
□ 1. 主机名改成这一台的（例如 minipc-远岭-01）
□ 2. 初始账户的密码改掉，改完用新密码登一次
□ 3. 重新生成这台机器的 SSH 主机密钥
□ 4. 重新生成机器唯一标识
□ 5. 网络：客户要固定 IP 的，在这儿设；不要沿用母盘里的
□ 6. 时区（母盘上是哪个时区，这一台在哪儿）

---------- 应用这一层 ----------
□ 7. 建客户自己的管理员账户，母盘里那个初始账户改密或删掉
□ 8. 该填的凭据重新填（邮箱、SMTP、要对接的系统）
□ 9. 定时任务里的收件人换成客户的
□ 10. 需要的话重新登录 Tailscale（这一台是这一台的身份）

---------- 交付这一层 ----------
□ 11. 那一页说明书按这一台的地址和账号填好、打印出来
□ 12. 机器编号贴在机身上，记进你自己的台账
====================================
```

**第 1、2 项是最基本的，也是最容易被“回头再改”的。** 回头就忘了——**装机当天不改，之后不会有人再想起来。**

**第 3、4 项要单独说。**

**整盘复制会把这台机器的身份一起复制过去**，具体是两样东西：

- **SSH 主机密钥**——每台机器本该有一把自己的。**几台机器共用一把**，远程连接的那一层就分不清它们；
- **机器唯一标识**（`/etc/machine-id`）——**几台机器带着同一个标识连进同一个网络，路由器可能给它们分同一个地址**，然后两台都时好时坏。

**做法（Ubuntu 上的通用做法）**：

```bash
sudo rm -f /etc/ssh/ssh_host_*
sudo dpkg-reconfigure openssh-server
```

第一条删掉复制过来的那几把主机密钥，第二条让系统重新生成一套。

```bash
sudo truncate -s 0 /etc/machine-id
sudo rm -f /var/lib/dbus/machine-id
sudo systemd-machine-id-setup
sudo ln -s /etc/machine-id /var/lib/dbus/machine-id
```

第一条把那个标识清空，第二条删掉另一处的副本，第三条重新生成一个，第四条把两处接回来。**改完重启一次。**

> **这两组命令是 Ubuntu 与 systemd 上的通用做法，本项目未在这台设备上逐条实测，需要核验。** 具体路径与命令随发行版和版本变化，**动手当天以你系统上的文档为准**。做完照第五节那张出厂检查单走一遍，**能不能用以那一遍的结果为准。**

## 五、出厂检查单

**这一节是这一章的验收：装完一台新机器，交出去之前逐项确认。**

**十一项，全部打勾才算这台机器可以交。**

```text
========== 出厂检查单 ==========
机器编号：　　　　　交给谁：　　　　　检查人：　　　　　日期：

□ 1. 主机名是这一台的，不是母盘那个
□ 2. 初始密码进不去了，新密码能进
□ 3. 该起来的服务都起来了，重启一次之后还在
□ 4. 模型在，问一句有回应
□ 5. 局域网能访问：另一台电脑上打开那个地址，进得去
□ 6. 断电再来电，服务自己回来（拔电源试一次）
□ 7. 备份任务在跑，而且还原验证过一次
□ 8. 定时任务里的收件人是客户的，不是你的
□ 9. 母盘里那个初始账户已经删掉或者改密
□ 10. 命令历史、浏览器记录、Tailscale 登录状态都是干净的
□ 11. 那一页说明书按这一台填好了，打印出来放在机器旁边

不通过的项目和处理：

检查人签字：
================================
```

**第 6 项容易被跳过，但它是客户最先遇到的一种情况**——办公室停一次电。**做法在[第 3 卷](../03-服务器基础/README.md)，实验在 [level-30／01](../../labs/level-30/01-remote-managed-box/README.md)**。

**第 7 项那个“还原验证过一次”是[level-20／01](../../labs/level-20/01-daily-backup/README.md)的要求**——**备份任务在跑不等于还得回来**，那个实验专门解决这一条。

**第 10 项是回头复查清理清单。** 母盘清干净了，装机过程中你又敲过命令、又开过浏览器——**这些是这一台上新产生的，要在交付前再清一次。**

## 什么时候该重做母盘

**四种情况，出现任何一种，这份母盘就过期了：**

```text
换了模型　　　　　　　　　　母盘里那个还是旧的，装出来的每一台都要手动换
系统升级了大版本　　　　　　旧母盘装出来的机器要立刻打一堆更新
加了新服务或者改了目录结构　母盘和你现在的做法对不上了
清理清单改过　　　　　　　　说明上一份母盘里可能漏了什么
```

**重做的成本是几个小时，不重做的成本是每装一台都要手动补一遍。** 装到第三台你就会算明白这笔账。

> **旧母盘不要删。** [第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)那条规矩在这里同样成立——**新的那份出问题的时候，旧的是唯一的退路。** 移动硬盘上留两份，文件名上的日期看得见。
