## 新词

**PyTorch**：一套用 Python 写的深度学习框架。本地跑模型的很多工具底下都是它。**它自己不带 GPU 驱动**，靠底下的计算栈干活——在 NVIDIA 那边是 CUDA，在这台设备上是 ROCm（第 5 章）。

**张量**（tensor）：一堆按行列（或者更多层）排好的数字。**一个数是标量，一行数是向量，一张表是矩阵，再往上堆就叫张量。** 模型里的参数和中间结果全是张量。本章那段验证代码做的事，就是造两个张量、让 GPU 把它们乘一次。

**Python 虚拟环境**（venv）：一个独立的 Python 包安装目录。**装在里面的包只对这个环境生效，不影响系统里的 Python。** 本教材直接装那条路一律用它，理由见下面的警告块。

**pip**：Python 的包安装工具。

**wheel**：Python 包的预编译发行格式，文件名以 `.whl` 结尾。**有 wheel 就不用自己编译**（第 15 章讲过 vLLM 在这台设备上没有 wheel）。

**每日构建**（nightly）：见第 7 章新词。**材料里三条 PyTorch 相关记录用的都是这种构建**，这一点本章要反复提。

**bf16**：一种 16 位的数字格式（brain floating point 16），用来在训练和推理时省内存、跑得快些。**代价是精度低**，边界上容易出问题——本章末尾那一节讲的就是这个。

**梯度**（gradient）：训练时用来决定“参数该往哪个方向调”的那组数。**梯度算出来是 NaN，训练就废了**。

**NaN**：Not a Number，一个表示“这不是个有效数字”的特殊值。**一旦出现就会沿着计算传染下去**。

**批量大小**（batch size）：一次同时处理多少条数据。

**学习率**（learning rate）：训练时每一步把参数调多少。

**推理**与**训练**：推理是拿已经训好的模型来算答案；训练是用数据去改模型的参数。**本教材主线是推理。**

## 先说清楚：本教材不给版本号

**第 8 章表一里 PyTorch 那一行写的是“本项目未记录可推荐的版本号，需要核验”。本章不填这个空。**

理由是明摆着的：本项目材料里三条 PyTorch 相关的记录（ROCm issue #5824、#5991、#6034，访问日期均为 2026-08-13）**用的都是每日构建**。每日构建是当天自动打的包，没有经过正式发布的测试。**拿一个每日构建的编号当版本推荐，是在给你一个不成立的确定感。**

**所以本章的做法是：**

1. **动手当天去 PyTorch 官方的安装页面**，按页面上的选择器选 Linux、pip、ROCm，把它给出的那条命令原样抄下来；
2. **把抄下来的命令、页面地址、ROCm 版本和当天日期一起记进[第 4 卷第 16 章](../04-Max395硬件/16-设备基线.md)的设备基线**；
3. **不要照抄别人博客里的版本号。** 那些数字绑着别人的内核、别人的 ROCm 版本、别人的发行版。

> **本教材不列 PyTorch 官方安装页面上那条命令的具体内容。** 那条命令随 ROCm 版本滚动更新，写死在书里的第二天就可能不对。**页面上给什么，你抄什么。**

**装之前先确认一件事：页面上给出的 ROCm 版本，和你第 14 章 `hipconfig --version` 看到的那个对得上。** 对不上的处理办法在本章末尾“看到不同结果怎么办”。

## 两条路，先选一条

| | 直接装 | 用容器 |
| --- | --- | --- |
| 装在哪 | 宿主机上一个 Python 虚拟环境里 | 容器里 |
| 适合什么人 | **长期就用一套**，不打算频繁换版本 | **要同时试几个版本**，或者不想在宿主机上留痕迹 |
| ROCm 从哪来 | 宿主机上那一套（第 11 章） | **镜像里自带的那一套**，可以和宿主机不同 |
| 出问题好不好清 | 删掉虚拟环境目录就行 | 容器删掉就没了 |
| 磁盘占用 | 几 GB | **镜像常在十几 GB** |
| 前置条件 | 第 11 章、第 14 章 | 第 11 章、第 14 章、第 15 章 |

**本教材的建议：先按直接装那条路走一遍。** 理由是变量少——出问题时不用先分清是容器的事还是 PyTorch 的事。**跑通之后要试别的版本，再上容器。**

**两条路有一件事是共通的，第 15 章那一节已经讲过，这里再说一遍：内核是共用的。** 容器里换一个更新的 ROCm，绕不过内核那一层的门槛（ROCm issue #5444，访问日期 2026-08-13）。

## 路线一：直接装

> **⚠️ 不要用 `sudo pip install` 把 PyTorch 装进系统的 Python。**
>
> Ubuntu 的很多系统组件本身是用 Python 写的，它们依赖系统 Python 里那些包的特定版本。**用 `sudo pip` 往里面塞包，可能把系统工具搞坏**——常见后果是软件更新工具、桌面里的某些程序打不开。
>
> 新版的 pip 会直接拦住这种做法并提示 `externally-managed-environment`。**看到那个提示是好事，说明它在保护你。不要去找绕过它的办法。**
>
> **本教材的做法是用虚拟环境**，下面第一步就是建它。
>
> **万一已经装进系统 Python 了怎么恢复**：跑 `sudo pip uninstall torch torchvision torchaudio` 把装进去的拆掉；系统工具已经出问题的，用 `sudo apt install --reinstall python3-<出问题的包名>` 重装对应的系统包。**拆不干净、系统工具还是坏的，就用[第 9 章](09-安装前备份.md)的备份恢复**，恢复介质见[第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)。

### 第一步：确认 Python 在

```bash
python3 --version
```

- **作用**：打印系统里 Python 3 的版本号。这条命令只读；
- **正常输出**：一行，形如

```text
Python 3.12.3
```

**Ubuntu 24.04 自带 Python 3，版本号随小版本变化，本项目未固定，需要核验**；

- **看到别的怎么办**：
  - **提示 `command not found`** —— 装 `python3`：`sudo apt install python3`。Ubuntu 桌面版正常情况下自带，出现这种情况说明有人拆过；
  - **版本号是 3.8 之类明显旧的** —— 有人装过别的 Python 并改了默认。**先搞清楚这台机器上有几个 Python**，处理办法在[第 2 卷](../02-Ubuntu/README.md)；
- **怎么停止或撤销**：只读命令，不需要撤销。

### 第二步：建一个虚拟环境

```bash
sudo apt install python3-venv
```

- **作用**：装建虚拟环境要用的那个模块。Ubuntu 把它拆成了单独的包；
- **正常输出**：一串安装进度，最后回到提示符。**已经装过的会提示 `is already the newest version`，那也是正常的**；
- **看到别的怎么办**：
  - **提示 `Unable to locate package`** —— 先 `sudo apt update` 再重试；
  - **提示要装的包名带版本号（比如 `python3.12-venv`）** —— 按提示装那个；
- **怎么停止或撤销**：`sudo apt purge python3-venv`。**不建议撤销**，这个包很小，别的东西也可能用到它。

```bash
python3 -m venv ~/torch-env
```

- **作用**：在你的家目录下建一个叫 `torch-env` 的虚拟环境。**这个目录就是后面所有 Python 包的家**；
- **正常输出**：**什么都不显示**，几秒钟后回到提示符。跑完 `ls ~/torch-env` 能看到 `bin`、`lib` 这几个目录；
- **看到别的怎么办**：
  - **提示 `ensurepip is not available`** —— 上一条的 `python3-venv` 没装成功，回上一步；
  - **提示目录已存在** —— 之前建过。**要重来就先删掉：`rm -rf ~/torch-env`**，这个目录里只有包，删了不影响别的；
- **怎么停止或撤销**：`rm -rf ~/torch-env`。**这就是这条路的完整卸载方法**——虚拟环境里的东西全在这一个目录里，删掉就干净了。

```bash
source ~/torch-env/bin/activate
```

- **作用**：进入这个虚拟环境。**从这一刻起，这个终端里跑的 `python` 和 `pip` 都是虚拟环境里的那一份**；
- **正常输出**：提示符最前面多出一个 `(torch-env)`，形如

```text
(torch-env) roland@minipc:~$
```

- **看到别的怎么办**：
  - **提示符没变** —— 环境没进去。确认路径写对了，或者换一个终端重试；
  - **提示 `No such file or directory`** —— 上一条建环境没成功；
  - **换了一个终端窗口，`(torch-env)` 不见了** —— **正常。虚拟环境只对当前这个终端生效**，每开一个新终端都要重跑这条命令；
- **怎么停止或撤销**：输入 `deactivate` 退出虚拟环境，提示符前面那个 `(torch-env)` 会消失。

### 第三步：装 PyTorch

> **⚠️ 这一步会下载几 GB 的东西。** 网络慢的话要等很久，中途断了要重来。**先用 `df -h /` 确认剩余空间够**（[第 4 卷第 13 章](../04-Max395硬件/13-SSD.md)）。

**命令去 PyTorch 官方安装页面抄**，选 Linux、pip、ROCm。抄下来的那条形状大致是

```text
pip install torch torchvision torchaudio --index-url <官方页面上给的那个地址>
```

- **作用**：从 PyTorch 官方给 ROCm 准备的那个下载地址装 PyTorch 及配套的两个包。`--index-url` 是告诉 pip 去哪儿下——**这一项不能省，省了会装到 NVIDIA 那一版，在这台设备上跑不起来**；
- **正常输出**：一长串下载和安装进度，最后一行是 `Successfully installed torch-... torchvision-... torchaudio-...` 加一堆依赖包名；
- **看到别的怎么办**：
  - **提示 `externally-managed-environment`** —— 你不在虚拟环境里。回第二步跑 `source ~/torch-env/bin/activate`，确认提示符前面有 `(torch-env)`；
  - **下载到一半断了** —— 重跑同一条命令。pip 会跳过已经装好的；
  - **装完了，但下一步验证说看不到 GPU** —— 大概率装成了 NVIDIA 那一版。跑 `pip uninstall torch torchvision torchaudio` 拆掉，**确认 `--index-url` 那一项抄对了**，重装；
  - **提示磁盘空间不足** —— 清空间，或者换一条路（容器）；
  - **提示找不到匹配当前 Python 版本的包** —— 官方那个下载地址里没有给你这个 Python 版本编的包。**这属于版本组合问题，抄下完整报错，去官方页面看它支持哪些 Python 版本**；
- **怎么停止或撤销**：中途按 `Ctrl+C`。装完要撤销，直接 `rm -rf ~/torch-env` 把整个虚拟环境删掉，**比一个个 `pip uninstall` 干净**。

## 路线二：用容器

**前提是第 15 章跑通了。**

镜像去 PyTorch 或 AMD 的官方页面抄当天给出的那个，**本项目未固定镜像名，需要核验**（第 15 章已标注同一条）。起容器的命令形状是

```bash
docker run --rm -it \
  --device=/dev/kfd --device=/dev/dri \
  --group-add video --group-add render \
  -v ~/models:/models \
  你抄下来的镜像名:标签 bash
```

- **作用**：起一个带 PyTorch 和 ROCm 的容器，把两个设备节点映射进去，把宿主机上的模型目录挂进去，然后进容器的命令行。
  - `-it` 表示进交互模式，**跑完不自动退出**，你可以在里面敲命令；
  - 其余参数第 15 章都解释过，本章不重讲；
- **正常输出**：第一次会先下载镜像（**常在十几 GB，要等**），下载完提示符变成容器里的样子，通常是 `root@` 加一串随机字符；
- **看到别的怎么办**：
  - **报权限错、或者进去之后看不到 GPU** —— 回第 15 章第四步的异常分支，**那一章的分支更全**；
  - **镜像拉不下来** —— 名字或标签抄错了，或者标签下架了。回官方页面重抄；
  - **进去之后 `python` 找不到 PyTorch** —— 镜像里的 PyTorch 可能装在某个特定的虚拟环境里。用 `pip list | grep -i torch` 找一下，或者看镜像页面的说明；
- **怎么停止或撤销**：在容器里输入 `exit` 退出，`--rm` 会把容器删掉。**镜像还在磁盘上**，清理办法在第 15 章“停止和清理”那一节。

**进了容器之后，下面那两段验证代码照样跑，一模一样。**

## 最小验证：两段代码

**分两段跑，不要合成一段。** 第一段只问“看不看得见”，第二段才真的让 GPU 算一次。**分开是为了出问题时能立刻分清是哪一步。**

### 验证一：能不能看到这块 GPU

```bash
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else '没有可用设备')"
```

- **作用**：打印三样东西——PyTorch 的版本、有没有可用的 GPU、这块 GPU 叫什么。`python -c "..."` 表示把引号里那段当成 Python 代码直接执行，不用先写文件。**这段代码只读，不改任何东西**；
- **正常输出**：三行，形如

```text
2.x.x+rocm6.x
True
AMD Radeon Graphics
```

  **三行都要看：**

  1. **第一行**是版本号，**里面应当带 `rocm` 字样**。带 `cu` 加数字（比如 `+cu124`）的是 NVIDIA 那一版，装错了；
  2. **第二行必须是 `True`**。这是本段的核心；
  3. **第三行**是设备名。**具体写法随 ROCm 版本和驱动变化，本项目未固定，需要核验**——有的版本显示 `AMD Radeon Graphics`，有的带上 `gfx1151`。**认得出是 AMD 的这块就算过**；

> **为什么在 AMD 的设备上还写 `torch.cuda`？**
>
> 这是 PyTorch 的历史包袱。**在 ROCm 版的 PyTorch 里，`torch.cuda` 这一套接口被接到了 ROCm 上**，名字没改。所以你看到 `cuda` 字样不用慌，也**不要因此以为需要装 CUDA**（那是 NVIDIA 的东西，这台设备上装不了也用不着）。
>
> 网上那些写 `.cuda()`、`device="cuda"` 的 PyTorch 代码，在这台设备上多数可以原样跑。

- **看到别的怎么办**：
  - **第二行是 `False`** —— 按顺序查四件事：① 版本号里有没有 `rocm`（没有就是装错版本，回第三步重装）；② 宿主机上第 14 章的 `rocminfo` 能不能看到 `gfx1151`；③ `groups` 里有没有 `render` 和 `video`（第 11 章第七步）；④ 走容器的话，两个 `--device` 映射有没有写全（第 15 章）。**四件里任何一件不对，都会是 `False`**；
  - **报 `ModuleNotFoundError: No module named 'torch'`** —— 没装成功，或者你不在虚拟环境里。确认提示符前面有 `(torch-env)`；
  - **报 `ImportError` 提到 `libhsa-runtime64.so` 或者别的 `.so` 文件找不到** —— ROCm 那一层的库路径没配好。回第 11 章第八步看 `/etc/ld.so.conf.d/` 那一节，**没重启过的先重启**；
  - **报 `RuntimeError: No HIP GPUs are available`** —— 和 `False` 同一类问题，按上面四件事查；
  - **整条命令跑了很久没反应** —— **这是要留意的一种情况**。材料里记录过基础操作挂起不报错的情况（ROCm issue #5991，访问日期 2026-08-13，**未给修复结论**）。按 `Ctrl+C` 中断，然后跑 `sudo dmesg | tail -30` 看系统日志里有没有 `amdgpu` 相关的缺页记录，抄下来；
- **怎么停止或撤销**：这段代码只读，不需要撤销。跑不动按 `Ctrl+C`。

### 验证二：能不能在 GPU 上做一次张量运算

**上一段过了才跑这一段。**

```bash
python -c "import torch; a = torch.randn(1024, 1024, device='cuda'); b = torch.randn(1024, 1024, device='cuda'); c = a @ b; torch.cuda.synchronize(); print(c.shape); print(float(c.sum()))"
```

- **作用**：在 GPU 上造两个 1024 行 1024 列的随机数张量，让 GPU 把它们乘一次，等 GPU 真的算完，然后打印结果的形状和所有元素的和。
  - `torch.randn(...)` 造随机数张量，`device='cuda'` 表示造在 GPU 上；
  - `@` 是矩阵乘法；
  - **`torch.cuda.synchronize()` 这一句不能省**——GPU 上的计算是异步的，不加这一句，程序可能在 GPU 还没算完时就往下走，**错误会晚一步才冒出来，看着像是别的地方出的问题**；

  **这段代码会真的占用显存和 GPU**，跑完就释放；

- **正常输出**：两行，形如

```text
torch.Size([1024, 1024])
-1234.567...
```

  **第一行必须是 `torch.Size([1024, 1024])`**。第二行是个随机数，**每次跑都不一样，这是正常的**——输入本来就是随机的。**要看的是它是个正常的数字，不是 `nan` 也不是 `inf`**；

- **看到别的怎么办**：
  - **第二行打印出 `nan`** —— 算出来的不是有效数字。**重跑一次**，还是 `nan` 的话把版本组合抄下来（PyTorch 版本、ROCm 版本、内核版本），这属于要上报的情况；
  - **报 `hipErrorOutOfMemory` 或者提到 `hipMalloc`** —— 显存申请失败。**这台设备上要先排除“假的内存不足”**——ROCm 可能只看到一部分内存（第 6 章、第 7 章）。回第 14 章看 `rocm-smi` 报的显存数对不对，处理在第 20 章；
  - **报 `Memory access fault by GPU node-1 ... Page not present or supervisor privilege`** —— **这是材料里记录过的一条**（ROCm issue #5824，访问日期 2026-08-13，2026-08-13 核对已关闭但页面未显示关闭说明）。报告指向某一版固件造成的固件回退，**但那份报告的环境是 Fedora 与 Nobara，不是 Ubuntu，需要核验**。处理方向：先按第 2 章第五节查固件版本和最近的系统更新，再怀疑框架；具体处理在第 20 章、第 21 章；
  - **报找不到对应的代码对象、`no kernel image is available`** —— 装的这一版里没有为 gfx1151 编译的代码对象（第 6 章、第 7 章）。**换版本，不要设 `HSA_OVERRIDE_GFX_VERSION`**（第 7 章）；
  - **进程挂在那儿既不出结果也不报错** —— 材料里记录过这种情况（ROCm issue #5991，访问日期 2026-08-13，**未给修复结论**）。按 `Ctrl+C`；杀不掉的话另开一个终端用 `sudo dmesg | tail -30` 看日志，抄下来；
  - **屏幕闪了一下、桌面卡住** —— GPU 那一层出了问题。第 20 章有一节讲这类情况；
- **怎么停止或撤销**：按 `Ctrl+C` 中断。**这段代码不写任何文件、不改任何配置**，中断之后显存会释放。**显存没释放（`rocm-smi` 里还占着）的处理办法在第 20 章。**

**两段都过了，PyTorch 这条路就算通了。**

## 通了之后不能得出的结论

**这两段代码过了，只说明四件事：** PyTorch 装对了版本、能看到这块 GPU、能在上面申请显存、能完成一次矩阵乘法。

**不能得出的结论有五条：**

1. **不能说明任何一个模型都能跑通。** 一次矩阵乘法用到的算子，比一个真实模型用到的少得多。第 7 章那句话在这里同样成立：**列入支持不等于全部算子可用**；
2. **不能说明速度**。本章不测速度，也不给任何速度数字。测法在第 19 章；
3. **不能说明长时间跑得稳。** 一秒钟的计算和连续跑几个小时是两回事——材料里记录过长上下文推理中途出现超时与设备丢失的情况（第 4 章已标注，**素材记录，需要核验**）；
4. **不能说明训练能用。** 训练那一侧的边界见下一节；
5. **不能拿来给客户承诺。** 承诺要绑版本、绑日期、绑你自己实测过的那条路（第 8 章、第 13 卷）。

## 推理和训练要分开看

**这一节是本章的边界声明，不能跳。**

**推理这一侧**：第 7 章的结论是可以走。本章上面那两段验证过的就是推理路径上最基础的东西。

**训练这一侧有明确记录的雷区：**

材料记录，PyTorch 的每日构建在这台设备上训练时有 **5 项 bf16 精度边界缺陷**——特定的超参组合会让梯度必然出 NaN（ROCm issue #6034，访问日期 2026-08-13，社区问题追踪）。记录到的触发条件包括：

| 触发条件 | 材料里记录的值 |
| --- | --- |
| 批量大小 | 在 2 的 13 次方那个阈值上 |
| 注意力头维度 | 32 |
| 层数 | 超过 12 层 |
| 矩阵学习率 | 0.20 |

**读这张表要带的四条限制，一条都不能省：**

1. **这是训练场景的记录，推理路径不受同一组条件约束**（第 7 章已标注同一条）；
2. **来源是社区问题追踪，用的是单一每日构建**，不是正式发布版；
3. **这四项是材料里记录到的触发条件，不是全部。** 没写进来的组合不等于安全；
4. **本项目没有在这台设备上复现过这些条件，需要核验。**

**实际做法：**

- **本教材主线是推理，不是训练。** 要在这台设备上训练，属于超出本教材主线的用法；
- 真要训练，**逐项避开上面那些组合**（材料里提到的方向是把批量大小提到 2 的 15 次方、学习率压回 0.15），**并且清楚这是单一构建上的记录**；
- **训练前后都要存检查点。** 梯度出 NaN 这类问题不报错、不崩溃，**只有你自己看损失曲线才能发现**；
- **不要把训练能力写进给客户的承诺。**

> **这一节讲的是数值精度的边界，不是“这台设备不能训练”。** 本项目没有做过训练场景的实测，**给不出“能”或者“不能”的结论，需要核验**。

## 正常结果

做完本章，你手上应当有这几样：

- 一个能用的 PyTorch，装在虚拟环境里或者容器里；
- 验证一：版本号里带 `rocm`，`torch.cuda.is_available()` 是 `True`，能打印出设备名；
- 验证二：矩阵乘法跑通，形状是 `torch.Size([1024, 1024])`，和不是 `nan`；
- 设备基线里多了 PyTorch 那几行，**带着核对日期**；
- 你能说出**为什么本教材不给 PyTorch 的版本号**；
- 你知道 `torch.cuda` 在这台设备上接的是 ROCm，**不需要装 CUDA**；
- 你能说出**推理和训练在这台设备上的结论不一样**，训练那一侧有 5 项 bf16 边界缺陷，而且那是单一每日构建上的记录。

## 看到不同结果怎么办

**官方页面给的 ROCm 版本和你装的对不上**：先看差多少。**页面要求的比你装的新**，两条路——升 ROCm（第 21 章，**动手之前先做备份，步骤见第 9 章**），或者找页面上有没有对应你这一版的选项。**页面要求的比你装的旧**，通常能跑，但属于没人测过的组合，**跑通了也要在基线里注明**。

**你搜到的教程给了一个具体的 PyTorch 版本号**：先看那篇教程的日期、它用的 ROCm 版本和发行版。**对不上就不要照抄。** 本教材的做法在本章第一节。

**`torch.cuda.is_available()` 是 `True`，但一跑真实模型就报错**：正常，这两件事本来就不等价（本章“通了之后不能得出的结论”第一条）。**把完整报错抄下来**，按第 20 章的症状表对。

**你想装 NVIDIA 那一版试试**：装不了，也没意义。**这台设备上没有 NVIDIA 的硬件**，CUDA 那一套跑不起来。看到 `torch.cuda` 就以为要装 CUDA，是本章最常见的一个误会。

**你同时要试两个 PyTorch 版本**：**不要在同一个虚拟环境里换来换去。** 建两个虚拟环境（`~/torch-env-a`、`~/torch-env-b`），或者用容器。**一次只改一个变量**，这是[第 4 卷第 10 章](../04-Max395硬件/10-功耗模式.md)那套判断方法的通用规矩。

**跑起来之后想看 GPU 到底有没有在干活**：第 19 章讲怎么观察，工具在[第 4 卷第 12 章](../04-Max395硬件/12-温度与频率.md)。**本章不测这个。**

**你只想跑 llama.cpp 或 Ollama，在想要不要装 PyTorch**：不用装。那两条路不经过 PyTorch（第 4 章那张表）。**Vulkan 那条路连 ROCm 都不需要**（第 8 章）。

**跑验证二时机器整个卡住、桌面假死**：这属于第 7 章第六条那一类——**先查固件版本和最近的系统更新，再怀疑框架**（第 2 章第五节）。恢复和处理在第 20 章、第 21 章。
