## 新词

**SSD**（Solid State Drive，固态硬盘）：用闪存芯片存数据的硬盘，里面没有会转的盘片，也没有机械臂。

**M.2**：一种硬盘的外形规格。长条形，像一片口香糖，插进主板上的插槽，另一头用一颗小螺丝固定。常写成 `2280` 这样的四位数：前两位是宽度 22 mm，后两位是长度 80 mm。

**插槽**（Slot）：主板上用来插硬盘、内存这类部件的接口座。一台机器上有几个插槽，决定了它最多能装几块盘。**插槽是物理的东西，软件命令看不到空的插槽**，只能看到已经插上盘的那些。

**协议**：设备和主板之间“说话的规矩”。同一个 M.2 插槽，有的只认 NVMe 协议的盘，有的两种协议都认。买盘之前要对上，买错了插上去认不到。

**NVMe**（Non-Volatile Memory Express）：专门为固态硬盘设计的一套协议，走 PCIe 通道。比早年的 SATA 协议快出很多。这台设备上的内置盘通常是 NVMe 盘。

**PCIe 通道**：主板上给高速设备用的数据通道。常写成 `PCIe 4.0 x4`：前面是代数，后面是通道数，两个数一起决定这条路有多宽。同一块盘插在 x4 的插槽和 x2 的插槽上，速度不一样。

**健康状态**：硬盘自己统计并汇报的一组数字——累计写进去多少数据、通电了多久、寿命用掉了百分之多少、有没有出过错。读这组数字要专门的工具，肉眼看不出来。

**已用寿命**（Percentage Used）：闪存有写入次数上限，厂商把累计写入量折算成一个百分比。`0%` 是全新，`100%` 是达到厂商标称的写入量。**到 100% 不等于当天就坏**，它是一个磨损指示，不是倒计时。

**分区**：把一块盘划成几块，各自装东西。系统装在哪一块、模型放在哪一块，就是分区的事。

**挂载**：把一个分区接到目录树上的某个位置，接上之后才能往里读写。没挂载的分区在“文件”程序里看不见。

## 这台设备上的硬盘：各家不同

Max395 是 AMD 的芯片，硬盘接什么、有几个插槽、走几条 PCIe 通道，**全部由整机厂决定**。AMD 公布的芯片规格里没有这一项（第 1 章）。

不同整机上常见的几种情况：

- **一个 M.2 插槽**：出厂装一块盘，装满了，想扩容只能换掉原来那块；
- **两个或更多 M.2 插槽**：出厂装一块，留一个空位给你自己加；也有出厂就装两块的机型（[第 1 卷第 11 章](../01-开箱与安装/11-收货验收.md)记录过“有的机型出厂装两块 SSD”）；
- **插槽长度不一样**：多数是 2280，也有机型只能放 2242 这种更短的盘；
- **通道数不一样**：同一台机器上的两个插槽，一个可能是 x4，另一个是 x2。

**分品牌的已知线索**

| 品牌 | 已知情况 |
| --- | --- |
| GMKtec EVO-X2 / EVO-X3 | Mini PC 形态。本项目未收集到这台机器的插槽数量与通道规格记录，**需要核验** |
| Beelink GTR9 Pro | Mini PC 形态。[第 1 卷第 11 章](../01-开箱与安装/11-收货验收.md)提示过有机型出厂装两块盘，具体到这个型号**需要核验** |
| Framework Desktop | 桌面形态，可自行维护的设计。插槽数量与规格**需要核验** |
| HP ZBook Ultra G1a | 笔记本形态，机身内部空间比 Mini PC 更紧，可插盘的位置通常更少，**需要核验** |
| 其他品牌 | 按订单页面、说明书和厂商官网的规格表为准 |

**这张表只给方向，不给结论。** 本项目没有逐机型拆机核对过插槽数量、长度和通道数，上面每一行都**需要核验**。以你的订单页面和机器随附的说明书为准，机型差异的完整说明见第 15 章。

## 怎么看自己这台有几块盘、插了什么

四条只读命令，从粗到细。

**一、列出所有盘**

```bash
lsblk -d -o NAME,SIZE,MODEL,TRAN
```

`-d` 只列盘本身、不列分区，`-o` 后面是要显示的列。`TRAN` 是接口类型，NVMe 盘显示 `nvme`，SATA 盘显示 `sata`，插在 USB 口上的移动硬盘显示 `usb`。

内置盘的设备名通常是 `nvme0n1`，第二块是 `nvme1n1`。**后面所有命令里的设备名都以这条命令的输出为准，不要照抄本章的例子。**

**二、看分区和挂载点**

```bash
lsblk
```

不加参数是完整的树：每块盘下面挂着哪几个分区，各自挂载在哪里。系统盘上通常能看到一个几百 MB 的 EFI 分区和一个占掉大部分容量的根分区。

**三、看盘的型号和序列号**

```bash
sudo apt install nvme-cli
sudo nvme list
```

第一条装工具，第二条列出每块 NVMe 盘的设备名、序列号、型号和容量。这条和[第 1 卷第 12 章](../01-开箱与安装/12-硬件问题处理.md)用的是同一条。

> 序列号属于设备标识信息。截图发给别人之前先遮掉它（[证据与发布规则](../../reference/证据与发布规则.md)）。

**四、看主板上认到几个 NVMe 控制器**

```bash
lspci | grep -i "non-volatile"
```

`lspci` 列出插在 PCIe 上的设备，`grep -i` 是不分大小写地过滤。输出几行就是认到几块 NVMe 盘。

**空插槽怎么看**

上面四条都看不到空插槽——**软件只能看到已经插了盘的位置**。想知道还有没有空位，只有三条路：

1. 查机器随附的说明书；
2. 查厂商官网这个型号的规格表；
3. 拆开看。

第三条在动手之前先读下面这一节。

## 加装或更换硬盘和保修的关系

> **⚠️ 开机状态下不要拔插 M.2 硬盘，会损坏硬盘和主板。** 要动手就先关机、拔掉电源适配器、按住电源键 10 秒放掉残余电，再拆。这条和[第 1 卷第 12 章](../01-开箱与安装/12-硬件问题处理.md)是同一条。

拆机和保修的完整说明在[第 1 卷第 12 章“拆机与保修”](../01-开箱与安装/12-硬件问题处理.md)，那里写了保修封条、条款怎么查、动手前留什么证据。这里不重抄，只补三件和硬盘有关的事。

**一、退换货窗口内不要动盘**

规格不符或功能故障，走退换货比自己修划算。拆过之后再申请退货，卖方可能以此为由拒绝。窗口期限见[第 1 卷第 11 章](../01-开箱与安装/11-收货验收.md)。

**二、加装和更换是两件不同的事**

- **加装第二块盘**：原来的系统盘不动，系统照常启动。新盘装上之后还要做分区、格式化、挂载才能用，这属于系统操作，见[第 2 卷](../02-Ubuntu/README.md)；
- **换掉出厂那块系统盘**：等于把系统一起换掉，**要重装 Ubuntu**（[第 1 卷第 7 章](../01-开箱与安装/07-安装Ubuntu.md)）。动手之前先把恢复介质做好（[第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)），把要留的数据备份出去。原来那块盘先别扔、别格式化，留着当退路。

**三、动过硬盘之后要重做一次基线**

设备识别信息、剩余空间、盘的温度都变了，旧基线不能再拿来比。方法见第 16 章。

另外一件容易忽略的事：**M.2 盘满载写入时会发热**。Mini PC 的机身空间小、风道短（第 11 章），加装的第二块盘如果没有散热片，长时间大量写入时温度可能明显高于内置那块。把盘的温度也记进基线（下一节给读法）。

## 模型文件占多少地方

**先说量级，不给具体数字。**

同一个模型，量化档不同，文件大小差得很远；同一个量化档，参数量不同，差得更远。一台机器上通常也不止放一个模型。本教材不抄具体数值，因为模型仓库的文件随时更新，抄下来的数字很快就不准。

要查某个模型某个量化档的精确大小，去模型仓库的文件列表里看——本项目[来源目录](../../reference/source-catalog.md)收录了一个例子，[unsloth/Qwen3.6-35B-A3B-GGUF 仓库文件页（hf-mirror 镜像）](https://hf-mirror.com/unsloth/Qwen3.6-35B-A3B-GGUF/tree/main)（访问日期 2026-08-13），页面上列出各量化档的文件名和精确大小。它是社区转档仓库，不是模型原厂，页面内容随仓库更新变化。**怎么选模型、怎么选量化档在第 6 卷**，本章只管地方够不够。

**为什么要留足空间，而不是“装满为止”**

1. **一台机器上通常放好几个模型。** 换一个模型试试、留一个旧版本做对照，都要占地方；
2. **下载过程中的峰值占用比文件本身大。** 有的下载方式会先落一个临时文件再改名，那一刻盘上同时存在两份；
3. **系统自己要占。** 系统更新、新内核、日志、`apt` 的软件包缓存都写在系统盘上；
4. **容器镜像很占地方。** 第 5 卷用到的 ROCm 容器镜像不小，而且旧镜像不会自己消失；
5. **RAG 要占两份。** 原始文档一份，切分并向量化之后的索引又是一份（第 7 卷）；
6. **系统盘写满之后，故障现象会很难看。** 写不了日志、装不了软件、更新做到一半失败，严重时桌面登不进去——登录过程本身也要写文件。

**本教材的做法**：系统盘上常年留出**至少 20 GB，再加上你最大那个模型的大小**。前一半留给系统自己，后一半留给“再下一个模型试试”。这是本教材定的操作余量，不是硬件指标，你可以按自己的用法调整。

> **⚠️ 系统盘写满会让系统无法正常工作，严重时登不进桌面。** 真的写满了，按下面的顺序清：
>
> ```bash
> sudo apt clean
> sudo journalctl --vacuum-size=200M
> sudo apt autoremove --purge
> ```
>
> 三条分别是：清掉已下载的软件包缓存、把日志压到 200 MB 以内、卸掉不再需要的旧内核和依赖。这三条都不删你的数据文件。清完再用 `df -h` 看还剩多少。还是不够就删模型文件——模型可以重新下载，系统装到一半坏掉要重来。**先清空间，再重启**，不要在盘满的状态下重启。

## 怎么查剩余空间

**看整体**

```bash
df -h
```

`df` 是看各个分区的用量，`-h` 表示用 GB、MB 这种可读格式。看挂载点是 `/` 的那一行，`Avail` 列就是系统盘还剩多少。

输出里通常还有一堆 `tmpfs` 开头的行，那是内存里的临时文件系统，不占硬盘，可以不管。

只看系统盘：

```bash
df -h /
```

**看哪个目录占了地方**

```bash
du -sh ~/* 2>/dev/null | sort -h
```

拆开看：`du` 统计目录占用，`-s` 只给每项的总数不展开，`-h` 可读格式，`~/*` 是你主目录下的每一项，`2>/dev/null` 把没有权限读的那些报错扔掉，`sort -h` 按容量从小到大排。**最占地方的在最后一行。**

**看模型放在哪儿、占了多少**

模型文件的存放位置由你用的推理框架决定。用官方安装脚本装的 Ollama 会创建一个名叫 `ollama` 的系统用户（[Ollama Linux 安装文档](https://docs.ollama.com/linux)，访问日期 2026-08-13），模型也就落在这个用户的目录下：

```bash
sudo du -sh /usr/share/ollama/.ollama/models
```

**这个路径随安装方式和版本变化，本项目未逐版本核对，需要核验。** 路径不对就用上一条的办法从大到小找。第 6 卷会讲清楚各个框架把模型放在哪里。

**图形界面的办法**

应用列表里有一个“磁盘使用分析器”，打开之后能看到一张按目录大小排的图，比命令直观。用哪个都行，看的是同一件事。

## 怎么看硬盘的健康状态

```bash
sudo apt install smartmontools
sudo smartctl -a /dev/nvme0n1
```

第一条装工具，第二条读出这块盘的全部自检信息。设备名以 `lsblk` 的输出为准。

这条命令[第 1 卷第 11 章](../01-开箱与安装/11-收货验收.md)和[第 12 章](../01-开箱与安装/12-硬件问题处理.md)已经用过，验收时看的是“这台机器是不是新的”。本章补的是**每一项怎么读**，因为这几个数要记进第 16 章的基线，以后要拿来对照。

| 字段 | 意思 | 正常是什么样 |
| --- | --- | --- |
| `Critical Warning` | 盘自己报的严重告警位 | `0x00`。不是 `0x00` 就要当回事 |
| `Percentage Used` | 已用寿命 | 新机器接近 `0%`；日常缓慢增长 |
| `Data Units Written` | 累计写入量 | 只增不减。单看没意义，看增长速度 |
| `Power On Hours` | 累计通电小时数 | 新机器只有个位数到几十小时 |
| `Media and Data Integrity Errors` | 介质与数据完整性错误数 | `0` |
| `Unsafe Shutdowns` | 非正常关机次数 | 断电、强制关机各加一次。不为零不一定是故障 |
| `Available Spare` | 备用块剩余百分比 | 接近 `100%`。明显往下掉要留意 |
| `Temperature` | 盘的当前温度 | 记进基线，跟自己比，不跟别人比 |

这几个是 NVMe 标准 SMART 日志里的字段。**各厂商的盘、各版本的工具在字段名和排列上会有出入，以你屏幕上实际的英文字段名为准。本项目未在 Max395 机型上逐机型核对输出格式，需要核验。**

只看关键几行：

```bash
sudo smartctl -a /dev/nvme0n1 | grep -E "Critical|Percentage|Power On|Integrity|Available Spare|Temperature"
```

`grep -E` 是按多个关键词过滤，中间的 `|` 表示“或者”。

**要不要跑自检**

```bash
sudo smartctl -t short /dev/nvme0n1
```

这是让盘自己做一次短时自检。**不是所有 NVMe 盘都支持，提示不支持属正常，不是故障。本项目未在 Max395 机型上实测，需要核验。** 日常判断用上面那张表里的几个数就够了，不必特意跑自检。

**TRIM 定时器**

```bash
systemctl status fstrim.timer
```

`fstrim` 是告诉 SSD 哪些块已经不用了，让它提前整理，这件事做和不做长期会影响写入速度。Ubuntu 通常预置了一个每周执行一次的定时器，输出里看到 `active (waiting)` 就是开着的，**不用改**。按 `q` 退出。

**这个定时器是否默认启用随 Ubuntu 版本和安装方式变化，本项目未逐版本核对，需要核验。** 看到 `inactive` 也不用慌，它不影响数据安全。

## 这一章涉及的可改设置

**一、装 `nvme-cli` 和 `smartmontools`**

- **默认状态**：Ubuntu 装完之后这两个不一定装了；
- **什么情况才需要改**：要看盘的型号、序列号和健康状态时装。不装不影响开机和跑模型；
- **改完怎么验证**：`sudo nvme list` 有输出、`sudo smartctl -a /dev/nvme0n1` 有输出；
- **怎么恢复**：`sudo apt remove nvme-cli smartmontools`。这两个包只读数据，卸掉不影响系统。

**二、`fstrim.timer`**

- **默认状态**：随 Ubuntu 版本而定，**先用上面那条命令读出你这台的当前状态并记下来**（**需要核验**）；
- **什么情况才需要改**：本教材没有推荐改动的场景。保持你机器上的现状；
- **改完怎么验证**：`systemctl status fstrim.timer` 的状态行；
- **怎么恢复**：改动前是什么状态就用 `sudo systemctl enable --now fstrim.timer` 或 `sudo systemctl disable --now fstrim.timer` 改回去。

**三、加装或更换 SSD（硬件改动）**

- **默认状态**：出厂配置。先用 `lsblk -d -o NAME,SIZE,MODEL,TRAN` 把现状抄下来，这是你的恢复目标；
- **什么情况才需要改**：空间确实不够，并且已经确认过保修条款、已经过了退换货窗口、已经把要留的数据备份出去。**空间只是紧张不是不够，先按上面的办法清理，别急着开机箱**；
- **改完怎么验证**：正常开机进桌面；`lsblk` 能看到新盘；`sudo smartctl -a` 读得到新盘的健康信息；连续开关机三次都正常；重做一次第 16 章的基线；
- **怎么恢复**：把原来的盘按原位装回去。所以拆之前要拍照，记清楚哪块盘插在哪个插槽、螺丝原来在哪个位置。

## 正常结果

`lsblk -d -o NAME,SIZE,MODEL,TRAN` 能列出这台机器上的盘，你知道有几块、各多大、接口类型是什么；`df -h` 里 `/` 那一行的可用空间，你知道是多少，也知道自己的余量目标；`sudo smartctl -a /dev/nvme0n1` 能输出健康信息，`Critical Warning` 是 `0x00`，`Media and Data Integrity Errors` 是 `0`。

盘的型号、容量、剩余空间、`Percentage Used`、`Power On Hours` 这几项已经抄下来，准备填进第 16 章的基线表。

## 看到不同结果怎么办

**`sudo nvme list` 提示找不到命令**：`nvme-cli` 没装上，重新执行 `sudo apt install nvme-cli`。提示“无法定位软件包”就先 `sudo apt update` 再装一次（[第 1 卷第 9 章](../01-开箱与安装/09-系统更新.md)）。

**`lsblk` 里只看到一块盘，但订单写了两块**：按[第 1 卷第 12 章“硬盘识别不到”](../01-开箱与安装/12-硬件问题处理.md)处理，先进 BIOS 看列表里认不认得到。**出厂预装的盘在 BIOS 里就认不到，不要拆机，直接联系卖方。**

**1 TB 的盘显示成 `931.5G`**：单位换算的差别，不是少给了容量。原因[第 1 卷第 11 章](../01-开箱与安装/11-收货验收.md)已经写清楚，不重复。

**`df -h` 里 `/` 只剩几个 GB**：按上面警告框里的三条清理，清完再看。清完还是紧张，说明模型放太多了，删掉不用的那几个。

**`Percentage Used` 已经用掉不少，或者 `Power On Hours` 上千**：买的是全新机的话，保存这段输出，按[第 1 卷第 11 章](../01-开箱与安装/11-收货验收.md)找卖方问是不是退货翻新品。用了一段时间的机器上这两个数慢慢涨是正常的，看的是**涨得快不快**，所以要有基线。

**`Critical Warning` 不是 `0x00`，或者 `Media and Data Integrity Errors` 不是 `0`**：**先备份数据，再排查。** 不要在这个状态下继续往盘上写大文件。保存 `smartctl` 的完整输出，在保修期内就联系卖方。

**外接的 USB 移动硬盘读不到健康状态**：常见，不是故障。健康信息要经过 USB 转接芯片传出来，很多转接芯片不透传这些指令。内置的 NVMe 盘不受影响。

**`sudo du -sh /usr/share/ollama/.ollama/models` 提示路径不存在**：说明模型不在这个位置。用 `du -sh ~/* | sort -h` 从主目录找，或者用“磁盘使用分析器”看整盘。各框架的模型目录见第 6 卷。

**加了第二块盘，`lsblk` 看得到但“文件”程序里没有**：盘认到了，还没分区、格式化、挂载。这属于系统操作，见[第 2 卷](../02-Ubuntu/README.md)。

**盘的温度看起来偏高**：先确认这是加装的那块还是内置那块。加装的盘没有散热片、又贴着机身内壁，温度比内置那块高属正常。判断依据还是基线（第 16 章）和第 12 章的方法，不要拿网上的数字比。

**想换一块更大的盘**：先读“加装或更换硬盘和保修的关系”那一节，再做恢复介质（[第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)），最后才动手。
