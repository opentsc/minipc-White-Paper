# 10　变体：旧档案批量数字化

## 这一章的任务

把档案室里几柜子纸，变成一张能筛的表加一堆能打开的 PDF。

**这一章和前两个变体最大的不同，不在技术，在打法。**

第 8、9 章那两个变体是长期服务——客户每个月都有新合同、新单据，你的东西一直在跑。**这一章是项目制**：有开始有结束，做完就完了，**钱一次性收，人一次性投**。

**所以这一章一半篇幅在讲怎么估工作量、怎么谈边界、怎么分批交。** 技术那一半反而是三个变体里最简单的——字段最少，每份只读一页。

> **先把证据说在前面，而且这一条比前两章更要紧。**
>
> **这个方向的公开证据是三个变体里最薄的。** 公开渠道能查到有服务商在卖本地 OCR 加本地模型的文档提取项目，**但没有一条是针对“旧档案批量数字化”这个具体场景的**，更没有可核验的客户名称、合同和金额。
>
> **这一章是方向判断，不是已验证的路。** 见本章最后一节。

## 开始前

- **主线第 1 章到第 7 章做完**，[第 8 章](08-变体-合同条款提取.md)那五处脚本改动做完；
- [第 7 卷第 2 章](../07-RAG/02-收集与整理文档.md)读过。**那一章的四堆整理法，这一章要在纸上先做一遍**；
- 手上有一批已经扫描好的档案 PDF，或者一个愿意让你看一眼档案室的客户；
- **一天读完这一章并把估算表做出来。** 真做起来是几个星期到几个月的项目。

## 新词

**卷**（也叫册、案卷）：**档案的基本单位。** 一个档案盒里装一卷或者几卷，一卷里有几页到几百页不等。**报工作量的时候，客户说的是“几柜”“几卷”，不是“几个文件”。**

**索引字段**：**只够让人找到这一卷的那几格**——文号、日期、标题、经办人。**这一章只抽这几格，不抽全文。**

**卷内首页**：一卷档案翻开的第一页。**红头文件的抬头、文号、日期、标题都在这一页上。** 这一章的全部产出来自这一页。

**分批交付**：**做一批交一批，不是全做完再一次交。** 这一章的核心打法。

## 边界在哪儿，先画清楚

**这一节要放在最前面，因为它决定你报的价对不对。**

一个档案数字化项目从头到尾是三段：

```text
第一段　纸变成 PDF
　　　　拆订、抚平、上扫描仪、按卷分开存成文件
　　　　这是体力活。可能是客户自己做，可能外包给扫描服务商
　　　　　　　　↓
第二段　PDF 变成台账　　　←　你做的是这一段
　　　　跑这一卷那套，出一张能筛的表
　　　　　　　　↓
第三段　建成能问答的库
　　　　第 7 卷那套。这是第二单，下面单说一节
```

**第一段不是你的活，也不该是你的活。**

理由三条：

- **它是纯体力活**，一天能扫多少页取决于纸的状况、扫描仪型号和干活的人，**跟你这台机器一点关系没有**；
- **它的风险在纸上**。拆订会破损、老纸会撕裂、缺页要找回来，**这些事出了，责任怎么算是另一套合同**；
- **市面上有专门做这件事的服务商**，客户自己找比你转手强。

**你要做的是把这条界线写进合同**（[第 13 卷](../13-项目交付/README.md)），而且要在第一次谈的时候就说出口：

> **可以照念的一句**：“扫描那一段我不做，您自己安排或者找扫描公司。您把扫好的 PDF 给我，我出台账。扫描一卷多少钱、多久，您问他们。”

**说清楚这一句，你后面所有的估算才成立。** 不说，客户默认扫描也归你，工期一开始就是错的。

## 客户的档案长什么样

**做估算之前先看一眼实物，看这五样。**

**一、纸的状况。** 泛黄、发脆、有霉斑、有虫蛀。**这三类扫出来的图质量差一大截**，字发虚，读不准。

**二、装订。** 骑马钉、线装、胶装、活页夹。**装订线压住边上的字**，扫的时候摊不平，靠近装订线那几个字会糊掉或者变形。

**三、复印件的复印件。** 老档案里很常见。**每复印一次对比度掉一档**，到第三代基本就是一片灰。

**四、手写的部分。** 签批意见、经办人签名、手填的日期。**这是最容易读错的一类**（[第 3 章](03-定义字段.md)那七条的第一条）。

**五、混在里面的照片、图纸、表格。** 它们没有文号也没有标题，**这一章那套字段对它们不适用**，要单挑出来。

**看完这五样，你心里要有一个数：这批档案里有多少比例是“干净的红头文件首页”。** 那部分是这套东西能干得好的，**剩下的要在报价里单独说。**

## 先在纸上做一遍四堆

**这一步是[第 7 卷第 2 章](../07-RAG/02-收集与整理文档.md)那套四堆整理法，在这里要在扫描之前做，而且是在纸上做。**

四堆：

```text
要数字化的　　这一批，编好号，交给扫描
已有电子版的　别扫了。原生电子档比扫描件强得多，直接要过来
破损要修的　　先修再扫，或者直接放弃这一卷（要客户点头）
不该数字化的　含隐私、含密级的，先不碰
```

**最后那一堆是这一章最要紧的一堆，而且最容易被忽略。**

[第 7 卷第 2 章](../07-RAG/02-收集与整理文档.md)那一节“哪些文件不该进库”在这里全部成立，**而且档案室里这类东西的密度比公司文档高得多**：

- **人事档案。** 身份证复印件、体检报告、家庭情况、工资表、处分记录；
- **有密级标记的。** 卷宗封面上盖着章的那些；
- **涉及第三方的。** 客户名单、供应商报价、别人家的合同副本。

**这一堆的处理办法只有一个：不碰，也不要为了省事替客户做决定。**

> **可以照念的一句**：“这几柜里有人事档案，我不动它们。要不要做、怎么做，您所里定了给我一个书面的说法。”

**这句话保护的是你自己。** 一个数字化项目做到一半发现里面有身份证号，比一开始就划出去麻烦十倍（[第 13 卷](../13-项目交付/README.md)）。

## 工作量怎么估

**这一节是本章的核心。**

**先说清楚估的是什么**：估的是**机器跑完要多久**，不是**这个项目要交多久**。**这两个数差得远**，下面第七步说。

### 六步估法

```text
第一步　数柜　　　　几个柜，或者几个货架、几个房间
第二步　抽一个柜数卷　这个柜里有几卷（几个档案盒）
第三步　抽三卷数页　　每卷大约多少页，取中间那个数
第四步　估总卷数　　　柜数 × 每柜卷数
第五步　跑十卷计时　　拿真实扫描件，跑十卷，量一卷平均多少秒
第六步　估机时　　　　总卷数 × 一卷平均秒数，再留出余量
```

**逐步说。**

**第一步、第二步是当场数出来的，不是问出来的。** 客户说“大概三十柜”，你自己去数一遍。**数出来是二十二柜的时候，你已经省了一笔。**

**第三步要取中间那个数，不要取平均。** 三卷分别是 30 页、80 页、600 页，**平均是 236，中间那个是 80**。那卷 600 页的是特例，**用平均去乘，整个估算会被它带偏。**

**第四步只算卷数，不算页数。** 这是这个变体和第 8 章最大的不同——**合同要跑全文，页数决定成本；档案只读首页，卷数决定成本。** 一卷 30 页和一卷 600 页，**在你这一段的成本是一样的。**

**这一条要跟客户说明白**，因为它对你有利也对客户有利：

> **可以照念的一句**：“我这一段按卷算，不按页算。您那卷五百页的，我也只读第一页。页数多少影响的是扫描那一段的钱，不是我这一段。”

**第五步是[第 5 章](05-批量处理.md)那个估法，换了个单位。** 那一章是先跑十份计时再乘份数，**这里是先跑十卷计时再乘卷数**。

**用真实扫描件跑，不要用干净的样张跑。** 老档案的图比现代打印件糊，**跑起来不一定更慢，但要用真的量。**

**第六步的余量，第一个项目至少留三成。** 留给三样东西：失败重跑、提示词调完之后整批重做、客户中途改字段。**这个数不是算出来的，是给自己留的口子**，做过几个项目之后你会有自己的数。

### 第七步，机时不是工期

**这一步最容易出事，单独拎出来。**

机器跑三天，**不等于这个项目三天能交**。中间还有：

```text
□ 等客户把第一批扫描件交过来
□ 跑完之后自己抽检
□ 抽检发现问题，调提示词，整批重跑
□ 交给客户看，客户提意见（“标题能不能不要带书名号”）
□ 按意见改，再跑一遍
□ 客户内部走签字流程
```

**这几件里没有一件是你能压缩的，而且没有一件在机时里。**

**报工期的时候按批报，不按总量报**，下面那一节说。

## 分批交付：一柜一批

**这是这个变体的第二个核心打法。**

**不要谈一个“三个月后交付全部”的项目。** 谈一个“一柜一批、跑完一批交一批”的项目。

### 一批的完整动作

**每一批走同样的六步，一步都不省**：

```text
1. 客户交这一柜的扫描件
2. 跑（这一卷那套）
3. 校验（第 7 章那套）
4. 抽检（客户在场或者客户抽）
5. 交付：台账 + PDF
6. 客户签一次
```

**第一批一定要小**，一柜，甚至半柜。**目的不是产出，是把这六步完整走一遍**——包括最后那个签字。

**很多项目栽在这儿**：前两个月闷头跑，第一次交付在第九个星期，**客户一看说“标题这一格我们要的是全称，不是简称”**，前面全部返工。

**第一批小、快、走完全流程，把返工的成本压在一柜里。**

### 分批还给你三样东西

**一、客户看得见进度。** “第 3 柜做完了，第 4 柜在跑”，比“完成度 40%”实在得多。**柜是客户自己数过的单位。**

**二、字段和提示词能在第一批定死。** 第一批交完签完字，**字段就不改了**。这一条要写进验收单，否则每一批客户都想加一格。

**三、钱能分批收。** 一柜一收，或者按批次里程碑收。**怎么分、按什么节点，[第 11 卷](../11-客户与报价/README.md)说，本章不下结论。**

## 字段怎么定：只要索引，不要全文

**这是本章技术那一半的核心，而且它就一句话——档案不抽全文，只抽够找到它的那几格。**

新建 `~/ai/scripts/archive_schema.json`：

```json
{
  "type": "object",
  "properties": {
    "档号": {
      "type": "string"
    },
    "文号": {
      "type": "string"
    },
    "成文日期": {
      "type": "string"
    },
    "标题": {
      "type": "string"
    },
    "发文单位": {
      "type": "string"
    },
    "经办人": {
      "type": "string"
    }
  },
  "required": [
    "档号",
    "文号",
    "成文日期",
    "标题",
    "发文单位",
    "经办人"
  ],
  "additionalProperties": false
}
```

**六格，是三个变体里最少的一份。** [第 3 章](03-定义字段.md)那三条规矩照旧：全部字符串、能限死的限死、字段名用中文。

**为什么只有六格**：照[第 3 章](03-定义字段.md)那三个问题筛一遍，档案这一类的答案很干脆——

- **下游谁用**：找档案的人。他要么记得文号，要么记得大概什么时候、什么事、谁经手的。**这六格正好覆盖这四种记忆。**
- **没有它会怎样**：少了标题，这张表就没法用眼睛扫；少了文号，精确查找就没了。**这六格少哪一格都疼。**
- **纸上一定有吗**：红头文件的首页上，这六格基本都有。**“经办人”是最容易缺的一格，缺了就空着。**

### 为什么没有“页数”这一格

**这一格看着该有，但它不该问模型。**

**理由很直接：模型只看了第一页，它不知道这一卷一共几页。** 你把这一格放进 schema，它要么留空，要么给你编一个。

**要那一列的话，从 PDF 本身读**——[第 4 章](04-单张跑通.md)装的 `poppler-utils` 里就有工具能打印一份 PDF 的页数，**跟模型没关系**。

**这一节比字段本身更值得记住**：[第 3 章](03-定义字段.md)那句“票面上一定有吗”，在这里的形式是**“模型看得到吗”**。**看不到的东西不要放进 schema。**

### 提示词

新建 `~/ai/scripts/archive_prompt.txt`：

```text
这是一份档案的首页图片。只读这一页上印着或者写着的信息，
严格按给定的 JSON 结构输出，不要输出 JSON 以外的任何文字。

标题照原文一字不差地抄，不要概括，不要删字，不要去掉书名号。
文号和档号里的括号、方括号、横杠、年份、字号，照原样抄，不要改写格式。
成文日期照原样抄，不要换算成别的写法。
发文单位写全称，不要简称。
手写的部分认不出来就填空字符串，不要按常见的名字凑一个。
这一页上没有的，一律填空字符串。不要从后面几页找，不要根据标题推断。
```

**三句话值得单说**：

**“文号里的括号照原样抄”** —— 公文文号形如 `远山办发〔2019〕17 号`，**那个六角括号 `〔〕` 它很喜欢换成圆括号**。换了之后，客户拿这个文号去别的系统里搜就搜不到。

**“不要按常见的名字凑一个”** —— **这一句是防手写签名那一格。** 签名认不出来的时候，模型有可能给你一个看着很像人名的东西。**空着是信号，凑出来的名字是灾难**（[第 3 章](03-定义字段.md)那段提示词第三句的意思，在这里变成了这一句）。

**“不要根据标题推断”** —— 标题里写着“关于二〇一九年度……的通知”，**它可能顺手把成文日期填成 2019 年**。那是推断，不是抄。

## 跑起来：只读首页

```bash
mkdir -p ~/ai/data/archive-cabinet-03 ~/ai/projects/archive-ocr
```

```bash
python3 ~/ai/scripts/ocr_batch.py ~/ai/data/archive-cabinet-03 ~/ai/projects/archive-ocr \
  --schema ~/ai/scripts/archive_schema.json \
  --prompt ~/ai/scripts/archive_prompt.txt \
  --max-pages 1 \
  --limit 3
```

**`--max-pages 1` 是这个变体最重要的一个参数，没有之一。**

一卷两百页的档案，**这个参数让模型只看第一页**。它省下来的不是一点，**是一百九十九页的机时。**

**这一条也是上面那条“按卷不按页”估法能成立的技术原因。**

> **有一类档案要单独处理**：扫描的时候把封面也扫进去了，**首页是封面不是正文**。这种要么在扫描那一段约定不扫封面，要么把 `--max-pages` 给到 2 或 3。**跑三份看一眼就知道你这批是哪种。**

跑完先看三份的结果，**六格空了几格**。空得多，先回去看是不是首页不对，再改提示词。

## 校验规则要改什么

**第 7 章那个 `validate.py` 照用，这一章是三个变体里改得最少的。**

```python
REQUIRED_FIELDS = [
    "标题",
    "成文日期",
]

AMOUNT_FIELDS = []
```

**必填只有两格**，因为档案的字段缺得比发票厉害——**没有文号的档案有的是，没有经办人的更多**。

**但标题不能空**。标题空了，这一行在台账上就是一片白，**人根本认不出这是哪一卷**。

**从 `OTHER_CHECKS` 里划掉** `check_invoice_no`、`check_amounts`、`check_sum`、`check_parties`——它们在这里都没有对象。**`check_date` 留着**，把 `YEAR_MIN` 改成这批档案最早的年份。

**加一条最简单的规则，专门查标题**：

```python
TITLE_MIN_LENGTH = 4


def check_title(record):
    """标题太短的，多半是没读全。"""
    title = text_of(record, "标题")
    if title == "":
        return []
    if len(title) < TITLE_MIN_LENGTH:
        return ["标题太短了，只有 %d 个字：%s" % (len(title), title)]
    return []
```

**加进 `OTHER_CHECKS`。** 这一条捞的是“只读到半个标题”——**首页有折痕、标题跨行、或者被印章压住半边**。

> **[第 7 章](07-错的怎么拦.md)那条边界在这里更明显**：档案这套字段之间**没有任何可以互相验算的关系**。发票有加税校验，物流单有明细加合计，**档案什么都没有**——六格各管各的，谁也证明不了谁。
>
> **所以这个变体对抽检的依赖比前两个都重。** 校验能做的只有“空不空、格式对不对”，**内容对不对全靠人抽。**

## 结果怎么交

**交两样东西，一样都不能少。**

```text
档案数字化-第3柜/
├── 台账.xlsx          客户要的是这个（第 5 章那个另存为）
├── ledger.csv         脚本直接出的那份，一起给
└── pdf/               扫出来的 PDF
    ├── 3-01-001.pdf
    ├── 3-01-002.pdf
    └── ...
```

**“能按字段查”这件事，就是靠这两样凑出来的**，不需要数据库，不需要系统：

```text
1. 客户在 Excel 里筛台账（按年份、按发文单位、按标题里的关键词）
2. 筛出那一行，看最后一列的文件名
3. 去 pdf/ 里找同名的那个文件，双击打开
```

**第一列是文件名，这一列是整套东西的钥匙**（[第 5 章](05-批量处理.md)那句“没有这一列的台账等于废的”，在这里是全部交付物的连接点）。

### 文件名的规矩，这个变体只剩一条硬的

[第 7 卷第 2 章](../07-RAG/02-收集与整理文档.md)那五条文件名规矩，在这里**只剩一条是硬的：文件名要能和台账对上，而且要和档号对上。**

**推荐直接用档号做文件名**：`3-01-001.pdf` 就是第 3 柜第 1 盒第 1 卷。

**理由是这个变体特有的**：客户找到台账上那一行之后，**还要能去档案室把纸质原件抽出来**。文件名等于档号，这条路才通。

**这件事要在扫描那一段就定下来**，扫描的人按档号命名文件。**扫完再改名是一个人干几天的活。**

> **可以照念的一句**：“扫描的时候麻烦按档号命名文件，一卷一个 PDF。这样您在表里筛出来，既能点开电子版，也能照这个号去柜子里拿原件。”

### 电子版怎么给

**别用 U 盘拷完就走。** 这批东西以后是要用的，**放在哪儿、谁能打开、备份在哪儿**，这三件事要写进交付说明（[第 13 卷](../13-项目交付/README.md)）。

**最省事的做法是放在客户自己的一台机器或者共享盘上**，一个文件夹，台账和 `pdf/` 挨着。**这一卷不展开搭系统那条路**，第 11 章讲对接。

## 数字化完之后，第二单

**这一节要说清楚，因为它是这个项目最大的一块后续价值，也最容易被讲成同一件事。**

客户拿到手的是一张表加一堆 PDF。**这张表能筛的只有那六格**：

```text
能答的：　这个月有几份是某单位发来的
　　　　　2019 年的档案有多少卷
　　　　　文号是某某号的那一卷在哪儿
　　　　　标题里带“采购”两个字的有哪几卷

答不了的：哪几份档案里提到过某个项目
　　　　　当年那个决定的理由写在哪一卷里
　　　　　这件事前后一共有几份文件
```

**下面那三个问题，表答不了，因为表里没有正文。**

**那是[第 7 卷](../07-RAG/README.md)那套。** 而且它是一个**明显更大的活**：

| | 第一单：数字化 | 第二单：建库 |
| --- | --- | --- |
| 每卷读几页 | 只读首页 | 每一页都要读 |
| 一卷两百页的成本 | 和一卷三十页一样 | 差七倍 |
| schema | 六格索引字段 | 一格正文，或者干脆不用 schema |
| 产出 | 一张表 | 一个能问答的库 |
| 提示词 | 抄那六格 | 把这一页上的字全部抄出来 |

**这两件事的工作量差一个数量级，所以报价必须分开报。**

> **可以照念的一句**：“第一单做完，您能按文号、日期、标题、经办人查。要能问‘哪几份文件里提过这件事’，那要把每一页的字都读出来再建一个库，那是另一件事，工作量不在一个量级上，我单独给您报。”

**先做第一单的理由和[第 7 卷第 11 章](../07-RAG/11-变体-律所合同库.md)那条“先做 50 份”是同一条**——**客户没见过效果之前，不会批一个大项目。**

## 验收怎么定

**四件事，按批做，不是最后一次性做。**

### 一、完整性对数（这个变体的第一位）

**三个数必须相等**：

```text
客户点的卷数　=　台账行数　=　pdf/ 里的文件数
```

**这一条排在最前面，因为漏一卷比错一格严重得多。**

错一格，客户翻开原件能改；**漏一卷，那一卷在这套东西里就不存在了**，谁也不会想起来去找它。

数文件数用[第 7 卷第 2 章](../07-RAG/02-收集与整理文档.md)那条命令的套路：

```bash
ls -1 ~/交付/档案数字化-第3柜/pdf/*.pdf | wc -l
```

**加上 `failed/` 里的份数一起对**（[第 5 章](05-批量处理.md)那一节）。

### 二、抽检

**从台账里随机抽**（[第 7 章](07-错的怎么拦.md)那条 `shuf` 命令），照文件名打开 PDF 对首页。

对的顺序：

```text
1. 标题　　　　　这一格错了，整行就没用了
2. 文号　　　　　尤其看括号有没有被换掉
3. 成文日期
4. 发文单位全称
5. 经办人　　　　手写的那一格，读不出来留空是对的，不算错
```

**第五项要事先说好口径**：手写签名读不出来填了空字符串，**算不算错**。**本章的建议是不算**——它举了手，这是设计好的行为。**这一条要写进验收单，否则抽检的时候会吵。**

### 三、能不能查回原件

**这一条是这个变体特有的验收项，别的变体没有。**

做法：**当着客户的面，从台账里随便挑三行**，照文件名去 `pdf/` 里打开一次，**再照档号去档案室把纸质原件抽出来一次**。

**三样对得上，这批就通了。** 对不上，多半是扫描那一段的命名没按档号来。

### 四、抽多少、通过标准，客户定

**你不要单方面给一个数字**（[第 7 卷第 11 章](../07-RAG/11-变体-律所合同库.md)那条规矩）。

**准确率数字这一章一个都不给。** 要给客户一个数，按第 13 章那套办法测（[第 13 卷](../13-项目交付/README.md)）。

### 还有一条不在技术里的

**纸质原件什么时候还、怎么还、损坏了算谁的。**

**这是档案项目特有的风险，而且它和你这一段没关系——但客户会认为有关系。** 拆订扫描是会伤纸的。

**做法：这一条写进合同，而且写在扫描那一方和客户之间，不是你和客户之间**（[第 13 卷](../13-项目交付/README.md)）。你只经手 PDF，**这一点越早说清楚越好。**

## 这个变体的三条实话

**一、它是一锤子买卖。** 做完就完了，客户不会每个月再来。**这决定了它的报价方式和前两个变体不一样**（[第 11 卷](../11-客户与报价/README.md)）。

**二、你做的这一段可能不是客户眼里最贵的一段。** 扫描一柜的钱、修补破损的钱、人工整理的钱，**加起来可能比你这一段多**。**知道这件事，你才不会把自己报成整个项目的价钱，也不会被压到不成比例的价钱。**

**三、这个方向的公开证据最薄。**

传统的档案数字化外包这个行业本来就有，**扫描服务商一直在做**。你加的是“扫完之后自动出一张能筛的台账”这一层。

**这一层有没有人愿意为它单独付钱，公开渠道查不到证据。** 本章能给的是方法，**给不了这门生意能不能做成的结论。**
