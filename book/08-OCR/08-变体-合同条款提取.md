# 08　变体：合同关键条款提取

## 这一章的任务

把主线那套搬到合同上，做一张能筛的合同台账。

**流程一步都不变。** 第 4 章那个 `ocr_one.py`、第 5 章那个 `ocr_batch.py`、第 6 章那套定时、第 7 章那套校验，**这一章一律照用**。

**换的只有三样**：一份新的 schema、一段新的提示词、几条新的校验规则。

**这一章真正教的不是合同，是“换一类文档要动哪几处”。** 第 9、10 章是同一套动作换材料。

> **先把一件事说在前面。** 这一章描述的客户需求和场景，**来自公开市场材料，属于方向判断，不是本项目已验证的成交案例。** 公开渠道能查到有服务商把本地 OCR 加本地模型做成的文档抽取项目挂牌出售，但没有可核验的客户名称、合同和金额。**照这一章做是合理的准备，不是一条保证能成交的路。** 见本章最后一节。

## 开始前

- **主线第 1 章到第 7 章做完。这一章不重讲任何主线步骤**；
- 手上有一批合同。**真实客户的合同要先谈好保密再动，谈之前一份都别拷贝**（[第 7 卷第 11 章](../07-RAG/11-变体-律所合同库.md)那一条，在这里同样成立）；
- 你自己完整读过其中至少三份。**定字段的人必须知道那几格长在哪一页**；
- 一天。定字段和调提示词半天，跑和核半天。

## 新词

**摘录字段**：**值是从原文上抄下来的**。合同编号、日期、金额、当事人名称都是这一类。**对不对，翻开原件一眼就能判。**

**摘要字段**：**值是模型自己组织的一句话**。“违约责任摘要”是这一类。**它没有一个可以逐字比对的原文**，所以对错不好判——**这是本章风险最高的一处，下面单说一节。**

**条款号**：合同正文里那个 `8.2`、`第十二条`。**它是摘要字段的抓手**——有了它，人能翻回原文核。

## 这类客户的文档长什么样

四种，按处理难度排。

**一、Word 导出的 PDF。** 字选得中，最省事。**但这一卷用不上这个优势**——本卷走的是把 PDF 拍成图再看图那条路（[第 4 章](04-单张跑通.md)那个 `pdftoppm`），文字版扫描版一视同仁。

**二、签字盖章之后扫描的那一份。** 字选不中，是一叠图片。**这一类在合同里比例很高**，因为有效力的是盖了章那一份。**本卷这套就是为它来的。**

**三、扫描件加手写补充。** 打印的合同上手写补了一条，或者金额栏是手填的。**手写这一块是最容易读错的**（[第 3 章](03-定义字段.md)那七条的第一条）。

**四、传真件、复印件的复印件。** 对比度低、字发虚。**这一类先别接进第一批**，跑通了再回头补。

### 和发票最大的两个差别

**一、页数。** 一张发票一页，一份合同十几页到几十页。[第 4 章](04-单张跑通.md)那个 `--max-pages 2` 在这里不够用，**要往上调**，跑一份的时间也跟着往上翻。**报工期之前先数一遍页数。**

**二、字段不在同一个地方。** 发票的八格全在一张纸上，位置固定。**合同的字段散在首页、签署页和中间某一条里**——合同编号在首页抬头，签订日期在最后签署页，违约责任在中间第几条。**这一条决定了这个变体的成败**，下面“页数怎么给”那一节说怎么办。

## 他们的痛点

一句话：**要从一堆旧合同里挑出某几份，只能一份份打开翻。**

展开是这几种，都很具体：

- **月底财务问：这个月有哪几份合同到期。** 没有表，只能凭记忆加翻文件夹；
- **老板问：我们和某家的合同违约金是怎么约的。** 合同在档案柜里，经办人换过两轮；
- **审计来了要一张合同清单**，带编号、当事人、金额、期限。**这张表从来没有过，每次来都现做一遍**；
- **新接手的法务要盘一遍过去三年的合同。** 一百多份，一份份读，两个星期。

**这几件事的共同点是：答案确实写在纸上，就是没有一张表。** 这一章做的就是那张表。

> **再标一次证据**：上面这几条痛点描述来自公开市场材料里反复出现的需求表述，**是方向判断**，不是本项目验证过的客户访谈结论。见本章最后一节。

## 和第 7 卷第 11 章的分工

**这两章长得像，做的是两件事。** 说不清楚这一条，你会在客户面前把两件事讲成一件。

| | [第 7 卷第 11 章](../07-RAG/11-变体-律所合同库.md)　合同库 | 本章　合同抽字段 |
| --- | --- | --- |
| 问法 | 问一句，答一句 | 不问，一次全抽 |
| 出来的是 | 一段话，后面挂着引用 | 一行数据 |
| 一次看几份 | 检索命中的那几段 | 一份一份全看过去 |
| 适合的问题 | “这一条是怎么写的” | “哪几份符合这个条件” |
| 答不好的 | “有哪几份约定了仲裁”（数不全） | “这一条到底什么意思”（它不解释） |
| 扫描件 | 进不去，要先过本卷 | 本来就是为它来的 |

**看第五行。** 那一行是两边的短板，**而且正好互补**——合同库答不好“有哪几份”，是因为检索每次只看得到几段；本章这张表答得了“有哪几份”，因为它一份份全看过。

**所以两者配合是这样**：

```text
本章跑一遍  →  一张台账，能筛能排能统计
　　　↓
第 7 卷那套  →  一个库，能问某一条的原文
```

**这是两单，可以分开卖，也可以先卖前面这一单。** 前面这一单便宜、快、看得见结果，客户点头之后再谈后面那一单（价钱怎么报在[第 11 卷](../11-客户与报价/README.md)）。

> **可以对客户说的一句话**：“先给您抽成一张表，您能按到期日筛、按金额排。等您觉得还要能问具体条款，我们再建一个能问答的库。”

## 最小起步规模：一类合同 50 份

**不要一上来就要全量，也不要五花八门混着来。**

四条理由，每一条都能对客户说出口：

**一、同一类合同的字段长得像。** 都是采购合同，抬头、条款顺序、编号规则都接近，**schema 一次就能定得准**。采购、租赁、劳务混在一起，你会发现有三分之一的合同缺你定的某一格。

**二、50 份一天跑得完，当天能看到那张表。** 一份十几页，比发票慢，但 50 份还是一天之内的事。**客户当天看到表，这件事的说服力比你讲一小时强。**

**三、提示词要改好几遍。** 这个变体的提示词比发票那段难调，**50 份重跑一次不心疼；五千份重跑一次要过夜**。

**四、客户没见过表之前，不会把全部合同给你。** 这条最实际（[第 7 卷第 11 章](../07-RAG/11-变体-律所合同库.md)那一条，在这里一模一样）。

### 这 50 份怎么挑

- **同一类业务的**；
- **近三年的。** 老合同的格式和现在不一样，扫描件也更差；
- **有五到十份是某个人自己熟的。** **核对的时候要用他**——他知道那几份里写了什么，判对错不用现翻。

## schema 怎么改

**这是本章的第一处改动，也是最要紧的一处。**

新建 `~/ai/scripts/contract_schema.json`，和第 3 章那份发票 schema 放一起：

```json
{

  "properties": {
    "合同编号": {

    },
    "甲方名称": {
      "type": "string"
    },
    "乙方名称": {
      "type": "string"
    },
    "签订日期": {
      "type": "string"
    },
    "生效日期": {

    },

    },

    },

    },

      "type": "string"
    },
    "违约责任条款号": {
      "type": "string"
    },
    "争议解决方式": {
      "type": "string",
      "enum": ["仲裁", "法院诉讼", "先协商后仲裁", "先协商后诉讼", "未约定", "其他"]
    }

```

**[第 3 章](03-定义字段.md)那三条定 schema 的规矩，这里一条不改**：全部用字符串、能限死的限死、字段名用中文。`enum` 那一格照样留了兜底项。

### 十一格，比发票多三格

[第 3 章](03-定义字段.md)说筛完通常剩五到十个，**这里是十一个，超了一格**。理由说得出来：

- **合同比发票复杂**，一份合同要回答的问题比一张发票多；
- **多出来的那三格是配对的**——`违约责任条款号` 是给 `违约责任摘要` 配的抓手，`生效日期` 和 `到期日期` 是给 `签订日期` 配的，三个日期一起才能回答“这个月哪几份到期”。

**你自己那批合同不一定要这么多。** 照[第 3 章](03-定义字段.md)那三个问题再筛一遍：这一格下游谁用、没有它会怎样、合同上一定有吗。**说不上来的先划掉。**

### 哪些是摘录，哪些是摘要

**这一节是本章最要紧的一段。**

**摘录类，八格**——值是从原文上抄下来的：

```text
合同编号　　甲方名称　　乙方名称　　签订日期
生效日期　　到期日期　　合同金额　　违约责任条款号
```

**对不对，翻开原件对一眼就知道。** 和发票那八格是同一种东西。

**摘要类，三格**——值是模型自己组织出来的：

```text
付款方式　　违约责任摘要　　争议解决方式
```

**这三格没有一段可以逐字比对的原文。** 合同上写的是一整条，出来的是一句话或者一个词。**判它对不对，要人读完那一条，再判断这句话有没有走样。**

**摘要类字段的风险高一档，具体高在哪儿**：

- **它会漏掉条件。** 原文是“逾期超过 30 日的，按未付款项每日万分之五支付违约金”，摘要成“违约金按每日万分之五计算”——**“超过 30 日”这个前提没了**；
- **它会把两条揉成一条。** 违约责任写在 8.1 和 8.3 两条里，出来一句话，**你不知道它综合了几条**；
- **它错的时候看不出来。** 摘录字段读错了，和原件一比就露馅；**摘要字段读走样了，读起来仍然很通顺。**

**三个对策，本章全用上了**：

**一、给摘要字段配一格出处。** `违约责任条款号` 就是干这个的。**有了它，人能直接翻到那一条，不用整份合同找。** 想让 `争议解决方式` 也能翻回去，照这个样子再加一格 `争议解决条款号` 就是。

**二、能变成摘录的就不要摘要。** `付款方式` 这一格，**这一章的做法是让它照抄付款条款的原文，不要概括成“月结 30 天”**。“月结 30 天”是模型的判断，原文可能是“乙方交货并经甲方验收合格后 30 日内支付”，**这两句话在有争议的时候不是一回事**。提示词那一段会把这条钉死。

**三、验收的时候摘要字段单独定口径。** 下面“验收怎么定”那一节说。

### `到期日期` 这一格，很多合同上根本没有

**这一格是本章最好的一个教学点。**

不少合同不写到期日，只写“本合同有效期三年，自生效之日起算”。**到期日是算出来的，不是写出来的。**

[第 3 章](03-定义字段.md)那句“票面上一定有吗”在这里就是这个意思。**处理办法是明确的：合同上没写的，留空。不让模型去算。**

理由和[第 3 章](03-定义字段.md)不让它换算金额是同一条——**模型这一层只负责抄，算是后面程序的事。** 让它算，它算错的时候不会告诉你。

**要那一列的话，在 Excel 里用生效日期加期限算，人算的错看得见。**

## 提示词要加什么

**这是第二处改动。**

主线那段提示词是给发票写的（[第 3 章](03-定义字段.md)那四句），**对合同不合用**。合同这一段要多说三件事：条款原文照抄、不做法律解释、找不到就留空。

新建 `~/ai/scripts/contract_prompt.txt`，内容：

```text
这是一份合同的图片，可能是扫描件，也可能是电子版。把下面要的信息读出来，
严格按给定的 JSON 结构输出，不要输出 JSON 以外的任何文字。

条款原文照抄，一个字都不要改写，不要润色，不要换成更书面的说法。
付款方式这一格，照抄付款条款的原文，不要概括成“月结多少天”这样的说法。
不解释法律含义，不判断条款有没有效，不评价对哪一方有利。
合同上没有写的、找不到的、要靠推算才知道的，一律填空字符串，不要猜，也不要编。
当事人名称写全称，不要简称。金额和日期照原样抄，不要换算，不要改写格式。
违约责任摘要用一到两句话说清赔什么、赔多少、什么条件下赔，说不清就照抄原文。
违约责任条款号照合同上的编号写，比如 8.2 或者第十二条，不要自己重新编号。
```

一条一条说它在挡什么。

**“条款原文照抄，一个字都不要改写”** —— 挡的是润色。**它很喜欢把口语化的条款改写得更工整**，改完意思不一定变，但你没法拿它去和原件对了。

**“付款方式照抄原文”** —— 上面说过，**这一条把一格摘要变回了摘录**，是本段性价比最高的一句。

**“不解释法律含义，不判断有没有效，不评价对哪一方有利”** —— **这是这个变体的红线**，和[第 7 卷第 11 章](../07-RAG/11-变体-律所合同库.md)第九、十条挡的是同一件事。

**这张表是给人筛合同用的，不是出法律意见的。** 它一旦在“违约责任摘要”那一格写出“该条款对甲方明显不利”，责任就转到你这儿来了。

**这件事要在三个地方同时挡住**（[第 7 卷第 11 章](../07-RAG/11-变体-律所合同库.md)那条规矩，这里照搬）：**提示词里挡一道，交表的时候你自己说清一次，合同里再写一条**（[第 13 卷](../13-项目交付/README.md)）。

**“当事人名称写全称，不要简称”** —— **它很喜欢把“鸿远科技发展有限公司”写成“鸿远科技”**，在别处无所谓，在合同上那是两个不同的主体。

**“找不到就填空字符串，不要猜”** —— **这是[第 3 章](03-定义字段.md)那段提示词里最值钱的一句，原样搬过来。** 合同上这一条尤其重要，因为合同里“没约定”本身就是一个有意义的结果——**争议解决那一格的 `未约定` 就是为它准备的。**

## 脚本要改哪几行

**这是第三处改动，一共五处小改，两个脚本各改一部分。**

主线那两个脚本已经能从命令行接 schema（`--schema`），**但提示词是写死在 `ocr_one.py` 里的**。跑两类单据就得改两次代码，**所以把提示词也做成文件**。

### 在 `ocr_one.py` 里改四处

**改动一，在 `PROMPT = (...)` 那一段下面、`def response_format` 上面，插进这个函数**：

```python
def load_prompt(prompt_path):
    """提示词从文件里读。不给文件就用上面那段发票的。"""
    if not prompt_path:
        return PROMPT
    return Path(prompt_path).read_text(encoding="utf-8").strip()
```

**改动二，`read_one` 的函数定义那一行加一个参数**。原来是：

```python
def read_one(src, schema, api_base, model, dpi=200, max_pages=2, timeout=600):
```

改成：

```python
def read_one(src, schema, api_base, model, dpi=200, max_pages=2, timeout=600,
             prompt=PROMPT):
```

**并且把函数里那一行**：

```python
        content.append({"type": "text", "text": PROMPT})
```

**改成**：

```python
        content.append({"type": "text", "text": prompt})
```

**改动三，`main` 里 `--timeout` 那一行下面加一行**：

```python
    parser.add_argument("--prompt", default=None, help="提示词文件，不填就用发票那段")
```

**改动四，`main` 里调用 `read_one` 那几行末尾加一个参数**：

```python
        record = read_one(
            src, schema, args.api, model,
            dpi=args.dpi, max_pages=args.max_pages, timeout=args.timeout,
            prompt=load_prompt(args.prompt),
        )
```

### 在 `ocr_batch.py` 里改三处

**改动五，最上面那句 import 加上 `load_prompt`**。原来是一行：

```python
from ocr_one import API_BASE, SCHEMA_FILE, IMAGE_SUFFIXES, detect_model, load_schema, read_one
```

改成：

```python
from ocr_one import (
    API_BASE, SCHEMA_FILE, IMAGE_SUFFIXES,
    detect_model, load_schema, load_prompt, read_one,
)
```

**改动六，`--limit` 那一行上面加一行**：

```python
    parser.add_argument("--prompt", default=None, help="提示词文件，不填就用发票那段")
```

**改动七，`fields = field_names(schema)` 那一行下面加一行，把提示词读进来一次**：

```python
    prompt = load_prompt(args.prompt)
```

**并且把循环里调用 `read_one` 那几行末尾加一个参数**：

```python
            record = read_one(
                src, schema, args.api, model,
                dpi=args.dpi, max_pages=args.max_pages, timeout=args.timeout,

            )
```

**改完两个脚本对发票那条主线一点影响都没有**——不带 `--prompt` 的时候，`load_prompt` 返回的还是原来那段 `PROMPT`。**这是这几处改动特意做成这样的**，主线跑了半年的东西不该因为加一个变体而变行为。


把那 50 份合同复制进 `~/ai/data/contracts-2026-08/`。

### 页数怎么给

**这是这个变体唯一一个要动脑子的参数。**

上面说过，合同的字段散在不同页上。**`--max-pages` 给小了，签署页看不到，签订日期和当事人签章那一头就抽不出来；给大了，一份合同发几十张图过去，慢得离谱，而且[第 3 章](03-定义字段.md)那条“多栏和表格串行”的毛病会随页数变多而变严重。**

**本章的做法是先测一份**：

```bash
python3 ~/ai/scripts/ocr_one.py ~/ai/data/contracts-2026-08/那一份.pdf \
  --schema ~/ai/scripts/contract_schema.json \
  --prompt ~/ai/scripts/contract_prompt.txt \
  --max-pages 6
```

**看哪几格是空的。** 空的那几格，翻开原件看它长在第几页，再决定 `--max-pages` 给多少。

> **有一条经验值得记住：签订日期和签章多半在最后一页，不在前六页。** 真要抽那一格，要么把 `--max-pages` 放到能覆盖整份，要么先用别的办法把首尾几页拆出来单跑。**本卷不展开拆页那条路**，第一批建议直接把页数给足，慢一点先把表跑出来。

**台账的列会自动跟着新 schema 走**——[第 5 章](05-批量处理.md)那个 `field_names` 是从 schema 里读的，**这个脚本一个字都不用改**。

## 校验规则要改什么

**第 7 章那个 `validate.py` 照用，改最上面那四项，删两条规则，加一条。**

### 改最上面那四项

```python
REQUIRED_FIELDS = [
    "甲方名称",
    "乙方名称",
    "签订日期",
    "合同金额",
]

AMOUNT_FIELDS = ["合同金额"]
```

**为什么必填里没有合同编号**：不少合同根本没有编号，尤其是格式合同和老合同。**空着不算错，所以它不该进必填。**

`INVOICE_NO_LENGTHS` 和 `YEAR_MIN` 这两项，前者用不上了，后者按你那批合同最早的年份改。

### 删两条

`check_invoice_no` 和 `check_sum` 在合同上没有对象，**把它们从 `OTHER_CHECKS` 那张表里划掉**。函数本身留着不碍事。

`check_parties` 改两个字段名就能用——**甲方和乙方不能是同一家**，这一条在合同上比在发票上更该有。

### 加一条：三个日期的先后

**这是合同版的“加税校验”，同样是一条关系校验。**

```python
def check_dates(record):
    """签订、生效、到期三个日期的先后要说得通。"""
    signed = to_date(text_of(record, "签订日期"))
    start = to_date(text_of(record, "生效日期"))
    end = to_date(text_of(record, "到期日期"))
    problems = []
    if signed and start and start < signed:
        problems.append("生效日期比签订日期还早")
    if start and end and end <= start:
        problems.append("到期日期不晚于生效日期")
    if signed and end and end <= signed:
        problems.append("到期日期不晚于签订日期")
    return problems
```

**加进 `OTHER_CHECKS` 那张表就生效了**，第 7 章那个脚本的结构就是为这件事准备的。

> **[第 7 章](07-错的怎么拦.md)最后那条边界在这里一字不改地成立**：这条日期校验证明的是三个日期彼此说得通，**不证明它们和合同上写的一样**。三个日期一起读错、而先后关系还对得上，它照样放行。**抽检不能省。**

### 摘要字段，校验管不了

**这一节要写清楚，它是这个变体最大的一个缺口。**

`付款方式`、`违约责任摘要`、`争议解决方式` 这三格，**除了“不能空”之外，没有任何规则能检查它们。**

- 摘要写得对不对，**只有读过那一条的人知道**；
- 争议解决方式虽然是 `enum`，模型只能从六个里挑，**但它挑错一个照样是合法值**；
- 条款号写成 `8.2` 还是 `第八条第二款`，**格式上都说得通，只是后者翻不到**。

**所以这三格的质量只能靠抽检，而且抽检的强度要比摘录字段高。** 下面那一节把这条写进验收。

## 验收怎么定

**三件事，都在客户在场的时候做完，做完签字。**

### 一、完整性对数

**这一条最先做，也最容易被跳过。**

```text
客户点的合同份数　=　台账行数　+　failed/ 里的份数
```

**三个数对不上，就是有文件没被找到**（[第 5 章](05-批量处理.md)那一节说过，多半是后缀不在那张表里）。**漏一份比错一格严重**——错一格看得出来，漏一份没人知道。

### 二、摘录字段抽检

从台账里随机抽（[第 7 章](07-错的怎么拦.md)那条 `shuf` 命令），照文件名打开合同，**按这个顺序对**：

```text
1. 合同金额　　　　错一位就是错一个数量级
2. 三个日期　　　　这三格是这张表最常被拿去筛的
3. 甲方乙方全称　　看有没有被简称
4. 合同编号
5. 违约责任条款号　照这个编号翻，翻得到吗
```

**第五项要真的翻一次。** 条款号是摘要字段唯一的抓手，**它错了，那一格就等于没有出处。**

### 三、摘要字段单独定一条口径

**这是本章和主线最不一样的一条验收，要单独写进验收单。**

**摘要字段不按“对不对”验收，按“有没有加原文没有的东西”验收。**

具体做法：抽出来的每一份，**把那一条原文和摘要并排读一遍**，只判三件事：

```text
□ 摘要里有没有出现原文里没有的数字、期限、条件
□ 摘要里有没有把原文的前提条件丢掉
□ 摘要里有没有出现判断性的话（对谁有利、是否有效、是否合理）
```

**三条里出现任何一条，这一格算不通过。** 第三条出现一次就要停下来回去改提示词，**那是红线被穿了。**

**抽多少、几处不通过算整批不通过，由客户定，你不要单方面给一个数字**（[第 7 卷第 11 章](../07-RAG/11-变体-律所合同库.md)那条规矩）。

**准确率数字这一章一个都不给。** 要给客户一个数，按第 13 章那套办法在你自己的机器上、拿客户自己那批合同测，**带日期、带模型名、带量化档**（[第 13 卷](../13-项目交付/README.md)）。价钱怎么报在[第 11 卷](../11-客户与报价/README.md)。

## 这个变体的三条实话

**一、摘要字段是这个变体唯一会出事的地方。**

客户拿着表上那句“违约金按 10% 计算”去跟对方谈，翻开原文写的是“逾期每日万分之五”——**这不是少报销了几百块的量级。**

**所以那一格配了条款号，所以验收要单独定口径，所以提示词里有那条红线。** 三样都做了还是要在合同里写一句：**这张表是索引，不是依据；以合同原件为准**（[第 13 卷](../13-项目交付/README.md)）。

**二、页数会让工期翻倍。**

五十份发票和五十份合同不是一个量级的活。**一份合同十几页，每一页都要发一张图过去。** 先数一遍总页数再报时间，别当场答应（[第 5 章](05-批量处理.md)那个估法照用，把“份”换成“页”）。

**三、客户会问“它能不能帮我审合同”。**

**不能，也不要接。** [第 7 卷第 11 章](../07-RAG/11-变体-律所合同库.md)那句话照念：

> “它不替您判断，它就是帮您把那几格抽出来、排成一张表。判断还是您来。”
