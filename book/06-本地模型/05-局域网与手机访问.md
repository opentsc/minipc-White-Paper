# 05　局域网与手机访问

## 这一章的任务

手机上打开一个图标，和家里这台机器上的模型对话。

**这是主线案例完成的地方。** 从第 2 章下模型开始，到这里，这台 Mini PC 就是全家或者全组人的 ChatGPT——问答不出家门，不上传给任何人，不按次数收费。

这一章还要把两件事收拾干净：防火墙上该开的口开对，以及**为什么绝对不能把这个界面直接挂到公网上**。

## 开始前

- 第 4 章做完，在 Mini PC 自己的浏览器里 `http://localhost:3080` 能对话；
- [第 3 卷第 3 章](../03-服务器基础/03-固定IP.md)的固定地址在手上，本章一直要用它。下面一律写成 `192.168.1.50`，**换成你自己那个**；
- [第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)做完，ufw 开着；
- 要用外网那一节的话，[第 3 卷第 6 章](../03-服务器基础/06-Tailscale.md)做完，手机上装了 Tailscale；
- 一部手机，和 Mini PC 连在同一个路由器下面；
- 40 分钟。

## 先在手机上试一次

不用改任何东西，直接试。

手机连着家里的 Wi-Fi，打开浏览器，地址栏输：

```text
http://192.168.1.50:3080
```

**注意三件事**：开头是 `http` 不是 `https`；地址后面的冒号和端口不能少；别在搜索框里输，要在地址栏里输——手机浏览器容易把它当成搜索词。

页面出来了，用第 4 章那个账户登录，选一个模型，问一句。

**这就通了。**

## 它为什么不用配就通了

这件事值得说清楚，不然你会以为自己漏了一步。

第 4 章那条 `docker run` 里的 `-p 3080:8080`，Docker 默认就把这个口开在了这台机器的**所有地址**上，包括局域网那个。而且——**Docker 发布端口是自己去改系统底层的转发规则实现的，它插在 ufw 的规则前面**（[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)专门讲过这件事）。

结果就是：**ufw 里没有放行 3080，局域网里照样连得上。**

看一眼：

```bash
ss -tln | grep :3080
```

`Local Address` 那一列是 `0.0.0.0:3080`，意思是所有地址上都开着。

**这是方便，也是这一章要处理的那件事。** 往下两节，一节把规则表补完整，一节真正把这个口收住。

顺便确认一下 Ollama 那个口：

```bash
ss -tln | grep 11434
```

它也是 `0.0.0.0:11434`。**但 Ollama 不是容器，是宿主机上的一个普通服务，ufw 管得到它。** 第 4 章只放行了 Docker 那个网段，所以局域网里的设备连不上 11434。要验证的话，在笔记本上试一次 `curl http://192.168.1.50:11434`，连不上才是对的。

## 把防火墙的规则表补完整

[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)那句话在这里生效：**那张规则表就是这台机器的门禁清单，每一行你都该说得出这个口是给谁开的。** 3080 现在通着却不在表里，这张表就不完整了。

```bash
sudo ufw allow from 192.168.1.0/24 to any port 3080 proto tcp
```

作用：允许从你家这个网段来的连接访问 3080。四段的含义[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)拆过，这里只换了端口号。**地址段换成你自己的。**

看一眼：

```bash
sudo ufw status verbose
```

现在表里应该有这么几行（省掉了前面几章的）：

```text
To                         Action      From
--                         --          ----
3080/tcp                   ALLOW IN    192.168.1.0/24
11434/tcp                  ALLOW IN    172.17.0.0/16
Anywhere on tailscale0     ALLOW IN    Anywhere
```

**这条规则的实际效果是让表看起来完整，不是真的挡住了什么**——Docker 那个口本来就通着。真要管住它，看下一节。

## 真正把这个口收住

[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)给过办法：**在 Docker 这一层限定它绑在哪个地址上。** 那一章拿监控面板做过一次，这一章对 Open WebUI 再做一次。

先把 Tailscale 那个地址拿到手（[第 3 卷第 6 章](../03-服务器基础/06-Tailscale.md)）：

```bash
tailscale ip -4
```

输出一行 `100.` 开头的地址。下面写成 `100.101.102.103`，**换成你自己那个**。

然后停掉旧容器，用带地址的写法重建：

```bash
docker stop open-webui
docker rm open-webui
docker run -d \
  --name open-webui \
  --restart unless-stopped \
  -p 192.168.1.50:3080:8080 \
  -p 100.101.102.103:3080:8080 \
  --add-host=host.docker.internal:host-gateway \
  -e OLLAMA_BASE_URL=http://host.docker.internal:11434 \
  -v "$HOME/ai/projects/open-webui/data:/app/backend/data" \
  ghcr.io/open-webui/open-webui:main
```

和第 4 章那条比，**只有 `-p` 那两行不一样**：端口前面各多了一个地址，意思是只在这个地址上开这个口。一个对局域网，一个对 Tailscale。

两个地址都换成你自己的。**没装 Tailscale 的就只留第一行 `-p`。**

数据在 `-v` 那个目录里，删了重建不丢，账户和对话记录都还在（[第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)验证过）。

确认：

```bash
ss -tln | grep :3080
```

`Local Address` 那一列从 `0.0.0.0:3080` 变成了两行具体的地址，就是生效了。

**再回手机上刷新一次，页面还在**——局域网那条路没断。

> **这一步不是必须的，但值得做。** `0.0.0.0` 的意思是“这台机器以后接到哪个网上，这个口就在哪个网上开着”。把笔记本带去咖啡馆、把机器搬去客户那儿、家里插了一根新网线——这些情况下 `0.0.0.0` 都会把口带过去，绑死地址不会。
>
> 收紧之后你会发现 `http://localhost:3080` 打不开了，这是对的：`localhost` 是 `127.0.0.1`，不在你绑的那两个地址里。在机器本地也要用 `http://192.168.1.50:3080`。介意的话再加一行 `-p 127.0.0.1:3080:8080`。

## 加到手机主屏

网页能用了，但每次要输一长串地址。**把它放到主屏上，用起来就和一个应用没区别。**

**iPhone**：用 Safari 打开那个地址，点底部中间的分享按钮，往下拉找到“添加到主屏幕”，改个名字，右上角添加。

**Android**：用 Chrome 打开那个地址，点右上角的菜单，找“添加到主屏幕”或者“安装应用”，确认。

主屏上多出一个图标，点开是全屏的，没有浏览器的地址栏。**家里人拿到手机看到的就是一个应用**，不需要知道后面是什么。

> **地址栏可能提示不安全，因为这是 `http` 不是 `https`。** 这个界面没有配证书，浏览器就会这么说。在你自己家的局域网里，以及 Tailscale 那条本来就加密的通道里，这个提示不影响使用（[第 3 卷第 6 章](../03-服务器基础/06-Tailscale.md)对监控面板说过同一句）。**要给它配上证书是第 10 卷的事。**

## 在外面也能用

家里通了，出门就断——除非走 Tailscale。

[第 3 卷第 6 章](../03-服务器基础/06-Tailscale.md)已经把这条路铺好了，这一章只是换个端口用：

```text
http://100.101.102.103:3080
```

**和局域网那个地址是两个地址，同时有效**：在家里用 `192.168.1.50`，在外面用这个 `100.` 开头的。

**真的到外面试一次。** 在家里试不算数，家里的流量可能还是走的局域网：

1. 把手机的 Wi-Fi 关掉，只用流量；
2. 确认手机上 Tailscale 的开关是开的；
3. 浏览器里打开 `http://100.101.102.103:3080`。

页面出来，这一章就全通了。

打不开的话，先看手机上 Tailscale 的开关是不是被系统的省电策略关掉了，再在 Mini PC 上跑 `tailscale status` 看手机那一行在不在（[第 3 卷第 6 章](../03-服务器基础/06-Tailscale.md)）。

嫌两个地址麻烦的，把主屏那个图标存成 Tailscale 那个地址就行——**在家里它一样通**，只是数据会绕一点点，日常感觉不出来。

## 不要把这个界面挂到公网上

**这一节是硬的。**

有人会想：既然手机能连，那在路由器上做个端口转发，把公网的某个端口转到 `192.168.1.50:3080`，不就随时随地都能用了，还不用装 Tailscale。

**不要这么做。** [第 3 卷第 6 章](../03-服务器基础/06-Tailscale.md)那一节讲过通用理由，这里再加上这个界面特有的三条。

**一、它后面挂着一台什么都肯干的机器。** 互联网上有大量程序整天不做别的，就是把所有地址的常用端口挨个敲一遍。一个新开的端口从开放到被第一次扫到，通常是几分钟到几小时。它们试弱密码、试已知漏洞。**Open WebUI 的管理员账户能改所有设置**，管理员密码要是简单，几小时就试出来了。

**二、丢的不只是这个界面。** 这台机器在你家的局域网里面，`~/ai/data` 里是你的资料，`~/ai/projects` 里是各个服务的数据库。**它能碰到的东西，进来的人也能碰到。**

**三、这是 `http`，不是 `https`。** 没有证书，账号密码和你问模型的每一句话，在公网上是明文走的。中间任何一段线路上的人都看得到。局域网和 Tailscale 里这一条影响不大，公网上完全是另一回事。

**替代做法就是上面那一节：用 Tailscale。** 它对公网一个端口都不开——所有设备都是主动往外连，在中间对上号。外面的扫描程序看不到你的任何服务，因为根本没有对外监听的入口。

真要把一个服务开给不特定的人用，那是第 10 卷的事，那时候的做法也不是端口转发。**家里这台机器，本教材从头到尾不直接暴露在公网上。**

## 交给别人用之前，再看三行

给家里人或者同事用之前，跑一遍这三条：

```bash
sudo ufw status verbose
```

表里每一行都说得出是给谁开的吗？说不出的删掉（[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)）。

```bash
ss -tln
```

开着的每个口都认得吗？多出来的那个是谁开的？

最后一条不是命令：**你的管理员密码是不是一个真密码。** 这个账户能改所有人的设置。

## 事实来源和版本日期

- Docker 发布端口时直接操作内核转发规则、位置在 ufw 的规则之前，用 `-p 地址:端口:端口` 限定绑定地址是官方支持的写法：[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)已写全，**本章原样套用到 Open WebUI 上，不重新论证**；
- Tailscale 分配的地址在 `100.` 开头那一段、机器重启和换网络之后不变、防火墙要单独放行 `tailscale0` 这个接口：[第 3 卷第 6 章](../03-服务器基础/06-Tailscale.md)与[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)已写全，**本章不重讲**；
- 不在路由器上做端口转发、家里这台机器不直接暴露在公网上：[第 3 卷第 6 章](../03-服务器基础/06-Tailscale.md)已拍板，**本章原样引用并补三条这个界面特有的理由**；
- Open WebUI 在容器里监听 8080：[Open WebUI 快速开始文档](https://docs.openwebui.com/getting-started/quick-start/)，访问日期 2026-08-14，厂商官方文档，事实状态 `official_source`；
- **手机上把网页加到主屏的菜单名称**：由 iOS 与 Android 的浏览器决定，各版本的文字不同，**以你手机上实际看到的为准**；
- **`ufw status verbose` 输出里的字段名会跟随系统语言显示成中文**：[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)已注明；
- 本章不改动任何内核参数、不改动设备节点权限，[第 4 卷第 18 章](../04-Max395硬件/18-不应随意修改的设置.md)的禁区清单在本章全部保持原状；
- 事实状态标记的含义见[证据与发布规则](../../reference/证据与发布规则.md)；
- 本章核验日期：2026-08-14。
