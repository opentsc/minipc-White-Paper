# 16　企业语义搜索改造

## 这一章的任务

给客户已有的一堆资料做一个按意思搜的入口。

**这一章和前面十五章都不一样：它不生成回答。**

前面那些库的形状是——检索找出几段，模型读完写一段话，引用挂在下面。**这一章只做前半截**：输入一句话，**把最相关的那几个文件和片段列出来，到此为止。**

**不生成，就不会瞎编。** 第 5 章那一整章要解决的问题，在这个场景里根本不存在。

做完这一章，你手上会多两个几十行的 Python 脚本，**一个把一批文件算成索引，一个输入一句话返回最相关的几条。** 它们能接进客户已经有的系统，也能单独卖。

## 开始前

- [第 6 卷第 8 章](../06-本地模型/08-局域网API.md)做完，`/v1` 那个接口通了，**那个 Python 环境（`~/ai-client`，装了 `requests`）还在**；
- [第 6 卷第 12 章](../06-本地模型/12-embedding与reranker.md)做完，`bge-m3` 装好了，`/v1/embeddings` 跑得通。**那一章那段 `embed_test.py` 的道理，这一章直接接着用**；
- 一批文字文件。**`.txt` 或者 `.md`**，PDF 要先转成文字（下面第一步说）；
- 主线第 1 到 7 章做完最好。**没做完也能跑这一章**，但你会不知道该怎么给它出题；
- 60 到 90 分钟。

## 新词

**语义搜索**：按意思搜，不按字面搜。[第 6 卷第 12 章](../06-本地模型/12-embedding与reranker.md)那一节讲的“东西买回来不满意怎么办”能搜到“退换货流程”，**就是这件事**。

**索引文件**：把一批文字切成片段、每段算好向量之后，存下来的那个文件。**这一章的索引是一个 JSON 文件**，自己存自己的，和 Open WebUI 那边的库是两份东西。

## 它和前面十五章的区别

一张表说清：

| | 问答库（第 1 到 15 章） | 语义搜索（这一章） |
| --- | --- | --- |
| 输入 | 一个问题 | 一句话，或者几个词 |
| 输出 | 一段回答，底下挂引用 | **几个文件和片段，按相关度排** |
| 模型干什么 | embedding 找片段，对话模型写回答 | **只有 embedding，没有对话模型** |
| 会不会瞎编 | 会，所以有第 5 章 | **不会。它只把库里已有的东西列出来** |
| 快慢 | 要等模型生成 | **快得多，没有生成那一步** |
| 谁在判断 | 模型先替你读了一遍 | **人自己读，自己判断** |

**最后一行是这两件事真正的分界。**

问答库替人读了一遍，**省的是读的工夫，代价是要防它瞎编、要核对引用**。语义搜索只把东西找出来，**读还是人读**——**省的是找的工夫，代价是省不掉读那一步。**

**很多场景要的其实是后一种。**

## 什么时候该做这个，不做问答库

**四种情况，这个比问答库合适。**

**一、客户要的是“找到那份文件”，不是“告诉我答案”。**

“三年前那个方案在哪儿”“上次做过类似的项目吗，材料在哪个文件夹”——**这类需求的终点是打开文件，不是读一段话。**

**二、客户不能接受任何生成的内容。**

有些行业、有些岗位，**一段模型写出来的话就是个麻烦**，哪怕它带着引用。**这个方案里没有一个字是模型写的**——列出来的全是原文片段。

**三、要接进已有的系统。**

客户已经有一个内部系统、一个搜索框、一个工单分派流程。**你要给它一个“按意思搜”的能力，不是给它一个聊天窗口。**

**四、文件量大、更新频繁，人不会天天去网页上传。**

这一条最实际。**脚本能挂定时任务，界面不能。**

**反过来，要问答、要引用、要有个人用的界面，就回去用主线那一套。** 两者不是替代关系，下面还有一节专说它们的关系。

## 动手：把一批文件变成一个能按意思搜的索引

**四步，全在命令行里。**

### 第一步，准备一批文字文件

新建一个工作目录，把要搜的文件放进 `docs`：

```bash
mkdir -p ~/ai-client-work/docs
cd ~/ai-client-work
```

PDF 要先转成文字。第 2 章那个 `pdftotext` 在这里换个用法——**不加 `-` 就是转成文件**：

```bash
pdftotext 手册.pdf 手册.txt
```

```bash
for f in *.pdf; do pdftotext "$f" "${f%.pdf}.txt"; done
```

作用：把当前目录下每一个 `.pdf` 转成同名的 `.txt`。`${f%.pdf}` 的意思是“把结尾那个 `.pdf` 去掉”。

**转完抽查两份，看看抽出来的字是不是顺的**（扫描件抽不出东西，双栏可能串行——第 2 章和第 14 章那两节）。**转出来是空文件的，那是扫描件**，走[第 8 卷](../08-OCR/README.md)。

**先放五到十份进 `docs` 就够跑通了**，跑通再往里加。

### 第二步，建索引

在 `~/ai-client-work` 下新建 `build_index.py`，内容照抄：

```python
import json
import os
import sys

import requests

# 换成你那台 Mini PC 的地址，本机跑就用 localhost
BASE = "http://192.168.1.50:11434/v1"
MODEL = "bge-m3"

DOC_DIR = "docs"           # 要搜的那批文件放这个目录
INDEX_FILE = "index.json"  # 算好的索引存到这个文件
SUFFIXES = (".txt", ".md")

CHUNK_SIZE = 500  # 一个片段多少个字
OVERLAP = 100     # 相邻两段重叠多少个字


def read_files(folder):
    """把目录里的文本文件读进来，返回 [(文件名, 全文), ...]。"""
    items = []
    for name in sorted(os.listdir(folder)):
        path = os.path.join(folder, name)
        if not os.path.isfile(path):
            continue
        if not name.lower().endswith(SUFFIXES):
            continue
        with open(path, "r", encoding="utf-8") as f:
            items.append((name, f.read()))
    return items


def split(text, size, overlap):
    """按字数切成一段一段，相邻两段留一点重叠。"""
    text = " ".join(text.split())
    if not text:
        return []
    step = size - overlap
    if step <= 0:
        sys.exit("重叠不能大于等于片段大小")
    pieces = []
    start = 0
    while start < len(text):
        pieces.append(text[start:start + size])
        start += step
    return pieces


def embed(text):
    """把一段文字送去算成向量，返回一个数字列表。"""
    resp = requests.post(
        BASE + "/embeddings",
        json={"model": MODEL, "input": text},
        timeout=120,
    )
    resp.raise_for_status()
    return resp.json()["data"][0]["embedding"]


def main():
    if not os.path.isdir(DOC_DIR):
        sys.exit("没有 %s 这个目录，先建一个，把文件放进去" % DOC_DIR)

    files = read_files(DOC_DIR)
    if not files:
        sys.exit("%s 里没有找到 .txt 或者 .md 文件" % DOC_DIR)

    records = []
    for name, text in files:
        pieces = split(text, CHUNK_SIZE, OVERLAP)
        print("%s　切成 %d 段" % (name, len(pieces)))
        for i, piece in enumerate(pieces):
            records.append({
                "file": name,
                "no": i + 1,
                "text": piece,
                "vector": embed(piece),
            })

    with open(INDEX_FILE, "w", encoding="utf-8") as f:
        json.dump({"model": MODEL, "records": records}, f, ensure_ascii=False)

    print()
    print("一共 %d 段，已经写进 %s" % (len(records), INDEX_FILE))


if __name__ == "__main__":
    main()
```

跑它：

```bash
~/ai-client/bin/python build_index.py
```

**正常输出**是一行一个文件，最后一行汇总：

```text
公司制度.txt　切成 12 段
产品手册.txt　切成 47 段

一共 59 段，已经写进 index.json
```

逐段说清这个程序：

- **`BASE` 和 `MODEL`** —— 和[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)那两行一样，**换机器换模型只改这两行**；
- **`CHUNK_SIZE` 和 `OVERLAP`** —— 就是第 6 章那两个旋钮，**只不过这次它们在你自己手里**。500 和 100 是一个能跑起来的起点，**本教材不说这两个值好**，你要按自己的文件和自己的题去调（第 6 章那条规矩在这里一样成立）；
- **`read_files()`** —— 只读 `.txt` 和 `.md`，别的一律跳过。**子目录也不进**，第一版就这么简单；
- **`split()`** —— 先把连续的空白压成一个空格，再按字数硬切。**`step = size - overlap` 是重叠的实现**：切完一段往前走 400 个字，于是相邻两段有 100 个字是重的；
- **`embed()`** —— 和[第 6 卷第 12 章](../06-本地模型/12-embedding与reranker.md)那个一模一样，**一个字没改**；
- **`records`** —— 每段记四样：哪个文件、第几段、原文、向量。**原文要存**，搜出来要给人看的就是它；
- **`json.dump(..., ensure_ascii=False)`** —— 不写这一项，中文会被存成一堆 `\u` 开头的转义，**文件还是能用，就是打开看不懂**。

> **第一次跑要等一会儿。** 每一段都要发一次请求，**几十段几秒钟，几千段要跑一阵**。屏幕上一行一行出文件名，就是在动。

### 第三步，搜

新建 `search.py`：

```python
import json
import math
import sys

import requests

# 和建索引时保持一致
BASE = "http://192.168.1.50:11434/v1"
MODEL = "bge-m3"
INDEX_FILE = "index.json"
TOP_N = 5  # 返回最相关的几条


def embed(text):
    """把一段文字送去算成向量，返回一个数字列表。"""
    resp = requests.post(
        BASE + "/embeddings",
        json={"model": MODEL, "input": text},
        timeout=120,
    )
    resp.raise_for_status()
    return resp.json()["data"][0]["embedding"]


def cosine(a, b):
    """算两个向量的相似度，结果越接近 1 越像。"""
    dot = sum(x * y for x, y in zip(a, b))
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(y * y for y in b))
    if na == 0 or nb == 0:
        return 0.0
    return dot / (na * nb)


def main():
    if len(sys.argv) < 2:
        sys.exit('用法：~/ai-client/bin/python search.py "要搜的那句话"')
    query = " ".join(sys.argv[1:])

    with open(INDEX_FILE, "r", encoding="utf-8") as f:
        data = json.load(f)

    if data.get("model") != MODEL:
        sys.exit("这份索引是用 %s 算的，和现在的 %s 对不上，重建一次"
                 % (data.get("model"), MODEL))

    qv = embed(query)

    scored = []
    for rec in data["records"]:
        scored.append((cosine(qv, rec["vector"]), rec))
    scored.sort(key=lambda pair: pair[0], reverse=True)

    print("搜：%s" % query)
    print()
    for score, rec in scored[:TOP_N]:
        print("%.4f　%s　第 %d 段" % (score, rec["file"], rec["no"]))
        print("      %s……" % rec["text"][:80])
        print()


if __name__ == "__main__":
    main()
```

跑它：

```bash
~/ai-client/bin/python search.py "东西买回来不满意怎么办"
```

**正常输出**是五条，一条两行：

```text
搜：东西买回来不满意怎么办

0.xxxx　公司制度.txt　第 4 段
      第七条　退换货。商品自签收之日起七日内，商品本体与配件齐全、不影响二次销售的……

0.xxxx　产品手册.txt　第 31 段
      ……
```

**要看的是排在最前面那几条对不对，不是那个分数本身。** [第 6 卷第 12 章](../06-本地模型/12-embedding与reranker.md)说过——**同一个模型内部的大小关系才有意义，数值不能跟别人的比。**

逐段说清这个程序：

- **`sys.argv`** —— 命令行里跟在脚本后面的那些词。`" ".join(sys.argv[1:])` 是把它们拼回一句话，**这样搜的时候加不加引号都行**；
- **那个 `data.get("model") != MODEL` 的检查** —— **这一段是本章最值钱的五行代码。** [第 6 卷第 12 章](../06-本地模型/12-embedding与reranker.md)那条规矩说：**同一个索引从头到尾必须用同一个 embedding 模型**，换了模型旧向量就作废。这五行让程序自己发现这件事，**而不是让你在几个月后对着一堆莫名其妙的搜索结果发呆**；
- **`cosine()`** —— 和[第 6 卷第 12 章](../06-本地模型/12-embedding与reranker.md)那个一模一样，**一个字没改**；
- **`scored.sort(...)`** —— 按分数从大到小排。`reverse=True` 就是从大到小；
- **`rec["text"][:80]`** —— 只打前 80 个字。**全打出来会刷满屏幕**，要看全文就打开那个文件。

### 报不出来的时候

- **`Connection refused`** —— 接口没通，回[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)；
- **说这个模型不支持 embeddings** —— `MODEL` 填成了对话模型，换成 `bge-m3`（[第 6 卷第 12 章](../06-本地模型/12-embedding与reranker.md)）；
- **`FileNotFoundError: index.json`** —— 先跑 `build_index.py`；
- **中文搜出来全是不相干的** —— 先确认索引不是空的（看建索引时那个总段数），再确认 `MODEL` 两个脚本里填的是同一个。

其余的到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。

## 这两个脚本能干什么，不能干什么

**这一节要老实说，因为你可能要拿它去见客户。**

**它能干的：**

- 几百到几千段的规模，**在这台机器上跑得又快又稳**；
- 没有任何联网的成分。**建索引和搜索全走本机那个接口**，断网照跑（第 9 章那套演示对它一样成立）；
- 输出是数据，**能接进别的程序**——改几行就能变成一个函数、一个接口、一个定时任务。

**它不能干的，五条：**

**一、量再大就撑不住。** 索引整份读进内存、每次搜索逐条算一遍。**几千段没问题，几十万段会又慢又占内存**——那时候要上专门的向量库，**本教材不做**。

**二、增量更新没有。** 改了一个文件，要整份重算。**文件多的时候要加一个“只算变了的”，本章不写。**

**三、切分是按字数硬切的。** 不看句号、不看段落、不看表格。**够用，不好看**——第 6 章说的那些毛病（把话截断、缺后半截）它全有。

**四、没有权限。** **谁能跑这个脚本，谁就能搜到全部内容。** 第 8 章那套按人分库在这里不成立。**这一条要在交付之前说清楚**，别让客户以为它自带权限。

**五、没有关键词那一路。** 第 6 章说的混合检索，**这个脚本只有向量那一半**。合同编号、发票号、型号这类精确字符串，**它未必搜得准**。要那一半，得再接一个关键词检索（[第 6 卷第 12 章](../06-本地模型/12-embedding与reranker.md)提过 BM25 那一类），**本章不做。**

> **这五条不是缺陷清单，是边界。** 拿它见客户的时候主动说出来——**和第 7 章说的“B 类里留几道它答不好的”是同一个道理。**

## reranker 在这里怎么用

[第 6 卷第 12 章](../06-本地模型/12-embedding与reranker.md)讲过它是什么，**这一章讲它接在哪儿。**

**分工那一句话照搬：embedding 从一万里挑二十，reranker 从二十里挑三。**

**在上面那个 `search.py` 里，它接在排序之后、打印之前**：

```python
# 粗筛：先按向量取前 20 条
rough = scored[:20]

# 精挑：把问题和这 20 条一起送给重排模型，让它逐条打分，重新排序
# 具体端点、请求格式和返回字段随你用的那套推理软件而变
# 动手当天以那套软件自己的文档为准

# 然后再取前 3 到 5 条打印
```

**装法两条：**

**一、如果你只是想在 Open WebUI 里用**，第 3 章改 embedding 模型的那一页上有一栏是给重排模型的，填一个模型名就行。

**这里有一个坑，第 9 章点过名**：**那一栏填的模型多数要联网下载。** 下载没走完就去断网演示，**当场翻车**——第 9 章那四个翻车点里的第三个说的就是这件事。**要用就在有网的时候先下好，然后照第 9 章检查清单第 6、7 条重走一遍。**

**二、如果你要在自己的脚本里用**，就是上面那段注释的位置。

> **具体填哪个模型名、Ollama 当前版本对重排的支持方式、请求和返回长什么样**：**本项目未核实，需要核验**。[第 6 卷第 12 章](../06-本地模型/12-embedding与reranker.md)已经把这一条挂起来了，**这一章也不替你核**——动手当天去你用的那套软件的文档上查，那才是准的。

**什么时候值得加，三条**（[第 6 卷第 12 章](../06-本地模型/12-embedding与reranker.md)那三条照搬）：

- 明明库里有对的，**就是排不到前面**；
- 问得绕一点就找不着；
- 库里有很多写法相近、内容不同的文档（各版本合同、各型号手册）。

**什么时候不加：**

- **刚建完索引，还没测过。** 先用 embedding 单跑，**用下面那套评测法测一轮再说**；
- 库不大，几百段以内。**粗筛的前几条基本就够**；
- **你不能接受它变慢。** 二十个候选就要跑二十次，**在一个要求“搜起来跟打字一样快”的场景里，这个代价未必划算。**

**这一条最要紧：加之前先测一轮，加之后用同一组题再测一轮。** 不这么做，**你不知道它到底有没有变好**——和第 6 章那条“一次只动一个”是同一条规矩。

## 和 Open WebUI 内置检索的关系

**先说清楚：这两套在做同一件事。**

Open WebUI 的知识库内部也是切分、算向量、按相似度取 Top K（第 3 章、第 6 章）。**这一章的脚本是把那一层单独拿出来，自己写了一遍。**

**为什么还要自己写一遍？** 上面那节“什么时候该做这个”说了四条，核心是**一件事：脚本能接进别的程序，界面不能。**

**要记住的三条：**

**一、索引是两份。** Open WebUI 那边有它自己的，你这个脚本有 `index.json`。**它们各算各的，互不知道对方存在。**

**二、改了 embedding 模型，两边都要重建。** Open WebUI 那边按第 3 章、第 10 章的做法重建；你这边把 `index.json` 删掉重跑 `build_index.py`。**漏了任何一边，那一边的结果就开始不对，而且不报错**（[第 6 卷第 12 章](../06-本地模型/12-embedding与reranker.md)那条规矩）。

**三、同一台机器上两套可以共存。** 它们共用的只有一样东西——**那个 `bge-m3` 和那个接口。** 内存和硬盘各占各的。

**给客户的时候常见的组合是这样的**：**人用 Open WebUI 那个网页问答**，**程序用这个脚本搜。** 一台机器，两个入口，**同一批文件。**

## 怎么给它评测

**第 7 章那张表要改一处才能用。**

问答库记三个格子：答对没有、引用对不对、有没有瞎编。

**语义搜索没有“答”，也不会“瞎编”**，剩下的只有一件事——**你要的那一条，排到第几了。**

**一道题记一个格子，三档：**

```text
语义搜索评测表

索引名：____________________      题集版本：v____
测试日期：______年__月__日      测试人：____________
本次改动：（这次动了什么。什么都没动就写“无”）
____________________________________________________

编号  要搜的那句话                  期望命中哪个文件／哪一段    在前 3  在前 5  没搜到
----  ----------------------------  --------------------------  ------  ------  ------
1     东西买回来不满意怎么办         公司制度.txt 退换货那一条     □       □       □
2                                                                □       □       □
……

“在前 3”的有几道：____ / 20

没搜到的题号：____________________________________

下一步动作（只写一条，一次只动一个）：
____________________________________________________
```

**几件事和第 7 章一样，不重讲：**

- **题目固定不变**，改了就没法和上次比；
- **一次只动一个**（片段大小、重叠、加不加重排），动完整张表重跑；
- **只记档位，不算百分比。** 理由第 7 章写全了——**一个数字写下来就会被人拿去用。**

**一件事和第 7 章不一样：**

**这里的“期望答案”是一个位置，不是一句话。** 出题的时候你要先知道**要的那一条在哪个文件、哪一段**——**所以出题的人还是得读过这批文件**（第 7 章那条前提）。

**这张表也一样是跟客户约定验收的那张纸**，规矩照第 17 章走：**题目由客户出，通过线由客户定，你不给数字。**

## 这个能力可以单独卖

**它是一个能拆出来单卖的东西，理由三条。**

**一、它解决的是一个客户自己说得清的问题。**

“我们文件搜不出来”——**这句话不用你教育客户。** 而“你需要一个 RAG 知识库”这句话，多数客户听完还是不知道要什么。

**二、没有生成，就没有那一整块顾虑。**

客户对 AI 最常见的两个担心是“它会不会瞎说”和“数据会不会出去”。**这个方案把第一个直接消掉了**（它一个字都不写），**第二个照第 9 章拔网线**。

**三、它能接进客户已经有的东西。**

客户不用换系统、不用换习惯、不用培训一屋子人。**给他们的搜索框换一个后端，或者加一个新的入口。**

**适合的客户长什么样：** 手上有几千上万份文件，已经有一个搜不出东西来的搜索框，**而且他们的人天天在抱怨找不到**。[第 6 卷第 12 章](../06-本地模型/12-embedding与reranker.md)开头那两个老毛病——**换个说法就搜不到、一个常用词命中一大片**——就是他们每天在经历的事。

> **证据要说清楚，这一条别含糊。**
>
> 公开渠道里能查到两条相关的服务商自述：一家新加坡咨询公司公开写明在客户部署中用过 Strix Halo 这一类机器，**并称在上面跑过真实客户的 workload**；另一家做检索系统的公司记录过一个客户要求在其自有 GPU 上索引几十亿条记录、并为此做了 embedding 模型选型。
>
> **这两条证明的是：有人把“做语义检索”当成一个项目在做，而且是收费的项目。**
>
> **它们不证明的是**：客户名称、合同金额、这台机器上做这件事能卖多少钱。**两条都是服务商第一人称自述，没有可核验的客户名、合同和发票**，事实状态 `candidate`；其中第二条用的硬件是客户自己的 GPU，**和这台 Mini PC 无关，规模也不能线性缩过来。**
>
> **照这一章做是合理的准备，不是一条保证能卖出去的路。** 价钱怎么报在[第 11 卷](../11-客户与报价/README.md)，本章不下价格结论。
