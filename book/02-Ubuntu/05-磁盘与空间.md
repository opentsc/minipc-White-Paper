# 05　磁盘与空间

## 这一章的任务

给模型文件划出一块专用存储区。

先看清这台机器现在有多少空间、够放几个模型。如果你有第二块硬盘或一块常年插着的移动硬盘，把它挂起来、设成开机自动挂载，再让 `~/ai/models` 指到它上面。做完之后，往 `~/ai/models` 里下模型，文件落在专用的那块盘上，系统盘不会被撑满。

**只有一块盘也能做完这一章**：看空间那两节照做，挂载那几节跳过，`~/ai/models` 就是第 1 章建的那个实际目录。后面各卷一律写 `~/ai/models`，两种情况都对得上。

## 开始前

- 第 1 章的 `ai` 目录已经建好；
- 打算挂第二块盘的话，先确认那块盘上有没有还要的数据；
- 20 分钟，加挂载的话再加 20 分钟。

## 新词

分区和挂载在[第 1 章](01-桌面与文件.md)和[第 4 卷第 13 章](../04-Max395硬件/13-SSD.md)解释过。这一章多 4 个。

**文件系统**（Filesystem）：一块分区上组织文件的格式。同一块盘格成不同的文件系统，能存的文件大小、支不支持权限都不一样。Linux 常用 `ext4`，Windows 用 NTFS，U 盘常见 exFAT。

**挂载点**（Mount Point）：分区接到目录树上的那个目录。挂载点是 `/mnt/aidata`，就表示进 `/mnt/aidata` 看到的是那块分区里的内容。

**UUID**：系统给每个分区生成的一串固定编号。设备名（`/dev/nvme1n1p1` 这类）会随插拔顺序变化，UUID 不会，所以开机自动挂载认的是 UUID。

**`/etc/fstab`**：一个配置文件，记着开机时要自动挂哪些分区、挂到哪里。这一章唯一要改的系统文件就是它。

## 现在有多少空间

```bash
df -h
```

作用：列出每个已挂载的分区用了多少、还剩多少。`-h` 表示用 GB、MB 这种可读格式。

输出里找挂载点是 `/` 的那一行，那是系统盘：

```
文件系统        容量  已用  可用 已用% 挂载点
/dev/nvme0n1p2  938G   87G  804G   10% /
```

`可用` 那一列就是还能用多少。一堆 `tmpfs` 开头的行是内存里的临时文件系统，不占硬盘，不用管。

只看系统盘：

```bash
df -h /
```

看 `ai` 目录下各个子目录各占多少：

```bash
du -sh ~/ai/*
```

`du` 统计目录占用，`-s` 只给每项的总数，`-h` 可读格式。刚开始几个目录都很小，模型下下来之后 `models` 会一骑绝尘。

这台机器上装的是什么盘、盘的健康状态怎么读、加装硬盘和保修的关系，在[第 4 卷第 13 章](../04-Max395硬件/13-SSD.md)，这里不重抄。

## 要留多少空间

模型文件的大小取决于参数量和量化档，同一个模型不同档能差好几倍，本教材不抄具体数字，[第 4 卷第 13 章](../04-Max395硬件/13-SSD.md)写了怎么去模型仓库查准确大小，[第 6 卷](../06-本地模型/README.md)讲怎么选。

这一章只管地方够不够，按本教材的操作余量算：**系统盘上常年留出至少 20 GB，再加上你最大那个模型的大小**。前一半给系统自己用——更新、新内核、日志、软件包缓存都写在系统盘上；后一半留给“再下一个模型试试”。

系统盘写满的后果比想象中重，写不了日志、装不了软件，严重时连桌面都登不进去。真的快满了，清理办法在[第 4 卷第 13 章](../04-Max395硬件/13-SSD.md)。

算下来空间不够，有两条路：只放一两个模型，用完删掉再换；或者加一块盘，走下面的步骤。

## 认盘

```bash
lsblk
```

作用：把这台机器上的盘和分区画成一棵树。

输出类似：

```
NAME        SIZE TYPE MOUNTPOINTS
nvme0n1     953G disk
├─nvme0n1p1   1G part /boot/efi
└─nvme0n1p2 952G part /
nvme1n1    1.8T disk
```

怎么读：

- 顶格的 `nvme0n1`、`nvme1n1` 是两块物理盘，缩进的是它们上面的分区；
- `MOUNTPOINTS` 那一列写了挂在哪里，空白表示还没挂载，没挂载的分区在“文件”里看不见；
- 上面这个例子里，`nvme0n1` 是系统盘，`nvme1n1` 是第二块盘，1.8 T，下面一个分区都没有。

看每个分区是什么文件系统、UUID 是多少：

```bash
lsblk -f
```

第二块盘那一行的 `FSTYPE` 列是空的，说明它还没格式化过，得先格。已经有 `ext4`、`ntfs` 之类的值，说明盘上已经有文件系统，很可能也有数据，**不要格式化**，直接跳到下面的“挂载”。

## 格式化（只在盘是空的时候做）

**格式化会清空整块分区上的全部数据，没有撤销，也没有回收站。** 动手之前确认两件事：一是 `lsblk` 里那块盘的容量和型号对得上你要格的那块，别把系统盘格了；二是盘上确实没有你还要的东西，不确定就先挂起来看一眼里面有什么。

用图形界面做，比命令安全，因为它会把盘的型号和容量明明白白显示出来。

1. 按 `Super` 键搜“磁盘”（Disks），打开；
2. 左边列出所有盘，点选第二块。**核对右上角显示的型号和容量**，确认是你要动的那块；
3. 右边如果有分区就点选它，点齿轮按钮选“格式化分区”。整块盘是空的，先点减号旁边的加号建一个分区，占满整块盘；
4. 类型选“Linux 内部使用”，也就是 `ext4`；
5. 卷名填 `aidata`；
6. 点“格式化”，弹窗里再确认一次，等它跑完。

选 `ext4` 的原因是它支持完整的 Linux 权限，第 4 章讲的属主、属组、`chmod` 在它上面才有效。exFAT 和 NTFS 适合和 Windows 交换文件，但不记权限，不要拿来放模型和项目。

## 挂载

建一个挂载点：

```bash
sudo mkdir -p /mnt/aidata
```

先手动挂一次，验证盘是好的：

```bash
sudo mount /dev/nvme1n1p1 /mnt/aidata
```

设备名换成你自己 `lsblk` 里看到的那个分区名，注意是分区（带 `p1` 那个），不是整块盘。命令成功没有输出。

确认挂上了：

```bash
df -h /mnt/aidata
```

输出里应该出现这块盘的容量。

把这个目录交给你自己：

```bash
sudo chown -R $USER:$USER /mnt/aidata
```

刚挂上的分区属主是 `root`，不改的话你自己的账户往里写文件会被拒绝。`$USER` 会自动换成你的账户名。

## 开机自动挂载

手动挂的挂载重启就没了，要写进 `/etc/fstab` 才会每次开机自动挂上。

**先取 UUID**：

```bash
sudo blkid /dev/nvme1n1p1
```

输出类似：

```
/dev/nvme1n1p1: LABEL="aidata" UUID="8f3a1c92-4b7d-4e21-9c05-2a6f8e1b7d33" TYPE="ext4"
```

把引号里那一长串 UUID 记下来，等会儿要填。

**备份配置文件**：

```bash
sudo cp /etc/fstab /etc/fstab.bak
```

**打开编辑**：

```bash
sudo nano /etc/fstab
```

用方向键移到文件最后，另起一行，加上：

```
UUID=8f3a1c92-4b7d-4e21-9c05-2a6f8e1b7d33  /mnt/aidata  ext4  defaults,nofail  0  2
```

UUID 换成你自己的。6 段分别是：认哪个分区、挂到哪里、什么文件系统、挂载选项、要不要备份、开机检查顺序。

`nofail` 这一项别省。它的意思是这块盘没插上或者坏了的时候，系统照常开机，只是不挂它。不写的话，盘一出问题开机就会停在那里等。

按 `Ctrl+O` 回车保存，`Ctrl+X` 退出。

**不重启就验证**：

```bash
sudo umount /mnt/aidata
sudo mount -a
df -h /mnt/aidata
```

第一条先卸载，第二条按 `/etc/fstab` 里写的重新挂一遍，第三条确认挂上了。`mount -a` 没有任何报错，`df -h` 能看到容量，就说明这一行写对了。

> **⚠️ `/etc/fstab` 写错会让系统开不到桌面。** 所以上面那条 `sudo mount -a` 必须在重启之前执行。它一旦报错，立刻把备份复制回去，不要重启：
>
> ```bash
> sudo cp /etc/fstab.bak /etc/fstab
> ```
>
> 已经重启并且卡在启动画面进不去，用[第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)做的恢复 U 盘启动到 Live 模式，把 `/etc/fstab` 改回来。其他症状到[第 15 卷](../15-故障排查/README.md)按症状查。

## 把 `~/ai/models` 指到这块盘上

在新盘上建一个模型目录：

```bash
mkdir -p /mnt/aidata/models
```

第 1 章建的 `~/ai/models` 现在是空的，删掉它：

```bash
rmdir ~/ai/models
```

`rmdir` 只能删空目录，里面有东西它会报错——这是好事，说明你有文件在里面。这种情况先把文件搬过去（`mv ~/ai/models/* /mnt/aidata/models/`），再执行 `rmdir`。

建一个指路牌指过去：

```bash
ln -s /mnt/aidata/models ~/ai/models
```

`ln -s` 建的叫软链接，本身不占空间，作用是让 `~/ai/models` 这个名字指向新盘上的真实目录。往 `~/ai/models` 写东西，文件实际落在第二块盘上。

验证：

```bash
ls -ld ~/ai/models
```

输出开头是 `l`，后面带一个箭头：

```
lrwxrwxrwx 1 roland roland 19  8月14日 14:02 /home/roland/ai/models -> /mnt/aidata/models
```

再看一眼容量：

```bash
df -h ~/ai/models/
```

显示的是第二块盘的容量，不是系统盘的，说明指对了。

## 完成检查

- `df -h /` 能看出系统盘还剩多少可用空间吗？
- 剩余空间够不够“20 GB 加上你打算下的最大那个模型”？
- 挂了第二块盘的话，`df -h /mnt/aidata` 能看到它的容量吗？
- `sudo mount -a` 执行完没有报错吗？（这一条没通过，先按上面的警告把 `/etc/fstab` 还原，不要重启）
- `ls -ld ~/ai/models` 的输出里有指向新盘的箭头吗？
- 重启一次，`df -h /mnt/aidata` 还能看到这块盘吗？
