# 11　环境变量与配置文件

## 这一章的任务

把第 10 章那套服务的端口从 3000 改成 3080，并且让它真的生效。

一件事要改两个地方：端口写在 `compose.yaml` 里，站点地址写在 Gitea 自己的配置文件里。两个地方的改法不同，让改动生效的命令也不同。做完之后你会知道改配置这件事的完整套路——改哪儿、怎么让程序读到、改坏了怎么退回去。

顺带把密码从 `compose.yaml` 里挪出去，放进 `.env`。

## 开始前

- 第 10 章那套服务还在跑，浏览器能打开 `http://localhost:3000`；
- 第 6 章的 `systemctl restart` 和第 10 章的 `docker compose up -d` 会用了；
- 30 分钟。

## 新词

**环境变量**（Environment Variable）：系统交给程序的一组“名字＝值”。程序启动时能读到它们，靠它们知道当前账户是谁、家目录在哪、去哪儿找命令。配置也可以这样传给程序，第 10 章 `compose.yaml` 里的 `environment` 那几行就是。

**`.env` 文件**：一个纯文本文件，一行一个“名字=值”。Docker Compose 会自动读取项目目录下的这个文件。把会变的、不能公开的值放进它，主配置文件里只留名字。

**配置文件**：程序自己的设置，存成文本文件。改它要重启程序才生效，程序不会自己发现你改了。

**`~/.bashrc`**：你这个账户的终端启动脚本。每开一个终端窗口，里面的内容执行一遍。要让某个环境变量每次都在，就写进它。

## 先看看现在有哪些环境变量

```bash
printenv
```

作用：把当前终端里所有环境变量打印出来，一行一个。输出几十行，看几个眼熟的：

- `HOME=/home/roland`——你的家目录，第 9 章 `-v` 里用的 `$HOME` 就是它；
- `USER=roland`——账户名，第 2 章用过；
- `PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:...`——一串目录，用冒号隔开。你打一条命令，系统就按这个顺序去这些目录里找。找不到就报 `command not found`。

只看一个：

```bash
echo $HOME
```

变量名前面加 `$` 表示“取它的值”。这个写法在第 2 章的 `$USER`、第 9 章的 `$HOME` 里都出现过。

## 临时设和永久设

**临时设**：

```bash
export DEMO_NAME=hello
echo $DEMO_NAME
```

第二条输出 `hello`。`export` 的意思是设一个环境变量，让这个终端里之后启动的程序都能读到。

现在按 `Ctrl+Alt+T` 另开一个终端窗口，在新窗口里执行：

```bash
echo $DEMO_NAME
```

输出是**空行**。

这就是临时的含义：**只在你设它的那个终端窗口里有效**，新开的窗口读不到，关掉窗口就没了。临时设适合试一下、跑一次，不适合长期配置。

**永久设**：写进 `~/.bashrc`。

改之前先备份：

```bash
cp ~/.bashrc ~/.bashrc.bak
```

打开：

```bash
nano ~/.bashrc
```

移到文件最后，另起一行加上：

```bash
export DEMO_NAME=hello
```

`Ctrl+O` 回车保存，`Ctrl+X` 退出。

改完之后当前这个窗口还是读不到，因为 `~/.bashrc` 只在开窗口那一刻执行。让它立刻生效：

```bash
source ~/.bashrc
```

`source` 的作用是把这个文件在当前终端里执行一遍。之后再开的新窗口自动就有了。

试完把这一行删掉，`~/.bashrc` 里不要堆没用的东西。

**这两种设法的区别，后面各卷会一直用到**：文档里让你 `export` 一下的，都是临时的，重开终端就没了，别以为设过一次就永远有效。

## 改配置文件的三条规矩

从这里开始进入正题。三条规矩，后面每次改配置都照做：

**第一，改之前先复制一份 `.bak`。**

```bash
cp 配置文件 配置文件.bak
```

系统目录里的文件要加 `sudo`。这一条第 5 章改 `/etc/fstab` 时做过，那不是特例，是每次都要做的动作。文本文件才几 KB，备份不占地方，代价是零；不备份的代价是改坏之后你只能凭记忆往回猜。

**第二，一次只改一处，改完立刻验证。** 一口气改五处，坏了不知道是哪处坏的，只能一处处退。

**第三，改完要让程序重新读一遍。** 改文件不会自动生效。让它生效的命令有两种，第 10 章讲过一次：

- 程序是 systemd 管的服务，用 `sudo systemctl restart 服务名`（第 6 章）；
- 改的是 `compose.yaml`，用 `docker compose up -d`（第 10 章）。

## 第一步，把密码和端口挪进 `.env`

进项目目录：

```bash
cd ~/ai/projects/gitea
```

先备份现在这份能跑的配置：

```bash
cp compose.yaml compose.yaml.bak
```

建 `.env`：

```bash
nano .env
```

内容两行：

```
GITEA_PORT=3080
GITEA_DB_PASSWORD=你在第10章设的那个密码
```

写法上注意三点：**等号两边不要加空格**；值里面不用加引号；一行一个。

`Ctrl+O` 回车保存，`Ctrl+X` 退出。

把它的权限收紧：

```bash
chmod 600 .env
```

`600` 是只有你自己能读能写，第 4 章讲过。密码类的文件都该是这个权限。

**`.env` 不能进 Git。** 这一条以及为什么，见[第 0 卷第 8 章](../00-使用说明/08-文件保护.md)，这里不重复。这个目录以后要交给 Git 管的话，先建一个 `.gitignore` 把 `.env` 写进去。

## 第二步，改 `compose.yaml` 引用它

```bash
nano compose.yaml
```

改三行。`${名字}` 这种写法的意思是“到 `.env` 里取这个值”：

原来的：

```yaml
      - GITEA__database__PASSWD=change-this-password
```

改成：

```yaml
      - GITEA__database__PASSWD=${GITEA_DB_PASSWORD}
```

原来的：

```yaml
    ports:
      - "3000:3000"
```

改成：

```yaml
    ports:
      - "${GITEA_PORT}:3000"
```

**冒号后面那个 3000 不要动。** 前面是宿主机端口，改的是它；后面是容器里程序监听的端口，容器内部的事，改了反而连不上。这是第 9 章讲端口映射时那两个数字的区别，到这里才真正用上。

最后是数据库那段：

```yaml
      - POSTGRES_PASSWORD=${GITEA_DB_PASSWORD}
```

保存退出。

改完先检查一下 Compose 读出来是什么：

```bash
docker compose config
```

作用：把变量都替换好之后的完整配置打印出来，不真的执行。输出里 `ports` 那行应该是 `3080:3000`，密码那几处是你 `.env` 里的真实值。

**这一步能挡住绝大多数低级错误**：变量名打错了，这里会显示成空的；YAML 缩进错了，这里直接报错并指出第几行。

## 第三步，让它生效

```bash
docker compose up -d
```

输出里会看到 Gitea 那个容器被重建（`Recreated`），数据库那个没变化的原样不动。

```bash
docker compose ps
```

`PORTS` 那列现在应该是 `0.0.0.0:3080->3000/tcp`。

浏览器打开 `http://localhost:3080`，页面回来了。旧的 `http://localhost:3000` 现在打不开——那个门已经关了。

## 第四步，改程序自己的配置文件

页面能打开了，但事情没完。进到任意一个仓库页面，看它给出的克隆地址，那里还写着 `http://localhost:3000/...`。

原因是：Gitea 安装的时候把站点地址记进了它自己的配置文件，那个文件在 `compose.yaml` 管不着的地方。

```bash
cd ~/ai/projects/gitea/data/gitea/conf
```

按规矩先备份：

```bash
cp app.ini app.ini.bak
```

打开：

```bash
nano app.ini
```

找到 `[server]` 那一段里的这行（按 `Ctrl+W` 可以在 `nano` 里搜索，输入 `ROOT_URL` 回车）：

```
ROOT_URL = http://localhost:3000/
```

把 3000 改成 3080，其他一个字都不动。保存退出。

同一段里还有一行 `HTTP_PORT = 3000`，**这行不要改**。它是容器里程序监听的端口，和 `compose.yaml` 冒号后面那个 3000 是同一个东西，改了就对不上了。

让它生效：

```bash
cd ~/ai/projects/gitea
docker compose restart gitea
```

**这里用 `restart`，不是 `up -d`。** 改的是程序自己的配置文件，容器本身的参数没变，只要让容器里的程序重新读一遍文件就行。第 10 章说“改文件用 `up -d`”指的是改 `compose.yaml`，两种情况分清楚：

| 改了什么 | 用哪条命令 |
| --- | --- |
| `compose.yaml` 或 `.env` | `docker compose up -d` |
| 容器里程序自己的配置文件 | `docker compose restart 服务名` |
| systemd 管的服务的配置文件 | `sudo systemctl restart 服务名` |

刷新页面，克隆地址里的端口跟着变了。

## 改坏了怎么退回去

改完起不来，不要接着改。把备份复制回来，起回上一个能跑的状态，然后慢慢查。

```bash
cd ~/ai/projects/gitea
cp compose.yaml.bak compose.yaml
docker compose up -d
```

配置文件那边同理：

```bash
cp ~/ai/projects/gitea/data/gitea/conf/app.ini.bak ~/ai/projects/gitea/data/gitea/conf/app.ini
docker compose restart gitea
```

**手上有 `.bak`，改配置这件事就没有下不来的时候。** 这也是那三条规矩里第一条最要紧的原因。

容器起不来的时候先看日志：`docker compose logs --tail 50 gitea`（第 10 章）。

## 换的端口被别人占了

`up -d` 报了 `port is already allocated` 或者 `address already in use`，说明这个端口上已经有程序在了。看是谁：

```bash
sudo ss -ltnp | grep 3080
```

- `ss` 列出网络连接，`-l` 只看在监听的，`-t` 只看 TCP，`-n` 直接显示数字端口，`-p` 显示是哪个程序；
- 加 `sudo` 才看得到程序名。

输出里最后一段写着占用它的程序。要么换一个端口（`.env` 里改一个数就行），要么把占用的那个停掉。**换端口更省事**，端口号从 1024 到 65535 随便挑，避开你已经用了的那几个。

## 不是 Docker 的服务怎么改

上面那套只在 Docker 里绕。systemd 管的服务改法一样，命令换成第 6 章的。

拿第 7 章留的那件事练手：给日志设一个固定的空间上限。

```bash
sudo cp /etc/systemd/journald.conf /etc/systemd/journald.conf.bak
sudo nano /etc/systemd/journald.conf
```

文件里大部分行前面有个 `#`，那是注释，被注释掉的行不生效，写在那里是告诉你有这么一项可以设、默认值是多少。

找到这一行：

```
#SystemMaxUse=
```

改成：

```
SystemMaxUse=500M
```

**井号要去掉**，去掉它这行才算数。保存退出。

让它生效：

```bash
sudo systemctl restart systemd-journald
```

验证：

```bash
systemctl status systemd-journald
```

`Active` 那行是 `active (running)`（第 6 章的读法），说明改完之后服务正常起来了。再看一眼日志占了多少：

```bash
journalctl --disk-usage
```

从此它最多占 500 MB，超了自动删最旧的。

**改系统配置文件之前那句 `sudo cp` 不能省。** `/etc` 下面的文件改坏，影响的是整台机器，不是一个容器。

有哪一步做不出来，到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。

## 完成检查

- `printenv` 能列出环境变量，`echo $HOME` 能打出你的家目录吗？
- `export` 设的变量，新开一个终端窗口还在吗？
- `~/ai/projects/gitea/.env` 建好了，权限是 `600` 吗？
- `docker compose config` 输出里的 `ports` 那行是 `3080:3000` 吗？
- 浏览器打开 `http://localhost:3080` 能进 Gitea 吗？
- 仓库页面上的克隆地址，端口跟着改了吗？改的是哪个文件？
- 改 `compose.yaml` 和改 `app.ini`，让它们生效的命令为什么不一样？
- 你手上有 `compose.yaml.bak` 和 `app.ini.bak` 吗？
