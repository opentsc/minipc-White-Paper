# 10　代码模型

## 这一章的任务

装一个会写代码的模型，先在终端里让它写一段脚本，再把它接进编辑器。

**做完之后，你写代码的地方就有一个本地助手了**——不联网，不按次数收费，公司的代码不出这台机器。

## 开始前

- 第 3 章做完，`ollama run` 能对话；
- 第 8 章做完，那个接口开着，`curl` 发得出请求。**接编辑器那一节全靠它**；
- 第 1 章那两张对照表在手边；
- 硬盘上留出 20 GB 或者 50 GB，看你挑哪一个；
- 会用一个编辑器。本章拿 VS Code 举例，别的编辑器思路一样；
- 一小时，下载时间另算。

## 新词

**补全**（completion）：你在编辑器里打字，它在光标后面用灰字提示接下来几行。按一下 Tab 就采纳。

**FIM**（fill in the middle，中间填空）：**在一个文件的中间补代码，前面和后面它都看得到。** 普通的对话模型只会顺着往下写，代码模型多数专门训练过这一项。

**agentic coding**：让模型连着干几步——读文件、改文件、跑一次、看报错、再改。**不是给你一段代码就完事，是替你把一件事做完。** 这一类工具在[第 9 卷](../09-Agent与RPA/README.md)展开，本章只装底下那个模型。

**插件**（extension）：装在编辑器里的一个小程序，给编辑器加功能。这一章要装的就是一个插件。

## 代码模型和通用模型差在哪

**差别不是“一个会写代码，一个不会”。** 第 9 章那几个通用模型都能写代码。真正的差别有三处：

**一、训练材料的比重不一样。** 代码模型看的代码多得多，所以对语言细节、库的用法、报错信息更熟。

**二、会 FIM。** 编辑器里的灰字补全靠的就是这个能力。**通用模型接进补全插件里，效果往往不对**——它不习惯“前后都有内容，只补中间”这种活。

**三、常常按连续改代码的场景训练过。** 读 diff、按报错改、一次改好几个文件，这类活代码模型做得顺。

**反过来也成立**：代码模型闲聊、写中文文案通常不如通用模型。**它是个专才。**

**所以怎么选，看你用得多不多：**

- **偶尔问一段代码** —— 第 9 章那个日常模型就够了，不用再装；
- **整天在编辑器里连着用** —— 装一个专门的。**这一章讲的是这种情况。**

### 装

```bash
ollama pull qwen3-coder:30b
```

作用：从 Ollama 的模型库直接拉。**这条最省事**，不用自己下文件、写 Modelfile。

要挑特定量化档、或者要和 llama.cpp 共用同一个文件的，走第 2 章那条路自己下：

```bash
hf download unsloth/Qwen3-Coder-30B-A3B-Instruct-GGUF --include "*Q4_K_M*" --local-dir ~/ai/models/qwen3-coder-30b
```

下完照第 3 章那套导进去。**两条路的取舍第 3 章那张表已经写清，本章不重讲。**

## 在终端里让它写一段脚本

先不接编辑器，在终端里试一次，看它顺不顺手。

```bash
ollama run qwen3-coder:30b "写一个 bash 脚本，列出 ~/ai/models 下面每个子目录占多大，按从大到小排。只给脚本，不要解释。"
```

作用：加载模型，把这一句作为提示词跑一次，打印结果就退出。**`ollama run` 后面直接跟一句话，就不进交互模式**，适合一次性的活。

**“只给脚本，不要解释”这句要养成习惯。** 不写的话它多半给你一大段前言和后记，你还得从里面挑代码。

输出是一段 bash 代码。**先别跑。**

### 跑之前自己读一遍

**这一节是硬的。**

模型写的脚本不报错也可能是错的。**它不知道你机器上有什么，它是照着一般情况写的。** 三条检查，每次都做：

**一、找会改东西的那几个词。** `rm`、`mv`、`>`（覆盖写入）、`sudo`、`chmod`、`chown`。**看到这些就停下来逐字读**——路径是不是你想的那个，有没有 `rm -rf` 加一个可能为空的变量。

**二、路径对不对。** 它很爱写 `/path/to/your/...` 这种占位符，也很爱把你的目录名拼错。

**三、有一行你看不懂，就别跑。** 把那一行贴回去，问它“这一行是什么意思，会改动什么”。**看不懂就跑，是这一章唯一真会闯祸的地方。**

确认没问题了，存成文件再跑：

```bash
nano ~/ai/scripts/model-size.sh
```

把脚本粘进去，`Ctrl+O` 回车保存，`Ctrl+X` 退出。然后：

```bash
bash ~/ai/scripts/model-size.sh
```

**用 `bash 文件名` 跑，不用先 `chmod +x`**——少一步，也少一个改权限的动作。

> **第一次跑拿不准的脚本，先在一个空目录里跑。** `mkdir -p /tmp/试一下 && cd /tmp/试一下`，在里面跑。`/tmp` 下的东西重启就没了（第 2 章用过这个办法试镜像）。

## 接进编辑器

终端里试顺手了，接进编辑器。

**这一节给的是配置要点，不是某个插件的逐步教程。** 插件的界面和选项名一年换好几次，**具体项目名和位置以你装的那个插件自己的文档为准，需要核验**。

### 装哪个插件

在 VS Code 的插件市场里搜“本地模型”“Ollama”或者“Continue”这类关键词，能找到好几个。**Continue 是这一类里常被提到的一个**，开源、支持连本地模型。

**别纠结挑哪个。** 这一类插件配置起来都是同样三样东西，换一个也是这三样。

### 要填的三样

不管哪个插件，填的都是这三样，**全部来自第 8 章**：

| 要填什么 | 填什么 | 从哪儿来 |
| --- | --- | --- |
| 提供方 / provider | 选 `openai`（OpenAI 兼容）或者直接选 `ollama` | 第 8 章讲过为什么用 OpenAI 兼容那一套 |
| 地址 / apiBase / baseURL | `http://192.168.1.50:11434/v1` | [第 3 卷第 3 章](../03-服务器基础/03-固定IP.md)那个固定地址加第 8 章那个端口 |
| 模型名 / model | `qwen3-coder:30b` | **和 `ollama list` 里的完全一致** |

有的插件还要一栏密钥。**随便填**，比如 `ollama`——第 8 章讲过这个值不校验，**但别留空**，有的客户端会因为空值直接不发请求。

**插件装在哪台机器上都行。** 装在 Mini PC 自己上，地址写 `http://localhost:11434/v1`；装在你平时用的笔记本上，就写上面那个局域网地址。**后者才是这一章的意义**——你在笔记本上写代码，算力在那台 Mini PC 上。

### 两种用法，用两个模型

装完之后一般有两处能用：

**一、对话。** 选中一段代码，问它这段干什么、帮我改成什么样。**这一处可以用重的模型**，等一两秒无所谓。

**二、补全。** 打字的时候出灰字。**这一处对速度很敏感**——半秒没出来你就已经自己打完了。**用轻的那个模型**，或者干脆先关掉补全，只用对话。

**一个实际建议：先只开对话。** 补全要调的东西多（触发时机、多长的上下文、什么时候不触发），一上来全开容易觉得“这东西没用”。**对话这一处立刻就有用。**

### 其他工具

同一套三样，也适用于别的工具：

- **Cline** —— VS Code 里的另一个，偏 agentic coding 那一类；
- **Aider** —— 命令行里的，直接改你仓库里的文件；
- **Zed** 这类自带 AI 的编辑器 —— 设置里同样是那三栏。

**本章不逐个展开。** 它们要么走 OpenAI 兼容那套接口，要么直接支持 Ollama，**填的东西和上面那张表一样**。真正让它们能用的是第 8 章那个接口，不是某个插件。

> **公司的代码要不要给它看，这是个正经问题。** 好消息是这一章从头到尾没有一个字节出过你的局域网。**坏消息是插件本身可能有别的联网行为**（更新检查、用量统计）。要交付给对数据有要求的客户，这一层要单独确认，属于[第 14 卷](../14-运维安全/README.md)的范围。

## 上下文长度和读代码

**代码比聊天长得多。** 一句提问几十个 token，一个一千行的源文件动辄上万。所以第 1 章那套估算，在这一章要真用一次。

### 先测出确切数字

**别估，测。** 第 8 章那个返回里的 `usage.prompt_tokens` 就是实测值。

新建一个文件叫 `count.py`：

```python
import pathlib
import requests

BASE = "http://192.168.1.50:11434/v1"
MODEL = "qwen3-coder:30b"
path = pathlib.Path("/你要数的那个文件的完整路径")

resp = requests.post(
    BASE + "/chat/completions",
    json={
        "model": MODEL,
        "messages": [
            {"role": "user", "content": path.read_text(encoding="utf-8")}
        ],
        "max_tokens": 1,
    },
    timeout=600,
)
resp.raise_for_status()

print(path.name, "大约", resp.json()["usage"]["prompt_tokens"], "个 token")
```

跑法和第 8 章一样：`~/ai-client/bin/python count.py`。

- **`path.read_text(...)`** —— 把文件内容整个读成一段文字，当作提问发过去；
- **`"max_tokens": 1`** —— 只让它回一个 token 就停，**我们要的是 `usage`，不是它的回答**。第 8 章标过这个参数名需要核验，**它要是不认，把这一行去掉就是**，只是会多等它说几句话。

**拿几个你常改的文件跑一遍，心里就有数了。** 一千行的 Python 大概多少、一个前端组件大概多少——**这些数只对你自己的代码风格成立，所以要自己测。**

### 这些 token 要占多少内存

第 1 章那条公式在这里代一次就行。以主线那个模型为例，第 1 章算过它每 token 的 KV cache 是 80 KiB，所以：

```text
 32K 上下文 →  2.7 GB
128K 上下文 → 10.7 GB
```

**在这台机器上，读代码开长上下文并不贵**——前提是模型的 KV 头数少。第 1 章那个对比在这里同样成立：**换成 KV 头数多的模型，同样长度要占 4 倍**。**换模型之前先按第 1 章那条公式算一遍**，别默认能开一样长。

### Ollama 实际用多长

**这里有一个容易搞混的地方：模型支持多长上下文，和 Ollama 跑的时候实际开多长，是两个数。**

上面那两个代码模型的原厂页面都标着原生 262,144。**但 Ollama 跑的时候用的是它自己的一个运行时设置**，不一定就是这个数。

**这个设置的参数名和默认值随 Ollama 版本变化，本项目未核实，需要核验**，以 Ollama 官方文档为准。判断的办法是实测：**把一份你知道长度的文件发过去，看它是不是真读到了后面的内容**——问一个只有文件末尾才有的细节，答得出来就是读进去了。

**要完全自己说了算，就绕开 Ollama 直接用 llama.cpp**，启动时用 `-c` 指定上下文长度（[第 5 卷第 17 章](../05-驱动与ROCm/17-llama.cpp-Vulkan.md)那一节讲过这个参数）。**这条路在第 13 章。**

### 别把整个项目丢进去

最后一条实际建议。**挑相关的那几个文件，不要一次把整个仓库贴进去。**

三条理由：

1. **上下文越长越慢。** 第 1 章讲过，每一轮它都要把整段重新处理一遍；
2. **KV cache 跟着涨**，长到一定程度会挤掉本来能用的内存；
3. **超长上下文里模型更容易漏掉中间的内容。** **这一条是社区里常见的说法，本项目未在这台设备上验证，需要核验**——但代价很低：先只给相关的文件，效果不好再加。

**判断标准还是那句：让它答一个只有那份材料里才有的细节，答不出来就是没读进去。**
