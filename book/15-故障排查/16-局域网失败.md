# 16　局域网失败

## 先分方向

**先在提供服务的那台机器上跑一句，看这个口绑在哪个地址上。**

```bash
ss -tln | grep :3080
```

`Local Address` 那一列只有两种，方向完全不同。

| 看到的 | 方向 |
| --- | --- |
| `127.0.0.1:3080` | 只绑了本机，局域网里怎么连都连不上 |
| `0.0.0.0:3080`，别的设备还是连不上 | 防火墙、地址变了，或者客户端不在同一网段 |
| 这个口根本不在列表里 | 服务没起来，去[第 15 章](15-OpenWebUI无法访问.md)或[第 22 章](22-重启后服务未启动.md) |

**Docker 那一层要单独记一条**：容器发布端口是自己去改系统底层的转发规则，**插在 ufw 的规则前面**。所以容器的口即使 ufw 里没放行，局域网里照样连得上；反过来，想真正管住它，也不能只靠加一条 ufw 规则，要在 Docker 这一层限定它绑在哪个地址上（[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)、[第 6 卷第 5 章](../06-本地模型/05-局域网与手机访问.md)）。

## 按顺序查

1. 先按上表看绑的是哪个地址。只绑 `127.0.0.1` 的，改服务自己的监听配置，不是改防火墙；
2. 两台设备是不是在同一个网段。手机连的是访客 Wi-Fi、或者路由器开了 AP 隔离，地址段就对不上（[第 3 卷第 2 章](../03-服务器基础/02-局域网与IP.md)）；
3. 服务器的地址是不是变了。按旧地址连不上、过几天就变一次，去[第 3 卷第 3 章](../03-服务器基础/03-固定IP.md)把它固定下来；
4. `sudo ufw status verbose` 对一遍规则表。**每一行你都该说得出这个口是给谁开的**，端口在不在表里、放行的网段对不对（[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)）；
5. 上面都对还是不通的，在服务器本机 `curl` 一次同一个地址。本机通、别的设备不通，问题在这台机器和客户端之间；本机也不通，回去查服务本身。

> 在外面而不是在家里连不上，那不是局域网失败。远程那条路在[第 3 卷第 6 章](../03-服务器基础/06-Tailscale.md)，**不要把这个界面直接挂到公网上**（[第 6 卷第 5 章](../06-本地模型/05-局域网与手机访问.md)）。

## 都不行

记这四样再去问——服务器上 `ss -tln` 那一行、`ufw status verbose` 的输出、两台设备各自的 IP 地址、客户端上试的完整地址（含 `http` 和端口）。

一台设备连得上、另一台连不上，问题在连不上那台，不在服务器。先拿一台已知能连的设备做基准。
