# 开源边界与证据规则

## 内容分层

### 可以公开

- 通用 Ubuntu 操作说明。
- 不含密钥的检查脚本。
- 脱敏后的配置示例。
- 虚构或获得授权的测试数据。
- 已经核对过来源的硬件和软件资料。
- 本地运行记录中可以公开的性能和成本数据。

### 默认不公开

- SSH 私钥、API 密钥、密码和会话信息。
- 真实客户资料、学生材料和聊天记录。
- 私有域名、内网地址、账号标识和设备序列号。
- 未经确认的客户案例、收入数字和内部工时。
- 可以直接进入内部系统的配置。
- 没有经过人工确认的对外声明。

## 事实状态

每一条重要判断都要注明状态：

| 状态 | 含义 |
| --- | --- |
| `local_checked` | 指定设备和版本上完成本地检查 |
| `official_source` | 有官方文档支持 |
| `case_material` | 来自具体案例，只适用于该案例范围 |
| `candidate` | 还没有完成验证 |
| `human_accepted` | Roland 已确认可以作为对外内容 |
| `published` | 已在真实公开渠道核验 |

`local_checked` 不等于 `human_accepted`，`human_accepted` 不等于 `published`。

## 项目案例格式

每个案例使用以下字段：

```text
案例名称：
设备与系统：
用户基础：
原来的做法：
使用的本地服务：
完成的任务：
运行记录：
人工检查：
成本记录：
失败与恢复：
可以公开的范围：
不能公开的范围：
事实状态：
```

## 发布前检查

- 删除个人路径、真实账号和内部域名。
- 扫描密钥、密码、令牌和私有连接信息。
- 检查截图中的通知、文件名和设备信息。
- 检查示例数据是否包含个人资料。
- 检查模型、软件和硬件版本是否写清日期。
- 区分事实、案例、推断和收入候选方向。
- 确认许可证已经选择并放入正确的目录。
- 由人工确认白皮书正文和发布范围。
