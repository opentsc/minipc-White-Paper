# 04　SSH

## 这一章的任务

坐在自己的笔记本前，远程登录这台 Mini PC，在上面完成一次完整的操作：看服务状态、重启一个容器、看日志、退出。

然后把登录方式从密码换成密钥——以后连它不用输密码，别人猜密码也没有用。

做完这一章，显示器和键盘就可以先不用了。后面每一章的操作，都是在这个远程终端里做的。

## 开始前

- 第 3 章做完，这台机器的地址已经固定，手上有这个地址；
- 知道 Mini PC 上那个账户的用户名和密码（[第 1 卷第 8 章](../01-开箱与安装/08-第一个账户.md)建的那个）；
- 一台和它在同一个局域网里的笔记本，Windows 或者 macOS 都行；
- 做过第 2 卷[第 9 章](../02-Ubuntu/09-Docker.md)那个容器最好，本章拿它当练习对象；
- 40 分钟。

## 新词

**SSH**：一条加密的远程登录通道。连上之后，你在笔记本上敲的命令送到那台机器上执行，结果送回来显示在你面前。中间的内容是加密的，同一个网络里的其他人看不到。

**服务端和客户端**：被连的那一头跑的程序叫服务端，在 Ubuntu 上是 `openssh-server`；你笔记本上用来连的那个叫客户端，Windows 和 macOS 都自带了。

**指纹**（Fingerprint）：服务器身份的一段摘要，一串字符。第一次连接时客户端会把它显示给你，确认之后记下来，以后每次连都拿它核对，防止你连到一台冒充的机器上。

**公钥和私钥**：成对生成的两个文件。公钥像一把锁，可以放到任何服务器上；私钥是唯一能开这把锁的钥匙，留在你自己的笔记本上。**私钥任何情况下都不外传**，见[第 0 卷第 8 章](../00-使用说明/08-文件保护.md)。

**密码短语**（Passphrase）：给私钥本身再加一层密码。设了的话，用这把钥匙之前要先输它。

## SSH 是什么

它做的事很简单：把你笔记本上的键盘和屏幕，接到那台机器的终端上。

第 2 卷学的那些命令，一条都不用变。你在笔记本上打 `docker ps`，命令在 Mini PC 上跑，输出回到你的屏幕上。感觉和坐在那台机器前面一模一样，只是键盘远了几米。

它走的端口是 `22`，这是第 2 章说的那种“一直等着别人来连”的端口。

## 在 Mini PC 上装并打开 SSH

Ubuntu 桌面版默认不装服务端（服务器版装了）。走到机器跟前，或者用它自己的键盘，打开终端：

```bash
sudo apt install openssh-server
```

装完它会自己起来，并且设成开机自启，不用另外操作。

确认 22 端口在等连接：

```bash
ss -tln | grep :22
```

第 2 章那条命令，这里加了 `grep` 只看 22。有输出，类似下面这样，就对了：

```
LISTEN   0        4096         0.0.0.0:22          0.0.0.0:*
LISTEN   0        4096            [::]:22             [::]:*
```

没有任何输出的话，把服务打开：

```bash
sudo systemctl enable --now ssh
```

第 2 卷第 6 章那条命令，让它现在起来、以后开机自己起来。

> 新版 Ubuntu 上 `systemctl status ssh` 有时显示 `inactive (dead)`，但 22 端口明明在听、也能连上。这不是故障：新版把它改成了“有人来连的时候才启动”，平时守着端口的是 `ssh.socket`。**判断它通不通，以 `ss -tln` 的输出和实际能不能连上为准**，不用纠结 `status` 那一行。

## 从笔记本连过去

现在离开 Mini PC，回到你的笔记本。

**macOS**：打开“终端”，输入下面这条，地址换成你的：

```bash
ssh 你的账户名@192.168.1.50
```

**Windows**：在开始菜单搜“终端”打开（老一些的系统搜“PowerShell”），输入同一条命令：

```
ssh 你的账户名@192.168.1.50
```

提示找不到 `ssh` 命令的话，去“设置 → 应用 → 可选功能”里加装“OpenSSH 客户端”，装完重开一个窗口。

`@` 前面是 Mini PC 上的账户名，不是你笔记本上的用户名，这两个不必相同。

### 第一次连接会问你一句

```
The authenticity of host '192.168.1.50 (192.168.1.50)' can't be established.
ED25519 key fingerprint is SHA256:aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789abcdefg.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

它在说：这台机器我没见过，它的指纹是这一串，要继续吗。

**打完整的 `yes` 再回车**，只按 `y` 不算。确认之后，这个指纹存进你笔记本上的 `~/.ssh/known_hosts`，以后连同一台机器不会再问。

讲究一点的做法是核对一遍。在 Mini PC 本地执行：

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

输出里那串 `SHA256:` 开头的字符，和屏幕上显示的对得上，就是同一台机器。家里的局域网里这一步可以省，去公司或者别人的网络里连机器时值得做一次。

接着它问密码：

```
你的账户名@192.168.1.50's password:
```

**输密码的时候屏幕上什么都不显示**，光标也不动，这是正常的，照打，回车。第 2 卷用 `sudo` 时见过同样的行为。

进去之后，提示符变成 Mini PC 的：

```
你的账户名@minipc-01:~$
```

**你已经在那台机器上了。** 这就是第 2 卷第 2 章的那个终端，只是它现在显示在你笔记本的窗口里。

## 连上之后做一次完整操作

试着把一次日常巡检做完，全程不碰 Mini PC。

先确认自己在哪台机器上：

```bash
hostname
```

输出是 Mini PC 的主机名，不是你笔记本的。这条命令在你分不清当前窗口连着哪台机器的时候很有用。

看 Docker 服务在不在跑：

```bash
systemctl status docker
```

看容器：

```bash
docker ps
```

重启那个监控面板，再看它启动时说了什么：

```bash
docker restart uptime-kuma
docker logs --tail 20 uptime-kuma
```

顺手看一眼硬盘还剩多少：

```bash
df -h /
```

退出：

```bash
exit
```

提示符变回你笔记本的，连接断开了。

**`exit` 只是断开连接，那台机器上的服务照常跑。** 容器还在、服务还在、文件都在，只是你不再连着它了。

有一件事要记住：**SSH 窗口里跑着的前台命令，窗口一关就跟着停。** 要跑几个小时的任务，做成第 2 卷[第 6 章](../02-Ubuntu/06-进程与服务.md)那样的服务，或者用第 8 章的办法，别直接扔在 SSH 会话里跑。

## 少打字：给它起个别名

每次打一长串地址很烦。在**笔记本上**建一个 SSH 的配置文件。

macOS 上：

```bash
nano ~/.ssh/config
```

Windows 上这个文件在 `C:\Users\你的用户名\.ssh\config`，用记事本打开就行，`.ssh` 目录不存在就先建一个。

写进去：

```
Host minipc
    HostName 192.168.1.50
    User 你的账户名
```

- `Host` 后面是你自己起的名字，随便叫；
- `HostName` 是真实地址；
- `User` 是 Mini PC 上的账户名。

保存之后，连它只要：

```bash
ssh minipc
```

macOS 上顺手把权限收一下，太松的话 SSH 会拒绝用这个文件：

```bash
chmod 600 ~/.ssh/config
```

这个别名第 5 章传文件时还要用。

## 换成密钥登录

密码登录有两个毛病：每次都要打，而且密码是可以一个一个试出来的。密钥登录两个毛病都没有。

### 一、在笔记本上生成密钥

**这一步在你的笔记本上做，不是在 Mini PC 上。** 私钥必须留在你自己手里。

```bash
ssh-keygen -t ed25519 -C "笔记本"
```

Windows 的终端里是同一条命令。

- `-t ed25519` 指定密钥类型，现在用这一种；
- `-C` 后面是一句备注，随便写，将来钥匙多了用来分清哪把是哪台机器的。

它会问三个问题：

1. **存到哪里**：直接回车用默认位置 `~/.ssh/id_ed25519`；
2. **Enter passphrase**：密码短语。留空回车就是不设，用起来最省事；设一个的话，笔记本丢了捡到的人也用不了这把钥匙。**笔记本会带出门的，建议设一个**，macOS 的钥匙串和 Windows 的 ssh-agent 会替你记住，不会每次都问；
3. **再输一次**确认。

完事之后 `~/.ssh` 里多了两个文件：

- **`id_ed25519`**：私钥。不带后缀的这个，**不外传、不复制给别人、不上传到任何地方**；
- **`id_ed25519.pub`**：公钥。`.pub` 结尾的这个，是要传到服务器上去的。

### 二、把公钥传上去

macOS 上有现成的命令：

```bash
ssh-copy-id minipc
```

它会问一次密码——这是你最后几次用密码。成功之后打印：

```
Number of key(s) added: 1
```

它做的事是：把公钥文件的内容追加到 Mini PC 上的 `~/.ssh/authorized_keys` 里，顺带把目录和文件的权限设对。

Windows 没有 `ssh-copy-id`，在终端里用这一条，**整条复制粘贴，不要手打**：

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh minipc "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

做的是同一件事，同样会问一次密码。

### 三、验证密钥能登

**新开一个终端窗口**，当前这个连着的先别关：

```bash
ssh minipc
```

**不问密码直接进去了，密钥就配好了。** 设了密码短语的话，这里问的是密码短语，不是账户密码，两者不一样。

还在问账户密码的话，先别做下一节，回头查这两处：

- 公钥传给的是不是同一个账户（`ssh-copy-id` 里的用户名和你现在登录用的是不是同一个）；
- 权限对不对。在 Mini PC 上执行 `ls -ld ~/.ssh` 和 `ls -l ~/.ssh/authorized_keys`，权限要分别是 `drwx------` 和 `-rw-------`。太松的话 SSH 会拒绝用这把钥匙，而且不明说原因。修一下：

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

## 关掉密码登录

**这一节最容易把自己锁在门外，顺序一步都不要跳。密钥没验证通过就关掉密码登录的话，你从任何地方都进不去了，只能接上显示器和键盘到机器跟前改回来。**

**第一步，保留后路。** 现在这个已经连上的 SSH 窗口，整个过程都不要关。改错了的话，它还连着，能直接改回来。

**第二步，确认密钥真的能登。** 上一节验证过了就行——新开窗口 `ssh minipc`，不问账户密码就进去。这一条没做到，停在这里，不要往下走。

**第三步，新建一个配置片段。** 在已经连上的那个窗口里：

```bash
sudo nano /etc/ssh/sshd_config.d/99-no-password.conf
```

写两行进去：

```
PasswordAuthentication no
KbdInteractiveAuthentication no
```

按 `Ctrl+O` 回车保存，`Ctrl+X` 退出。

不直接改 `/etc/ssh/sshd_config` 主文件，是因为新版 Ubuntu 的主文件开头有一行 `Include /etc/ssh/sshd_config.d/*.conf`，这个目录里的设置优先生效。单独放一个小文件的好处是要退回去只用删掉它，主文件一个字没动过。

**第四步，检查语法。**

```bash
sudo sshd -t
```

**没有任何输出就是没问题。** 有输出的话照着提示改，一时改不对就先把刚建的那个文件删掉，别往下做。

**第五步，让它生效。**

```bash
sudo systemctl restart ssh
```

**已经连着的窗口不会被断开**，换的是以后新连接的规则。命令报错并提到 `ssh.socket` 的话，改执行 `sudo systemctl restart ssh.socket`。

**第六步，验证。** 再新开一个窗口：

```bash
ssh minipc
```

能进去，说明密钥这条路还通。

再从一台没有你私钥的设备上连一次（比如另一台电脑，或者手机上的 SSH 工具），应该被直接拒绝：

```
Permission denied (publickey).
```

看到这一行，密码那条路就关上了。以后有人来试密码，试一万次也没有用。

**被关在外面了怎么办**：接上显示器和键盘，在机器本地登录，把那个文件删掉，重启服务：

```bash
sudo rm /etc/ssh/sshd_config.d/99-no-password.conf
sudo systemctl restart ssh
```

密码登录立刻回来，再从头查一遍密钥哪里没配对。

顺带一句：`root` 账户的远程登录，Ubuntu 默认就是关着的，不用另外设置。哪些端口对外开、开给谁，是第 9 章的事。

## 指纹变了怎么办

以后某一天连它，可能会看到一大段警告，开头是：

```
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@    WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!     @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
```

意思是：这个地址上的机器，指纹和上次记的对不上了。

两种可能。**第一种是你自己干的**：重装了系统、换了机器、或者这个地址被分配给了另一台设备。这种情况下把旧记录删掉再连就行：

```bash
ssh-keygen -R 192.168.1.50
```

**第二种是你没干过这些事**，那就先别连，去搞清楚这个地址上现在是什么机器。

## 连不上的两种常见情况

**`Connection refused`**：地址找到了，但 22 端口没人应。多半是 `openssh-server` 没装，或者服务没起来。回 Mini PC 上执行 `ss -tln | grep :22` 看一眼。

**`Connection timed out` 或者 `No route to host`**：根本没找到这台机器。这是网络的问题，不是 SSH 的问题。回第 2 章 `ping` 一次那个地址，ping 不通就先解决 ping。

有哪一步做不出来，到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。

## 事实来源和版本日期

- Windows 10 1809 及以上和 Windows 11 自带 OpenSSH 客户端。没有的话在系统设置的“可选功能”里加装，菜单位置随 Windows 版本变化，以你机器上实际看到的为准；
- 新版 Ubuntu 的 `openssh-server` 默认用 socket 激活，没有连接时 `systemctl status ssh` 显示 `inactive` 属于正常，判断以 `ss -tln` 和能否连上为准；
- `/etc/ssh/sshd_config.d/` 这个包含机制是新版 Ubuntu 的做法。老版本的主配置文件里没有那一行 `Include`，那就直接改主文件里的 `PasswordAuthentication`，改之前先 `sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak`；
- 本章核验日期：2026-08-14。
