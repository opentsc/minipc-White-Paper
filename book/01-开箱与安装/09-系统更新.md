# 09　系统更新

## 完成结果

系统的软件包已经更新到当前版本，知道图形界面和终端两条更新路径的区别，国内网络下已经换好软件源镜像，知道什么时候必须重启。

## 开始前需要准备什么

- 已完成第 8 章，能登录桌面并打开终端（快捷键 `Ctrl+Alt+T`）；
- 网络已连通（有线或 Wi-Fi）；
- 账户密码（执行 `sudo` 时要输入）；
- 30 分钟到 1 小时的时间，更新过程中不要断电、不要强制关机。

## 新词

**软件包**（Package）：Ubuntu 里一个可安装的软件单元，包含程序文件和安装说明。装软件、卸软件、升级软件，操作的都是软件包。

**软件源**（Repository，也叫仓库）：存放软件包的服务器地址。Ubuntu 不像 Windows 那样一个个去官网下载安装包，而是从软件源统一取。系统里记着一份软件源地址清单，装任何软件都从这些地址找。

**软件包清单**（Package Index）：软件源上有哪些包、各是什么版本，系统本地存了一份目录。这份目录不会自动实时更新，需要用命令去刷新。

**镜像站**（Mirror）：软件源的副本服务器。内容和官方源一致，只是放在别的地方。国内访问官方源慢的时候，换成国内的镜像站会快很多。

**内核**（Kernel）：操作系统里直接和硬件打交道的那一层。CPU 调度、内存分配、显卡和网卡的驱动，都由内核负责。内核也是一个软件包，也会随系统更新升级。

## 图形界面更新

Ubuntu 桌面自带一个更新程序。

1. 按 `Super` 键（键盘上的 Windows 徽标键），输入“软件更新器”或 “Software Updater”，回车打开；
2. 程序会自动检查有没有可用更新，检查过程持续几秒到一分钟；
3. 如果有更新，会列出软件名称和大小，点“立即安装”；
4. 输入账户密码，等待下载和安装完成；
5. 如果这次更新包含内核或系统核心组件，程序会弹窗提示“需要重启计算机以完成更新”，点“立即重启”。

如果程序显示“您的系统是最新的”，说明当前没有可更新的内容。

图形界面适合日常用。它做的事和终端里的 `sudo apt update` 加 `sudo apt upgrade` 基本相同，但看不到具体在装哪些包，出错时给出的信息也少。下面的终端方式能看到全过程。

## 终端更新：三条命令的区别

打开终端，依次执行。

**第一条：刷新软件包清单**

```bash
sudo apt update
```

作用：连上软件源，把“有哪些包、各是什么版本”的清单重新拉一遍。

正常输出示例：

```
命中:1 http://cn.archive.ubuntu.com/ubuntu noble InRelease
获取:2 http://security.ubuntu.com/ubuntu noble-security InRelease [126 kB]
正在读取软件包列表... 完成
有 23 个软件包可以升级。运行 'apt list --upgradable' 来查看它们。
```

这条命令**不安装任何软件，也不升级任何软件**。它只更新清单。执行完之后系统里的软件版本没有任何变化。

数字和地址跟你的网络、软件源和时间有关，和示例不一样是正常的。

想先看看有哪些包要升级：

```bash
apt list --upgradable
```

这条命令只是列出来看，不需要 `sudo`，也不会改动系统。

**第二条：升级已安装的软件**

```bash
sudo apt upgrade
```

作用：把已经装在系统里的软件包升级到清单里的新版本。

执行后会先列出将要升级的包，然后问一句：

```
需要下载 156 MB 的归档。
解压缩后会消耗 12.3 MB 的额外空间。
您希望继续执行吗？ [Y/n]
```

看清列表后输入 `Y` 回车继续，输入 `n` 回车取消。取消不会有任何改动。

这条命令有一个限制：**它不会为了完成升级而卸载任何已安装的包**。如果某个包的新版本要求先卸载另一个包，`apt upgrade` 会跳过它，在输出里显示成“下列软件包的版本被保留”或 “The following packages have been kept back”。

**第三条：允许卸载的升级**

```bash
sudo apt full-upgrade
```

作用：和 `apt upgrade` 一样升级软件，区别是**允许卸载挡路的旧包**来完成升级。上一条里“被保留”的包，通常用这条能装上。

代价是它可能卸载你正在用的软件。执行后同样会列出清单，这次要多看一眼：列表里有没有 `将会删除` 或 `The following packages will be REMOVED` 这一段，以及删的是什么。确认没问题再输入 `Y`。

**三条命令对照**

| 命令 | 做什么 | 会不会改动系统 |
| --- | --- | --- |
| `sudo apt update` | 刷新软件包清单 | 不装、不升、不删，只更新清单 |
| `sudo apt upgrade` | 升级已装软件 | 会安装新版本，不会卸载已装的包 |
| `sudo apt full-upgrade` | 升级已装软件 | 会安装新版本，也可能卸载包 |

**顺序**：先 `update`，再 `upgrade`。不先刷新清单，系统手里的目录是旧的，`upgrade` 可能什么都升不了。

**日常用法**：

```bash
sudo apt update && sudo apt upgrade
```

`&&` 表示前一条成功执行完再执行后一条。前一条报错时后一条不会跑。

> **⚠️ 更新过程中不要断电、不要长按电源键关机。** 软件包正在写入时中断，系统里会留下装了一半的包，后续装任何软件都可能报错。真的中断了，恢复方法见[第 0 卷第 9 章“遇到系统更新中断”](../00-使用说明/09-停止与恢复.md)。

## 内核更新是怎么回事

系统更新时，内核也会随着更新。内核更新和普通软件更新有两点不同。

**第一，必须重启才生效。** 普通软件装完就是新版本，内核不行——正在跑的还是旧内核，新内核要等下次开机才加载。

**第二，旧内核会保留。** Ubuntu 装新内核时不会立刻删掉旧的。开机时在 GRUB 菜单选 `Advanced options for Ubuntu`，能看到已安装的几个内核版本，可以选旧的启动。新内核出问题时，这是最直接的退路。

查看当前用的内核版本：

```bash
uname -r
```

输出是一串类似 `6.17.0-1011-oem` 或 `6.14.0-32-generic` 的字符串。前面几段是版本号，末尾的 `generic` 是 Ubuntu 的通用内核，`oem` 是 Ubuntu 给较新硬件提供的另一条内核线。你看到的具体数字取决于装的是哪个 Ubuntu 版本、已经更新过几次，和这里的示例不一样是正常的。

**为什么内核版本对这台机器重要**

Max395 是较新的平台。它的显卡和 NPU 能不能被识别、能不能正常出画面、能不能把系统内存拿给 GPU 用，取决于内核里有没有对应的支持代码。这些支持是随内核版本一版一版进去的，内核太旧就没有。

具体到操作层面：第 5 卷装 GPU 驱动的时候，第一步就是确认内核版本，不同版本对应的安装步骤和参数不一样。所以现在先把系统更新到位，并记下 `uname -r` 的输出。

这台机器到底该用哪条内核线、装到哪个版本，第 5 卷会给结论（具体版本需要核验，以第 5 卷为准）。这一章不装驱动、不改内核参数。

> **⚠️ 不要手动删除内核软件包**（例如 `sudo apt purge linux-image-*` 这类写法）。删到正在用的那个内核，下次开机会进不去系统。腾空间交给 `sudo apt autoremove` 处理，它只清理系统判断为不再需要的旧内核。真的把系统删坏了，恢复方法是用第 10 章做的恢复 U 盘启动到 Live 模式，先把数据抢救出来，再重装系统。

## 换软件源镜像（国内网络）

在国内访问 Ubuntu 官方软件源，下载速度可能只有几十 KB/s，`apt update` 会卡很久甚至超时。换成国内镜像站能解决。

### 先备份

换源前先把当前的软件源配置文件复制一份。出错时能原样还原。

先看看配置文件在哪：

```bash
ls /etc/apt/sources.list.d/
```

Ubuntu 24.04 及更新的版本，主配置文件是 `/etc/apt/sources.list.d/ubuntu.sources`。更早的版本用的是 `/etc/apt/sources.list`。

备份（Ubuntu 24.04 及更新版本）：

```bash
sudo cp /etc/apt/sources.list.d/ubuntu.sources /etc/apt/sources.list.d/ubuntu.sources.bak
```

如果上一条提示文件不存在，说明是旧布局，改用：

```bash
sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak
```

`.bak` 是备份文件的常见后缀，系统不会去读它，它只是一份原样副本。

确认备份存在：

```bash
ls -l /etc/apt/sources.list.d/
```

输出里应当能看到 `ubuntu.sources` 和 `ubuntu.sources.bak` 两个文件。

### 用图形界面换源

1. 按 `Super` 键，输入“软件和更新”或 “Software & Updates”，回车打开；
2. 切到第一个标签页“Ubuntu 软件”；
3. 找到“下载自”（Download from）下拉框，点开；
4. 选“其他站点…”（Other…）；
5. 在弹出的服务器列表里展开 “China”，选一个镜像站，点“选择服务器”；
6. 回到主窗口，点“关闭”；
7. 程序会提示“可用软件信息已过期”，点“重新载入”，它会去新地址重新拉一次软件包清单。

常用的国内镜像地址：

```
https://mirrors.tuna.tsinghua.edu.cn/ubuntu/
```

```
https://mirrors.aliyun.com/ubuntu/
```

上面两个分别是清华大学和阿里云的镜像站。列表里不一定同时有这两个，能选到哪几个取决于 Ubuntu 版本自带的服务器名单（需要核验）。如果列表里没有你想要的那个，服务器列表对话框里通常有一个“自定义”或输入框，可以直接把上面的地址填进去；不同版本的界面措辞不同（需要核验）。

列表上方还有一个“选择最佳服务器”按钮，点它会逐个测速再自动选一个。测速要几分钟。

### 换完之后验证

```bash
sudo apt update
```

正常表现：输出里的地址变成了你选的镜像站，下载速度明显变快，最后正常显示“正在读取软件包列表... 完成”。

### 出错怎么还原

如果换源后 `apt update` 报错（地址填错、镜像站正在维护、证书不匹配都可能），把备份文件复制回去：

```bash
sudo cp /etc/apt/sources.list.d/ubuntu.sources.bak /etc/apt/sources.list.d/ubuntu.sources
sudo apt update
```

旧布局的还原命令是：

```bash
sudo cp /etc/apt/sources.list.bak /etc/apt/sources.list
sudo apt update
```

还原后 `apt update` 恢复正常，说明问题出在刚才填的地址上。

> **⚠️ 换源本身不会删除任何数据，但地址填错会让之后所有的软件安装和更新都失败。** 所以备份那一步不要跳过。上面的还原命令是这一步唯一需要的恢复方法。

## 什么时候必须重启

大部分软件更新完立刻生效，不需要重启。以下几类需要：内核、`systemd`、显卡驱动、C 运行库这类系统底层组件。

系统会自己给出提示。判断方法有两个。

**方法一：看提示文字。** 更新完成后，在终端里新开一个会话（或用 SSH 登录），如果需要重启，会显示这一行：

```
*** System restart required ***
```

**方法二：看标记文件。** 需要重启时，系统会建一个空文件作为标记：

```bash
ls /var/run/reboot-required
```

- 输出 `/var/run/reboot-required`：需要重启；
- 提示 `No such file or directory`（没有那个文件或目录）：不需要重启。

想知道是哪些包要求重启：

```bash
cat /var/run/reboot-required.pkgs
```

输出是一个包名列表。看到 `linux-image` 开头的名字，说明这次更新了内核。

重启：

```bash
sudo reboot
```

或者用桌面右上角的状态菜单选“关机/注销”→“重启”。

重启不是可选项。内核已经换了但没重启，跑的还是旧内核，这时候去装 GPU 驱动会出现版本对不上的问题。

## 不要做的事：跨发行版升级

Ubuntu 有一条命令能把整台机器从当前版本升级到下一个发行版本：

```bash
sudo do-release-upgrade
```

> **⚠️ 这一章不要执行这条命令，之后没有明确理由也不要执行。** 尤其不要加 `-d` 参数，那是升级到还没正式发布的开发版。

理由有三条。

**第一，它换的东西太多。** 跨发行版升级会换掉内核、显卡驱动栈、Python 版本和大量系统库。第 5 卷之后配好的驱动、模型运行环境和服务，可能在升级后全部失效，要重新配一遍。

**第二，没有一键回退。** 普通软件更新出问题可以降级或还原配置，跨发行版升级中途失败或升级后开不了机，通常只能重装系统。

**第三，新版本对这台硬件的支持情况需要单独核验。** 新发行版不等于对 Max395 支持更好，也出现过新内核引入新问题的情况。什么时候值得升，要看具体版本的实际表现（需要核验）。

如果 Ubuntu 弹窗提示“有新的 Ubuntu 版本可用，是否现在升级”，选“不升级”或直接关掉窗口。这个提示不影响日常的安全更新，安全更新走的是本章前面的 `apt upgrade`，和跨版本升级是两回事。

真要升级发行版，前提是：整套系统已经跑通、第 10 章的镜像备份已经做好、并且确认过新版本对这台硬件的支持情况。

## 正常结果

- `sudo apt update` 正常结束，没有报错；
- `sudo apt upgrade` 执行完毕，`apt list --upgradable` 只剩很少或没有可升级项；
- 如果提示需要重启，已经重启过一次，重启后 `ls /var/run/reboot-required` 提示文件不存在；
- `uname -r` 能输出内核版本，并且已经记下来。

## 看到不同结果怎么办

**`apt update` 报“无法解析域名”或 `Could not resolve`**：

先确认网络本身通不通：

```bash
ping -c 4 223.5.5.5
```

`-c 4` 表示发 4 个包就停。有回包说明网络通，问题在域名解析（DNS），可以换一个镜像站再试；完全没有回包说明网络没连上，回第 2 章检查网线，或在右上角状态菜单里连 Wi-Fi。

**`apt update` 报 `Failed to fetch` 或连接超时**：官方源在国内访问慢是常见原因，按本章“换软件源镜像”换成国内镜像。已经换过镜像的，可能是镜像站正在同步，等几十分钟再试，或换另一个镜像站。

**报 `Could not get lock /var/lib/dpkg/lock-frontend`**：同时有另一个程序在装软件。可能是后台的自动更新在跑，也可能是图形界面的“软件更新器”还开着。关掉图形更新窗口，等几分钟再执行一次。不要手动删除锁文件，删了可能让两个程序同时写同一个数据库，把软件包数据库弄坏。

**`upgrade` 输出里有“下列软件包的版本被保留”**：这是正常提示，不是错误。用 `sudo apt full-upgrade` 处理，执行前看清列表里要卸载什么。

**换源后 `apt update` 报 `NO_PUBKEY`、证书错误或大量 404**：镜像地址填错，或者填的地址不支持当前 Ubuntu 版本。按本章“出错怎么还原”把备份复制回去，`apt update` 恢复正常后再重新选一个镜像站。

**更新中途断电或强制关机后，装软件一直报错**：见[第 0 卷第 9 章“遇到系统更新中断”](../00-使用说明/09-停止与恢复.md)。

**更新并重启后黑屏、进不去桌面**：开机时按住 `Shift` 键或反复按 `Esc` 调出 GRUB 菜单，选 `Advanced options for Ubuntu`，再选上一个内核版本启动。能进系统说明是新内核的问题，处理方法见[第 12 章](12-硬件问题处理.md)。

## 完成检查

- `sudo apt update` 执行完没有报错吗？
- `sudo apt upgrade` 执行完了吗，`apt list --upgradable` 还剩多少条？
- `apt update` 和 `apt upgrade` 的区别，你能说出来吗？
- 国内网络下的软件源镜像换好了吗，换源前的备份文件还在吗？
- `ls /var/run/reboot-required` 提示文件不存在吗？如果存在，重启过了吗？
- `uname -r` 的输出记下来了吗？
- `do-release-upgrade` 这条命令，你知道不要碰吗？
