# 05　文件传输

## 这一章的任务

把笔记本上的一批资料传到这台机器的 `~/ai/data` 里去，再从它那里取一个文件回来。

用的是一个真实场景：你手上有一批要处理的发票扫描件，放在笔记本的桌面上，目录名是 `2026-08-invoice`。目标是把它整批传到服务器的 `~/ai/data/2026-08-invoice`——第 2 卷[第 1 章](../02-Ubuntu/01-桌面与文件.md)约定过，原始资料放在 `ai/data`。第 8 卷做单据识别，就是从这个位置取料。

三种办法，各有各的用处，这一章三种都给。

## 开始前

- 第 4 章做完，在笔记本上敲 `ssh minipc` 能直接进去；
- 笔记本上有一批要传的文件，几十 MB 到几 GB 都行；
- 第 2 卷[第 12 章](../02-Ubuntu/12-日常备份.md)的 `rsync` 用过最好，这一章是它的跨机器版本；
- 30 分钟。

## 新词

**scp**：走 SSH 通道复制文件的命令。用法和本机复制文件的 `cp` 几乎一样，多了一个“哪台机器”。

**SFTP**：走 SSH 通道的文件传输方式。图形界面里那种“把远程机器挂成一个文件夹”，底下用的就是它。

**增量同步**：只传两边不一样的部分。第一次要传完整的一份，之后每次只传变化的，几秒钟完事。第 2 卷第 12 章讲过。

## 三种办法怎么选

| 办法 | 适合什么 | 两头要有什么 |
| --- | --- | --- |
| `scp` | 一次性传一批，传完就完事 | Windows、macOS、Ubuntu 都自带 |
| `rsync` | 同一个目录要反复同步，只传变化的部分 | Ubuntu、macOS 自带，Windows 没有 |
| 图形界面挂载 | 偶尔拖两个文件，想用鼠标操作 | Ubuntu 自带，Windows 和 macOS 要另装软件 |

三种走的都是第 4 章那条 SSH 通道，所以密钥配好之后，三种都不用再输密码，传输过程也都是加密的。

## 一、scp：一次性传一批

传一个文件：

```bash
scp ~/Desktop/report.pdf minipc:~/ai/data/
```

- 前面是本机的文件；
- 后面 `minipc` 是第 4 章起的那个别名。没配别名就写全 `你的账户名@192.168.1.50`；
- **冒号后面是那台机器上的目标路径**，这里是 `~/ai/data/`。

正常输出一行，传完就退回提示符：

```
report.pdf                          100%   12MB   95.3MB/s   00:00
```

四个数字分别是完成度、文件大小、速度、用时。

**冒号不能漏。** 漏掉冒号的话，`scp` 会当成本机内部的复制，在当前目录下生成一个名叫 `minipc` 的文件，东西根本没出去，而且不报错。

传整个目录，加 `-r`：

```bash
scp -r ~/Desktop/2026-08-invoice minipc:~/ai/data/
```

传完之后那台机器上就有了 `~/ai/data/2026-08-invoice`。

反方向，从服务器取一个文件回笔记本：

```bash
scp minipc:~/ai/data/2026-08-invoice/report.pdf ~/Downloads/
```

带机器名的那一头是谁，方向就是从谁到谁，两个位置对调就是反过来传。

**Windows 上**同一条命令，本地路径写成 Windows 的写法，路径里有空格要用引号包起来：

```
scp "C:\Users\你的用户名\Desktop\report.pdf" minipc:~/ai/data/
```

`scp` 的短板有两个：传到一半断了要从头来；同一批文件传第二遍，它会全部重传一遍，不管那些文件变没变。所以它适合一次性的活。

## 二、rsync：反复同步同一个目录

第 2 卷第 12 章用 `rsync` 把家目录同步到移动硬盘上。同一个工具，把目标改成 `别名:路径`，它就跨机器了。

```bash
rsync -av --progress ~/Desktop/2026-08-invoice/ minipc:~/ai/data/2026-08-invoice/
```

三个参数：

- **`-a`** 递归整个目录，保留文件的时间和权限；
- **`-v`** 打印传了哪些文件；
- **`--progress`** 显示每个文件的进度和速度。传大文件时没有它，屏幕上半天没动静，你不知道是在传还是卡住了。

第一次跑要把整批传过去。**跑第二遍试试，几秒钟就完了**，因为它只比对差异，没变的文件一个字节都不传。以后这个目录里加了新文件，重跑同一条命令就是了。

传到一半断了，重跑同一条命令，已经传完的文件不会再传。**大文件传到一半断掉**的话，加上 `-P` 让它下次接着传，不用从头来：

```bash
rsync -avP ~/Desktop/2026-08-invoice/ minipc:~/ai/data/2026-08-invoice/
```

`-P` 是 `--partial` 和 `--progress` 合起来的写法。

### 源路径末尾那个斜杠

这是 `rsync` 最容易搞错的地方，两种写法都不报错，结果差一层目录：

```bash
rsync -av ~/Desktop/2026-08-invoice/ minipc:~/ai/data/2026-08-invoice/
```

源路径**带**末尾斜杠：把这个目录**里面的东西**放进目标目录。结果是 `~/ai/data/2026-08-invoice/发票001.pdf`。这是你要的。

```bash
rsync -av ~/Desktop/2026-08-invoice minipc:~/ai/data/2026-08-invoice/
```

源路径**不带**末尾斜杠：把**这个目录本身**放进目标目录。结果是 `~/ai/data/2026-08-invoice/2026-08-invoice/发票001.pdf`，多套了一层。

拿不准就先加 `--dry-run` 跑一遍，它只打印会做什么，不真的传，第 2 卷第 12 章讲过这个参数。

### `--delete` 跨机器时更要小心

`--delete` 让目标目录和源目录保持一模一样，源里删掉的文件目标里也删掉。本机备份时它很好用，跨机器时风险大一截：目标路径多写少写一层，删掉的可能是那台机器上完全不相干的东西。

**跨机器用 `--delete` 之前，先加 `--dry-run` 跑一遍，看清楚它要删哪些文件，再把 `--dry-run` 去掉正式跑。**

### Windows 上没有 rsync

Windows 不自带 `rsync`。笔记本是 Windows 的话：一次性传用上面的 `scp`，要反复同步就用下面第三种办法。确实想用 `rsync`，得先装 WSL，在 WSL 里面用，本教材不展开这条路。

## 三、图形界面挂载

不想打命令、只想拖两个文件的时候用这个。它把那台机器挂成一个文件夹，用起来跟本地目录差不多。

**在 Ubuntu 上**（另一台 Ubuntu，或者这台机器自己去连别人）：

1. 打开“文件”，点左边侧栏最下面的“其他位置”；
2. 窗口底部有一行“连接到服务器”，在输入框里输：

```
sftp://192.168.1.50/
```

3. 点“连接”。第一次会问账户名和密码，第 4 章配了密钥的话直接就进去了；
4. 那台机器出现在侧栏，双击进目录、拖文件进去、双击打开文档，都和本地目录一样；
5. 用完点侧栏里它旁边的弹出图标断开。

**在 macOS 上**：访达的“连接服务器”不支持 `sftp://` 这种地址，要图形界面得另外装一个客户端，Cyberduck、FileZilla 这类都行。命令行的 `sftp` 是系统自带的：

```bash
sftp minipc
```

进去之后 `put 文件名` 是上传，`get 文件名` 是下载，`bye` 退出。另一条路是第 7 章的共享文件夹，访达认那种地址。

**在 Windows 上**：文件资源管理器同样不认 `sftp://`，要图形界面得装 WinSCP 或者 FileZilla。终端里的 `sftp` 命令和 `scp` 一样是自带的，用法同上。

挂载适合偶尔看一眼、拖两个小文件、直接打开服务器上的一个文档改完存回去。**不适合传几十 GB，也不适合当备份的目标**——网络一断，正在写的程序当场报错，那边留下一个写了一半的文件。大批量还是用前面两种。

## 核对：传过去的和这边一样吗

传完不核对，等于没传。第 2 卷第 1 章核对 U 盘的做法，换成命令是这样。

先在笔记本上看源目录（macOS 上）：

```bash
ls ~/Desktop/2026-08-invoice | wc -l
du -sh ~/Desktop/2026-08-invoice
```

第一条数文件个数，第二条看总共多大。Windows 上没有这两条命令，在资源管理器里右键“属性”看“包含”那一行。

然后连过去看目标：

```bash
ssh minipc
ls ~/ai/data/2026-08-invoice | wc -l
du -sh ~/ai/data/2026-08-invoice
```

**文件个数必须一样，总大小差个几 KB 是正常的**，两边的文件系统统计方式不同。

要更严格，挑一个大文件对一下指纹。在 Mini PC 上：

```bash
sha256sum ~/ai/data/2026-08-invoice/big.zip
```

在笔记本上，macOS 是：

```bash
shasum -a 256 ~/Desktop/2026-08-invoice/big.zip
```

Windows 是：

```
certutil -hashfile "C:\Users\你的用户名\Desktop\2026-08-invoice\big.zip" SHA256
```

两边打印出来的那一长串一模一样，这个文件就是一字不差地过去了。

## 传得慢的时候

- **Wi-Fi 换成网线。** 千兆网口跑满大约是每秒 110 MB，一个 10 GB 的文件一分半钟。Wi-Fi 常常只有它的几分之一，而且不稳定；
- **中间的设备也算数。** 两头都是千兆口，中间串了一个百兆的老交换机，速度就卡在那一段；
- **几万个小文件比一个同样大小的大文件慢得多**，每个文件都有固定开销。碎文件太多的话，先在笔记本上打包成一个压缩包再传，到了那边解开。

## 两种常见报错

**`Permission denied`**：目标位置你没有写权限。最常见的是路径少写了 `~`——`~/ai/data` 是你的家目录里面，`/ai/data` 是系统根目录下面，普通账户写不进去。

**`No such file or directory`**：目标目录不存在。**`scp` 和 `rsync` 都不会自动建目录**，先建好再传：

```bash
ssh minipc "mkdir -p ~/ai/data/2026-08-invoice"
```

引号里的命令会在那台机器上执行完就退出，不用先登进去再退出来。

有哪一步做不出来，到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。
