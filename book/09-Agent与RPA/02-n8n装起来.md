# 02　n8n 装起来

## 这一章的任务

把 n8n 跑起来，浏览器打开，建好账户，**并且让它连得上这台机器上的 Ollama**。

做完之后你手上有一个空的编辑器，还有一个能用的模型地址。**下一章开始往里放节点。**

这一章的部署动作和[第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)那个监控面板、[第 6 卷第 4 章](../06-本地模型/04-Open-WebUI.md)那个 Open WebUI 是同一套，**参数不重讲**。真正要花时间的是最后那一节。

## 新词

**n8n**：一个把“什么时候开始、中间做什么、结果去哪儿”摆成一张图的工具。**图画完就是一条能跑的流程，不用写代码。**

**节点**（node）：图上的一个方块，**一个方块干一件事**——抓一个网页、发一个请求、写一个文件。

**触发器**（trigger）：一条流程的第一个节点，**决定这条流程什么时候开始跑**。本卷会用到两种：手动点一下就跑（第 3 章），和到点自己跑（第 6 章）。

**画布**（canvas）：编辑器中间那块空白地方。节点摆在上面，节点之间的连线也画在上面。

**工作流**（workflow）：画布上这一整套节点加连线，存下来就是一条工作流。[第 1 章](01-Agent是什么.md)的新词。

**执行**（execution）：工作流跑一次，叫一次执行。**每一次执行都被记下来，事后能一个节点一个节点点开看**，这是本卷最常用的调试办法。

**凭据**（credential）：账号密码、密钥这类东西，在 n8n 里单独存一份，节点用的时候引用它，**不写在节点里，也不跟着工作流被导出**。

## n8n 是什么，本卷为什么用它

一句话——**把节点摆在画布上，用线连起来，就是一条能跑的流程。**

选它做主线，三条理由：

**一、单个容器就能跑。** 一条 `docker run`，一个数据目录，没了。**这一条比听上去重要**：本卷做出来的东西是要装到别人机器上的，装的东西越少，交付越轻，出事的地方越少。

**二、每一步的输入输出都看得见。** 点开任何一个节点，左边是它收到什么、右边是它吐出什么，**一眼就知道是在哪一步断的**。这件事在写代码的路子上要自己加打印语句才能做到。

**三、常见的活都有现成节点。** 抓网页、读 RSS、发邮件、读写文件、连数据库，不用自己写。

**其他框架不在这里比。** LangGraph、CrewAI、AutoGen、MCP 这些各自的定位，**第 16 章一章讲完**，也会讲为什么主线没选它们。现在只需要知道一件事：**本卷学的是做自动化的路数，不是学一个软件的用法。** 路数换个工具照样成立。

## 先把目录建好

```bash
mkdir -p ~/ai/projects/n8n
mkdir -p ~/ai/data/daily
```

第一个目录放 n8n 自己的东西——你建的工作流、凭据、执行记录都落在这儿。一个项目一个目录，[第 2 卷第 1 章](../02-Ubuntu/01-桌面与文件.md)的约定。

**第二个目录是给第 6 章准备的**，那一章要把日报写成文件落在这儿。**现在就建，是为了省一次容器重建**——下面那条命令里有一行把它挂进容器，等第 6 章再加的话，得把容器停掉删掉重来一次。

## 部署

这一章的主命令：

```bash
docker run -d \
  --name n8n \
  --restart unless-stopped \
  -p 5678:5678 \
  -e GENERIC_TIMEZONE="Asia/Shanghai" \
  -e TZ="Asia/Shanghai" \
  -e N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true \
  -e N8N_RUNNERS_ENABLED=true \
  --add-host=host.docker.internal:host-gateway \
  -v "$HOME/ai/projects/n8n:/home/node/.n8n" \
  -v "$HOME/ai/data/daily:/data" \
  docker.n8n.io/n8nio/n8n
```

整段复制粘贴，最后回车。第一次要下镜像，几百 MB 到一 GB，看网速。下完打印一长串十六进制字符，就是跑起来了。

**前四个参数[第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)讲透了**，这里只说本章特有的几处。

**`-e GENERIC_TIMEZONE="Asia/Shanghai"` 和 `-e TZ="Asia/Shanghai"`。这一对不能省。**

官方文档写明，自托管的 n8n 实例默认时区是 America/New York。**不改的话，第 6 章那个“每天早上 7 点发日报”会按纽约时间的 7 点跑**，落到这边是下午或者晚上。这种错不会报任何错，只会让你觉得“它怎么在半夜给我发日报”。

两个变量的分工是：`GENERIC_TIMEZONE` 管定时类节点按哪个时区算点，`TZ` 管容器里系统本身的时区。**两个都填，填一样的值。** 不在东八区就换成你自己那个时区名。

**`-e N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true` 和 `-e N8N_RUNNERS_ENABLED=true`。** 官方示例命令里就带着这两个，**照抄**。后一个官方写明是打开它的任务运行器；前一个按名字是让 n8n 检查自己配置文件的权限，**这两个变量各自的详细含义以官方文档为准，需要核验**。

**`--add-host=host.docker.internal:host-gateway`。** 这一行是给最后一节准备的，作用到那一节再讲。**[第 6 卷第 4 章](../06-本地模型/04-Open-WebUI.md)那条 `docker run` 里有一模一样的一行。**

**`-v "$HOME/ai/projects/n8n:/home/node/.n8n"`。** 容器往 `/home/node/.n8n` 写的东西，落在你硬盘上那个目录里。**你建的工作流、存的凭据、每一次执行记录，全在这里面**，删了容器不会丢（[第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)验证过这件事）。

> 官方示例用的是 Docker 的命名卷 `n8n_data`，那种卷落在系统盘一个很深的目录里。**本教材一律用目录映射**，落在 `~/ai/projects` 下面，理由和[第 6 卷第 4 章](../06-本地模型/04-Open-WebUI.md)一样——[第 2 卷第 12 章](../02-Ubuntu/12-日常备份.md)那套备份直接就能覆盖到它。

**`-v "$HOME/ai/data/daily:/data"`。** 把宿主机的 `~/ai/data/daily` 接到容器里的 `/data`。**这一行决定了第 6 章那个文件写在哪儿。**

**这里有一件事现在就要想清楚，后面会反复撞上**：**容器里的路径和你在终端里看到的路径不是一回事。** n8n 官方文档专门写了这一条——在 Docker 里跑的时候，节点里填的路径指的是容器内部的文件系统。你在节点里填 `/data/日报.md`，文件真正落在宿主机的 `~/ai/data/daily/日报.md`；你在节点里填 `/home/你的账户名/ai/data/daily/日报.md`，**它会告诉你找不到这个目录**，因为容器里根本没有那个路径。

**最后一行 `docker.n8n.io/n8nio/n8n` 是镜像地址。** 注意它不在 Docker Hub 上，是 n8n 自己的镜像仓库，**地址要一个字不差**。这一行没写标签，取的是最新的那一份，跟着上游滚动。要固定版本，去镜像页面挑一个带版本号的标签，**当前可用的标签需要核验**，以你部署当天页面上的为准。[第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)讲过本教材为什么一律写明标签。

> **官方示例是 `-it --rm` 前台跑的**，关掉终端窗口容器就没了，跑完自动删掉。那是给试一下用的。**服务类容器一律 `-d` 加 `--restart unless-stopped`**，这是[第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)定下的规矩。

### 国内拉镜像慢

和[第 6 卷第 4 章](../06-本地模型/04-Open-WebUI.md)那两条路一样：配一个镜像加速地址，或者找一台网络通的机器 `docker pull` 之后 `docker save` 成文件拷过来，再 `docker load` 进去。**加速站的可用性变化很快，本教材不写具体地址。**

## 看它起来没有

```bash
docker ps
```

`STATUS` 那列是 `Up` 加上跑了多久就对了。

```bash
docker logs n8n
```

第一次启动它要初始化，等一会儿。**日志最后几行里会出现一个 `http://localhost:5678` 之类的地址**，出现了就是好了。

**容器起来了又马上退出**，`docker ps` 里看不到、`docker ps -a` 里 `STATUS` 是 `Exited`——先看日志：

```bash
docker logs n8n
```

**最常见的是写不进那个数据目录。** 容器里的程序不是以你的身份跑的，**目录属主对不上它就写不进去**。看一眼：

```bash
ls -ld ~/ai/projects/n8n
id -u
```

第一条看那个目录属于谁，第二条看你自己的编号（多数机器上是 1000）。对不上就把属主改过来：

```bash
sudo chown -R 1000:1000 ~/ai/projects/n8n ~/ai/data/daily
```

改完 `docker start n8n` 再看一次日志。**`1000` 这个数字是 n8n 镜像里那个账户的编号**，需要核验——你机器上不是这个的话，以 `docker logs` 里报出来的为准。

其余的到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。

## 防火墙放行

只在这台机器上自己用，这一节可以跳过。**局域网里别的电脑要打开这个界面**，加一条规则：

```bash
sudo ufw allow from 192.168.1.0/24 to any port 5678 proto tcp
```

写法和[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)放行 3001、[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)放行 11434 那两条一模一样，**只换了端口号**。地址段换成你自己的。

看一眼表，确认这一行进去了：

```bash
sudo ufw status verbose
```

**这张表上每一行你都该说得出这个口是给谁开的**，这是[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)的规矩。

> **[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)那一节要在这里再说一遍**：Docker 用 `-p` 开的口，ufw 其实管不到——上面那条规则加不加，局域网里都连得上 5678。真要管住它，用带地址的写法 `-p 192.168.1.50:5678:5678`，那要停掉容器删掉重建。**这个界面能进去就能改工作流、能看到你存的凭据，别把它开到公网上。** 出门要用走 [Tailscale](../03-服务器基础/06-Tailscale.md)。

## 第一次打开，建账户

浏览器打开：

```text
http://localhost:5678
```

局域网里别的机器上访问，把 `localhost` 换成 `192.168.1.50`。

第一次进来是一个建账户的页面，填邮箱、姓名、密码。**这个账户和系统账户没有关系，是 n8n 自己的**，记在密码管理器里。

**界面上的措辞随版本变化，需要核验，以你实际看到的为准。** 本卷后面所有说“点哪儿”的地方都适用这一句。

建完进去是一个空的工作区。**先不用管里面有什么**，第 3 章逐块讲。

## 关键一节：让 n8n 找得到 Ollama

**这一节是本章的正题，做不完后面每一章都卡住。**

### 问题在哪儿

n8n 跑在容器里。**容器里的 `localhost` 指的是容器自己，不是你这台机器。**

n8n 官方文档给的 Ollama 默认地址是 `http://localhost:11434`。**在容器里照这个填，一定连不上**——容器内部的 11434 端口上什么都没有。

### 两件事已经做过了

**第一件，[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)已经把 Ollama 改成监听 `0.0.0.0:11434`。** 没这一步，Ollama 只在 `127.0.0.1` 上听，容器怎么找都找不到。忘了做没做，跑一句：

```bash
ss -tln | grep 11434
```

`Local Address` 那列是 `0.0.0.0:11434` 就对了。**还是 `127.0.0.1:11434`，回[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)那一节重做。**

**第二件，上面那条 `docker run` 里的 `--add-host=host.docker.internal:host-gateway`。** 这一行给容器里加了一条记录——**`host.docker.internal` 这个名字，指向宿主机。**

### 所以容器里的地址是这个

```text
http://host.docker.internal:11434
```

**本卷所有要连模型的地方，填的都是这个地址。** 第 3 章那个 HTTP Request 节点、第 5 章那个摘要节点、第 7 章那个分类节点，一律是它。

**记住三个地址的分工，别混**：

| 你在哪儿写 | 写什么 | 例子 |
| --- | --- | --- |
| Mini PC 的终端里 | `localhost` | `curl http://localhost:11434/v1/models` |
| n8n 的节点里（容器内） | `host.docker.internal` | `http://host.docker.internal:11434/v1/chat/completions` |
| 局域网里别的电脑上 | 固定地址 | `http://192.168.1.50:11434/v1/models` |

**三行写的是同一个服务**，只是站的位置不一样。

### 先验证一次，别等到第 3 章才发现不通

进到容器里试一次：

```bash
docker exec -it n8n sh
```

作用：在一个正在跑的容器里执行命令。`docker exec` 是执行，`-it` 让你能像在终端里一样交互，`sh` 是要执行的那个程序——一个简单的命令行。**执行完提示符会变**，从这一刻起你打的命令是在容器里跑的。

然后：

```sh
wget -qO- http://host.docker.internal:11434/v1/models
```

作用：向 Ollama 那个列模型的端点要一次数据，把返回打在屏幕上。`-q` 是安静模式，`-O-` 是把下载到的内容打出来而不是存成文件。

**打印出一段带 `"id"` 的 JSON 就是通的**，里面那些名字就是[第 6 卷](../06-本地模型/README.md)装的那几个模型，第 3 章要照抄其中一个。

退出容器：

```sh
exit
```

> **这个镜像里有哪些命令行工具，随版本变化，需要核验。** `wget` 不在的话试 `curl -s http://host.docker.internal:11434/v1/models`；两个都没有，跳过这一步，直接到第 3 章用 HTTP Request 节点试——**那个节点跑一次的效果和这条命令一样**，失败的时候节点上会红一下，点开能看到错在哪儿。

### 不通的话，换成写死地址

`host.docker.internal` 这条路在你这台机器上不通的话，**把它换成[第 3 卷第 3 章](../03-服务器基础/03-固定IP.md)那个固定地址**：

```text
http://192.168.1.50:11434
```

**固定地址就是为这种时候准备的**——它不会变，写进配置是安全的。[第 6 卷第 4 章](../06-本地模型/04-Open-WebUI.md)给过同一条退路。

走这条路要确认防火墙放行了 11434（[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)那条规则），**否则表现是卡住不动最后超时**，不是当场报错。

### 顺手存一个 Ollama 凭据

**这一步现在做不做都行**，第 3 章到第 6 章走的是 HTTP Request 那条路，不需要凭据。**第 5 章会提到另一条路——用现成的模型节点**，那条路要先存一个凭据，现在顺手做掉。

左侧菜单进凭据（Credentials）→ 新建 → 搜 Ollama → Base URL 填上面那个地址 → 保存。**看到连接测试通过的提示就成了。**

**界面措辞和菜单位置需要核验，以你实际看到的为准。**

n8n 的模型节点叫 Ollama Chat Model，是挂在别的节点下面的子节点，**第 5 章讲它和 HTTP Request 那条路各自的取舍。**
