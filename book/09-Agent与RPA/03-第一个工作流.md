# 03　第一个工作流

## 这一章的任务

搭一条三个节点的流程，手动点一下，让它去问模型一句话，把答案显示出来。

三个节点是：**手动触发 → 发一个请求给 Ollama → 把答案从返回里挑出来。**

这条流程本身没有任何用处。**它的用处是让你把这几个动作做熟**——怎么加节点、怎么连线、怎么填参数、怎么执行、怎么看每个节点收到了什么吐出了什么。**后面每一章都是这几个动作的重复**，案例一到案例三，一个新动作都没有。

**这一章是本卷的基本功，界面操作写得比别的章细。**

## 开始前

- [第 2 章](02-n8n装起来.md)做完，浏览器打开 `http://localhost:5678` 能进到工作区；
- [第 2 章](02-n8n装起来.md)最后那一节做完，容器里能连到 `http://host.docker.internal:11434`；
- [第 6 卷第 8 章](../06-本地模型/08-局域网API.md)读过。**那一章讲的接口、请求体的写法、返回里那条 `choices[0].message.content` 的路径，这一章直接用，不重讲**；
- 手边有一个模型名。跑一句 `ollama list`，抄一个下来，下面一律写 `qwen3.6-35b`，**换成你自己那个**；
- 40 分钟。

## 新词

**条目**（item）：节点之间流转的数据，一份叫一条。**一个节点吐出几条，下一个节点就被执行几次。** 这一条现在记不住不要紧，第 5 章处理多篇文章的时候会撞上它。

**表达式**（expression）：填在参数框里的一小段取值写法，用两层大括号包起来，例如 `{{ $json.choices[0].message.content }}`。**它的意思是“这里不要填死值，去上一个节点的数据里取”。**

**`$json`**：表达式里指代“这一条数据本身”的写法。**`$json.abc` 就是这条数据里那个叫 `abc` 的字段。**

**面板**（panel）：双击一个节点打开的那个窗口。**左边是它收到什么，中间是参数，右边是它吐出什么。** 本卷说“点开某个节点看输出”，说的都是右边那一块。

**画布**（canvas）、**节点**（node）、**触发器**（trigger）、**执行**（execution）：[第 2 章](02-n8n装起来.md)的新词。

## 先认一遍界面

**下面所有界面上的字都需要核验，随版本变化，以你实际看到的为准。** 位置和形状一般不怎么变，认位置比记文字可靠。

打开 `http://localhost:5678`，新建一条工作流（页面上通常有一个“新建”“Create workflow”之类的按钮）。进去之后是一块空白，这就是**画布**。

要认的地方有五处：

**一、画布中间那个加号。** 空白画布上通常有一个大大的加号或者一句“添加第一个节点”。**点它就是加节点**，会弹出一个搜索框，打名字找。

**二、节点之间的小圆点和连线。** 每个节点方块的右边有一个小圆点，**从这个圆点按住往外拖，拖到另一个节点的左边**，就连上了。连线代表数据的流向：左边那个跑完，把结果交给右边那个。

**三、右上角的执行按钮。** 通常写着“执行工作流”“Execute workflow”之类。**点它，整条流程从头跑一遍。**

**四、右上角的保存。** n8n 不会自动帮你存，**改完记得存**。旁边还有一个开关，管这条流程是不是正式跑起来，**第 6 章才用得着，现在别碰**。

**五、左侧菜单。** 里面有工作流列表、凭据、还有一项是执行记录（Executions）。**执行记录那一项是本卷最常打开的地方**，本章最后一节说它。

## 第一个节点：手动触发

点画布上的加号，在搜索框里打 `manual` 或者“手动”。

选中那个手动触发的节点。**它的名字在不同版本里写法不一样**，可能是 `Trigger manually`，可能是一句 `When clicking Execute workflow`，**认意思不认字**——就是那个“我点一下它才跑”的触发器。

选中之后画布上多出一个方块。**它没有任何参数要填**，关掉面板就行。

**为什么第一条流程用手动触发**：它跑不跑完全由你说了算，改一次试一次，试到满意为止。**第 6 章会把它换成定时触发**，换掉之后这条流程就不用你管了。

## 第二个节点：HTTP Request

从手动触发那个方块右边的小圆点拖出一条线，松手，搜索框弹出来，打 `HTTP`，选 **HTTP Request**。

**这是本卷用得最多的一个节点。** 它干的事只有一件——**按你填的参数往外发一个网络请求，把对方的返回交给下一个节点。** [第 6 卷第 8 章](../06-本地模型/08-局域网API.md)那条 `curl` 命令干的是同一件事，这里换成在界面上填。

双击它，打开面板，从上往下填四处。

### 一、Method 选 POST

这个参数是问“用哪种方式发”。默认是 `GET`，**改成 `POST`**。

**为什么是 POST**：`GET` 是去取东西，`POST` 是把东西送过去。这次要把一段 JSON 送给 Ollama，所以是 `POST`。[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)那条 `curl` 里的 `-d` 参数，效果就是把方式变成了 `POST`。

### 二、URL 填这个

```text
http://host.docker.internal:11434/v1/chat/completions
```

**这一串三段，每一段都在[第 2 章](02-n8n装起来.md)或者[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)说过**：

- `host.docker.internal` —— 从容器里指向这台机器（[第 2 章](02-n8n装起来.md)那一节）。**填 `localhost` 一定连不上**；
- `11434` —— Ollama 的端口；
- `/v1/chat/completions` —— 管对话的那个端点。

[第 2 章](02-n8n装起来.md)那条退路在这里同样成立：`host.docker.internal` 不通，换成 `http://192.168.1.50:11434/v1/chat/completions`，**地址换成你自己那个固定地址**。

### 三、打开 Send Body，格式选 JSON

往下找到 **Send Body** 这个开关，**打开它**。开关一开，下面会多出几个参数：

- **Body Content Type** 选 **JSON**；
- **Specify Body** 选“用 JSON 写”那一项（措辞可能是 Using JSON，**以实际界面为准**）。

**这两步是在告诉它：我要送过去的是一段 JSON，我自己写。** 另一个选项是让你一个字段一个字段地填，本章不用那种，**因为直接写 JSON 和[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)那条 `curl` 长得一模一样，对照着看更清楚。**

### 四、把请求体抄进去

下面那个大框里填：

```json
{
  "model": "qwen3.6-35b",
  "messages": [
    {"role": "user", "content": "用一句话介绍你自己"}
  ],
  "stream": false
}
```

**`model` 那一行换成你自己 `ollama list` 里的名字**，一个字都不能差，写错了返回会告诉你模型不存在。

四个字段，前三个[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)讲过，**第四个是这一章要特别说的**：

- **`model`** —— 用哪个模型；
- **`messages`** —— 这次对话的内容。一个列表，每条有 `role`（谁说的）和 `content`（说了什么）。这里只有一条，角色是 `user`；
- **`stream: false`** —— **不要流式。**

**`stream` 这一条值得单说。** [第 6 卷第 8 章](../06-本地模型/08-局域网API.md)最后讲过：流式是让它一个字一个字往回吐，给人看的界面用它，**程序对程序不用**。这里更硬一点——**流式的返回是一行一行的碎片，HTTP Request 节点收到之后没法当成一段完整的 JSON 交给下一个节点。** 不写这一行默认也是不开，**写上是为了防止哪天你抄了别处的例子把它打开。**

### 顺手把超时调大

面板往下拉，找到选项（Options）那一块，**加一项超时（Timeout）**。

**为什么要改它**：本地模型第一次被叫醒要把权重读进内存，十几秒到几分钟（[第 6 卷第 7 章](../06-本地模型/07-多模型切换.md)）。**默认的超时值不一定等得起**，等不起的表现是节点报一个超时错误，而模型其实好好的，只是还没答完。

填一个宽松的值，比如 600000（这个参数的单位一般是毫秒，600000 就是 600 秒）。**这个参数的默认值和单位需要核验，以你面板上写的为准。** [第 6 卷第 8 章](../06-本地模型/08-局域网API.md)那段 Python 里的 `timeout=600` 是同一件事。

## 执行一次，读结果

点右上角执行。

**第一次会等一阵**，模型要加载。等的时候节点上会转圈。

跑完之后，双击 HTTP Request 那个节点，看面板右边那一块。**你会看到一段和[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)里一模一样的返回**，形状大致是这样（**下面是格式示意，数值随模型和版本变化**）：

```json
{
  "id": "chatcmpl-xxxxxxxx",
  "object": "chat.completion",
  "created": 1765000000,
  "model": "qwen3.6-35b",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "我是一个跑在本地的语言模型，可以陪你聊天、写东西、读文件。"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 12,
    "completion_tokens": 27,
    "total_tokens": 39
  }
}
```

**这一段面板上通常有两种看法**，一种是排好版的树状视图，一种是原始的 JSON 文本，界面上有按钮可以切。**树状那种更容易一层层点开看结构**，JSON 那种更容易照抄路径。

**要看的还是[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)那三处**：

- **`choices[0].message.content`** —— 模型说的话。**下一个节点要取的就是它**；
- **`usage`** —— 这次用掉多少 token；
- **`finish_reason`** —— 为什么停下来。`stop` 是正常说完，`length` 是被长度上限截断了。

### 节点报红了怎么办

节点方块上出现红色标记，**双击打开，面板上会写着错在哪儿**。本章最可能撞上的两种：

- **连接被拒绝或者连不上** —— URL 填错了，或者 `host.docker.internal` 这条路不通。回[第 2 章](02-n8n装起来.md)那一节，先在容器里试一次，不通就换固定地址；
- **返回里说模型不存在** —— `model` 那个名字写错了。跑一次 `ollama list` 照抄。

其余的到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。

## 第三个节点：把答案挑出来

上一步拿到的是一整段 JSON。**日常要的只是里面那一句话**，这个节点干的就是把它挑出来。

从 HTTP Request 右边拖一条线出去，搜 `set` 或者“编辑字段”，选 **Edit Fields (Set)**。

**这个节点的作用是新增或者改写流转数据里的字段。** 打开它：

1. 模式选手动映射（Manual Mapping）那一种；
2. 加一个字段，名字填 `回答`，类型选字符串（String）；
3. **值那一格要填表达式，不是填死字。** 值输入框旁边一般有一个固定值和表达式的切换（Fixed／Expression），**切到表达式那一边**，然后填：

```text
{{ $json.choices[0].message.content }}
```

**这一行就是[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)那条路径**，念法一样——“choices 这个列表里第 0 个，它的 message，它的 content”。那一章 Python 里写 `data["choices"][0]["message"]["content"]`，这里写成表达式，**指的是同一个东西。**

**表达式填对了，输入框下面通常会当场把取到的值显示出来**，那句话就在那儿。**显示的是 `undefined` 或者空的**，说明路径写错了——回上一个节点的输出面板，一层层点开对着抄。

再执行一次。点开这个节点的输出，应该只剩干干净净的一行：

```json
{
  "回答": "我是一个跑在本地的语言模型，可以陪你聊天、写东西、读文件。"
}
```

**三个节点的流程到这儿就通了。**

## 执行记录在哪儿看

左侧菜单里那一项执行记录（Executions），**点进去是这条流程跑过的每一次**，一次一行，标着什么时候跑的、成了还是失败了。

**点开任意一次，画布会原样重现那一次的样子**——每个节点当时收到什么、吐出什么，全都在。

**这是本卷最重要的一个调试办法，比什么都管用。** 后面几章凡是遇到“结果不对但不知道错在哪一步”，都是到这儿来，从左往右一个节点一个节点点开看，**看到哪一个节点的输出开始不对劲，问题就在那一个节点上。**

**第 11 章会把这个执行记录讲深**——保留多久、失败了怎么自动重试、怎么在客户问“昨天那单怎么没处理”的时候答得上来。

## 三件后面一直要用的事

**一、改一处，执行一次。** 别一口气改五个参数再跑。**改一处跑一次，坏了立刻知道是刚才那一处坏的。**

**二、只跑一个节点。** 节点面板上一般有一个只执行这一个节点的按钮，**调一个节点的参数时用它**，不用整条流程从头跑一遍，省时间也省一次模型加载。**这个按钮的位置和措辞需要核验。**

**三、把节点改个名字。** 在节点上点右键可以重命名。**流程一长，画布上五个 HTTP Request 谁也分不清谁**，改成“抓 RSS”“问模型”这种名字，后面写表达式引用它的时候也好认。第 5 章会用到按名字引用别的节点。
