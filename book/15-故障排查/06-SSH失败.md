# 06　SSH 失败

## 先分方向

三种错误信息各指向不同的一层，看你收到的是哪一种，方向就定了。不要凭“连不上”三个字乱查。

| 你看到的 | 在哪一层 | 去哪儿 |
| --- | --- | --- |
| `Connection timed out`、`No route to host` | 网络。根本没找到这台机器 | [第 5 章](05-网络失败.md) |
| `Connection refused` | 服务。地址找到了，22 端口没人应 | [第 3 卷第 4 章](../03-服务器基础/04-SSH.md) |
| `Permission denied (publickey)` | 认证。机器应答了，就是不认你 | [第 3 卷第 4 章](../03-服务器基础/04-SSH.md)换密钥登录那两节 |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | 指纹和上次记的对不上 | [第 3 卷第 4 章](../03-服务器基础/04-SSH.md)“指纹变了怎么办” |

## 按顺序查

1. 先 ping 一次那个地址。ping 不通就不是 SSH 的问题，回[第 5 章](05-网络失败.md)；
2. ping 得通，到机器跟前看 22 端口有没有在等连接（[第 3 卷第 4 章](../03-服务器基础/04-SSH.md)）。没有，就是 `openssh-server` 没装或者服务没起来；
3. 端口在等、连接还是被拒，看防火墙放行了没有（[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)“放行 SSH，然后才启用”）；
4. 报 `Permission denied (publickey)`，查私钥在不在、公钥有没有装到机器上（[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)“密钥放哪、丢了怎么办”）；
5. 地址本身老在变的，去[第 3 卷第 3 章](../03-服务器基础/03-固定IP.md)把它固定下来。

> **新版 Ubuntu 的 SSH 是按连接唤起的，`systemctl status ssh` 显示 `inactive` 不代表出故障**，判断以端口在不在等、连不连得上为准（[第 3 卷第 4 章](../03-服务器基础/04-SSH.md)）。

## 都不行

**关掉密码登录之后被锁在外面，从远程救不回来。** 接上显示器和键盘在机器本地登录，把那个禁用密码的配置片段删掉、重启 SSH 服务，两条命令在[第 3 卷第 4 章](../03-服务器基础/04-SSH.md)“被关在外面了怎么办”。密码登录立刻就回来了，再从头查密钥哪里没配对。

改 SSH 配置的时候记住一条：**正在连着的那个窗口不要关**，它是唯一的后路。

还是连不上的，用 `ssh -v` 把连接过程打出来，看第一处报错和它前面那几行，其余可以不看。
