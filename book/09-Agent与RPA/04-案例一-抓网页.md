# 04　案例一：抓网页

## 这一章的任务

**案例一从这一章开始。**

先说清整个案例要做成什么：**每天早上你还没起床，机器已经去看过几个你关心的网站，把新出来的内容整理成一份中文摘要，发到你邮箱里，或者存成一个按日期命名的文件。**

这个案例分三章做完：

- **第 4 章（本章）——把内容抓下来。** 这一章结束时，你点一下执行，屏幕上出现几条最新的文章标题、链接和正文；
- **第 5 章——让本地模型把它们写成摘要**；
- **第 6 章——让它每天早上自己跑，把结果送到你手上。**

**定时那一步在第 6 章，这一章还是手动点。** 先把抓的这一步做对，再谈自动。

## 开始前

- [第 3 章](03-第一个工作流.md)做完。**加节点、连线、执行、看每个节点输入输出、填表达式，这一章全部直接用，不重讲**；
- [第 2 章](02-n8n装起来.md)那个 n8n 在跑，浏览器进得去；
- 一个你自己关心的网站，手边留着，**下面那节找 RSS 的办法要拿它试一次**；
- 40 分钟。

## 新词

**抓取**：让程序去访问一个网页，把内容取回来。**和你用浏览器打开那个页面是同一件事**，区别只在于干这件事的是程序不是人。

**RSS**（简易信息聚合，Really Simple Syndication）：**一个站点主动提供的、专门给程序读的内容清单。** 它是一个固定格式的文件，里面一条一条列着这个站最近发了什么——标题、链接、发布时间、摘要或者正文。**站点提供它的目的就是让别人订阅**，所以走这条路最省事，也最不容易惹麻烦。

**订阅源地址**（feed URL）：那个 RSS 文件的网址。找到它是这一章第一件事。

**robots.txt**：放在一个网站根目录下的一个文本文件，地址固定是 `站点域名/robots.txt`。**站点用它告诉程序：哪些地方欢迎来，哪些地方别碰。**

**CSS 选择器**：一小段写法，用来指定“网页上的哪一块”。例如 `h2 a` 的意思是“所有 `h2` 标题里面的链接”。**从网页里挑内容要用它。**

**HTML**：网页的原始文本。你在浏览器里看到的排版，是浏览器照着这段文本画出来的。

## 抓东西的规矩

**这一节放在动手之前，因为它比技术重要。**

程序抓东西和人用浏览器看，技术上没差别，**分量上差得很远**——你一分钟点不了三十个页面，程序能。所以这件事有几条线，**本教材要求你一条都不越**。

**一、只抓公开页面。** 不登录、不输密码、任何人打开链接就能看到的页面，才抓。**要登录才能看到的东西不抓**，那不是公开内容，抓它意味着你在用某个账号的身份去取数据，性质完全不同。

**二、先看 robots.txt。** 在浏览器里打开 `站点域名/robots.txt`，例如：

```text
https://ubuntu.com/robots.txt
```

里面是几行简单的规则：`User-agent` 那行说这条规则管谁，`Disallow` 那行说哪些路径别抓，有的站还会写 `Crawl-delay` 说明两次访问之间至少隔多久。**写着不让抓的路径就别抓。** 这个文件的内容站点随时会改，**每次要抓一个新站点，自己打开看一眼**，本教材不替任何站点声明它写了什么。

**三、控制频率，别给人家添麻烦。** 一天一次就够了。**这也是本案例选“每天早上一次”而不是“每五分钟一次”的原因之一。** 同一个站点连着请求几十次这种事，本卷从头到尾不做。

**四、看站点自己的条款。** 有些站在页面底部或者服务条款里明确写了允许或者不允许自动抓取，**写了的就按它的来**，比 robots.txt 的分量更重。

**五、抓下来的东西怎么用，也有线。** 抓回来自己看、自己做摘要、自己判断要不要点开原文，**这是正常使用**；把人家的正文原样搬出去发在自己的公众号、网站、群里，**那是另一件事，涉及版权**。本案例做的日报是给你自己看的，**里面留着原文链接**，要看全文点过去看。这一点第 6 章还会说一遍。

**六、出问题先停。** 对方站点开始返回错误、变慢、或者明确挡你，**先把这条流程停掉，别硬试**。这条线不是技术问题，是态度问题。

> **本案例用 RSS 做主线，很大程度上就是为了绕开这些麻烦。** 一个站点提供 RSS，等于它主动把“我最近发了什么”整理好放在那儿给人订阅——**这是它希望你走的那条路。**

## 优先找 RSS

**同一个站，能走 RSS 就不要去解析网页。** 三条理由：

**一、格式固定。** RSS 是一个规定好的结构，标题就在标题那个位置，链接就在链接那个位置。**网页不是**，网页的结构是人家设计师定的，今天这样明天那样。

**二、人家改版不会弄坏你。** 站点重新设计页面，RSS 通常照旧；**你要是照着网页结构写了一串选择器，改版当天全部失效。**

**三、它本来就是给程序读的。** 走这条路你不用猜人家愿不愿意。

### 怎么知道一个站有没有 RSS

三个办法，从易到难：

**一、看页面上有没有订阅入口。** 不少站在页脚或者侧栏放一个 RSS 图标，点它就是订阅源地址。

**二、在域名后面试几个常见的路径。** 直接在浏览器地址栏里试：

```text
站点域名/feed
站点域名/rss
站点域名/atom.xml
站点域名/blog/feed
```

**打开之后满屏都是尖括号包着的标签，就是它。** 浏览器可能直接给你显示成一个订阅页面，也可能显示成一堆原始文本，两种都算找到了。

**三、看网页源码。** 在页面上按 `Ctrl+U` 看源码，搜 `application/rss+xml`，那一行里的 `href` 就是地址。

**三个办法都试过还是没有，那个站就是没提供 RSS**，走本章后半段那条解析网页的路。

## 动手一：用 RSS 抓一批文章

**本章用 Ubuntu 官方博客的订阅源做例子**，理由是它公开、地址稳定、内容和这本书的读者相关：

```text
https://ubuntu.com/blog/feed
```

**动手之前照上面那节做一遍**：打开 `https://ubuntu.com/robots.txt` 看一眼，心里有数再往下走。**换成你自己那个站的时候，这一步同样要做。**

### 新建一条工作流

新建，起名叫“日报-案例一”。**这条流程从这一章一直用到第 6 章**，中间不再新建。

### 第一个节点：手动触发

和[第 3 章](03-第一个工作流.md)一样，加一个手动触发。第 6 章会把它换掉。

### 第二个节点：RSS Read

从手动触发拖一条线出去，搜 `RSS`，选 **RSS Read**。

这个节点只有一个必填参数：

- **URL** 填 `https://ubuntu.com/blog/feed`。

选项里有一项是忽略 SSL 问题（Ignore SSL Issues），**别开它**。那一项的作用是跳过证书检查，**正常的站点不需要跳**，要跳说明有别的问题。

执行一次。

### 看它抓到了什么

点开 RSS Read 那个节点的输出面板。**你应该看到一批条目，一篇文章一条**（[第 3 章](03-第一个工作流.md)新词里的“条目”，这里第一次真的用上了）。

每一条里有一组字段。**字段名以你面板上看到的为准**——RSS 这个格式各家站点写法有出入，官方文档也没有列死输出字段名。常见的有这么几个：

| 大致是什么 | 一般叫什么 | 拿它干什么 |
| --- | --- | --- |
| 文章标题 | `title` | 日报里那一行标题 |
| 文章地址 | `link` | 日报里那个“看原文”的链接 |
| 发布时间 | `pubDate` 或 `isoDate` | 挑最近几天的 |
| 摘要 | `contentSnippet` 或 `description` | 短，够做摘要的输入 |
| 正文 | `content` 或 `content:encoded` | 长，里面常带 HTML 标签 |

**这一步要做的事只有一件——把面板上真实的字段名抄下来。** 下一章写提示词要用它们，抄错一个字，模型收到的就是空的。

> **有的站的 RSS 只给摘要不给正文**，那也够用：日报本来就是给你决定“要不要点开看”的，**摘要加标题加链接足够了**。硬要全文的话，得再去抓一次原文页面，那是本章后半段那条路，**不推荐为了这个去做**。

### 现在的问题：条目太多

一个活跃的博客，订阅源里一次可能给你十几条。**每天全部丢给模型做摘要，既慢又没必要**——你要的是新的那几条。

**这件事第 5 章解决**，那一章会讲怎么只留最近的几条、多条内容怎么交给模型。**这一章到这儿就够了。**

## 动手二：没有 RSS 的站怎么办

**这条路能走通，但要先接受两件事**：它随人家改版失效，而且要你自己去看网页结构。**能走 RSS 就别走这条。**

两个节点：**HTTP Request 把网页取回来，HTML 节点从里面挑出你要的部分。**

### 第一步：HTTP Request 取回网页

[第 3 章](03-第一个工作流.md)那个节点，参数不一样：

- **Method** 选 **GET**。这次是去取东西，不是送东西；
- **URL** 填那个页面的地址；
- **Response Format** 选 **Text**。

**第三项要说一句。** 这个参数管“把对方的返回当成什么处理”，默认是自动判断（Autodetect）。**选 Text 是让它把整页 HTML 当成一段文本原样交出来**，下一个节点才有东西可挑。选了 Text 之后，下面一般还会让你指定“放进哪个字段”，**默认常是 `data`，以你面板上显示的为准**，下一步要用到这个名字。

执行一次，点开输出。**你会看到一大段尖括号密密麻麻的文本**，那就是这个页面的原始 HTML。

### 第二步：找到你要那块的 CSS 选择器

**这一步在浏览器里做，不在 n8n 里做。**

1. 用浏览器打开那个页面；
2. 在你要的那块内容上点右键，选“检查”（Inspect）；
3. 右边弹出的面板里，高亮的那一行就是这块内容对应的 HTML。看它的标签名和 `class`；
4. 在那一行上点右键，一般有一项是复制选择器（Copy selector），**复制出来的那一串就能直接用**。

**复制出来的选择器常常很长很脆**，形如 `#main > div:nth-child(3) > article > h2 > a`。**能自己写短一点更好**，比如 `article h2 a`——层级写得越死，人家页面动一点你就失效。

### 第三步：HTML 节点提取

从 HTTP Request 拖一条线出去，搜 `HTML`，选 **HTML** 节点。

- **Operation** 选 **Extract HTML Content**；
- **Source Data** 选 **JSON**；
- **JSON Property** 填上一步那个字段名（默认常是 `data`）；
- **Extraction Values** 那一块，一组一组地加。每一组三项：
  - **Key** —— 你给这块内容起的名字，例如 `标题`；
  - **CSS Selector** —— 上一步找到的那一串；
  - **Return Value** —— 要取什么。取文字选文本（Text），取链接地址选属性（Attribute）然后填属性名 `href`。

一篇文章通常要加三组：标题、链接、正文。

页面上有一批文章、你要全部取下来的话，**打开 Return Array（返回数组）那个开关**，取到的会是一个列表而不是一条。

执行，点开输出，对着页面核一遍。**取到的是空的**，十有八九是选择器写错了，或者那块内容是页面打开之后才用脚本画上去的——**后面这种情况这条路取不到**，那属于浏览器自动化的范围，第 14 章讲，**也讲它为什么不稳。**

> **这条路的脆弱是写在骨子里的，不是你写得不够好。** 你依赖的是别人页面的内部结构，而那个结构人家想改就改，**改了不会通知你，你也不会收到报错——你只会某天发现日报是空的。** 第 11 章讲怎么让这种“悄悄变空”被发现。

## 抓完先看一眼

**不管走哪条路，抓完先看三样东西，别急着接下一章。**

**一、条数对不对。** 面板上那个条目数，和你在浏览器里数到的差不多吗？**差很多说明选错了地方或者只取到了一部分。**

**二、正文里有没有一堆标签。** RSS 的 `content` 字段和网页抓下来的正文，里面常带着 `<p>`、`<a href=...>` 这类东西。**这些送给模型也能读，但白白占掉 token**。清掉它们的做法第 5 章讲。

**三、有没有空的。** 十条里有两条标题是空的，说明有的条目结构不一样。**下一章要处理这种情况**，不然模型会对着空内容编一段出来。

- **本章不给任何抓取速度、成功率数字。** 能不能抓到、抓得多快，取决于对方站点；
