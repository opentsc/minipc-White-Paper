# 案例 03　发票文件夹变 Excel 台账

**等级 60。分类：单据处理与交付。**

这份文档用于一台已经能跑本地视觉模型的 Mini PC。完成以后，这台机器上有一条能交出去的流水线：一个文件夹的扫描件丢进去，出来一张 Excel 打得开的台账；读不出来的单独堆在一边，读出来但说不通的被挑到另一张表上等人看；台账能存成带格式的 xlsx，金额那几列选中就能求和。同时你手上会有两张自己测出来的记录表——一份单据要跑多久，每一格读对了没有。附带一个体检脚本，一条命令逐项检查，不通过的写清回教材哪一章。

对应教材[第 8 卷第 2 章](../../../book/08-OCR/02-环境准备.md)、[第 3 章](../../../book/08-OCR/03-定义字段.md)、[第 4 章](../../../book/08-OCR/04-单张跑通.md)、[第 5 章](../../../book/08-OCR/05-批量处理.md)、[第 7 章](../../../book/08-OCR/07-错的怎么拦.md)、[第 11 章](../../../book/08-OCR/11-对接.md)和[第 13 章](../../../book/08-OCR/13-速度与准确率实测.md)。视觉模型那一层在[第 6 卷第 11 章](../../../book/06-本地模型/11-视觉模型.md)。

体检脚本只读，不改任何配置，在没配置过的机器上跑也不会出事——查不到的项目它报“跳过”，不报错。它唯一会“动”的地方是向视觉模型服务发一张 1×1 的小图，那会让那个模型被加载进内存，**那是这套东西本来就要做的事**。它不读任何单据，也不读跑出来的台账。

## 完成结果

- **服务在跑**：`ocr-vlm` 这个服务起着，`/v1/models` 问得到模型名，图文一起发的请求跑得通。
- **有一份 schema**：`~/ai/scripts/invoice_schema.json` 在，字段全部是字符串，`required` 写全，`additionalProperties` 关掉。
- **一个文件夹跑完出一张台账**：`ledger.csv` 的行数和你自己数的份数对得上，失败的复制在 `failed/` 并且记了原因。
- **错的被挑出来**：`review.csv` 在，每一行的第三列写清楚了哪儿不对，不是笼统一句“有问题”。
- **台账能进 Excel**：`ledger.xlsx` 双击打开不乱码，表头加粗冻结、带筛选，金额那几列选中能求和，发票号码没有变成科学计数法。
- **有两张实测记录表**：速度那张分开记了 PDF 转图和模型识别两段；准确率那张按字段记，不按张记。两张的“条件”和“适用范围”都没留空。
- `check-ocr.sh` 一条命令跑完全部检查，通过与否有明确的退出码。

## 准备条件

- 教材[第 8 卷第 2 章](../../../book/08-OCR/02-环境准备.md)做完，`ocr-vlm` 服务在跑，**起服务的时候挂了 `--mmproj`**。这一条不成立的话，模型看不见图。
- 教材[第 8 卷第 4 章](../../../book/08-OCR/04-单张跑通.md)装过 `poppler-utils`，`pdftoppm -v` 有输出。
- 教材[第 8 卷第 3、4、5、7 章](../../../book/08-OCR/03-定义字段.md)做完，`~/ai/scripts/` 下面有 `ocr_one.py`、`ocr_batch.py`、`validate.py` 三个脚本。
- **一批真实单据，同一类的。** 发票就全是发票，别混着合同和送货单。**用客户的真实材料，不要用干净的样张**——教材[第 10 章](../../../book/08-OCR/10-变体-旧档案批量数字化.md)那条。三十份以上，做准确率那一步够用。
- 硬盘上留几 GB。模型文件占大头，跑出来的 JSON 和台账很小。
- 半天到一天。文件干净的话半天够，**准确率那一半的时间全在人工标注上**。

检查环境。

```bash
systemctl status ocr-vlm --no-pager
curl -s http://127.0.0.1:8090/v1/models
pdftoppm -v
df -h /
```

## 操作步骤

### 1　复制到固定位置

```bash
mkdir -p "$HOME/apps"
cp -R labs/level-60/03-invoice-ocr "$HOME/apps/invoice-ocr"
cd "$HOME/apps/invoice-ocr"
chmod 755 scripts/check-ocr.sh
```

只下载了这个案例，就把案例目录放到 `$HOME/apps/invoice-ocr`。

### 2　先跑一次体检，看现在差哪几项

**动手之前先跑一次**，把不通过的那几项抄下来，做完再跑一次对照。

```bash
./scripts/check-ocr.sh
```

刚做完教材第 2 章的机器上，多半是第 1、2、4 项通过，第 3 项和第 5 项不通过。**那是对的**——schema 还没写，脚本还没抄。

### 3　把单据放好

教材[第 4 章](../../../book/08-OCR/04-单张跑通.md)那张目录图，三类东西各有各的位置：

```bash
mkdir -p ~/ai/data/invoices-2026-08
mkdir -p ~/ai/projects/invoice-ocr/out ~/ai/projects/invoice-ocr/failed
```

把单据复制进 `~/ai/data/invoices-2026-08/`。

**`data/` 里只有原件，脚本一个字都不往里写。** 这一条守住，你随时能回头核对。

**数一遍有多少份，记住这个数。** 第 6 步要对它。

```bash
find ~/ai/data/invoices-2026-08 -type f \( -name '*.pdf' -o -name '*.png' -o -name '*.jpg' \) | wc -l
```

### 4　定 schema

```bash
cp invoice_schema.example.json ~/ai/scripts/invoice_schema.json
```

**模板里那八个字段是教材主线用的一组起点，不是任何规范。** 打开你自己那批单据，按教材[第 3 章](../../../book/08-OCR/03-定义字段.md)那三个问题筛一遍：下游谁用、没有它会怎样、票面上一定有吗。

**改完再跑一次体检**，第 3 项应该通过：

```bash
./scripts/check-ocr.sh
```

### 5　单张跑通，而且要对 10 张

```bash
python3 ~/ai/scripts/ocr_one.py ~/ai/data/invoices-2026-08/你那份.pdf
```

**八格齐了、都是字符串、没有多余字段，形状就对了。**

**然后把 JSON 和原单据并排放着，一格一格对**，按教材[第 4 章](../../../book/08-OCR/04-单张跑通.md)那六步的顺序：价税合计、发票号码、开票日期、买卖双方、种类、金额税额。

**至少对 10 张。** 一张说明不了什么。**对下来那份“哪几格最常错”的记录，第 7 步定校验规则要用。**

同一格连着几张都错，回教材[第 3 章](../../../book/08-OCR/03-定义字段.md)改提示词，不要往下走。

### 6　整批跑

**先跑三份：**

```bash
python3 ~/ai/scripts/ocr_batch.py ~/ai/data/invoices-2026-08 ~/ai/projects/invoice-ocr --limit 3
```

三份都成功、台账有三行，再全跑：

```bash
python3 ~/ai/scripts/ocr_batch.py ~/ai/data/invoices-2026-08 ~/ai/projects/invoice-ocr
```

**跑完对三个数**（教材[第 5 章](../../../book/08-OCR/05-批量处理.md)那一节）：成功加跳过加失败，等不等于第 3 步数出来的总份数；台账多少行；失败几份。

**中途要停就按 `Ctrl+C`**，下次重跑接着来，跑完的不会重跑。

### 7　拦错，然后复核

```bash
python3 ~/ai/scripts/validate.py ~/ai/projects/invoice-ocr
xdg-open ~/ai/projects/invoice-ocr/review.csv
```

**脚本最上面那四项要按你自己那批单据改**——必填哪几格、发票号码几位、年份最早到哪年（教材[第 7 章](../../../book/08-OCR/07-错的怎么拦.md)）。

**在表格软件里按第三列排一次序**，同一类问题会挨在一起。**某一类特别多，那不是复核的事，是回教材第 3 章改提示词的事。**

复核完重跑两个脚本，复核队列里改好的那几行应该消失了。

### 8　台账进 Excel

```bash
python3 -m pip install --user openpyxl
python3 ~/ai/scripts/ledger_to_xlsx.py ~/ai/projects/invoice-ocr/ledger.csv
xdg-open ~/ai/projects/invoice-ocr/ledger.xlsx
```

脚本在教材[第 11 章](../../../book/08-OCR/11-对接.md)。**打开之后确认两件事**：金额那几列选中，底下状态栏显示得出合计；发票号码那一列**没有变成 `2.44E+19` 那种样子**。

**变成科学计数法了，说明那一列被当成数了**，回教材那一章看 `NUMBER_COLUMNS` 那一节。

### 9　测速度和准确率

**这一步不能省，它是你跟客户谈话时唯一的底气。**

速度：

```bash
python3 ~/ai/scripts/ocr_timing.py ~/ai/data/invoices-2026-08 --limit 20
```

准确率，先出一张空表：

```bash
python3 ~/ai/scripts/compare.py ~/ai/projects/invoice-ocr ~/ai/projects/invoice-ocr/truth.csv --make 30
```

**照第一列的文件名打开原件，一格一格照票面填。**

> **填之前不要去看跑出来的结果。** 先看结果再标答案，就变成了对着结果找理由（教材[第 13 章](../../../book/08-OCR/13-速度与准确率实测.md)那一节）。

填完比对：

```bash
python3 ~/ai/scripts/compare.py ~/ai/projects/invoice-ocr ~/ai/projects/invoice-ocr/truth.csv
```

**两张记录表照教材第 13 章那两份空表填完**，条件那几栏一栏都不能空。**填完把速度那几行并进教材[第 4 卷第 16 章](../../../book/04-Max395硬件/16-设备基线.md)那份设备基线。**

## 验收标准

**七条全部满足才算通过。**

1. `./scripts/check-ocr.sh` 输出“体检通过”，退出码是 0（`echo $?` 查）。
2. **三个数对得上**：成功加跳过加失败，等于第 3 步数出来的总份数；台账行数等于成功加跳过。
3. **随便挑三行，照第一列的文件名找到原件，八格逐格对得上。** 对不上的那一格说得出是哪一类问题。
4. **故意造一份错的，它必须被拦住。** 挑一份跑对了的，把它的 JSON 里价税合计改成一个对不上的数，重跑 `validate.py`，**它出现在 `review.csv` 里，而且第三列写清楚了金额加税额等于多少、价税合计写的是多少**。
5. **`review.csv` 里那几行你都看得懂**，每一行说得出属于哪一类：必填空着、位数不对、日期认不出、金额不是数、算不平、买卖双方同名。
6. **`ledger.xlsx` 双击打开不乱码**，金额那几列选中能求和，**发票号码没有变成科学计数法**。
7. **两张实测记录表填完**，条件那几栏没留空，**“适用范围”那一栏还在**。

**第 4 条是这个案例和“把发票拖进对话框问一句”的分界线。** 过不了这一条，你交出去的是一张没有人把过关的表。

**第 7 条管的是你跟客户开口那一刻。** 没有这两张表，你只能说“挺准的”，**而这句话客户听过太多次了**。

## 可以出售的结果

- **单据批量转台账（轻交付）**：客户把一批扫描件发给你，你跑完把台账发回去，**客户不用买机器、不用装环境**。做完按约定删干净并出一份书面确认——**那份确认是这个形态的信任来源**（教材[第 12 章](../../../book/08-OCR/12-轻交付形态.md)）。
- **整机预装 OCR 工作站**：机器加系统加这条流水线，装在客户自己那儿。**卖点是材料不出门**——律所、诊所、会计事务所这一类，从制度上就不允许把凭证发给外面的人（教材[第 12 章](../../../book/08-OCR/12-轻交付形态.md)那条升单路径）。
- **换一类材料就是另一个客户**：合同关键条款、物流单与表格件、旧档案批量数字化，各自的 schema、提示词和校验规则在教材第 8 到第 10 章。**同一台机器、同一套脚本，换一份 schema 就是另一单。**
- **对接**：台账进 Excel、进数据库、给别的系统（教材[第 11 章](../../../book/08-OCR/11-对接.md)）。**这一项必须单独报价**——客户的系统千奇百怪，而你在报价的时候看不见它。
- **定期跑**：月结、对账季、审计前。接教材[第 6 章](../../../book/08-OCR/06-文件夹监测.md)那个定时任务，**新单据丢进收件箱自动处理**。
- **实测与验收**：按教材[第 13 章](../../../book/08-OCR/13-速度与准确率实测.md)那套在客户自己那批材料上测一遍，出两张记录表。**这一项能单独收费**，而且它是报价的依据。

**上面这些是可以准备的方向，不是已经验证过的成交路径。** 公开渠道里，这个方向**有需求证据、有定价参照，没有可核验的成交案例**。成本怎么算、五种计价方式各配什么场合，在教材[第 14 章](../../../book/08-OCR/14-按页计价.md)；报价单和合同在教材第 11 卷和第 13 卷。

**还有一条硬的**：不给准确率数字，不把实测出来的数写进合同。**能承诺的是“错的会被挑出来”，不是“每一格都对”**（教材[第 7 章](../../../book/08-OCR/07-错的怎么拦.md)那三句话）。

## 常见问题

### 第 1 项说连不上

```bash
systemctl status ocr-vlm --no-pager
sudo systemctl start ocr-vlm
```

起来之后**等模型加载完**再跑体检。端口不是 8090 的话：

```bash
CHECK_OCR_PORT=你的端口 ./scripts/check-ocr.sh
```

### 第 2 项拿不到回答

三种常见原因，按顺序看：

1. **起服务的时候没挂 `--mmproj`**。**这是最常见的一种**——没有它模型看不见图（教材第 8 卷第 2 章）。
2. **模型还在加载**，超过了脚本等的那个秒数。`CHECK_TIMEOUT=600 ./scripts/check-ocr.sh` 再试一次。
3. **模型名不对**。`CHECK_OCR_MODEL=模型名 ./scripts/check-ocr.sh` 指定。

### 第 3 项说 schema 有问题

打开那个文件看一眼，最常见的是**中文引号混进去了**——JSON 只认半角双引号 `"`。用文本编辑器打开，把 `“` 和 `”` 换掉。

### 跑出来八格全是空的

**先看第 2 项过没过。** 过了的话，多半是提示词或者 schema 的问题，回教材第 3 章。

**只有某几格空**，那是正常信号——空字符串是模型在举手说这一格没看清（教材第 3 章）。空得多的那几格，调 `--dpi 300` 试一份看看。

### 台账打开是一屏乱码

用的程序没认出 `utf-8-sig` 那个记号。在表格软件里打开时会弹一个导入对话框，**字符集选 Unicode (UTF-8)**，分隔符选逗号（教材第 8 卷第 5 章）。

### 发票号码在 Excel 里变成了 2.44E+19

**那一列被当成数了。** 回教材[第 11 章](../../../book/08-OCR/11-对接.md)，把发票号码从 `NUMBER_COLUMNS` 里拿掉。**这是那一章唯一一处会毁数据的地方。**

### review.csv 一行都没有

两种可能，处理方式完全不同：

- **这一批确实干净** —— **抽检照做，不能省**（教材第 8 卷第 7 章最后那一节说了理由）；
- **校验规则没配对** —— 打开 `validate.py` 看最上面那四项，是不是必填字段填错了、发票号码位数写的不是你这批的位数。

### 复核完重跑，怕把手改的覆盖掉

**不会。** `ocr_batch.py` 看到 JSON 已经在了就跳过，**连模型都不会去问**（教材第 8 卷第 5 章那个跳过机制）。**手改 JSON 加重跑是一条安全的回写路径。**

其余的按教材第 15 卷的症状表走。

## 停止和恢复

**停掉服务**：

```bash
sudo systemctl stop ocr-vlm
sudo systemctl start ocr-vlm
```

**把这一批的结果整个删掉重来**：

```bash
rm -rf ~/ai/projects/invoice-ocr
```

**原件还在 `~/ai/data/` 里，一个字都没动过。** 这就是那条“`data/` 里只写不读”的规矩换来的东西。

**只想重跑某几份**：把它们在 `out/` 里的 JSON 删掉，重跑批量脚本。

**改了提示词想整批重做**：

```bash
rm ~/ai/projects/invoice-ocr/out/*.json
```

然后重跑。**重做完要用同一份 `truth.csv` 再比一次**，确认这次改动是变好还是变坏（教材第 8 卷第 13 章）。

**把这一批备份走**：

```bash
tar -czf "invoice-ocr-$(date +%F).tar.gz" -C "$HOME/ai/projects" invoice-ocr
```

> **这个包里有客户的往来单位和金额。** 它和原件一样，按内部资料对待。

体检脚本本身不用停也不用恢复，它只读，删掉就是了。

## 隐私边界

- **`~/ai/data/` 和 `~/ai/projects/` 里装的是客户的财务凭证。** 这两个目录、它们的备份、发出去的那个包，**全部按内部资料对待**（教材第 2 卷第 12 章）。
- **这两个目录不进 Git。** 本案例的 `.gitignore` 已经把单据、台账、复核队列、比对结果和填过的 schema 全挡在外面，**只留 `.example` 模板**。
- **做轻交付的话，删干净并出一份书面确认**（教材[第 12 章](../../../book/08-OCR/12-轻交付形态.md)那份模板）。**确认书里写“删了什么、什么时候删的”，不写“数据已被物理销毁”。**
- **一客户一目录，两个客户的单据绝对不能混。** 批量脚本是按目录跑的，混进去的那一份会跑进别人的台账里。
- **`truth.csv` 里是客户真实单据的逐格内容**，它本身就是客户资料，**和原件一样对待**。
- **体检脚本的输出里有内网地址、端口、模型名和目录路径。** 往外发之前逐行看一遍（教材第 0 卷第 8 章）。
- **体检脚本不读任何单据、不读台账和 JSON、不读任何密钥、不发送任何数据到外部。** 它调用的是系统自带的查询命令，加上向本机服务发的一张 1×1 的小图。
- **示例 schema 和这份文档里的一切示例数据都是虚构的**，不对应任何真实单位与真实票据。

## 当前范围

这个案例只做**一类单据、一台机器、一个文件夹**。

**没有做**：自动触发（教材第 8 卷第 6 章那个定时任务和目录流转）、进数据库和给别的系统开接口（教材第 8 卷第 11 章后两节）、给接口加认证（教材第 10 卷）、把这些串成一个能自己往下走的流程（教材第 9 卷）、多客户隔离与出厂检查（教材第 10 卷）。

**下一步可以接三样**：按教材第 8 卷第 6 章接上定时任务，让新单据丢进收件箱就自动处理；按第 8 卷第 8 到第 10 章换一套 schema，同一台机器做合同、物流单或者旧档案；按第 8 卷第 11 章把台账接进客户已有的系统——**那一项记得单独报价。**
