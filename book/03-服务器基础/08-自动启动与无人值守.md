# 08　自动启动与无人值守

## 这一章的任务

拔掉电源，再插上，什么都不做，两分钟之后从笔记本连过去——SSH 能进、面板能开、共享文件夹能连、Tailscale 在线。

这一章要解决的是第 1 章说的第三件事：**你不在的时候，没人给它按开机键，也没人替它把服务拉起来。**

做完这一章，这台机器就可以塞进角落了。

## 开始前

- 第 2 卷[第 6 章](../02-Ubuntu/06-进程与服务.md)的 `systemctl` 五个动作会用；
- 第 2 卷[第 8 章](../02-Ubuntu/08-定时任务.md)的定时任务、[第 9 章](../02-Ubuntu/09-Docker.md)的容器已经在跑；
- 第 4 章的远程登录可用，最后一节要从笔记本远程验证；
- 能接上显示器和键盘，改 BIOS 那一节要用；
- 一小时，其中大半在等机器重启。

## 新词

**无人值守**：机器长期运行，出了状况自己处理，不需要人在旁边。这一章的目标就是它。

**来电自启**：主板固件里的一个设置。市电断了又来，机器自己开机，不用人按电源键。**这一项不在 Ubuntu 里，在 BIOS 里**，系统装得再好，这一项没开，停电之后机器就一直躺着。

**睡眠**（Suspend）：把当前状态存进内存，关掉屏幕和大部分硬件，按一下键盘就醒。省电，醒得快，但内存要一直供电，断电就全丢了。

**休眠**（Hibernate）：把内存里的内容整个写进硬盘，然后彻底关机。断电不丢，但醒来慢。

**这两样对服务器都是灾难**：机器睡着的时候网络是断的，你从外面连它，看到的就是“连不上”，跟关机没区别。桌面版 Ubuntu 默认闲一段时间就会睡。

**目标**（Target）：systemd 里表示“系统要进入哪种运行状态”的东西。`graphical.target` 是带图形桌面，`multi-user.target` 是只有命令行。开机默认进哪个，可以改。

## 三条自启的路

一台机器上的服务分三类，各走各的路，机制不一样。这三条第 2 卷都讲过，这一章不重讲，只教你把三条路各查一遍，确认都是通的。

| 类型 | 靠什么自启 | 在哪一章讲过 |
| --- | --- | --- |
| systemd 服务 | `systemctl enable` | 第 2 卷[第 6 章](../02-Ubuntu/06-进程与服务.md) |
| Docker 容器 | `--restart unless-stopped` | 第 2 卷[第 9 章](../02-Ubuntu/09-Docker.md) |
| 定时任务 | cron 本来就是开机自启的 | 第 2 卷[第 8 章](../02-Ubuntu/08-定时任务.md) |

### 一、查 systemd 服务

一条命令把这台机器上关键的几个一次问完：

```bash
systemctl is-enabled ssh docker smbd tailscaled cron
```

作用：逐个回答这几个服务开机自启是开还是关。正常输出五行：

```
enabled
enabled
enabled
enabled
enabled
```

**`enabled` 就是开着的。** 某一行是 `disabled`，把它打开，比如 Samba 那个：

```bash
sudo systemctl enable smbd
```

某一行报 `Failed to get unit file state`，说明那个服务根本没装。前面几章没做的部分会这样，正常，跳过它。

> `ssh` 那一行有可能是 `alias` 或者 `masked` 之类的字样，新版 Ubuntu 把 SSH 改成了按需启动，第 4 章说过。判断它通不通，以 `ss -tln | grep :22` 和实际能不能连上为准。

要看全部开机自启的服务，用第 2 卷第 6 章那条命令的变体：

```bash
systemctl list-unit-files --type=service --state=enabled
```

输出一屏，按 `q` 退出。**眼生的不要关**，第 2 卷第 6 章那句话仍然有效。

### 二、查 Docker 容器

一条命令列出所有容器和它们各自的重启策略：

```bash
docker inspect -f '{{.Name}} {{.HostConfig.RestartPolicy.Name}}' $(docker ps -aq)
```

正常输出一行一个容器：

```
/uptime-kuma unless-stopped
```

**要的是 `unless-stopped`。** 显示 `no` 的容器，机器重启之后不会自己回来。

改一个已经跑着的容器，不用删了重建：

```bash
docker update --restart unless-stopped 容器名
```

作用：只改重启策略，容器照常跑，数据一点不动。

用 Docker Compose 起的那一套（第 2 卷[第 10 章](../02-Ubuntu/10-Docker-Compose.md)），在 `compose.yaml` 里每个服务下面写一行：

```yaml
    restart: unless-stopped
```

改完在那个目录里执行 `docker compose up -d` 让它生效。

再确认 Docker 本身是自启的——容器的重启策略是 Docker 执行的，Docker 自己没起来，一切免谈：

```bash
systemctl is-enabled docker
```

### 三、定时任务不用管

`cron` 是系统服务，开机自己起，你写进 `crontab` 的任务跟着就在。确认一下任务还在：

```bash
crontab -l
```

第 2 卷第 12 章那条每周备份、第 8 章那条整理下载目录，应该都在。

**有一件事要注意**：定时任务是按时间点触发的，不是按“开机后补跑”。凌晨 4 点的备份，机器那时候正好断着电，这一次就跳过了，不会等来电之后补一遍。要紧的任务别只安排一个时间点。

## 让它来电自己开机

上面三条路管的都是“开机之后”。**机器根本没开机的话，三条路一条都用不上。**

停电之后来电，绝大多数机器的默认行为是**保持关机**，等人按电源键。要改这个行为，得进 BIOS。

### 进 BIOS

关机，接上显示器和有线键盘，按电源键，出现品牌 Logo 时连按对应按键。完整做法见[第 4 卷第 7 章](../04-Max395硬件/07-BIOS入口.md)，那一章还写了进不去时怎么办。

### 找哪一项

这一项各家叫法不同，**按功能找，别按名字硬对**。常见的写法有这么几种：

- Restore on AC Power Loss
- AC Power Loss / After Power Failure
- Power On After Power Fail
- State After Power Failure
- AC Recovery
- State After G3

它的可选值通常是三个：

| 值 | 意思 |
| --- | --- |
| `Power On` / `Always On` | 来电就开机。**服务器选这个** |
| `Last State` | 恢复断电前的状态。断电前开着就开，断电前关着就还是关着 |
| `Power Off` / `Stay Off` | 来电不开机，等人按电源键。这通常是出厂默认值 |

`Last State` 也能用，但有个坑：你哪天主动关机之后遇上停电，来电它就不开了。**选 `Power On` 最稳**。

### 分品牌线索

| 品牌 | 选项常见叫法 | 常见位置 |
| --- | --- | --- |
| GMKtec EVO-X2 / EVO-X3 | Restore AC Power Loss、State After G3 | `Advanced` → `ACPI Settings`，或 `Chipset` 下面 |
| Beelink GTR9 Pro | Restore AC Power Loss、Power On After Power Fail | `Advanced` → `ACPI`，或 `Chipset` 下面 |
| Framework Desktop | Power On AC Attach、After Power Failure | `Advanced` 或独立的 `Power` 菜单 |
| HP ZBook Ultra G1a | 笔记本形态，通常没有这一项 | 见下面一段 |
| 其他品牌 | AC Recovery、After Power Failure、State After Power Failure | `Advanced`、`Chipset`、`Power` 三个菜单里挨个翻 |

**这张表是线索，不是保证。** 选项名和菜单位置由整机厂决定，同一个品牌不同固件版本也会变，本项目未逐机型实测。三个菜单都翻遍还是找不到，去品牌官网的支持页下载你这个型号的说明书，搜 “power loss” 或者 “power fail”。

**HP ZBook Ultra G1a 这类笔记本形态的机器**，本来就带电池，短时间停电它自己顶过去了，等于不需要这一项。停电时间长到电池耗尽，多数笔记本的默认行为是来电后不自动开机，BIOS 里也未必给你改的余地。拿笔记本当长期服务器的话，这一条要提前接受。

**说明书里也没有的机器，就是不支持。** 这不是你操作的问题，接一个 UPS（不间断电源）可以绕过去，让机器在停电的那几分钟里根本不断电。UPS 属于采购的事，本教材不展开。

### 改完保存

找到之后改成 `Power On`，按 `F10` 保存退出（各家按键见第 4 卷第 7 章）。机器会重启一次。

**改 BIOS 之前先用手机把那一屏拍下来。** 第 4 卷第 7 章那条规矩这里同样适用，一次只改一项，改坏了照着照片改回来。

## 关掉睡眠和休眠

桌面版 Ubuntu 默认闲一段时间就睡。**机器一睡，网络就断，你在外面看到的和它关机了一模一样。**

### 图形界面里关

有桌面的话，这条路最直观：

1. 点右上角状态菜单，选“设置”；
2. 左边选“电源”；
3. 找到“自动挂起”，把它关掉；
4. 顺手把“息屏”设成“从不”——屏幕黑不黑不影响服务，但省得你以为机器死了。

### 命令行里彻底关掉

图形界面那一项管的是“闲置多久之后睡”。要连别的程序主动让它睡这条路也堵上，用这一条：

```bash
sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target
```

作用：把这四种“睡”的方式全部封掉，之后谁来叫它睡都叫不动。输出四行 `Created symlink ...`。

**这台机器以后不会再睡了。** 想退回去的话：

```bash
sudo systemctl unmask sleep.target suspend.target hibernate.target hybrid-sleep.target
```

验证一下：

```bash
systemctl status sleep.target
```

输出里有 `Loaded: masked`，就是封住了。

## 关掉图形界面（可选）

这一节是可选的，跳过不影响后面任何一章。

桌面环境一直占着一两 GB 内存和一部分显存。这台机器以后靠远程管，屏幕上那个桌面没人看。第 6 卷跑本地模型的时候，显存是要抠着用的，这部分能省下来。

**代价是以后没有桌面了。** 第 3 章图形界面改网络那条路、第 4 卷有些要在桌面上看的东西，都得换成命令行。**不确定要不要关的，先跳过这一节，等第 6 卷嫌内存紧张了再回来。**

先看现在是什么状态：

```bash
systemctl get-default
```

输出 `graphical.target`，就是开机进桌面。

改成只进命令行：

```bash
sudo systemctl set-default multi-user.target
```

输出一行 `Created symlink ...`。**这条命令不会立刻关掉桌面**，下次开机才生效。

```bash
sudo reboot
```

重启之后屏幕上是一个黑底白字的登录提示，没有桌面。SSH、Docker、Samba、Tailscale 全都照常跑，一个都不受影响。

**要把桌面找回来**：

```bash
sudo systemctl set-default graphical.target
sudo reboot
```

只想临时开一次桌面、不改默认值：

```bash
sudo systemctl start graphical.target
```

关掉桌面之后，机器空出来多少内存，用第 2 卷第 6 章那条命令看：

```bash
free -h
```

`available` 那一列比关之前多出来的，就是省下的。

## 真的拔一次电

前面全部是配置。**没试过的自启不算自启**，现在动手验一次。这是这一章唯一真实的验收。

> **拔电对正在写盘的程序是硬中断。** 先看一眼没有正在跑的备份、没有正在传的大文件；跑着数据库的机器（第 2 卷第 10 章那套），先 `cd` 进项目目录执行 `docker compose stop` 把它停干净，验收完再 `docker compose start` 起回来。

### 第一步，记下现在有什么

在 Mini PC 上执行，把输出抄下来或者截个图：

```bash
docker ps --format '{{.Names}}\t{{.Status}}'
systemctl is-active ssh smbd tailscaled
tailscale ip -4
```

这是断电之前的样子，一会儿要拿它对照。

### 第二步，拔

**直接拔插座，不要用 `sudo poweroff`。** 用命令关机是正常关机，来电自启那一项根本不参与，试不出东西来。要模拟的就是停电。

拔掉电源线或者关掉插排。机器的灯全灭。

等 30 秒。

### 第三步，来电

把电源插回去。**不要按电源键。**

BIOS 那一项设对了的话，机器自己就启动了——风扇转起来，指示灯亮。**按了电源键就白试了**，那样测的是你手动开机。

插上之后机器没反应，等 10 秒还是没反应，那就是 BIOS 那一项没生效，回上面那一节重新找。找不到就先按电源键把它开起来，往下的验证照做，只是以后停电要有人去按一下。

### 第四步，等两分钟

从来电到服务全起来，一般是一到两分钟：固件自检、系统启动、Docker 起来、容器一个个拉起来。

这段时间不要碰它。

### 第五步，在笔记本上验

**全程在笔记本上做，不要走到机器跟前。** 这一章的目标就是不用走过去。

```bash
ping -c 3 192.168.1.50
```

通了说明系统起来了、网络也起来了，固定地址还是它。

```bash
ssh minipc
```

进得去说明 SSH 服务自己回来了。

进去之后，把第一步那三条再跑一遍：

```bash
docker ps --format '{{.Names}}\t{{.Status}}'
systemctl is-active ssh smbd tailscaled
tailscale ip -4
```

**容器列表要和断电之前一样**，`Status` 那列是 `Up 几分钟`；三个服务都是 `active`；Tailscale 那个地址一个字没变。

再从浏览器打开面板 `http://192.168.1.50:3001`，页面在、数据在。

最后拿手机试一次第 6 章那条外网的路，`http://100.101.102.103:3001`。

**这六项全过，这台机器就能塞进角落了。**

有哪一项没过：容器没起来看 `--restart` 那一列，服务没起来看 `systemctl is-enabled`，机器压根没开看 BIOS 那一项。都对不上的话，到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。

## 事实来源和版本日期

- 来电自启选项的名称和菜单位置由整机厂决定，随固件版本变化，上面那张分品牌线索表来自项目补充材料与各品牌的通行做法，**本项目未逐机型实测，需要核验**，以你机器随附的说明书或品牌官网支持页为准；
- `systemctl mask` 封锁 sleep 相关 target 的做法适用于当前的 systemd，`unmask` 可以完整还原；
- 不同机器从来电到服务全部就绪的时间不同，一到两分钟是常见范围，容器多、镜像大的机器会更久；
- 本章核验日期：2026-08-14。

## 完成检查

- 三类服务各靠什么自启？三条路你都查过一遍了吗？
- `docker inspect` 那条命令列出来的容器，重启策略都是 `unless-stopped` 吗？
- 已经在跑的容器要改重启策略，需要删了重建吗？
- 来电自启这一项在哪里设？为什么在 Ubuntu 里找不到？
- 它的三个常见取值分别是什么意思？为什么推荐 `Power On`？
- 你这台机器的 BIOS 里，这一项叫什么名字，在哪个菜单下？
- 服务器为什么不能睡？关掉睡眠用的是哪条命令，怎么还原？
- 关掉图形界面之后，SSH 和 Docker 还能用吗？怎么把桌面找回来？
- 拔电测试的时候，为什么不能用 `sudo poweroff`？来电之后为什么不能按电源键？
- 拔电重启之后，你是走到机器跟前验的，还是在笔记本上验的？
