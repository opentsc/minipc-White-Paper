# 04　Open WebUI

## 这一章的任务

在浏览器里和模型对话，界面和你用过的那些聊天网站差不多。家里人各有各的账户，各自的对话记录互不打扰。

这是主线上最见效的一步——**做完这一章，这台机器对使用它的人来说就是一个网站，不再是一台要敲命令的服务器。**

## 开始前

- 第 3 章做完，`ollama run` 能对话，`ollama ps` 里是 `100% GPU`；
- [第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)的 Docker 装好了，不加 `sudo` 能跑 `docker ps`。**那一章的五个参数这一章直接用，不重讲**；
- [第 3 卷第 3 章](../03-服务器基础/03-固定IP.md)的固定地址在手上；
- [第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)的 ufw 开着（没做那一章的话，本章有一小节可以跳过）；
- 40 分钟，第一次拉镜像慢一些。

## 新词

**Open WebUI**：一个网页版的聊天界面，自己不跑模型，把请求转给后面的 Ollama。多用户、有账户体系、能存对话记录。

**宿主机**（Host）：跑着 Docker 的这台机器本身（[第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)新词）。这一章反复要处理的就是“容器里面”怎么找到“容器外面这台机器”。

## 先让 Ollama 能被容器连到

**这一步不做，后面界面能打开但一个模型都看不到。**

第 3 章装完 Ollama，它的接口开在 `127.0.0.1:11434`。`127.0.0.1` 的意思是“只有这台机器自己能连”。**容器有它自己独立的一套网络**（[第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)新词），从容器里看，`127.0.0.1` 指的是容器自己，不是你的 Mini PC。所以容器连不上它。

改法是让 Ollama 也在别的地址上监听。用第 3 章那套动作：

```bash
sudo systemctl edit ollama
```

在两行注释之间填：

```ini
[Service]
Environment="OLLAMA_HOST=0.0.0.0"
```

保存退出，然后让它生效：

```bash
sudo systemctl daemon-reload
sudo systemctl restart ollama
```

**第 3 章设 `OLLAMA_MODELS` 的话，两行写在同一段 `[Service]` 下面**，一行一个 `Environment=`，不要写成两段。

确认：

```bash
ss -tln | grep 11434
```

作用：看 11434 这个端口现在开在哪个地址上（[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)用过这条命令）。

正常输出里 `Local Address` 那一列是 `0.0.0.0:11434`。**还是 `127.0.0.1:11434` 的话，上面那段配置没生效**，回去看是不是写在了注释外面。

> **`0.0.0.0` 意味着同一个局域网里任何设备都能无密码调用你的模型。** 家里或者可信的内网可以这么开，**不要把 11434 这个端口开到公网上**。第 5 章会把这件事和防火墙一起讲清楚。
>
> 想紧一点的话，可以只让它在 Docker 那个内部网络的地址上监听，把 `0.0.0.0` 换成 `ip a show docker0` 里看到的那个地址（多数机器上是 `172.17.0.1`）。**这样局域网里的设备就直接调不到 Ollama 了**，只有容器能。第 5 章那条路仍然走得通，因为家里人是从 Open WebUI 进来的，不是直接找 Ollama。

## 防火墙那一关

[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)把入站默认设成了拒绝。**容器去找宿主机的 11434，对宿主机来说也是入站**，会被 ufw 挡下来。

先看 Docker 那个内部网络的网段：

```bash
ip a show docker0
```

输出里 `inet` 后面那一段，多数机器上是 `172.17.0.1/16`。

放行它：

```bash
sudo ufw allow from 172.17.0.0/16 to any port 11434 proto tcp
```

作用：只允许从 Docker 内部网络来的连接访问 11434。写法和[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)那条放行监控面板的一模一样，只是把 `from` 后面换成了 Docker 的网段。

**没装 ufw 的跳过这一节。** 上面 `ip a show docker0` 看到的网段和 `172.17.0.0/16` 不一样的，按你看到的那个填。

## 起容器

先建目录：

```bash
mkdir -p ~/ai/projects/open-webui/data
```

一个项目一个目录，[第 2 卷第 1 章](../02-Ubuntu/01-桌面与文件.md)的约定。

然后是这一章的主命令：

```bash
docker run -d \
  --name open-webui \
  --restart unless-stopped \
  -p 3080:8080 \
  --add-host=host.docker.internal:host-gateway \
  -e OLLAMA_BASE_URL=http://host.docker.internal:11434 \
  -v "$HOME/ai/projects/open-webui/data:/app/backend/data" \
  ghcr.io/open-webui/open-webui:main
```

整段复制粘贴，最后回车。第一次要下镜像，几 GB，看网速。

前面四个参数[第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)已经讲透了，这里只说这一章特有的三处。

**`-p 3080:8080`。** 冒号后面的 8080 是 Open WebUI 在容器里监听的端口，这是它自己定的，不能改。冒号前面的 3080 是你在浏览器里输的，这个你自己挑。

**这里不能用 3000。** [第 2 卷第 10 章](../02-Ubuntu/10-Docker-Compose.md)那个 Gitea 已经占了宿主机的 3000，3001 是[第 9 章](../02-Ubuntu/09-Docker.md)那个监控面板。**官方文档的例子映射到 3000，照抄会撞车**，表现是 `docker run` 直接报端口已被占用。挑一个没人用的就行，本教材用 3080。

不确定某个端口有没有被占，跑一句 `ss -tln | grep :3080`，没有输出就是空着的。

**`--add-host=host.docker.internal:host-gateway` 加上 `-e OLLAMA_BASE_URL=http://host.docker.internal:11434`。** 这两个是一对，合起来解决上一节那个问题。

- 第一个给容器里加了一条记录：`host.docker.internal` 这个名字指向宿主机；
- 第二个告诉 Open WebUI 去哪儿找 Ollama。`-e` 是往容器里传配置，[第 2 卷第 10 章](../02-Ubuntu/10-Docker-Compose.md)里 `compose.yaml` 的 `environment` 就是它。

**这一对不通的话，换成写死地址**——把 `--add-host` 那行去掉，`OLLAMA_BASE_URL` 换成[第 3 卷第 3 章](../03-服务器基础/03-固定IP.md)那个固定地址：

```text
-e OLLAMA_BASE_URL=http://192.168.1.50:11434
```

地址换成你自己那个。固定地址就是为这种时候准备的——**它不会变，写进配置是安全的**。

**`-v "$HOME/ai/projects/open-webui/data:/app/backend/data"`。** 容器往 `/app/backend/data` 写的东西落在你硬盘上那个目录里。**账户、对话记录、上传的文件全在这里**，删了容器也不会丢（[第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)验证过这件事）。

> 官方文档的例子用的是 Docker 的命名卷，那种卷落在系统盘一个很深的目录里。**本教材一律用目录映射**，落在 `~/ai/projects` 下面，理由是[第 2 卷第 12 章](../02-Ubuntu/12-日常备份.md)那套备份直接就能覆盖到它。

**最后一行 `ghcr.io/open-webui/open-webui:main` 是镜像和标签。** `main` 这个标签跟着上游滚动，今天拉和下个月拉不是同一份。**要固定版本，去镜像仓库页面挑一个带版本号的标签**，[第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)讲过为什么本教材一律写明标签。**当前可用的标签需要核验**，以你部署当天官方文档和镜像页面上的为准。

### 国内拉镜像慢

`ghcr.io` 在国内经常很慢或者直接连不上。两条路：

**一、配镜像加速。** 编辑 `/etc/docker/daemon.json`（没有就新建），填上你找到的加速地址，然后 `sudo systemctl restart docker`。**加速站的可用性变化很快，本教材不写具体地址**，用之前自己试一下通不通。

**二、找一台网络通的机器搬过来。** 这条最稳：

```bash
# 在网络通的那台机器上
docker pull ghcr.io/open-webui/open-webui:main
docker save ghcr.io/open-webui/open-webui:main -o open-webui.tar

# 把 open-webui.tar 拷到 Mini PC 上，然后在 Mini PC 上
docker load -i open-webui.tar
```

`docker save` 把镜像导成一个文件，`docker load` 再读回来。文件几 GB，用 U 盘或者[第 3 卷第 5 章](../03-服务器基础/05-文件传输.md)那套办法拷。载入之后原样执行上面那条 `docker run`，它本地已经有镜像，不会再去下。

## 看它起来没有

```bash
docker ps
```

`STATUS` 那列是 `Up` 加上跑了多久就对了（[第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)）。

第一次启动它要初始化，可能要等一两分钟。**页面打不开先看日志**：

```bash
docker logs --tail 50 open-webui
```

这是容器出问题时的第一条命令，[第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)讲过。

## 第一次打开

在 Mini PC 自己的浏览器里输：

```text
http://localhost:3080
```

第一次打开是一个注册页面。

**第一个注册的账户自动成为管理员。** 所以这一步必须是你自己来，填你自己的名字、邮箱和密码。

> **这个密码是你新设的，和系统账户、和 Ollama 都没有关系。** 记进密码管理器（[第 0 卷第 8 章](../00-使用说明/08-文件保护.md)）。这个账户能建人、删人、改所有设置。

注册完直接进主界面。

**左上角有一个模型选择框**，点开，应该能看到 `ollama list` 里那几个模型，包括第 3 章导进去的 `qwen3.6-35b`。

**一个模型都看不到**，说明它没连上 Ollama。按这个顺序查：

1. `ss -tln | grep 11434` —— 是 `0.0.0.0:11434` 吗？还是 `127.0.0.1:11434`？
2. `docker logs --tail 50 open-webui` —— 日志里有没有连接被拒绝之类的行；
3. ufw 那条规则加了没有；
4. 都对还是不行，把 `OLLAMA_BASE_URL` 换成上面那个固定地址的写法，重建容器。

**改了 `docker run` 的参数要怎么生效**：不是 `restart`，是停掉、删掉、用新参数重新 `run`：

```bash
docker stop open-webui
docker rm open-webui
```

然后把改好的那条 `docker run` 再跑一遍。**数据在 `-v` 那个目录里，删了重建不会丢**，账户和对话记录都还在（[第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)验证过）。

## 界面怎么用

三件事就够日常了。

**选模型。** 左上角那个框，点开挑一个。**每次新建对话都可以换**，同一个界面里几个模型随便切，第 7 章讲怎么按用途挑。

**新建对话。** 左边栏顶上那个新对话按钮。**一次对话就是一个话题**，换个话题就新建一个，别在同一个对话里从头聊到尾——上下文越长模型越慢（第 1 章讲过 KV cache），也越容易被前面的内容带偏。

**历史记录。** 左边栏列着以前的对话，点进去接着聊。想删就在那一条上找删除。**这些记录存在你自己的硬盘上**，不上传到任何地方。

界面上还有一堆别的东西，先不用管。用得上的后面各章会点到。

## 给家里人建账户

回到你自己那个管理员账户，进管理员面板，找到用户那一页。

**两种给法：**

**一、让他们自己注册，你来放行。** 把 `http://192.168.1.50:3080` 发给他们（第 5 章会讲怎么在手机上打开），他们自己填注册表。**新注册的账户默认进不去**，要在管理员面板里把状态改成通过，才能用。

**二、你直接建。** 在用户那一页上直接新建，填好名字和密码给他们。

**角色那一栏保持默认的普通用户，不要给管理员。** 管理员能改所有人的设置、能看后台，家里人不需要。

> **各个账户之间的对话记录是分开的**，你看不到他们的，他们也看不到你的。这是这一章值得做的主要理由之一——共用一个账户的话，所有人的记录混在一起。
>
> 新注册要不要审批、默认给什么角色，这些都在管理员面板的设置里，**具体项目名和默认值随版本变化，需要核验**，以你打开时看到的为准。

## 数据在哪，怎么备

```bash
ls -lh ~/ai/projects/open-webui/data
```

里面有一个数据库文件和几个目录。**账户、密码、全部对话记录、上传的文件，都在这儿。**

这个目录在 `~/ai/projects` 下面，[第 2 卷第 12 章](../02-Ubuntu/12-日常备份.md)那套定时备份的范围里已经包含它了——**不用另外配，那一章做过就已经在备了**。

两句补充：

- **想要一份干净的备份**，备之前先 `docker stop open-webui`，备完再 `docker start open-webui`。容器跑着的时候数据库正在被写，直接复制出来的那一份可能不完整；
- 这个目录里的文件属主可能是 `root`，和[第 2 卷第 10 章](../02-Ubuntu/10-Docker-Compose.md)里那个数据库目录一样。**看不进去是正常的，不是故障**，备份的时候用 `sudo` 跑。

**第一次备完，试一次还原。** [第 2 卷第 12 章](../02-Ubuntu/12-日常备份.md)那一节的要求在这里同样成立——没还原过的备份不算备份。

## 事实来源和版本日期

- 官方镜像为 `ghcr.io/open-webui/open-webui:main`、容器内监听 8080、数据卷挂在容器内的 `/app/backend/data`、连别处的 Ollama 用 `OLLAMA_BASE_URL`：[Open WebUI 快速开始文档](https://docs.openwebui.com/getting-started/quick-start/)，访问日期 2026-08-14，厂商官方文档，事实状态 `official_source`。**`main` 是滚动更新的标签，不是固定版本号；当前可用的版本标签需要核验**；
- `ENABLE_OLLAMA_API` 与 `OLLAMA_BASE_URL` 控制请求路由：[Open WebUI 环境变量配置文档](https://docs.openwebui.com/reference/env-configuration/)，访问日期 2026-08-13，厂商官方文档，**部分变量只在初次启动时读取**，事实状态 `official_source`；
- **`--add-host=host.docker.internal:host-gateway` 这个写法**：属 Docker 让容器找到宿主机的通用做法，**本项目未在这台设备上实测，需要核验**。不通时改用[第 3 卷第 3 章](../03-服务器基础/03-固定IP.md)那个固定地址；
- **管理员面板里新用户审批与默认角色的项目名和默认值**：随 Open WebUI 版本变化，**本项目未固定，需要核验**，以界面上实际看到的为准；
- **`OLLAMA_HOST=0.0.0.0` 让 Ollama 监听全部地址、`ss -tln` 里从 `127.0.0.1:11434` 变成 `0.0.0.0:11434`**：素材记录，本项目未在这台设备上实测，**需要核验**；
- 用 `systemctl edit ollama` 或者 `/etc/systemd/system/ollama.service.d/` 下的覆盖文件给服务设环境变量：[Ollama Linux 安装文档](https://docs.ollama.com/linux)，访问日期 2026-08-14，厂商官方文档，事实状态 `official_source`；
- Docker 用 `-p` 发布的端口不受 ufw 的规则约束、要管住得在 Docker 这一层限定绑定地址：[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)已写全，**第 5 章接着用，本章不重讲**；
- Docker 的五个基础参数、目录映射的意义、改参数之后怎么让它生效：[第 2 卷第 9 章](../02-Ubuntu/09-Docker.md)与[第 10 章](../02-Ubuntu/10-Docker-Compose.md)已写全，**本章不重讲**；
- `docker0` 的默认网段、`docker save` 与 `docker load` 的行为：属 Docker 的通用行为，未针对本项目设备单独实测。**你机器上的网段以 `ip a show docker0` 的输出为准**；
- 国内镜像加速地址：**本教材不写具体地址**，这类站点的可用性变化很快；
- 事实状态标记的含义见[证据与发布规则](../../reference/证据与发布规则.md)；
- 本章核验日期：2026-08-14。
