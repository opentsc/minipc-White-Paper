# 13　方向篇：采购审核

## 这一章的任务

**先把这一章的性质说清：这是一篇方向篇，不是一个案例。**

前面十二章，每一章做完你手上会多一样能跑的东西。**这一章不会。**

**理由只有一条**：采购审核这件事，**规则全长在具体那家公司的制度里，公开渠道拿不到一份能当范本的**。本项目手上的素材够写清这条路怎么搭、坑在哪儿、要问客户什么，**不够写出一条照抄能跑的流程**——写出来那份东西会是编的，而它一旦被人拿去用在真的付款流程上，**代价是钱。**

**所以这一章给四样：**

- **这条路的三段结构**，每一段各接前面哪一章；
- **这类流程和前面三个案例不一样的地方**——它每一步都要留证据，错了直接是钱；
- **要做的话该问客户哪几个问题**，一张单子，问不完不要开工；
- **一个最小可行的起点**——不做“判断能不能过”，只做“挑出异常的”。

**这一章最后那条边界是硬的，先写在这儿**：

> **审核结论必须人签字。机器只做初筛和标红。**

## 开始前

- [第 8 卷](../08-OCR/README.md)做完，**一沓单据跑进去出一张台账**，字段是你自己定的，错的被挑到复核队列上；
- [第 7 章](07-案例二-进件分类.md)和[第 8 章](08-案例二-结果台账.md)做完，**文件夹进件、模型判断、结果落成一行台账**这条路你跑通过；
- [第 10 章](10-案例三-人工确认.md)那张六条清单读过。**这一章第一条“发钱”从头到尾在场**；
- [第 11 章](11-日志与重试.md)做完，执行记录会看。**这条线上“某一天悄悄没跑”的代价比前面几条都大**；
- **不需要 90 分钟。这一章没有动手的部分**，读完加上把最后那张单子抄走，40 分钟。

## 新词

**单据**：**采购这条线上流转的那些纸和文件**——请购单、报价单、采购订单、送货单、验收单、发票、付款申请。[第 8 卷](../08-OCR/README.md)整卷在讲怎么把它们变成字段。

**规则**：**一句能判真假的话。** “单笔超过五万要走招标”“这家供应商不在白名单里”“这笔费用没有对应的预算科目”，**每一条都能判出对错，不需要模型。**

**阈值**：**规则里那个数。** 五万、三家比价、超预算 10%，**这些数字是客户内部定的，本教材一个都不给。**

**白名单**：**允许的那份清单。** 供应商白名单、可用的预算科目、有权审批的人。[第 9 章](09-案例三-邮件草稿.md)那个 `允许的发件人` 是同一个东西。

**初筛**：**先挑一遍，把要人看的挑出来。** 这一章允许机器做的全部工作。

**标红**：**挑出来之后，在旁边写清楚哪儿不对。** **不是写“有问题”，是写“单笔 68,000 元，超过了 50,000 元这条线”**——这一条[第 8 卷第 7 章](../08-OCR/07-错的怎么拦.md)立过规矩。

**留痕**：**这一步是谁在什么时候做的、依据是什么，事后查得到。** 采购这条线上，**留痕本身就是交付物的一部分**，不是附赠的。

## 这条路长什么样

**三段，每一段前面都讲过。**

```text
一、单据变成字段
    第 8 卷那条流水线。一份采购申请、一张发票、一份合同，
    进去是扫描件，出来是一组字段：供应商、金额、日期、科目、经办人。

        ↓

二、规则一条一条过
    这一章的正题。金额阈值、供应商白名单、预算科目、必要的附件齐不齐。
    每一条只判真假，判完记一句人话，说清哪儿不对。

        ↓

三、人签字
    第 10 章。机器把可疑的那些挑出来、标红、排好队，
    审核的人一份份看，签字的是人。
```

**三段里，第一段和第三段前面全写过了，这一章能写的只有中间那一段。**

**而中间那一段恰恰是没有通用版的那一段。**

## 为什么本教材不给完整实现

**三条理由，一条比一条硬。**

### 一、规则长在制度里，不长在技术里

**“单笔超过多少要走比价”——这个数是客户内部定的。**

不同的公司，这条线可能是三万、五万、十万；有的公司按金额分档，有的公司按物料类别分；有的公司这条线对固定资产和耗材是两套。**这不是本教材写不写得出来的问题，是它根本没有一个正确答案。**

**更要命的是同一家公司这条线还会变。** 换了财务总监、换了年度预算、上了新的 ERP，**规则跟着改一遍。**

**所以这一章要给的不是规则，是问出规则的办法**——下面那张单子。

### 二、这类流程的错，改不回来

**[第 10 章](10-案例三-人工确认.md)那句话在这里要加重一次。**

前面三个案例的错各有各的代价：日报摘歪一条，十秒；文件分错目录，三十秒；**一封信发出去，收不回来。**

**采购审核判错一笔，钱付出去了。**

**而且它有一个前三个案例都没有的性质**——**判错的方向有两个，两个方向的后果不一样，但都是钱：**

- **该拦的没拦住**——一笔不该付的款走完了流程。**这笔钱要追回来，而追回来这件事跟技术没关系了**；
- **不该拦的拦住了**——供应商的货款压了两周。**这一种看着轻，实际是客户业务上的损失**，而且它会让整套东西被弃用。

**前一种是这一章所有边界的来由。**

### 三、这条线上每一步都可能要拿出去给人看

**审计、内控、税务、上级单位检查。**

**意思是这条流程的产物不只是“结果对不对”，还包括“这个结果是怎么来的”**——哪一条规则命中了、当时那份单据长什么样、谁在什么时候看过、签的是谁的字。

**这一条改变了设计。** 前面三个案例里，执行记录是给你排查用的（[第 11 章](11-日志与重试.md)）；**这一条线上，那份记录是交付物。** 它的保留期限、里面能不能有客户的原始单据、谁能看，**都要在合同里写清楚**（[第 13 卷](../13-项目交付/README.md)）。

> **[第 11 章](11-日志与重试.md)那个保留策略在这一条线上要重新定一次。** 那一章说的是“执行记录会不会把硬盘堆满”；**这一条线上要先问的是“按客户的规矩，这些记录必须留多久”**，然后才轮到硬盘够不够。**这两件事的顺序不能反。**

## 风险边界

**这一节只有一条，但它压住整章。**

> **审核结论必须人签字。机器只做初筛和标红。**

**拆成三句，逐句写死：**

**一、机器不出“通过”这个结论。**

它可以输出“这一笔没有命中任何一条规则”，**不能输出“这一笔可以付”**。这两句话在字面上很接近，**在责任上差着一整条链子**。

**做法上的区别很具体**：台账里那一列写的是 `未命中规则`，**不是** `通过`。**这一个词的差别，交付的时候要专门讲一次。**

**二、机器不动金额，不动收款账号。**

[第 10 章](10-案例三-人工确认.md)那张清单第一条第六条，在这条线上是同一件事。**读出来的金额和账号只能原样带着走，不许算、不许改、不许补全。**

**读错了怎么办**——[第 8 卷第 7 章](../08-OCR/07-错的怎么拦.md)那套校验拦一道，拦不住的进复核队列，**人看。这一条不给机器留任何自动修正的口子。**

**三、签字这一步不接任何自动化。**

**不管客户的系统上那个“同意”按钮多好点。** 这条线上的最后一步永远是人在客户自己的系统里点，**你这套东西的产物到“一份标好红的清单”为止。**

**客户会问“能不能顺便帮我们把审批也点了”。** [第 10 章](10-案例三-人工确认.md)那条规矩原样搬过来——**没在清单上写明可以自动做的动作，一律先当成不能自动做**，要改就单独谈一次，**而这一件谈不下来的时候要能说不。**

## 要做的话，先问客户这几个问题

**这是这一章唯一能直接抄走的东西。**

**问不完不要开工。** 少问哪一条，那一条就会在做到一半的时候变成返工。

### 一、规则那一组

```text
1. 哪几类单据要过审核？（请购、订单、发票、付款申请，还是全部）
2. 每一类的必填字段是哪几个？缺一个算不算不通过？
3. 金额分几档？每一档的线是多少？这条线是含税还是不含税？
4. 有没有供应商白名单？它在哪儿？谁在维护？多久更新一次？
5. 预算科目从哪儿来？一笔费用对不上科目，是拦下来还是记一条？
6. 有没有“必须几家比价”这类规则？几家？谁来判断比价是不是真的？
7. 同一笔业务分几张单子报的（拆单），要不要拦？怎么认？
```

**第 7 条是这张单子里最容易被漏掉、也最容易做错的一条。** 认拆单要跨多份单据看，**它不是一条规则，是一类分析**，起步阶段先不做，**记下来当二期。**

### 二、边界那一组

```text
8. 判错了拦住一笔正常的款，谁受影响？他多久会发现？
9. 判错了放过一笔，你们现在靠什么发现？
10. 这套东西出的结论，在你们内部算什么？（参考意见，还是一道正式关卡）
11. 审计和内控要看什么？记录要留多久？
12. 谁能看到这些记录？我需不需要能看到？
```

**第 10 条决定了整个项目的性质。**

**答“参考意见”**——这单可以做，风险可控，**报价也低**。

**答“一道正式关卡”**——**先停下来。** 那意味着客户要把这套东西放进他们的内控流程里，**它要经得起审计问“这道关卡失效的时候你们怎么知道”。** 这是另一个量级的活，**没做过就别接**（[第 11 卷](../11-客户与报价/README.md)那条“接不接”的判断）。

**第 12 条要老实答。** 你要不要能看到客户的采购金额和供应商，**这件事在合同里写死**——[第 0 卷第 8 章](../00-使用说明/08-文件保护.md)那套，以及数据不出场所那一条（[第 13 卷](../13-项目交付/README.md)）。

### 三、现状那一组

```text
13. 现在这件事谁在做？一天几笔？一笔看多久？
14. 他现在是怎么看的？（对着哪几个系统、翻哪几份文件）
15. 最近半年有没有出过事？出的是哪一类？
16. 你们现在的单据，有多少是纸质的、多少是电子的？
```

**第 15 条问出来的东西最值钱。**

**客户答得出具体一件事**——比如“上个月有一笔重复付款”——**那就是这个项目的第一条规则**，而且验收的时候拿它当例子最有说服力。

**客户答“没出过事”**，两种可能：真没出过，或者**出了没发现**。后一种更常见，**而它正好是第 9 条要问的东西。**

> **这十六个问题不是需求调研模板，是一张“问完才知道能不能接”的单子。** 里面有几条的答案会让你直接说不接——**第 10 条答“正式关卡”是一条，第 16 条答“全是纸质的、每天两百笔”是另一条。**
>
> **能说不接，是这一章想给的东西之一。**

## 最小可行的起点

**问完了、也决定要做，从哪儿下手。**

**一句话：先只做“挑出异常的”，不做“判断能不能过”。**

### 这两件事差在哪

| | 挑出异常的（起步做这个） | 判断能不能过（不做） |
| --- | --- | --- |
| 机器输出什么 | **一张“这几笔要看”的清单** | 一个通过或者不通过的结论 |
| 规则要写多全 | **写几条算几条**，漏掉的那些照旧走人工 | **必须写全**，漏一条就是放过一笔 |
| 漏了一条规则会怎样 | 那一类照旧全部人工看，**和现在一样** | **那一类被自动放过了** |
| 客户内部要不要改流程 | **不用改**，人还是全看，只是先看红的那几笔 | 要改，而且要过内控 |
| 值不值钱 | **值**，它把“从头翻到尾”变成了“先看这五笔” | 值更多，风险也是另一个量级 |

**第三行是这一节的正题。**

**“挑出异常的”这种做法有一个性质：漏掉一条规则，后果是回到现状，不是造成损失。** 人本来就要全看，**机器只是把最可疑的排到了前面。**

**“判断能不能过”没有这个性质。** 它一旦上线，没被规则命中的就走过去了，**你漏掉的每一条规则都是一个洞。**

**所以起步阶段的正确做法是：机器不减少人的工作量，只改变人的工作顺序。**

**这句话要跟客户说清楚**，别让他以为第一期就能裁掉一个人。**说不清这句，第一个月客户就会失望**——[第 10 章](10-案例三-人工确认.md)做法一那条“交付的时候说错这句话”，是同一个坑。

### 起步的三条规则

**从最硬、最不会有歧义的三条开始，一条模型都不用调：**

**一、必填字段缺不缺。** 供应商、金额、日期、经办人，**缺一个就标红。** 这一条[第 8 卷第 7 章](../08-OCR/07-错的怎么拦.md)那套校验直接就有。

**二、金额过没过线。** 一个数一条规则，**判出来的结果没有任何解释空间。**

**三、供应商在不在白名单里。** 一份清单一条规则，**和[第 9 章](09-案例三-邮件草稿.md)那个 `允许的发件人` 是同一个写法。**

**这三条的共同点：全部能判真假，全部不需要模型，全部说得清为什么。**

**模型在这条线上做什么**——**做第一段，把扫描件变成字段**（[第 8 卷](../08-OCR/README.md)）。**规则这一段不要让模型判**，理由是[第 8 卷第 7 章](../08-OCR/07-错的怎么拦.md)那句话：**能用一条规则判死的事，不要交给一个会给出“另一个合法的值”的东西。**

### 起步的那段代码长什么样

**这一段是一个骨架，不是一份能跑的实现。** 阈值、白名单、字段名全部要换成客户那边的，**换之前它一行都不该上生产。**

```javascript
// 挑异常 —— 一笔一笔过规则，命中了就记一句人话
// 模式：每条各跑一次
// 这一段只挑出要人看的，不判断能不能付

// 一、下面这几行是要按客户制度改的，本教材不给任何数值 ——————————————
const 金额上线 = null;              // 例如 50000。填 null 表示这条规则不启用
const 供应商白名单 = [];            // 例如 ['某某科技', '某某贸易']。留空表示不启用
const 必填字段 = ['供应商', '金额', '日期', '经办人'];

// 二、一笔单据的字段，来自第 8 卷那条流水线
const 单 = $json;

// 三、一条一条过，命中的全部记下来，不像第 9 章那样撞上一条就停
const 命中 = [];

for (const 字段 of 必填字段) {
  const 值 = String(单[字段] ?? '').trim();
  if (!值) {
    命中.push(`必填字段“${字段}”是空的`);
  }
}

const 金额 = Number(String(单.金额 ?? '').replace(/[,，\s¥￥元]/g, ''));
if (!Number.isFinite(金额)) {
  命中.push(`金额读不成一个数：${单.金额}`);
} else if (金额上线 !== null && 金额 > 金额上线) {
  命中.push(`金额 ${金额}，超过了 ${金额上线} 这条线`);
}

if (供应商白名单.length > 0) {
  const 供应商 = String(单.供应商 ?? '').trim();
  if (供应商 && !供应商白名单.includes(供应商)) {
    命中.push(`供应商“${供应商}”不在白名单里`);
  }
}

return {
  json: {
    单号: 单.单号 ?? '',
    供应商: 单.供应商 ?? '',
    金额: 单.金额 ?? '',
    要人看: 命中.length > 0,
    // 注意这一列写的是“未命中规则”，不是“通过”
    结论: 命中.length > 0 ? '要人看' : '未命中规则',
    理由: 命中.join('；'),
    过规则的时间: new Date().toISOString(),
  },
};
```

**四处要说明。**

**一、命中了不停，全部记下来。**

[第 9 章](09-案例三-邮件草稿.md)那段筛邮件的代码是撞上一条就停，**这里正好相反**——审核的人要一次看到这笔单子全部的问题，**而不是修好一个又冒出来一个。**

**二、`金额上线` 的默认值是 `null`，不是一个数。**

**这是故意的。** 本教材不给这个数，**填不填是你去问客户的动作**（上面那张单子第 3 条）。**没填的时候这条规则不启用，而不是用一个默认值悄悄生效。**

**三、`结论` 那一列写的是 `未命中规则`。**

**这就是上一节那条边界在代码里的样子。** 有人会觉得这一个词太啰嗦，**改成 `通过` 更好看**——**改了这一个词，这条流程的性质就变了。**

**四、这段代码没有实跑过，属通行写法，需要核验。**

**更要紧的是**：**它是一个骨架**。真实的采购规则里有分档、有按物料类别分、有跨单据的判断，**那些都要在这个骨架上长出来，而怎么长取决于客户答的那十六个问题。**

### 起步之后怎么长

**顺序是这样的，一条一条加，不要一次上齐：**

1. **头两周只出清单，不进任何审批流程。** 让审核的人自己对着看——**机器挑出来的，是不是他本来也会挑出来的那几笔**；
2. **对得上，把清单接进他现在的工作方式**（发一封信、写一张表，[第 8 章](08-案例二-结果台账.md)那套）；
3. **他开始信这张清单之后**，再加规则。**每加一条，回头看两周**；
4. **加到他说“基本上我看的就是这几笔”，这一期就做完了。**

**不做的那些，写进二期**——拆单、跨单据比对、和客户的 ERP 对接。**每一项单独报价**（[第 17 章](17-这个能力怎么卖.md)）。

## 这一章能承诺什么，不能承诺什么

**能承诺的：**

- **这条路的结构是清楚的**，三段各接哪一章，正文写全了；
- **那十六个问题问完，你能判断这一单接不接**；
- **最小起点那条“只挑出异常的，不判断能不能过”，是一条能拿去跟客户谈的做法。**

**不能承诺的：**

- **本章没有一条可以照抄的规则**，一个阈值都没有；
- **本章那段代码没有实跑过**，而且它是骨架不是实现；
- **公开渠道里，这个方向本项目没有找到可核验的成交案例**，**也没有找到可以引用的定价参照**——[第 17 章](17-这个能力怎么卖.md)那张市场参照表里没有采购审核这一行。**这一条比[第 8 卷第 14 章](../08-OCR/14-按页计价.md)那几行还弱**；
- **本章不提供任何法律、财税与内控意见。** 内控要求、留档期限、审批权限怎么设，**以客户自己的制度和主管部门要求为准**。

> **一句实话放在这儿**：**这一章之所以是方向篇，不是因为写不动，是因为素材只到这儿。** 硬写一份完整实现出来，读者拿去接单，**出事的时候他手上那份规则是本教材编的。** 那个后果本教材承担不起，**所以停在这里。**
