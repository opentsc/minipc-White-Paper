# 06　Tailscale

## 这一章的任务

人在外面，用手机流量打开家里这台机器上的监控面板；用笔记本连着咖啡馆的 Wi-Fi，`ssh` 进去看一眼服务还在不在。

全程不碰路由器，不申请公网 IP，不在互联网上开任何一个端口。

做完这一章，这台机器对你来说就不再只是“家里那台”，走到哪儿它都在手边。

## 开始前

- 第 3 章做完，这台机器的地址已经固定；
- 第 4 章做完，在笔记本上敲 `ssh minipc` 能进去；
- 这台机器能正常上网，第 3 章验证过了；
- 一部手机，Android 或者 iPhone 都行；
- 一个能用来注册的账号。Tailscale 不自己发账号密码，它用你已有的 Google、Microsoft、GitHub、Apple 这类账号登录，挑一个你长期在用、自己拿得住的；
- 40 分钟。

## 新词

**公网 IP**：互联网上全球唯一的一个地址。有它，别人才能从外面直接找到你。家庭宽带多数情况下拿不到固定的公网 IP，运营商给的那个会变，有的地区干脆不给。

**NAT**：路由器把家里一堆设备藏在一个出口后面的做法。你从里面往外连没问题，外面的人主动往里连，找不到具体是哪一台。这就是为什么在外面直接输家里那个 `192.168.1.50` 打不开——**那是家里的门牌号，出了小区没人认**。

**端口转发**：在路由器上开一个洞，把公网上某个端口的流量转到家里某台设备的某个端口上。这是把服务开到互联网上的传统办法，本教材不用它，理由见下一节。

**虚拟组网**：让分散在各处的几台设备，像插在同一台交换机上一样互相看得见。它们之间的数据在互联网上走，但是加密的，中间的人看不到内容。

**Tailscale**：一个做虚拟组网的服务。你在每台设备上装一个客户端，用同一个账号登录，它们就自动组成一个只属于你的网络，互相之间能用一个固定地址连通。

**Tailnet**：你自己那张网的名字，也就是用同一个账号登录的所有设备构成的这一组。别人的设备进不来，你的设备也看不到别人的。

**MagicDNS**：Tailscale 提供的一个便利功能，让你用设备名而不是一串数字互相访问，比如直接写 `minipc`。

## 为什么不在路由器上开端口

这一卷不教端口转发，这一节说清楚原因。

端口转发是能用的：在路由器上把公网的 3001 端口转到 `192.168.1.50:3001`，你在外面输 `你的公网IP:3001`，面板就打开了。步骤不难，十分钟能配完。

代价是这个口对全世界开着。

**互联网上有大量程序，整天不做别的，就是把所有地址的常用端口挨个敲一遍。** 一个新开的端口，从开放到被第一次扫到，通常是几分钟到几小时。之后它会持续被访问，一天几百到几千次，全是自动的，跟你是谁、有没有名气没关系。

它们敲门是为了两件事：试弱密码，和试已知漏洞。你那个面板的管理员密码要是简单，几小时就试出来了；用的镜像版本要是有已知漏洞，对方连密码都不用试。真出了事，丢的是这台机器上的全部资料，而且这台机器还在你家的局域网里面，它能碰到的东西，对方也能碰到。

还有三件麻烦事：家庭宽带的公网 IP 会变，变了外面就打不开；很多地区的宽带压根不给公网 IP，转发配了也没用；换一个路由器，这套配置要重做一遍。

Tailscale 这条路，这三件麻烦事都没有，而且**对公网一个端口都不开**。外面的扫描程序看不到你的任何服务，因为根本没有对外监听的入口——所有设备都是主动往外连，在中间对上号。

真要把一个服务开给不特定的人用（比如做成对外的网站），那是第 10 卷的事，那时候的做法也不是端口转发，而是把服务放到一台本来就在公网上的机器后面。**家里这台机器，本教材从头到尾不直接暴露在公网上。**

## 在 Mini PC 上装 Tailscale

从笔记本 `ssh` 进去，或者直接在机器跟前做，都一样。

Tailscale 官方给了一条安装脚本：

```bash
curl -fsSL https://tailscale.com/install.sh | sh
```

作用：识别你的系统是 Ubuntu 哪个版本，把 Tailscale 的软件源加进来，然后装上。输出是一堆 `apt` 的正常刷新和安装信息，最后一行提示装完了。

这是第 2 卷[第 9 章](../02-Ubuntu/09-Docker.md)装 Docker 时那四步的自动版，做的事一样。

> **`curl ... | sh` 是把网上下载的脚本直接交给系统执行。** 只对你信得过的来源这么做，地址要看清楚是官方域名。不放心就先把脚本存下来读一遍再跑：`curl -fsSL https://tailscale.com/install.sh -o install.sh`，看完 `sh install.sh`。

装完确认一下：

```bash
tailscale version
```

输出两三行，第一行是版本号，就装上了。

## 让它加入你的网络

```bash
sudo tailscale up
```

作用：把这台机器连进你的 tailnet。第一次执行，它会打印一段话和一个网址：

```
To authenticate, visit:

	https://login.tailscale.com/a/xxxxxxxxxxxx
```

**这条命令会停在这里等你**，别按 `Ctrl+C`。

把那个网址复制到浏览器里打开——用笔记本的浏览器打开也行，网址是一次性的，跟在哪台机器上打开没关系。页面上选一个账号登录（第一次会让你注册，选 Google、Microsoft、GitHub 这些里的一个），登录之后点确认，把这台设备加进来。

回到终端，那条命令自己往下走了，打印 `Success.`。

看看现在的状态：

```bash
tailscale status
```

正常输出一行一台设备：

```
100.101.102.103  minipc               你的账号@      linux   -
```

四列分别是：**Tailscale 分配给它的地址**、设备名、属于谁、什么系统。

**记住第一列那个 `100.` 开头的地址，这一章后面全靠它。** 它和第 3 章那个 `192.168.1.50` 是两个地址，同时有效：在家里用 `192.168.1.50`，在外面用这个 `100.` 开头的。

也可以单独把它打出来：

```bash
tailscale ip -4
```

只输出一行，就是那个地址。

**这个地址是固定的**，机器重启、换网络、搬到别的城市，它都不变。这一点和第 3 章折腾半天才固定下来的局域网地址不一样，它天生就不变。

装好之后 Tailscale 是开机自启的，不用另外设置。第 8 章会再确认一次这件事。

## 把笔记本和手机也加进来

**一台设备只有加进同一个 tailnet，才能用那个 `100.` 开头的地址连它。** 所以笔记本和手机都要装。

**macOS**：去 Tailscale 官网的下载页，或者在 App Store 里搜 Tailscale，装完打开，用**同一个账号**登录。菜单栏出现一个图标，点开能看到设备列表。

**Windows**：去官网下载页拿安装包，双击装，登录同一个账号。托盘区出现图标，右键能看到设备列表。

**手机**：在手机的应用商店里搜 Tailscale 装上，登录同一个账号，把开关打开。iPhone 上会问要不要允许添加 VPN 配置，允许它——Tailscale 在手机上是用系统的 VPN 接口实现的，这一步是必须的。

**账号必须是同一个。** 用了另一个账号，那台设备会自己组一张空网，两边看不见对方，表现就是地址 ping 不通。

三台设备都加完之后，在 Mini PC 上再看一次：

```bash
tailscale status
```

现在应该是三行，每行一台设备，各有各的 `100.` 开头的地址。手机那行后面可能跟着 `idle` 或者 `offline`，手机屏幕黑着的时候会这样，是正常的，用的时候它自己就活了。

## 用这个地址连它

先在家里试一次，确认路走得通。

### SSH

在笔记本上：

```bash
ssh 你的账户名@100.101.102.103
```

地址换成你自己那个。第 4 章配的密钥照样管用——密钥认的是账户，不是地址。

第一次连会问一次指纹（第 4 章讲过），打完整的 `yes`。

进去之后照例确认一下自己在哪台机器上：

```bash
hostname
```

第 4 章给它起的别名 `minipc` 现在只对家里那个地址有效。再加一个走 Tailscale 的别名，在**笔记本上**打开那个配置文件：

```bash
nano ~/.ssh/config
```

在原来那段下面再加一段：

```
Host minipc-out
    HostName 100.101.102.103
    User 你的账户名
```

以后在外面就是 `ssh minipc-out`，在家里还是 `ssh minipc`。两个别名指向同一台机器的两个地址。

嫌麻烦的话，两个都用 Tailscale 那个地址也行——在家里它一样能连通，只是数据会绕一点点，日常用感觉不出来。

### 浏览器打开那个面板

第 2 卷第 9 章跑起来的监控面板，在家里的访问地址是 `http://192.168.1.50:3001`。换成 Tailscale 的地址：

```
http://100.101.102.103:3001
```

在笔记本浏览器里输这个，页面出来，就通了。

手机上也是同一个地址，在手机浏览器里输一遍，把它存成书签。

**注意是 `http` 不是 `https`**，这个面板没配证书，浏览器可能提示“不安全”。在 Tailscale 这条通道里，数据本身是加密的，这个提示说的是网页那一层。要给它配上证书，是第 10 卷的事。

### 手机上的 SSH

手机上装一个 SSH 客户端也能进去，安卓和 iPhone 上都有现成的应用。地址填那个 `100.` 开头的，账户填你的账户名。第 4 章关掉密码登录之后，手机上要能连就得把私钥导进那个应用里——**私钥导进手机之前先想清楚，那部手机丢了等于钥匙丢了**，做法和保管原则见[第 0 卷第 8 章](../00-使用说明/08-文件保护.md)，第 9 章还会再说一次密钥怎么管。

只是想看看服务在不在，用浏览器打开面板就够了，不用在手机上放私钥。

## 真的到外面试一次

在家里通了不算数——家里那些流量走的可能还是局域网。

**把手机的 Wi-Fi 关掉，只用流量。** 然后：

1. 确认手机上 Tailscale 的开关是打开的；
2. 浏览器里打开 `http://100.101.102.103:3001`；
3. 面板出来了，这一章就成了。

页面打不开的话，先看手机上 Tailscale 的开关是不是被系统省电策略关掉了，再看 Mini PC 上 `tailscale status` 里手机那一行在不在。

笔记本带出门也一样，接上外面的 Wi-Fi，`ssh minipc-out`，能进去就对了。

## 它是别人的服务

有三件事要说清楚。

**第一，它是第三方服务，要注册账号。** 你的设备列表、设备名、在线状态这些信息存在 Tailscale 那边。设备之间传的内容它看不到（那部分是端到端加密的），但“你有哪几台设备、什么时候在线”这类信息它是知道的。介意这个的话，有自建的同类方案，本教材不展开。

**第二，它有免费方案，个人用够。** 一个人几台设备，用免费方案没问题。具体的设备数上限、哪些功能要付费，以你注册当天官网价格页上写的为准，本教材不抄这些数字——它们会变。

**第三，它是一条依赖。** Tailscale 的账号登录服务出问题的时候，已经连着的设备之间通常还能继续通，但新设备加不进来。所以家里那个 `192.168.1.50` 别丢，它是不依赖任何外部服务的那条路。**两条路都留着。**

顺带一句：第 9 章要给这台机器装防火墙，那时候要单独给 Tailscale 这条通道放行，不然装完防火墙就从外面连不上了。那一章会写。

不想用了的话，在 Mini PC 上执行 `sudo tailscale down` 就断开了，机器上其他东西不受影响；要彻底不用，再去网页端的设备列表里把这台设备删掉。

有哪一步做不出来，到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。

## 事实来源和版本日期

- 安装命令 `curl -fsSL https://tailscale.com/install.sh | sh` 来自 Tailscale 官方文档的 Linux 安装说明，随文档更新可能变化，以你安装当天的官方页面为准；
- Tailscale 分配的地址在 `100.` 开头的那一段范围内，具体数字由服务端分配；
- 免费方案的设备数量和功能界线由 Tailscale 定，会变，以官网价格页当天的说明为准，本章不引用具体数字；
- 手机端要求允许添加 VPN 配置，这是 iOS 和 Android 的系统机制，各版本的提示文字不同，以你手机上实际看到的为准；
- 本章核验日期：2026-08-14。
