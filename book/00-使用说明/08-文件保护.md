## 新词

**密钥**（Key）：用于身份验证或加密的一组字符串，通常很长，不可预测，形如 `sk-aBcDeFgH...`、`ssh-rsa AAAAB3...` 或一串随机字符。密钥泄露后，持有密钥的人可以冒用你的身份或账户。

**API 密钥**：用于访问云端服务接口的密钥。泄露后，对方可以用你的账户发送请求，产生费用或删除数据。

**SSH 私钥**：用于远程登录设备的密钥文件，通常保存在用户目录的 `.ssh/` 文件夹中，常见文件名是 `id_rsa` 或 `id_ed25519`（不含 `.pub` 后缀）。同名的 `.pub` 文件是公钥，可以安全放在服务器上；私钥不带 `.pub` 后缀，不能共享。

**令牌**（Token）：用于验证身份或会话状态的字符串，比如登录状态、访问权限凭证或 OAuth 令牌。令牌通常有时效，过期失效，但过期前泄露仍然有风险。

**Cookie**：网站存在你浏览器里的一小段数据，用来记住你的登录状态。把它复制给别人，对方可能不用密码就能进入你的账户。

**环境变量**：操作系统提供的一种存储配置信息的方式，程序可以从环境变量里读取密钥，而不需要把密钥写进代码文件。

**硬编码**：把密钥、密码这类会变的信息直接写死在代码或配置文件里。这样一来，文件传给谁，密钥就跟着传给谁。

**shell**：终端里负责接收和执行你输入命令的那个程序。Ubuntu 默认是 bash。它会把你敲过的命令记进历史文件。

**Git**：记录文件修改历史的工具，可以回到任意一次修改之前的状态。

**仓库**（Repository）：Git 管理的一个项目目录，包含项目文件和它们的全部修改历史。

**GitHub**：在网上托管 Git 仓库的平台。仓库设成公开后，里面的内容和历史所有人都能看到。

**`.gitignore`**：告诉 Git 哪些文件不需要跟踪和提交的配置文件。在这里列出含密钥的文件，防止它们意外被提交到仓库。

**内网地址**：只在局域网内有效的 IP 地址，常见格式是 `192.168.x.x` 或 `10.x.x.x`。泄露内网地址可能让外部人员了解你的网络结构。

## 不能公开的内容

以下内容不能出现在任何你打算分享的文档、截图、配置文件或代码里：

- **SSH 私钥文件内容**：`.ssh/id_rsa`、`.ssh/id_ed25519` 等私钥文件，不能复制内容分享；
- **API 密钥**：含有长随机字符串的字符，通常以 `sk-`、`Bearer `、`token=` 开头；
- **数据库密码和服务管理后台密码**；
- **真实客户资料**：客户的姓名、企业名称、邮箱、内部文件内容、聊天记录；
- **私有域名和内网地址**：`192.168.x.x`、`10.x.x.x`，或类似 `host.internal`、`server.local` 格式的地址；
- **真实设备序列号和账号标识**；
- **会话令牌和 Cookie**：从浏览器或服务里导出的登录状态信息。

## 常见泄露场景

**截图含有敏感信息。** 截终端或浏览器截图时，画面里可能包含 API 密钥、内网地址、文件路径或用户名。在分享截图之前，放大检查截图的每个区域，看看有没有上面列出的内容。

**配置文件含有硬编码密钥。** 一些程序的配置文件需要填入 API 密钥或密码。如果把这类配置文件上传到 GitHub 或通过聊天工具发送，密钥会立刻暴露。应该用环境变量存储密钥，程序从环境变量读取，配置文件里只放变量名，不放密钥本身。

**命令历史含有密钥。** 在终端里直接输入含密钥的命令，命令历史文件（`.bash_history` 或 `.zsh_history`）会保存这条命令。在命令前加一个空格，多数 shell 会跳过这条不记历史，但这依赖 shell 的具体设置，不是可靠的保护措施。密钥最好通过环境变量或密钥管理工具传入。

**日志文件含有敏感内容。** 程序日志可能记录输入内容、错误信息、访问令牌或请求头。分享日志文件之前需要逐行检查，删除敏感内容再共享。

**`.env` 文件没有排除在 Git 外。** `.env` 文件通常用来存放本地环境变量，包括密钥和密码。如果在 `.gitignore` 里没有排除 `.env`，执行 `git add .` 时就可能意外提交进代码仓库。

## 如何保护密钥

基本措施：

1. 把密钥存在环境变量里，程序从环境变量读取，配置文件和代码里不写密钥；
2. 如果用 `.env` 文件，在项目根目录的 `.gitignore` 里加上 `.env`，防止提交到 Git；
3. 定期检查项目目录，确认没有硬编码密钥；
4. 密钥泄露后，立刻在对应服务平台撤销（Revoke）该密钥，再重新生成一个新密钥，替换所有使用旧密钥的地方。

## 遇到泄露，第一步

发现密钥已经暴露（比如发现提交到了 GitHub，或者发给了不该看到的人）：

1. **立刻撤销密钥**：登录对应的服务平台（如 OpenAI、AWS、GitHub），找到密钥管理页面，撤销泄露的密钥，不要等待；
2. **生成新密钥**：撤销后立刻生成新密钥，替换所有使用旧密钥的位置；
3. **检查日志**：查看该密钥在泄露期间是否有异常使用记录，如果有，按平台提供的安全事件流程处理；
4. **从 Git 历史清理**（如果提交到了仓库）：Git 历史包含密钥即使删除文件也仍然可以找到，需要用专用工具清理历史（见教材后续章节，或查阅官方文档的“移除敏感数据”说明）。

- 删除个人路径、真实账号名称和内部域名；
- 扫描密钥、密码、令牌和私有连接信息；
- 检查截图中的所有可见文字区域；
- 检查示例数据是否包含真实个人资料；
- 确认软件版本、模型版本和日期已标注。
