# 09　防火墙与密钥

## 这一章的任务

两件事。

**第一件，只留该开的门。** 前面几章陆续开了几个口——SSH 的 22、监控面板的 3001、共享文件夹的 445。装一道防火墙，把这几个说得出用途的口留着，其余一律关掉，而且每个口写清楚是开给谁的。

**第二件，把钥匙管好。** 第 4 章生成的那把密钥现在是你进这台机器的唯一凭证，密码那条路已经关了。这一章说清楚它放在哪、怎么备份、换机器怎么迁、丢了怎么办。

## 开始前

- 第 4 章做完，密钥登录可用，密码登录已经关掉；
- 第 6 章的 Tailscale 在跑（没做第 6 章的话，跳过对应那一小节）；
- 第 7 章的共享文件夹在跑（没做的话同样跳过）；
- **能接上显示器和键盘**。这一章有一步万一做错会把你挡在门外，本地登录是唯一的退路；
- 40 分钟。

## 新词

**防火墙**（Firewall）：守在网络入口的一道过滤。每一个想进来的连接，它按你定的规则决定放行还是丢掉。它不管进来之后干什么，只管让不让进。

**入站**（Incoming）：别人主动连你。笔记本 `ssh` 进这台机器、浏览器打开这台机器上的面板，对这台机器来说都是入站。

**出站**（Outgoing）：这台机器主动连别人。`apt update` 去下载软件包、Tailscale 连它的服务、容器去拉镜像，都是出站。

**默认策略**：没有任何规则匹配上的时候怎么办。服务器的通行做法是**入站默认拒绝、出站默认允许**——别人来找我，得我点头才行；我出去办事，不拦。

**规则**（Rule）：一条例外。“允许从局域网来的、发往 445 端口的连接”，就是一条规则。

**ufw**：Ubuntu 上的防火墙管理工具，全称是 Uncomplicated Firewall。底下真正干活的是系统内核，ufw 是给它下命令的那一层，命令比底下那套好记得多。

**网络接口**（Interface）：机器上一个具体的网络出入口。有线网口是一个（`enp` 开头，第 3 章见过），Wi-Fi 是一个（`wl` 开头），Tailscale 装完之后也会多出一个虚拟的，叫 `tailscale0`。规则可以只针对某一个接口。

## 先看看现在开着哪些口

第 2 章那条命令，再跑一次：

```bash
ss -tln
```

现在的输出应该比第 2 章那时候长了：

```
State    Recv-Q   Send-Q     Local Address:Port      Peer Address:Port
LISTEN   0        4096       127.0.0.53%lo:53             0.0.0.0:*
LISTEN   0        128              0.0.0.0:22             0.0.0.0:*
LISTEN   0        4096             0.0.0.0:3001           0.0.0.0:*
LISTEN   0        50               0.0.0.0:445            0.0.0.0:*
```

一个个认：

| 端口 | 是谁 | 给谁用 |
| --- | --- | --- |
| 22 | SSH | 你自己，从笔记本和手机 |
| 3001 | 那个监控面板 | 你自己，从浏览器 |
| 445 | Samba 共享 | 家里或者组里那几个人 |
| 53 | 系统的 DNS 缓存 | 只有这台机器自己，`127.` 开头（第 2 章讲过） |

**说不出用途的端口，是这一章要关掉的。** 这台机器现在这四个都说得出，很好——防火墙装上去主要是防以后：以后每装一个新东西，它可能悄悄开一个口，防火墙在的话它默认进不来，你得主动放行才行。

## 装 ufw

```bash
sudo apt install ufw
```

Ubuntu 上通常已经装了，那就会提示已是最新版本。

**现在不要启用它。** 先放规则，最后才启用，顺序在下一节。

看看它认识哪些常用服务：

```bash
sudo ufw app list
```

输出一个列表，里面应该有 `OpenSSH` 和 `Samba`。这些是预置的“应用配置”，写规则时可以直接用名字，不用记端口号。

## 放行 SSH，然后才启用

**这一节顺序写死，一步都不能调换。**

**第一步，放行 SSH。**

```bash
sudo ufw allow OpenSSH
```

作用：允许任何地方连 22 端口。输出：

```
Rules updated
Rules updated (v6)
```

两行分别是 IPv4 和 IPv6 的规则，都加上了。

不用应用名、直接写端口也一样：

```bash
sudo ufw allow 22/tcp
```

两条二选一，做过一条就别做另一条了，不然规则列表里会有两条重复的。

**第二步，设默认策略。**

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
```

作用：入站默认拒绝，出站默认允许。各输出一行 `Default incoming policy changed to 'deny'` 之类的提示，后面跟一句“记得更新你的规则”。

**这两条现在还没生效**，防火墙没启用，设的是它启用之后的行为。

**第三步，确认规则真的在里面。**

```bash
sudo ufw status
```

防火墙还没启用，所以输出是：

```
Status: inactive
```

看不到规则。**换一条能在未启用时看的**：

```bash
sudo ufw show added
```

输出里必须有 `ufw allow OpenSSH` 那一行。**没有的话，回第一步重做，不要往下走。**

**第四步，启用。**

```bash
sudo ufw enable
```

它会先问一句：

```
Command may disrupt existing ssh connections. Proceed with operation (y|n)?
```

意思是这条命令可能会中断现有的 SSH 连接。第一步做过了，打 `y` 回车。

输出：

```
Firewall is active and enabled on system startup
```

后半句是说它开机自启，不用你另外 `enable` 一次。

> **先放行 SSH 再启用防火墙，顺序反了你当场被挡在门外，而且连不回去。** 真出了这事：接上显示器和键盘，在机器本地登录，执行 `sudo ufw disable`，防火墙立刻关掉，SSH 马上回来，然后从第一步重做。

**第五步，验证你还进得去。** 这一步不能省。

**新开一个终端窗口**，当前这个连着的先别关：

```bash
ssh minipc
```

能进去，这一节就过了。和第 4 章关密码登录时留后路的做法一样——改动生效之后，用一个新连接验证，旧连接留着当退路。

## 放行前面几章开的口

现在防火墙开着，除了 SSH 什么都进不来。第 2 卷那个面板打不开了，共享文件夹也连不上了，这是对的，接下来一个个放回去。

### 那个监控面板，只对局域网开

```bash
sudo ufw allow from 192.168.1.0/24 to any port 3001 proto tcp
```

地址段换成你自己的。这条命令四段：

- **`from 192.168.1.0/24`**：只允许从这个网段来的连接。`/24` 是第 3 章说的“前三段一样的算一个网”，也就是你家里那一网的所有设备；
- **`to any`**：发往这台机器的任何一个地址；
- **`port 3001`**：目标端口；
- **`proto tcp`**：只放 TCP。

**和上面 SSH 那条比，多了 `from` 这一段，这就是“只对局域网放行”的写法。** 不写 `from` 就是对所有地方开着。

### 共享文件夹，也只对局域网开

```bash
sudo ufw allow from 192.168.1.0/24 to any port 445 proto tcp
```

用应用名也行，但应用名那种写法不带 `from`，等于对所有地方开：

```bash
sudo ufw allow from 192.168.1.0/24 to any app Samba
```

这样才是既用应用名、又限定来源。

**共享文件夹尤其要限定局域网。** 445 是互联网上被扫得最狠的端口之一，别给它留全开的机会。

### Tailscale 那条通道，整条放行

第 6 章那条路走的是 `tailscale0` 这个虚拟接口。防火墙一开，它也被拦了，表现是在外面连不上。

```bash
sudo ufw allow in on tailscale0
```

作用：从 `tailscale0` 这个接口进来的连接，一律放行。

**为什么这里敢整条放行**：能从这个接口进来的，只有用你的账号登录、加进了你那张网的设备（第 6 章讲过）。这个接口上没有陌生人。

没装 Tailscale 的话跳过这一条。

### SSH 也可以收紧（可选）

上面那条 `allow OpenSSH` 是对所有地方开的。这台机器不对公网暴露（第 6 章那一节），所谓“所有地方”实际上就是局域网加 Tailscale，风险有限。

想再紧一点的话，把它换成限定来源的：

```bash
sudo ufw allow from 192.168.1.0/24 to any port 22 proto tcp
sudo ufw delete allow OpenSSH
```

**两条命令的顺序不能反。** 先加新的，确认新的在里面、新窗口还能连进来，再删旧的。

删完之后，从局域网和 Tailscale 都能连（Tailscale 那条走的是上面 `tailscale0` 的规则），从别的地方连不上。

## `ufw status` 怎么看

```bash
sudo ufw status verbose
```

`verbose` 表示连默认策略一起显示。正常输出：

```
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing), disabled (routed)
New profiles: skip

To                         Action      From
--                         --          ----
22/tcp (OpenSSH)           ALLOW IN    Anywhere
3001/tcp                   ALLOW IN    192.168.1.0/24
445/tcp                    ALLOW IN    192.168.1.0/24
Anywhere on tailscale0     ALLOW IN    Anywhere
22/tcp (OpenSSH (v6))      ALLOW IN    Anywhere (v6)
```

从上往下读：

- **`Status: active`** 是防火墙开着；
- **`Default:`** 那行是默认策略，要的是 `deny (incoming), allow (outgoing)`；
- 下面的表格一行一条规则。**`To` 是开的哪个口，`From` 是开给谁**。`From` 是 `Anywhere` 就是对所有地方开着，是一个网段就是只对那个网段开；
- 带 `(v6)` 的是 IPv6 的对应规则，加规则时自动跟着加的，不用管。

系统语言是中文的话，`Status`、`Action` 这几个词会显示成中文，意思一样。

**这张表就是这台机器的门禁清单。** 每一行你都该说得出“这个口是给谁开的”。说不出的那一行，删掉。

### 删一条规则

先带编号看一遍：

```bash
sudo ufw status numbered
```

每行前面多了一个 `[ 1]`、`[ 2]` 这样的编号。按编号删：

```bash
sudo ufw delete 3
```

它会把那条规则打印出来让你确认，打 `y` 回车。

**删一条之后编号会重排**，要删多条就一条一条来，每删一条重新看一次编号，不要照着旧的编号连着删。

也可以照着原来加的样子删：

```bash
sudo ufw delete allow 3001/tcp
```

## Docker 开的口不归 ufw 管

这件事得说清楚，不然你以为关上了其实没关。

第 2 卷第 9 章那条 `docker run` 里的 `-p 3001:3001`，Docker 是自己去改系统底层的转发规则实现的，**它插在 ufw 的规则前面**。结果是：ufw 里就算没有放行 3001，容器那个口在局域网里照样连得上。

上一节那条放行 3001 的规则，实际效果是让规则列表看起来完整，Docker 那个口本来就通着。

**这台机器的处境不算糟**：它没有对公网开的口（第 6 章那一节），所以“绕过 ufw”能绕到的范围，也就是你自己的局域网和 Tailscale。

真要把容器的口管起来，办法是在 Docker 这一层限定，让它只绑在你要的地址上。停掉旧容器，用带地址的写法重建：

```bash
docker stop uptime-kuma
docker rm uptime-kuma
docker run -d \
  --name uptime-kuma \
  --restart unless-stopped \
  -p 192.168.1.50:3001:3001 \
  -p 100.101.102.103:3001:3001 \
  -v "$HOME/ai/projects/uptime-kuma/data:/app/data" \
  louislam/uptime-kuma:1
```

和第 2 卷第 9 章那条比，只有 `-p` 那两行不一样：**端口前面多了一个地址**，意思是只在这个地址上开这个口。两个 `-p` 分别对应局域网地址和 Tailscale 地址。数据在 `-v` 那个目录里，删了重建不丢，第 2 卷第 9 章验证过。

改完确认一下：

```bash
ss -tln | grep :3001
```

`Local Address` 那一列从 `0.0.0.0:3001` 变成了具体的地址，就是生效了。

嫌麻烦的话这一节可以先跳过，但**要知道 `ufw status` 里那张表管不到容器的口**。第 14 卷讲对外交付的机器时，这件事就不能跳了。

## 密钥放哪、丢了怎么办

第 4 章生成了密钥、关掉了密码登录。从那时起，**那个私钥文件就是进这台机器的唯一凭证**。这一节说清楚怎么管它。

### 它现在在哪

**笔记本上**（钥匙本人）：

```
~/.ssh/id_ed25519        私钥，不带后缀，不外传
~/.ssh/id_ed25519.pub    公钥，.pub 结尾，可以随便传
~/.ssh/config            第 4 章那两个别名
~/.ssh/known_hosts       连过的机器的指纹
```

Windows 上这些文件在 `C:\Users\你的用户名\.ssh\` 下面。

**Mini PC 上**（锁）：

```
~/.ssh/authorized_keys   所有被允许登录的公钥，一行一把
```

看看这台机器上现在认几把钥匙：

```bash
ssh-keygen -lf ~/.ssh/authorized_keys
```

作用：把 `authorized_keys` 里每一把钥匙的指纹打出来。正常输出一行一把：

```
256 SHA256:aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789abcdefg 笔记本 (ED25519)
```

倒数第二段是第 4 章 `ssh-keygen -C` 那个备注。**备注就是这时候用的**——钥匙多了之后，全靠它认出哪一行是哪台设备的。备注写得含糊的，趁现在去 `authorized_keys` 里把那一行末尾改清楚，改备注不影响钥匙本身能不能用。

### 备份到哪

**私钥是文件，文件会丢。** 笔记本被偷、硬盘坏了、系统重装忘了导出，三件事任何一件发生，你就进不去这台机器了——密码那条路第 4 章已经关掉。

三条备份的路，从好到差：

1. **密码管理器**。多数密码管理器能存文件或者长文本，把私钥内容存进去，跟着密码库一起加密、一起同步。**这是首选**；
2. **一块加密的 U 盘，锁在抽屉里**。平时不插，只在换机器时拿出来；
3. **另一台你自己的机器上，放在 `~/.ssh` 里**。这不算备份，算多一把钥匙，但确实能救急。

**三条绝对不能做的**：

- 不把私钥传进任何云盘、聊天工具、邮箱，哪怕只发给自己；
- 不把私钥放进任何 Git 仓库，`.gitignore` 里加上 `.ssh/`；
- 不把私钥内容贴进截图、日志、文档。

理由和判断标准见[第 0 卷第 8 章](../00-使用说明/08-文件保护.md)。**公钥（`.pub` 结尾那个）不在此列，它本来就是给出去的。**

第 4 章设过密码短语的话，私钥文件即使流出去，对方还要过密码短语这一关。这就是那一步的价值。

### 换新机器怎么迁

**推荐做法是不迁，重新生成一把。** 一台设备一把钥匙，丢了只需要撤掉那一把，别的设备不受影响。

在新笔记本上：

```bash
ssh-keygen -t ed25519 -C "新笔记本"
```

然后要把新公钥送上去。**旧笔记本还能用的话**，最省事：

```bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub 你的账户名@192.168.1.50
```

它会问密码——但密码登录已经关了，这条走不通。改成从旧笔记本上转手：把新公钥的内容（`.pub` 那个文件，一行文本）复制出来，在旧笔记本上 `ssh minipc` 进去，然后：

```bash
nano ~/.ssh/authorized_keys
```

**另起一行**贴进去，保存退出。回新笔记本上试 `ssh 你的账户名@192.168.1.50`，能进去就成了。

**旧笔记本已经用不了了**，那就接上显示器和键盘，在机器本地登录，做同一件事。这是第 4 章那条“留一条本地的路”存在的理由。

**确实要把旧钥匙一起搬过去**（比如你就想一把钥匙走天下），复制 `id_ed25519` 和 `id_ed25519.pub` 两个文件到新机器的 `~/.ssh/`，然后**必须把权限收紧**：

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519
```

权限太松的话 SSH 会拒绝用这把钥匙，而且不明说原因，第 4 章遇到过。

### 丢了怎么办

笔记本丢了、私钥可能流出去了，做三件事，**第一件立刻做**。

**一、从服务器上删掉那把公钥。** 从任何一台还能登进去的设备连上 Mini PC（另一台笔记本、手机上的 SSH，或者接显示器本地登录）：

```bash
nano ~/.ssh/authorized_keys
```

找到丢掉那台设备对应的那一行——**按行末的备注认**，删掉整行，保存退出。

不确定哪一行是哪把，先跑一次 `ssh-keygen -lf ~/.ssh/authorized_keys` 看指纹和备注的对应。

**这一步做完，那把钥匙立刻失效**，不用重启任何服务，SSH 每次连接都是现读这个文件的。

**二、验证。** 用留下的那把钥匙连一次，确认自己没删错：

```bash
ssh minipc
```

进不去的话，赶紧接显示器本地登录，把误删的那一行加回来——所以**改这个文件之前先复制一份**：

```bash
cp ~/.ssh/authorized_keys ~/.ssh/authorized_keys.bak
```

**三、清理别的地方。** 那把钥匙可能不止用在这一台机器上。凡是你用它登过的服务器、代码托管平台（GitHub 这类的 SSH 密钥设置页），逐个去把对应的公钥删掉。这一步容易忘，趁着还记得赶紧做。

顺带一句 Samba 那边（第 7 章）：共享文件夹用的是另一套密码，和 SSH 密钥无关。设备丢了同样要处理，做法是 `sudo smbpasswd -a 账户名` 重设一个新密码，然后告诉还在用的那几个人。

有哪一步做不出来，到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。

## 事实来源和版本日期

- `ufw` 的应用配置列表（`ufw app list` 输出的那些名字）由各软件包安装时提供，装了什么就有什么，以你机器上的实际输出为准；
- Docker 发布端口时直接操作内核转发规则、位置在 ufw 的规则之前，这是 Docker 当前的行为；用 `-p 地址:端口:端口` 限定绑定地址是官方支持的写法；
- `ufw status` 的字段名会跟随系统语言显示成中文；
- 本章核验日期：2026-08-14。
