# 06　进程与服务

## 这一章的任务

找一个正在后台跑的服务，看它的状态、把它停掉、再起回来、决定它下次开机要不要自己起来。

做完之后你手上有一套 5 个动作，对任何服务都通用。后面各卷的本地模型服务、Docker、定时任务、自动备份，全部靠这 5 个动作管，这一章是它们的地基。

## 开始前

- 第 3 章装的 `htop` 已经能用；
- 用有 `sudo` 权限的管理员账户操作；
- 20 分钟。

## 新词

进程、PID、服务这几个词在[第 0 卷第 9 章](../00-使用说明/09-停止与恢复.md)解释过。这一章多 3 个。

**systemd**：Ubuntu 的初始化系统。开机之后第一个跑起来的程序就是它，之后所有服务由它拉起来、盯着、崩了按规则重启。`systemctl` 是给它下命令的工具。

**服务单元**（Unit）：systemd 管的每个服务对应一个配置文件，文件名以 `.service` 结尾，例如 `cups.service`。命令里写服务名时，`.service` 可以省略不写。

**守护进程**（Daemon）：一直在后台运行、没有窗口的程序。服务跑起来之后，在进程列表里的样子就是一个守护进程。

## 进程和服务差在哪

**进程**是正在运行的程序。你双击打开的浏览器是进程，终端里跑的一条命令也是进程。它跟着你——你关掉窗口它就没了，你注销登录它也没了。

**服务**是交给 systemd 管的后台程序。它有一个固定的名字、一个开机自启的开关、一套统一的启停命令。关掉终端、注销登录、换个人上机，都不影响它继续跑。

服务跑起来之后当然也是进程，两个词说的是同一个东西的两面：进程是它此刻的运行状态，服务是它被管理的方式。

判断标准很直接：要它在你没登录的时候也一直跑着，就做成服务。第 6 卷的本地模型服务之所以要做成服务，就是为了你合上机器走人之后，别人还能访问它。

## 看进程

```bash
ps aux | head -20
```

作用：列出当前所有进程，只取前 20 行看一眼格式。

输出的列，日常要看的就 4 个：`USER` 是哪个账户跑的，`PID` 是进程编号，`%CPU` 和 `%MEM` 是占了多少处理器和内存，最后一列是命令本身。

按名字找一个进程：

```bash
ps aux | grep firefox
```

输出里会有一行是 `grep` 命令自己，忽略它。这条命令和用 PID 终止进程的做法，在[第 0 卷第 9 章](../00-使用说明/09-停止与恢复.md)讲过。

看动态的：

```bash
htop
```

打开一个满屏的界面，上半部分是每个 CPU 核心的占用条和内存条，下半部分是进程列表，默认按 CPU 占用排序，谁在吃资源一眼能看到。

界面里几个键：

- `F6` 换排序依据，选 `PERCENT_MEM` 就是按内存排；
- `F4` 输入关键词过滤，只留下名字匹配的进程；
- `F5` 切换成树形，能看出谁是谁启动的；
- `F9` 结束选中的进程；
- `q` 或 `F10` 退出。

**`F9` 只对你自己启动的程序用。** 系统进程被结束掉，轻则桌面退出你被踢回登录界面，重则要重启才能恢复。分不清的时候先看 `USER` 那一列是不是你的账户名。

没装 `htop` 的机器上有系统自带的 `top`，功能类似，界面粗糙一些，按 `q` 退出。

## 挑一个服务练手

先看看现在有哪些服务在跑：

```bash
systemctl list-units --type=service --state=running
```

作用：列出所有正在运行的服务，一行一个，最后一列是它的说明。这条命令只读，不需要 `sudo`。输出满一屏之后按 `q` 退出。

从里面挑一个练手对象。本教材用 `cups`，它是打印服务，Ubuntu 桌面版通常自带，停掉它最多是暂时不能打印，没有别的影响。

确认它在：

```bash
systemctl status cups
```

提示 `Unit cups.service could not be found` 的话，这台机器没装打印服务，换 `bluetooth` 试；两个都没有，就从上面的列表里挑一个你认得出、停掉不影响你干活的。

**不要拿 `NetworkManager`、`gdm`、`systemd-logind` 这几个练手。** 它们分别管着网络、图形登录界面和登录会话，停掉的后果依次是断网、桌面直接退出、当前登录会话崩掉。练手要挑一个你说得出它管什么、停掉会损失什么的服务。

## 五个动作

### 一、看状态

```bash
systemctl status cups
```

正常输出：

```
● cups.service - CUPS Scheduler
     Loaded: loaded (/usr/lib/systemd/system/cups.service; enabled; preset: enabled)
     Active: active (running) since Thu 2026-08-14 09:12:33 CST; 2h 5min ago
   Main PID: 1043 (cupsd)
      Tasks: 1 (limit: 38000)
     Memory: 4.2M
        CPU: 892ms
     CGroup: /system.slice/cups.service
             └─1043 /usr/sbin/cupsd -l
```

逐行读：

- **`Loaded`** 那行末尾的 `enabled` 是**开机自启的状态**，`enabled` 表示下次开机会自己起来，`disabled` 表示不会；
- **`Active`** 那行是**现在的状态**。`active (running)` 是正在跑，后面跟着从什么时候开始跑、跑了多久；停着是 `inactive (dead)`；起失败是 `failed`；
- **`Main PID`** 是它在进程列表里的编号，括号里是程序名。拿这个数字去 `htop` 里搜，能找到同一个东西；
- 最下面还会附几行最近的日志，服务出问题时先看这几行。

`status` 是只读的，不需要 `sudo`。输出超过一屏时按 `q` 退出，不是 `Ctrl+C`。

### 二、停

```bash
sudo systemctl stop cups
```

作用：停掉这个服务。命令成功没有输出。

再执行一次 `systemctl status cups`，`Active` 那行应该变成 `inactive (dead)`。

这时候去 `htop` 里搜 `cupsd`，找不到了——服务停了，对应的进程就没了。

### 三、起

```bash
sudo systemctl start cups
```

再看状态，`Active` 回到 `active (running)`。注意 `Main PID` 换成了另一个数字，这说明它是新起的一个进程，不是原来那个被唤醒了。

### 四、重启

```bash
sudo systemctl restart cups
```

作用：先停再起，等于把上面两条连起来做。改完配置文件之后用它让新配置生效，第 11 章会一直用这条。

重启期间有几秒钟服务不可用，这时候有人正在用它，请求会失败。

### 五、开机自启

```bash
sudo systemctl enable cups
```

作用：让它下次开机自动启动。**这条命令不会把现在停着的服务起起来。**

```bash
sudo systemctl disable cups
```

作用：取消开机自启。**这条命令也不会把正在跑的服务停掉。**

“现在跑不跑”和“下次开机起不起”是两件独立的事，四条命令各管一头：

| 命令 | 现在 | 下次开机 |
| --- | --- | --- |
| `start` | 起来 | 不变 |
| `stop` | 停掉 | 不变 |
| `enable` | 不变 | 自己起来 |
| `disable` | 不变 | 不起 |
| `enable --now` | 起来 | 自己起来 |

最后一行的写法是把两件事一次做完：

```bash
sudo systemctl enable --now cups
```

后面各卷装完一个服务，最常用的收尾就是这一条。

`disable` 要用在你说得清它管什么的服务上。看着眼生的服务不要关，很多系统组件的名字跟它的作用对不上号，关掉之后出的问题也不会立刻显现。

## 服务起不来的时候

`start` 或 `restart` 之后，`status` 显示 `failed`，原因通常就在 `status` 输出最下面那几行日志里。要看更多：

```bash
journalctl -u cups -n 50
```

`-u` 指定服务名，`-n 50` 表示最近 50 行。日志怎么读、怎么按时间和关键词找，是下一章的内容。

按日志改完配置之后，用 `sudo systemctl restart 服务名` 再试一次。改了配置反而更糟的话，把配置换回备份再重启，做法见[第 0 卷第 9 章](../00-使用说明/09-停止与恢复.md)。

有哪一步做不出来，到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。

## 完成检查

- `systemctl list-units --type=service --state=running` 能列出正在跑的服务吗？
- `systemctl status` 的输出里，哪一行看现在跑没跑，哪一行看开机自启是开还是关？
- 你练手的那个服务，停掉之后 `Active` 变成什么了？
- 再起回来之后，`Main PID` 的数字和停之前一样吗？
- `enable` 和 `start` 的区别，你能说出来吗？
- `htop` 里按哪个键退出，按哪个键结束进程，什么时候不该按后面那个？
