# 10　恢复介质

## 完成结果

关键信息已经记录在设备之外，恢复 U 盘已经做好并验证过能启动，整块 SSD 的镜像已经备份到移动硬盘，知道系统进不去时怎么用 Live 模式把文件抢救出来。

## 开始前需要准备什么

- 已完成第 9 章，系统能正常开机、能上网；
- 一个容量 8 GB 或以上的 U 盘（和第 6 章那个分开，不要覆盖已有的安装盘）；
- 一块移动硬盘，可用空间不小于 Mini PC 内置 SSD 的标称容量（1 TB 的 SSD 就准备 1 TB 以上的空间）；
- 另一台能上网、能下载文件的电脑；
- 纸和笔，或另一台能记东西的设备（手机、平板都行）；
- 做镜像那一步需要连续几个小时，中途不能拔线、不能关机，挑一段不用这台机器的时间做。

## 新词

**恢复介质**（Recovery Media）：系统坏掉、进不去桌面时，用来启动机器、取回数据或重装系统的外部设备。这里指一个 Ubuntu 启动 U 盘和一块存了系统镜像的移动硬盘。

**Live 模式**（试用模式）：从 U 盘直接启动的一个完整 Ubuntu 系统，跑在内存里，不读也不改硬盘上的系统。Ubuntu 安装盘启动后选“试用 Ubuntu”（Try Ubuntu）进入的就是这个模式。关机后 Live 模式里做的改动全部消失，硬盘上的东西不受影响。

**挂载**（Mount）：把一块磁盘或磁盘上的一个分区接到当前系统的某个目录上，之后通过这个目录读写里面的文件。Windows 里插上 U 盘自动出现一个盘符，Linux 里对应的动作就叫挂载。没挂载的分区在文件管理器里看不到内容。

**分区**（Partition）：一块物理磁盘可以划成几个独立区域，每个区域叫一个分区。第 7 章安装 Ubuntu 时，安装程序在 SSD 上建了一个 EFI 分区（放启动文件，几百 MB）和一个主分区（放系统和你的文件，占了绝大部分容量）。

**磁盘镜像**（Disk Image）：把整块磁盘从头到尾原样复制成一个文件，包含分区表、启动文件、系统和数据。文件后缀通常是 `.img`。把这个文件写回磁盘，磁盘就回到做镜像那一刻的状态。

## 为什么现在做

恢复盘的作用，是在系统起不来的时候把机器和数据救回来。它必须在系统还能用的时候做好。

系统起不来之后再做，会遇到三个问题：这台机器已经用不了，得借另一台电脑；硬盘里的数据这时候已经取不出来，只能靠之前的备份；而这台机器上的关键信息（账户名、磁盘设备名、系统版本）都存在起不来的那块硬盘里，想查也查不到。

这一章花的几个小时，换的是后面出问题时有退路。

## 第一步：记录并保存关键信息

在系统还能用的时候，把下面几项查出来抄下来。

**账户名**

```bash
whoami
```

输出就是你的账户名，例如 `roland`。

**主机名**

```bash
hostname
```

输出是设备在网络里的名字，例如 `minipc-01`。

**磁盘设备名和容量**

```bash
lsblk -d -o NAME,SIZE,MODEL
```

`-d` 表示只列磁盘本身不列分区，`-o` 后面是要显示的列。输出示例：

```
NAME     SIZE MODEL
nvme0n1  1.8T Samsung SSD 990 PRO 2TB
```

`nvme0n1` 就是内置 SSD 的设备名。后面做镜像和恢复时都要用它认盘，抄下来。

**Ubuntu 版本号**

```bash
cat /etc/os-release
```

输出里的 `VERSION=` 那一行就是版本，例如 `24.04.4 LTS (Noble Numbat)`。

也可以用：

```bash
lsb_release -a
```

如果提示命令不存在，用上面的 `cat` 那条。

**内核版本**

```bash
uname -r
```

第 9 章已经查过，一起记下来。

**要记的清单**

| 项目 | 你的值 |
| --- | --- |
| 账户名 | |
| 主机名 | |
| 登录密码 | |
| 内置 SSD 设备名 | |
| 内置 SSD 容量 | |
| Ubuntu 版本号 | |
| 内核版本 | |
| 品牌和型号 | |
| 序列号（第 1 章已记录） | |
| 购买日期和订单号 | |

**保存在哪里**

写在纸上收好，或者存进手机、另一台电脑、云盘。

关键在于：**不要只存在这台 Mini PC 里**。存在这台机器上，等于这台机器坏了才需要它、这台机器坏了就拿不到它。

密码写在纸上时收进抽屉，不要贴在机身上。

## 第二步：做第二个 Ubuntu 启动 U 盘

做法和第 6 章完全一样：下载 Ubuntu 镜像文件，用 balenaEtcher 或 Ventoy 写进 U 盘。步骤见[第 6 章：Ubuntu 安装盘](06-Ubuntu安装盘.md)，这里不重复。

两点不同：

**第一，版本要和现在装的一致。** 第一步记下的 Ubuntu 版本号是多少，就下载哪个版本。版本一致，Live 模式里的工具和你系统里的行为才对得上。

**第二，这个 U 盘做完就收起来，专门当恢复盘用。** 不要拿它日常存文件，也不要重新格式化。在 U 盘上贴个标签，写上 Ubuntu 版本号和制作日期。

> **⚠️ 制作会清空 U 盘上的全部内容。** 动手前确认这个 U 盘里没有要保留的东西，也确认写入目标选的是这个 U 盘，不是移动硬盘或电脑的系统盘。写错盘的数据拿不回来。第 6 章里核对目标盘的方法同样适用。

已经有第 6 章那个安装 U 盘的话，技术上它就能当恢复盘用。做第二个的理由是：安装盘可能被别的用途覆盖掉，也可能就在需要它的时候找不到或读不出来。两个 U 盘分开放，坏一个还有一个。

## 第三步：给整块 SSD 做镜像备份

这一步把整块内置 SSD 复制成移动硬盘上的一个文件。

### 需要多大空间、要多久

**空间**：镜像是整块盘的原样复制，文件的标称大小等于整块盘的容量，和盘里实际用了多少无关。1 TB 的 SSD 产生约 1 TB 的文件，2 TB 的产生约 2 TB。移动硬盘如果是 ext4 格式，实际占用可能小一些（系统会把全是零的部分做稀疏处理），但准备空间时按整块盘的容量准备最稳妥。

**时间**：取决于两边的读写速度，瓶颈通常在移动硬盘和它的接口上。按 USB 3.0 移动硬盘常见的 100 到 200 MB/s 估算，1 TB 大约 1.5 到 3 小时；接在 USB 2.0 口上会长到十几个小时。实际速度和你的移动硬盘型号、接口和线材有关（需要核验）。

先把移动硬盘接在主机后面的 USB 3.0 口上（接口内部是蓝色的那种，或标有 `SS` 字样），不要接在扩展坞或 USB 集线器上。

### 为什么要从 Live 模式做

给正在运行的系统盘做镜像，复制过程中系统还在往盘里写东西，得到的镜像可能是不一致的——前半段和后半段不是同一时刻的状态，写回去之后系统可能起不来。

从 Live U 盘启动之后，内置 SSD 没有被使用，这时候做出来的镜像是干净的。

### 操作步骤

1. 关机（右上角状态菜单 →“关机”）；
2. 插入第二步做好的恢复 U 盘，接好移动硬盘；
3. 开机，按启动选择菜单的按键，选 U 盘启动。按键因品牌而异，见下表；
4. 出现 Ubuntu 启动画面后，选**“试用 Ubuntu”**（Try Ubuntu），**不要**选“安装 Ubuntu”；
5. 进入桌面后，按 `Super` 键，输入“磁盘”或 “Disks”，回车打开 GNOME 自带的“磁盘”程序；
6. 左栏列出所有磁盘。点中内置 SSD——按容量和型号认，就是第一步记下来的那块。注意点的是磁盘本身，不是磁盘下面的某个分区；
7. 右侧确认设备名是 `/dev/nvme0n1`（或你记下的那个），确认容量对得上；
8. 点右上角的菜单按钮（三条横线或三个点），选**“创建磁盘映像…”**（Create Disk Image…）；
9. 文件名填一个带日期的名字，例如 `minipc-ssd-2026-08-14.img`；保存位置选**移动硬盘**，不要选 Live 系统的桌面（Live 模式跑在内存里，关机就没了）；
10. 点“开始创建”，等待完成。

**进入启动选择菜单的按键**（和第 7 章相同）：

| 品牌 | 常见按键 |
| --- | --- |
| GMKtec EVO-X2 / EVO-X3 | `F7` 或 `F12` |
| Beelink GTR9 Pro | `F7` 或 `F12` |
| Framework Desktop | `F12` |
| HP ZBook Ultra G1a | `F9` |
| 其他品牌 | 通常是 `F12` 或 `Esc` |

完成后，在移动硬盘上能看到那个 `.img` 文件。把文件名、日期和对应的机器记在第一步的清单上。

这一趟同时也验证了恢复 U 盘能用：能从它启动进桌面，说明这个 U 盘是好的。

### 如果安装时开了磁盘加密

第 7 章按“清除整块磁盘并安装 Ubuntu”的默认流程走，通常没有开加密。如果你当时勾选了加密选项，镜像里的数据仍然是加密状态，写回去之后还是要原来的密码才能开机。密码丢了，镜像也救不回数据。这种情况下，第一步清单里的密码那一栏尤其不能空着。

## 用 Live 模式抢救文件

系统进不去桌面、但硬盘本身还是好的时候，用这个方法把文件取出来。

### 图形方式

1. 插入恢复 U 盘和移动硬盘，开机，按启动菜单键选 U 盘；
2. 选“试用 Ubuntu”；
3. 打开“文件”（Files）程序；
4. 左栏找到“其他位置”，下面会列出内置盘的分区，通常显示为容量加设备名。点一下，系统会把它挂载起来，然后显示里面的内容；
5. 依次进入 `home` → 你的账户名，这里面就是你的文档、下载、图片和桌面文件；
6. 选中要救的文件，复制到移动硬盘；
7. 复制完成后，在左栏右键点移动硬盘选“弹出”，等图标消失再拔线。

如果点分区时弹出密码框，说明这块盘是加密的，输入你的登录密码解锁。

### 命令方式

图形界面挂载不上时用这个。在 Live 模式里打开终端（`Ctrl+Alt+T`）。

先看有哪些分区：

```bash
lsblk -f
```

`-f` 会多显示文件系统类型和标签。输出示例：

```
NAME        FSTYPE LABEL  SIZE MOUNTPOINTS
nvme0n1                   1.8T
├─nvme0n1p1 vfat          1G
└─nvme0n1p2 ext4          1.8T
```

要找的是容量最大、`FSTYPE` 是 `ext4` 的那个分区，上面这个例子里是 `nvme0n1p2`。`vfat` 那个小分区是 EFI 启动分区，里面没有你的文件。

建一个目录当挂载点，然后挂上去：

```bash
sudo mkdir -p /mnt/rescue
sudo mount /dev/nvme0n1p2 /mnt/rescue
```

`mkdir -p` 是新建目录，`-p` 表示上级目录不存在就一起建。Live 模式里的 `sudo` 不需要密码。

确认挂上了：

```bash
ls /mnt/rescue/home
```

正常输出是你的账户名。看到账户名，说明挂对了盘。

把文件复制到移动硬盘。移动硬盘在 Live 模式里通常挂在 `/media/ubuntu/` 下面，先看看它叫什么：

```bash
ls /media/ubuntu/
```

然后复制（把 `你的账户名` 和 `移动硬盘名称` 换成实际值）：

```bash
cp -r /mnt/rescue/home/你的账户名/文档 /media/ubuntu/移动硬盘名称/
```

`-r` 表示连同目录里的所有内容一起复制。整个主目录都要救的话，把 `/文档` 去掉，直接复制 `你的账户名` 这一层。

复制完成后卸载，再拔移动硬盘：

```bash
sudo umount /mnt/rescue
```

**命令是 `umount`，不是 `unmount`**，中间没有 `n`。

### 挂载报错怎么办

**报 `unknown filesystem type 'crypto_LUKS'`**：这个分区是加密的。先解锁再挂载：

```bash
sudo cryptsetup open /dev/nvme0n1p2 rescue
sudo mount /dev/mapper/rescue /mnt/rescue
```

执行第一条时会要密码，输入你的登录密码。

**报 `wrong fs type`**：选错分区了，多半选到了 EFI 分区。回去看 `lsblk -f` 的输出，选 `ext4` 那个。

**报 `can't read superblock` 或有大量输入输出错误**：分区结构或硬盘本身有损坏。不要反复重试，反复读可能让情况更糟。这时候优先联系卖方，或者找数据恢复服务。

## 把镜像写回硬盘

这一步只在系统彻底坏掉、需要恢复到备份那一刻的状态时才做。

> **⚠️ 写回镜像会把目标磁盘上的全部内容覆盖掉，覆盖之前的数据拿不回来，没有撤销、没有回收站。** 做之前先按上面“用 Live 模式抢救文件”，把镜像做好之后新产生的文件复制到移动硬盘——写回操作会把这些新文件全部抹掉，因为它们不在镜像里。

**确认设备名的方法**（这一步不能跳）：

1. 把不相关的 U 盘和移动硬盘都拔掉，只留存着镜像的那块移动硬盘；
2. 在终端执行：

```bash
lsblk -d -o NAME,SIZE,MODEL,TRAN
```

`TRAN` 列显示的是接口类型：`nvme` 是内置 SSD，`usb` 是 U 盘或移动硬盘。

3. 对照第一步记下来的设备名和容量，确认目标是内置 SSD；
4. 在“磁盘”程序左栏点中目标盘，右侧上方会显示设备名、容量和型号，再核对一次。

**写回步骤**：

1. 从恢复 U 盘启动，选“试用 Ubuntu”；
2. 接上存着镜像的移动硬盘；
3. 打开“磁盘”程序，左栏选中内置 SSD（确认设备名和容量）；
4. 点右上角菜单，选**“恢复磁盘映像…”**（Restore Disk Image…）；
5. 选择移动硬盘上的 `.img` 文件；
6. 程序会显示目标磁盘的名称和容量，并提示所有数据将被覆盖。**读完这句提示再确认**；
7. 等待写入完成，时间和做镜像时差不多；
8. 完成后关机，拔掉 U 盘和移动硬盘，正常开机。

**写错的后果**：

- 写到了移动硬盘上：移动硬盘里的镜像文件和其他内容一起没了，等于备份也没了；
- 写到了 U 盘上：U 盘容量通常小于镜像，程序会报错拒绝执行，一般不至于造成损失；
- 把旧镜像写回了内置盘：做镜像那一刻之后产生的所有文件全部消失，只剩镜像里的状态。

三种情况都没有恢复办法。所以确认设备名要在写入之前做完。

## 正常结果

- 关键信息清单已经填好，存在这台机器之外的地方；
- 恢复 U 盘做好了，能从它启动进入 Live 桌面；
- 移动硬盘上有一个 `.img` 镜像文件，大小和内置 SSD 的容量对得上；
- 知道系统进不去时，怎么用 Live 模式挂载硬盘、把文件复制出来。

## 看到不同结果怎么办

**从 U 盘启动不了，启动菜单里没有 U 盘**：换一个 USB 口（优先用主机后面的口，不要用扩展坞）；确认 U 盘制作成功（回第 6 章）；进 BIOS 确认 USB 启动没有被禁用。

**Live 模式桌面进不去，卡在启动画面**：等 2 到 3 分钟。超过 5 分钟没反应，重启，在启动画面出现时按一下方向键调出菜单，选带 `safe graphics` 字样的那一项启动。

**“磁盘”程序里看不到内置 SSD**：Live 模式下看不到内置盘，说明硬盘在这一层就没被识别，是硬件层面的问题，见[第 12 章“硬盘识别不到”](12-硬件问题处理.md)。

**创建镜像时中途报读取错误**：SSD 可能有坏块。不要反复重试，先把还能读的重要文件按“用 Live 模式抢救文件”单独复制出来，然后按下面的方法查硬盘健康状态，再联系卖方。

**移动硬盘空间不够，程序报错**：换一块更大的，或者先把移动硬盘里的其他文件清出去。整块盘的镜像没法只备份“用到的部分”，需要压缩备份的话，第 3 卷的备份章节会讲别的工具（见[第 3 卷](../03-服务器基础/README.md)）。

**镜像做到一半移动硬盘掉线**：多半是接口供电不足或线松了。换一个 USB 口，换一根线，不要经过集线器，重做一次。做到一半的镜像文件删掉，它不完整，不能用。

**查硬盘健康状态**：

```bash
sudo apt install smartmontools
sudo smartctl -a /dev/nvme0n1
```

第一条装工具，第二条读取硬盘自检信息。看这几项：`Critical Warning`（严重警告，正常是 `0x00`）、`Media and Data Integrity Errors`（介质和数据完整性错误，正常是 `0`）、`Percentage Used`（已用寿命百分比，新盘应当接近 0%）。这几项异常，说明是硬盘本身的问题，联系卖方时把这段输出一起发过去。

## 联系卖方前需要保存的信息

- 品牌、型号和序列号；
- 购买日期和订单号；
- `sudo smartctl -a /dev/nvme0n1` 的完整输出（保存成文本或截图）；
- 出错时的屏幕截图或照片，包含完整的错误提示文字；
- 问题描述：什么时候开始的、做什么操作时出现的、出现过几次；
- 已经排查过的项目：换过 USB 口、换过线、Live 模式下试过。

## 完成检查

- 账户名、主机名、磁盘设备名、Ubuntu 版本号都记下来了吗？
- 这份记录保存在这台 Mini PC 以外的地方了吗？
- 恢复 U 盘做好了吗，能从它启动进入 Live 桌面吗？
- 移动硬盘上的镜像文件在吗，大小和 SSD 容量对得上吗？
- 镜像文件名上写了日期吗？
- 你知道写回镜像之前要先确认什么吗？
