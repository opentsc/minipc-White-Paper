# 08　案例二：结果台账

## 新词

**台账**：**一件事做了几次、每次什么时候做的、结果怎么样，一行一条记下来的那张表。** [第 8 卷第 5 章](../08-OCR/05-批量处理.md)的新词，这一章原样借用。

**追加**（append）：**往一个已经有内容的文件末尾接着写，不是把原来的内容盖掉。** 这一章写台账靠它。

**转义**：**一个字符本来有特殊含义，你想让它就是一个普通字符，就得按规矩改写一次。** CSV 里的逗号和双引号要转义，命令行里的单引号要转义（[第 7 章](07-案例二-进件分类.md)那个 `引起来`）。**这一章第二次撞上转义。**

**去重**：**同一件事已经做过了，就不要再做一遍。** 这一章最后一节。

**幂等**：**同一件事做一遍和做十遍，结果一样。** [第 8 卷第 6 章](../08-OCR/06-文件夹监测.md)的新词，[第 11 章](11-日志与重试.md)会把它讲透。

## 为什么要台账

**两个理由，都不是技术理由。**

### 一、出了问题能查

**没有台账的时候，你手上只有目录。**

客户说“上周三我交的那份合同不见了”。你打开 `合同/` 翻，没有；打开 `待定/` 翻，也没有。**接下来你什么也做不了**——你不知道那份文件当时有没有进来过、机器判成了什么、有没有搬成功。

**有台账的时候，你打开表格搜一下文件名。** 三种结果：

- **表里没有这一行**——文件根本没进过收件箱。**问题在交件那一头**，不在你这儿；
- **有这一行，类别是「待定」**——机器拿不准，文件在 `待定/` 里。**告诉客户去哪儿找**；
- **有这一行，结果是「失败」**——搬的时候出错了。**看最后那一列写了什么。**

**这三句话的差别，就是台账的全部价值。** [第 8 卷第 5 章](../08-OCR/05-批量处理.md)那句“文件名是回溯的钥匙”，说的是同一件事。

### 二、跟客户交付的时候，这就是工作量证明

**这条更实在。**

一条自动流水线跑起来之后，**它是安静的**。客户看不见它在干活，只看见文件夹里的文件在变多。**到了对账、续费、扩范围的时候，你拿什么说明这一个月做了什么。**

台账就是那个东西。**一个月一千二百行，其中「待定」四十行**，这两个数往那儿一放，谈的东西就具体了——**做了多少、有多少是机器没把握的、那四十份是哪一类。**

> **这一条要在报价的时候就说。** [第 11 卷](../11-客户与报价/README.md)那套按工作流报价的思路，**报的量从哪儿来，就是从这张表来。**

## 记什么

**七列，一列一列说它为什么在。**

| 列 | 记的是什么 | 为什么要它 |
| --- | --- | --- |
| 时间 | 这一行是什么时候写的 | 按时间查；也能看出这条流程是不是还活着 |
| 文件名 | 交件人给的那个原名 | **回溯的钥匙**。客户嘴里说的是这个名字，不是新名字 |
| 类别 | 机器判成了什么 | 筛「待定」靠它 |
| 理由 | 模型自己给的那一句 | **判错的时候，这一列告诉你它是被什么误导的** |
| 去处 | 文件最后放在哪儿 | 客户问“在哪儿”，答案就是这一格 |
| 结果 | 成功还是失败 | 失败的要能一眼筛出来 |
| 出错信息 | 失败时命令行报的话 | 排查用 |

**“理由”那一列值得单说。**

它看上去是多余的——文件已经归好类了，还留一句理由干什么。**但它是这张表里最难重建的一列。**

判错的那一份，**你事后去看原件，只能看出它应该是合同**；**你看不出机器当时为什么判成了发票。** 有了这一列，你会看到它写着“有金额和税额”——**这一句直接告诉你提示词该怎么改**（[第 8 卷第 7 章](../08-OCR/07-错的怎么拦.md)那条“同一类问题多了就回去改提示词”）。

**这一列不给客户看也没关系，它是给你自己看的。**

## 第一步：先建好这张表

**追加模式不会帮你写表头**，所以先手工建一个只有表头的文件。

```bash
printf '\xEF\xBB\xBF"时间","文件名","类别","理由","去处","结果","出错信息"\n' > ~/ai/projects/intake/台账.csv
```

看一眼：

```bash
cat ~/ai/projects/intake/台账.csv
```

**两处说明：**

**一、开头那个 `\xEF\xBB\xBF`，是[第 8 卷第 5 章](../08-OCR/05-批量处理.md)那个 `utf-8-sig` 记号。** 三个字节，放在文件最前面，**Excel 看到它才知道这是 UTF-8，中文才不会乱码。** 那一章是让 Python 写的，这里没有 Python，就直接用 `printf` 把这三个字节打进去。

**二、每一格都用双引号包着。** 理由下面那一节说。

**这条命令用的是 `>` 不是 `>>`**——**它会把已有的内容盖掉。** 台账已经有数据了再跑一次，数据就没了。**只在第一次建的时候跑它。**

## 第二步：拼台账，写进去

三个节点，接在[第 7 章](07-案例二-进件分类.md)那个“搬文件”后面。

### 先改一处设置：搬文件失败也要记一行

**在“搬文件”那个节点的设置里，把 On Error 那一项改成“继续”**（措辞可能是 Continue，**以实际界面为准，需要核验**）。

**不改的话，`mv` 出错的那一份会让整条流程当场停下**，后面写台账那几步根本轮不到跑——**结果就是失败的那些一行记录都没有，正好是你最需要记录的那种情况。**

**这个设置和它的另外两个选项，[第 11 章](11-日志与重试.md)讲。** 这里先照做。

### 九之后：Code 节点，改名叫“拼台账”

从“搬文件”拖一条线出去，加一个 **Code** 节点。

- **Mode** 选“跑一次，处理全部数据”那一项；
- 代码照抄：

```javascript
// 拼台账 —— 把这一轮处理过的每一份，各拼成一行 CSV
// 模式：跑一次，处理全部数据

const 两位 = (n) => String(n).padStart(2, '0');
const d = new Date();
const 时间 =
  `${d.getFullYear()}-${两位(d.getMonth() + 1)}-${两位(d.getDate())}` +
  ` ${两位(d.getHours())}:${两位(d.getMinutes())}:${两位(d.getSeconds())}`;

// CSV 里一格的写法：整格用双引号包住，格里本来有的双引号写两遍
const 一格 = (v) => `"${String(v === undefined || v === null ? '' : v).split('"').join('""')}"`;

const 归宿们 = $('定归宿').all();
const 结果们 = $input.all();

const 行们 = 结果们.map((结果, i) => {
  const 归宿 = 归宿们[i] ? 归宿们[i].json : {};
  const 成功 = String(结果.json.exitCode) === '0';
  return [
    时间,
    归宿.文件名,
    归宿.类别,
    归宿.理由,
    成功 ? 归宿.目标路径 : '',
    成功 ? '成功' : '失败',
    成功 ? '' : 结果.json.stderr,
  ]
    .map(一格)
    .join(',');
});

return [{ json: { 台账片段: 行们.join('\n') + '\n' } }];
```

**五处要说明。**

**一、`一格` 那一行是这段代码的正题，它在做 CSV 的转义。**

CSV 用逗号分格。**可是“理由”那一列是模型写的一句话，里面完全可能有逗号**；文件名里也可能有。不管的话，一行会被 Excel 拆成八格九格，**整张表从那一行开始就错位了。**

规矩有两条，两条都要做：

- **整格用双引号包住**——包住之后，格里的逗号就是普通逗号，不再是分隔符；
- **格里本来有的双引号，写两遍**——`他说"好"` 要写成 `"他说""好"""`。**不写两遍的话，第一个双引号就把这一格提前结束了。**

**这是这一卷第二次做转义**，上一次是[第 7 章](07-案例二-进件分类.md)那个给命令行用的单引号。**两次是同一件事：这段文字要放进一个有自己语法的地方，就得按那个地方的规矩改写一次。**

**二、`$('定归宿').all()` 和按下标对齐。**

[第 5 章](05-案例一-模型摘要.md)那个 `$('节点名').item` 取的是“和当前这条对得上的那一条”，**那是在每条各跑一次的模式下用的**。这个节点选的是跑一次处理全部数据，**没有“当前这条”**，所以改用 `.all()` 把全部拿过来，再按下标一一对上。

**这依赖一件事：“搬文件”吐出来的条数和顺序，跟“定归宿”是一样的。** 正常情况下是这样，**但这一条本项目没有实测过，需要核验**——跑一次，把输出里的文件名和你实际看到的对一遍。

**三、`String(结果.json.exitCode) === '0'` 这个写法。**

命令行的规矩是：**跑完返回 0 表示成了，别的数字表示出了事。** 这里判它是不是 `0`。

**用 `String(...)` 包一层，是因为这个字段可能是数字也可能是字符串**；而且万一这个字段根本不在（节点报错的时候），`String(undefined)` 是 `'undefined'`，**照样判成失败**，不会因为一个 `undefined` 把代码搞崩。

**四、失败的那几行，“去处”留空。** 文件没搬成，就不该写一个它并不在的路径进去。**台账里的每一格都要是真的**，这一条比“表格填满”重要。

**五、最后返回的是一条数据，里面是一大段多行文字。**

**这一轮处理了五份，就是五行，一次写进去。** 换成每份各写一次的话，一轮要开五次文件，**没必要，而且五次里断在第三次的话，台账会是半截的。**

### 十之后：Convert to File

拖出去，加 **Convert to File**（[第 6 章](06-案例一-每日推送.md)用过）：

- **Operation** 选 **Convert to Text File**；
- **Text Input Field** 填 `台账片段`；
- 字符编码保持默认，**默认是 UTF-8**。

> **这里不要再加一次那个 `utf-8-sig` 记号。** 那三个字节只该出现在文件最前面，**每次追加都加一遍的话，文件中间会冒出一堆看不见的怪字符**，Excel 打开是乱的。上面建表头那一步已经加过了，**这里就是纯 UTF-8。**

### 十一之后：Read/Write Files from Disk

再拖出去，加 **Read/Write Files from Disk**：

- **Operation** 选 **Write File to Disk**；
- **File Path and Name** 填 `/intake/台账.csv`；
- **Input Binary Field** 填上一步那个字段名（默认常是 `data`，**以面板上显示的为准**）；
- **选项里加上 Append，打开它。**

**最后那一项是这一步的关键。** 官方文档写明这个节点的写文件操作有一个追加选项——**打开是往末尾接着写，不打开是整个盖掉。**

**不打开的表现很好认**：台账永远只有最近这一轮的那几行，**前面的全没了。** 发现这个表现，回来看这个开关。

**表头下面多出两三行就成了。**

## 第三步：这张表怎么看

### 最省事的看法

**用表格软件打开，做三件事：**

- **按“类别”那一列排序**——「待定」会聚在一起，**这就是今天要人看的那一堆**；
- **按“结果”那一列筛「失败」**——有没有搬不动的；
- **按“文件名”搜**——客户问某一份在哪儿，一秒钟就答得上来。

[第 8 卷第 7 章](../08-OCR/07-错的怎么拦.md)那条建议在这里同样成立——**同一类东西反复出现在「待定」里，那不是复核的事，那是回[第 7 章](07-案例二-进件分类.md)加一个类别、改一段提示词的事。**

### 行数多了怎么办

**一天几十行的话，一年下来一两万行，表格软件还开得动。**

**再多就该进数据库了。** 做法不用重写——[第 8 卷第 11 章](../08-OCR/11-对接.md)那个把台账 CSV 装进 SQLite 的脚本，**只用 Python 自带的东西，什么都不用装**。拿过来改一处：**把那个脚本里的列名换成这一章这七列**，其余不动。

**换过去之后能干的事，那一章都写了**——按月份统计、按类别统计、按文件名精确查、把结果导给别的系统。

> **什么时候才真的需要数据库，[第 8 卷第 11 章](../08-OCR/11-对接.md)那一节写了判断标准。** 在到那个门槛之前，**一个 CSV 文件比一个数据库好交付**——客户双击就能看，不用装任何东西。

### 台账要不要按月分成几个文件

**这一章不分，就一个文件。** 理由是分了之后查一个文件名要开好几个文件，**而查是这张表最主要的用途。**

**真要分**，把上面那个写文件节点的路径改成表达式，按月拼一个名字：

```text
/intake/台账-{{ $now.format('yyyy-MM') }}.csv
```

**这个日期写法需要核验**，以你面板上的预览为准。**分了之后每个月第一次跑之前，要手工建一次那个月的表头文件**——上面那条 `printf` 换个文件名再跑一遍。

## 第四步：已经处理过的，不要再处理一遍

**这是[第 7 章](07-案例二-进件分类.md)埋下的那件事。**

### 先说现在为什么大多数时候不会重复

**因为文件被搬走了。**

一份文件分好类之后，它已经不在 `inbox/` 里了。下一轮 `find` 去扫收件箱，**根本扫不到它**。

**这一层是天然的，不用写任何代码。** [第 8 卷第 6 章](../08-OCR/06-文件夹监测.md)那套目录流转就是这个道理——**搬走这个动作本身，就是“这份归我了”的标记。**

### 那还差什么

**两种情况会漏。**

**一、搬失败了。** 权限不够、目标目录被人删了、磁盘满了。文件还在 `inbox/` 里，**下一轮会再处理一遍。**

**这一种其实是我们想要的。** [第 8 卷第 5 章](../08-OCR/05-批量处理.md)那一条：**失败的那些每次重跑都会自动再试一次，文件修好了、权限修好了，直接重跑就补上了。** 不要挡它。

**二、同名文件又进来一次。** 客户以为上次没成功，又拷了一份同名的进来。**这一份会被当成新文件重新走一遍**，多花一次模型调用，多一行台账。

**还有一种更麻烦的**：这条流程改到一半，你手工把某个文件从分类目录拷回 `inbox/` 去试，**试完忘了删。**

### 做法：拿台账当那份“跑过的记录”

**[第 8 卷第 5 章](../08-OCR/05-批量处理.md)那个跳过机制的思路，原样搬过来。**

那一章的做法是：**每份单据跑完在 `out/` 里留一个同名的 JSON，下次看到这个 JSON 已经在了就跳过。**

这里没有 `out/` 那个目录，**但台账里已经有那份记录了**——处理成功过的文件名，表里有一行。**所以规则是：文件名在台账里出现过，而且那一行的结果是「成功」，这一轮就跳过它。**

**“而且结果是成功”这半句不能省。** 少了它，上面第一种情况（搬失败了）就被挡住了，**失败的那一份从此再也不会被重试**，永远躺在收件箱里。

### 三个节点，插在“拆成一条一份”后面

**位置**：接在[第 7 章](07-案例二-进件分类.md)那个“拆成一条一份”后面，**在“读进来”之前**。原来那条线断开重连。

**一、Read/Write Files from Disk，改名叫“读台账”：**

- **Operation** 选 **Read File(s) From Disk**；
- **File(s) Selector** 填 `/intake/台账.csv`；
- 选项里 **Put Output File in Field** 填 `台账`；
- **节点设置里把“只跑一次”（Execute Once）打开。**

**最后那一项要说一句。** 上一个节点吐出来的是几条数据（几个待处理的文件），**这个节点不打开这个开关的话会跑几遍，把同一个台账读几份回来**。台账只需要读一次。

**二、Extract From File，改名叫“拆台账”：**

- **Operation** 选 **Extract From CSV**；
- **Input Binary Field** 填 `台账`；
- **节点设置里把 Always Output Data 打开。**

**这个节点把 CSV 拆成一行一条数据**，每一行的列名就是字段名。

**Always Output Data 那一项是给一种情况准备的**：台账里只有表头、一条数据都没有的时候（第一次跑就是这样）。**不打开的话，这个节点吐出零条，后面的节点全都不跑，这条流程从这儿就断了。** 打开之后它会吐一条空的出来，**后面照常跑。**

**这个节点拆出来的字段名叫什么、第一行算不算表头，需要核验**——跑一次看输出面板，**列名应该就是你在表头里写的那七个中文名。**

**三、Code 节点，改名叫“挑没处理过的”：**

- **Mode** 选“跑一次，处理全部数据”那一项；
- 代码照抄：

```javascript
// 挑没处理过的 —— 台账里成功处理过的文件名，这一轮不再碰
// 模式：跑一次，处理全部数据

// 一、把台账里“结果”是成功的那些文件名收进一个集合
const 处理过 = new Set();
for (const 行 of $input.all()) {
  const 名字 = 行.json['文件名'];
  const 结果 = 行.json['结果'];
  if (名字 && String(结果).trim() === '成功') {
    处理过.add(String(名字).trim());
  }
}

// 二、这一轮扫到的文件，逐个对一下
const 这一轮 = $('拆成一条一份').all();
const 要处理的 = 这一轮.filter((条) => !处理过.has(条.json.文件名));

// 三、跳过了几个，写一行到执行记录里，事后能看
console.log(`这一轮扫到 ${这一轮.length} 个，跳过 ${这一轮.length - 要处理的.length} 个`);

return 要处理的;
```

**三处说明：**

- **`new Set()` 是一个不重复的集合**，`.add(...)` 往里放，`.has(...)` 问在不在。**台账有一万行也不慢**，比一行行去比对快得多；
- **`行.json['文件名']` 用的是方括号写法**，因为字段名是中文。**取不到值的话，先去上一个节点的输出面板看列名到底叫什么**；
- **`console.log(...)` 那一行是打给你自己看的。** 这个节点的输出面板上会有一块日志，**跳过了几个，一眼看得见**。这一行删掉也不影响功能。

**把这个节点连到“读进来”。** 原来“拆成一条一份”直连“读进来”那条线要删掉。

### 验一次

**这一次要故意制造重复。**

1. 往 `inbox/` 里丢一份文件，等一分钟，执行一次。**文件被分类搬走，台账多一行**；
2. **把它从分类目录里拷一份回 `inbox/`，名字不改**；
3. 等一分钟，再执行一次。

**第二次的表现应该是**：“挑没处理过的”那个节点的日志里写着跳过 1 个，输出是空的，**后面的节点全是灰的，模型一次都没被调用**，台账没有多出新行。

**那份文件会一直留在 `inbox/` 里。** 这是对的——**这条规则的意思是“不再处理它”，不是“把它删掉”。** 删文件这件事本卷任何一条流程都不做，[第 10 章](10-案例三-人工确认.md)会把这条写成一条硬规矩。

> **这一条规则的性质有个名字，叫幂等。** 意思是同一件事做一遍和做十遍，结果一样。**这条流程现在有了这个性质**——同一份文件丢进来十次，模型只被问一次，台账只多一行。**[第 11 章](11-日志与重试.md)会讲为什么这条性质是自动重试的前提。**
