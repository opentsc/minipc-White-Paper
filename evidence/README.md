# 商业证据库

本项目的商业章节以 B 级材料为主。它回答“现在有人在卖什么、客户在找什么、Max395 可以如何承接”，不把技术可行性写成已经获得收入。

## 分类

| 分类 | 含义 | 目录 |
| --- | --- | --- |
| H | 精确 Max395 的购买、交付或实际使用 | [`hardware/`](hardware/README.md) |
| B1 | 有产品、服务、价格、购买或咨询入口 | [`b1-products/`](b1-products/README.md) |
| B2 | 有生产使用、客户部署或服务商第一方交付说明 | [`b2-deliveries/`](b2-deliveries/README.md) |
| B3 | 有采购、外包、询价、招聘或公开预算需求 | [`b3-demand/`](b3-demand/README.md) |
| D | 从硬件能力和邻近市场推导的可售产品 | [`inference/`](inference/README.md) |
| X | 不采用或需要降级的材料 | [`rejected/`](rejected/README.md) |

同一案例可以同时说明硬件和产品，但统计时只按研究问题所需的最高证据使用一次。

## 写入正文的规则

- 写清来源是厂商、服务商、客户、采购方还是社区用户；
- 挂牌价、项目预算、中标价和实际付款分开；
- 服务商自述不写成独立客户确认；
- 邻近硬件案例不写成 Max395 精确案例；
- 本地运行不自动等于满足 HIPAA、GDPR 或其他合规要求；
- 能运行某个工作负载，不等于该工作负载已经有人付费；
- 页面内容和价格需要在引用日期重新核验。

## 当前判断

已有材料足以支持 6 套商业产品的设计：设备、私有知识库、OCR、本地 API、Agent/RPA 和运维。公开材料仍未形成“普通买家使用 Max395 提供某项服务并取得可独立核验收入”的完整证据链。
