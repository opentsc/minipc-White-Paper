# 案例 02　私有知识库（带评测问题集）

这份文档用于一台已经跑着 Ollama 和 Open WebUI 的 Mini PC。完成以后，这台机器上有一个用真实文件建起来的知识库：回答带原文出处，点开能翻到那一段，查不到的时候它说查不到，而且这一切在拔掉网线之后照样成立。同时你手上会有一张填过的评测表——二十道固定的题，跑一遍打勾打叉，以后每次改参数、加文件都重跑同一张表。附带一个体检脚本，一条命令逐项检查，不通过的写清回教材哪一章。

对应教材[第 7 卷第 3 章](../../../book/07-RAG/03-建第一个知识库.md)、[第 4 章](../../../book/07-RAG/04-让回答带来源.md)、[第 5 章](../../../book/07-RAG/05-阻止瞎编.md)、[第 7 章](../../../book/07-RAG/07-评测问题集.md)和[第 9 章](../../../book/07-RAG/09-断网演示.md)。embedding 模型那一层在[第 6 卷第 12 章](../../../book/06-本地模型/12-embedding与reranker.md)。

体检脚本只读，不改任何配置，在没配置过的机器上跑也不会出事——查不到的项目它报“跳过”，不报错。它唯一会“动”的地方是向 embedding 接口发一句话算一次向量，那会让那个模型被加载进内存，**那是这套东西本来就要做的事**。

## 完成结果

- **有个库**：Open WebUI 里建了一个知识库，文件传完、索引走完，份数和你自己数的对得上。
- **向量模型是本地的**：管理员面板里的语义向量模型指向本机的 `bge-m3`，不是那个要联网下载的默认模型。
- **回答带出处**：每个回答下面有引用，点开能看到原文片段和它出自哪个文件。
- **查不到会说查不到**：自定义模型上写了系统提示词，故意问库里没有的事，它明说没查到，然后停下。
- **有一张评测表**：二十道题跑完，三个格子逐个打过勾，`／20` 那一栏填了数，“本次改动”那一栏没留空。
- **断网照跑**：拔掉网线、关掉无线，新开一个对话再问三道题，答案和引用照常出来。
- `check-rag.sh` 一条命令跑完全部检查，通过与否有明确的退出码。

## 准备条件

- [案例 01：全家或全公司的 ChatGPT](../../level-50/01-family-chatgpt/README.md) 做完，那个体检脚本是通过的。**这个案例建在它上面。**
- 教材第 6 卷第 12 章做完，`ollama pull bge-m3` 拉过，`/v1/embeddings` 跑得通。
- 一批文件。**用真实文件，别用样例**——教材第 9 卷第 9 章那份检查清单第 5 条。自己公司的制度文件是最省事的一批（教材第 7 卷第 12 章说了五条理由）。
- 那批文件你自己读过，**或者能找到一个天天在回答这些问题的人**。出评测题要靠他。
- 硬盘上留几 GB。库本身不大，索引和上传的原件都在 Open WebUI 的数据目录里。
- 半天到一天。文件干净的话半天够。

检查环境。

```bash
ollama list | grep -i bge
docker ps --format '{{.Names}}\t{{.Status}}'
df -h /
```

## 文件

```text
README.md                      就是这份
eval-questions.example.md      评测问题集模板，二十道题的骨架，示例题都是虚构的
system-prompt.example.txt      系统提示词，教材第 7 卷第 5 章那七条，照抄
scripts/check-rag.sh           体检脚本，只读
```

两个 `.example` 文件本身不会被执行，**它们是给你照抄和照填的**。

## 操作步骤

### 1　复制到固定位置

```bash
mkdir -p "$HOME/apps"
cp -R labs/level-60/02-private-rag "$HOME/apps/private-rag"
cd "$HOME/apps/private-rag"
chmod 755 scripts/check-rag.sh
```

只下载了这个案例，就把案例目录放到 `$HOME/apps/private-rag`。

### 2　先跑一次体检，看现在差哪几项

**动手之前先跑一次**，把不通过的那几项抄下来，做完再跑一次对照。

```bash
./scripts/check-rag.sh
```

刚做完案例 01 的机器上，多半是第 1 项通过、后面几项跳过或者不通过。**那是对的**——库还没建。

### 3　按教材整理文件

教材第 7 卷第 2 章那一整章。四件事：

```bash
mkdir -p ~/kb/{ready,need-ocr,excluded,archived}
```

- 能选中字的进 `ready/`；
- 扫描件挑出来放 `need-ocr/`（教材第 7 卷第 2 章那条 `pdftotext` 命令一批一批查）；
- 空白表单、工资表、个人信息这类进 `excluded/`；
- 旧版本进 `archived/`。

**`ready/` 里有几份，数下来记住。** 第 5 步要对这个数。

### 4　先把向量模型换成本地的

**顺序不能反：先定模型，再建库**（教材第 7 卷第 3 章第一节）。

管理员面板 → 设置 → 文档，把语义向量模型换成本机的 `bge-m3`。**这一页的栏目名称和位置随版本变化，需要核验，以你界面上看到的为准。**

**这一步是后面断网演示的前提。** 默认那个向量模型要从外网下载，留着它，拔网线当场翻车（教材第 7 卷第 9 章那四个翻车点里的第三个）。

### 5　建库、传文件、对数

工作区 → 知识库 → 新建 → 把 `ready/` 里的文件传进去，等每个文件的索引状态走完。

**走完之后数一遍库里有几份，和第 3 步记的那个数对上。** 对不上就去找少了哪一份（教材第 7 卷第 3 章第五步）。

### 6　建一个自定义模型，把提示词写进去

工作区 → 模型 → 新建一个（比如叫 `公司制度助手`），挂上第 5 步那个库。

然后把系统提示词粘进去：

```bash
grep -n '' system-prompt.example.txt
```

**分割线以下那一整段，原样复制到系统提示词那一栏。**

改完在**新对话**里测，模型选择框里选的要是这个自定义模型——教材第 7 卷第 5 章那两条“改完不生效的常见情况”。

### 7　考它一遍：故意问库里没有的

教材第 7 卷第 5 章那四类题，每类问两三道：明显没有的、像有其实没有的、半有半没有的、前提就是错的。

**合格的表现是明说资料里没有，然后停下。** 它接一句“不过通常来说……”就是没生效，回教材那一节查。

### 8　把评测问题集填出来

```bash
cp eval-questions.example.md eval-questions.md
```

**模板里的题全是虚构的示例，一道都不要直接用。** 按你自己那批文件重出二十道，四类各五道（教材第 7 卷第 7 章）。

**C 类那五道从第 7 步搬过来，不重新出。**

**期望答案要在跑之前写好。** 跑完再写，就变成了对着结果找理由（教材第 7 卷第 17 章那一节）。

### 9　跑一遍，填表

一道一道问，一道一道记。每题三个格子：答对没有、引用对不对、有没有瞎编。

**引用要真的点开看**，不能凭回答里那句“出自某某文件”就打勾。

**只打勾打叉，不算百分比。** 合计只数“三个格子全是勾”的有几道，记成 `17／20` 这种写法。

`eval-questions.md` 里存着的这一份就是基线。**以后每次改参数、加文件，把同一张表重跑一遍。**

### 10　断网试一次

教材第 7 卷第 9 章那份检查清单先过一遍，然后：

```bash
nmcli networking off
ping -c 3 example.com
```

第二条应该不通。**这时候新开一个对话，问三道不同的题**，答案和引用照常出来。

问完插回去：

```bash
nmcli networking on
```

**这一步在自己机器上先走一遍，别在客户面前第一次试**（教材第 7 卷第 12 章那一节）。

### 11　再跑一次体检，存一份

```bash
./scripts/check-rag.sh
echo $?
./scripts/check-rag.sh > "check-$(date +%F).txt" 2>&1
```

交付给客户的机器，这份输出是验收单的附件之一。**往外发之前按教材[第 0 卷第 8 章](../../../book/00-使用说明/08-文件保护.md)看一遍**——输出里带内网地址、容器名、模型名和数据目录路径。

一台配好的机器上，`./scripts/check-rag.sh` 的输出（地址、路径、容器名会换成你自己的）：

```text
结果　通过 5 项，不通过 0 项，跳过 0 项

```

还没配的机器上，不通过的那几项后面会带着回哪一章，比如：

```text
第 1 项　embedding 模型装了没有
  不通过　本地没有 bge-m3，也没找到别的 embedding 类模型（教材第 6 卷第 12 章）
```

没装某样东西的项目报“跳过”，不算不通过。没装 Docker 的机器上第 2 项就是跳过，退出码仍然是 0。

## 验收标准

七条全部满足才算通过。

1. `./scripts/check-rag.sh` 输出“体检通过”，退出码是 0（`echo $?` 查）。
2. 界面上库里的文件份数，和你自己在 `ready/` 里数的那个数对得上。
3. 随便问一道题，回答下面有引用，**点开能看到原文片段，和原文件里那一段对得上**。
4. 故意问四道库里没有的（教材第 7 卷第 5 章那四类各一道），**四道都明说资料里没查到，而且没有下文**。
5. `eval-questions.md` 二十道题填完，三个格子逐格记过，`／20` 那一栏有数，“本次改动”那一栏没留空。
6. `nmcli networking off` 之后，**新开对话问三道不同的题**，答案和引用照常出来；问完插回去。
7. `sudo reboot` 之后**不做任何操作**，两分钟内网页界面还在，那个库还在，再问一道题照常答。

**第 6 条是这个案例和“把文件拖进对话框”的分界线。** 过不了这一条，你没有任何东西可以演示给客户看。

**第 7 条管的是交付出去以后。** 库还在但容器没自己回来，客户第二天早上打电话给你。

## 可以出售的结果

- **私有知识库交付**：给客户把他自己的文件建成一个能查的库，回答带出处，查不到会说查不到。交付时当场跑一次体检脚本，把输出和那张填完的评测表一起放进验收单。**卖点是断网那一下**——律所、诊所、会计事务所这类不敢把资料贴进云端的客户，看的就是这一条（教材第 7 卷第 11 章）。
- **评测与验收服务**：按教材第 7 卷第 17 章那套流程，和客户一起把二十道题跑完、签字、存档。**这一项能单独收费，也是尾款的依据。** 半年后客户说“它不如以前了”，把同一张表重跑一遍就有结论。
- **文档整理**：多数客户的文件是乱的。按教材第 7 卷第 2 章那四堆分法整理一遍、定文件名规矩、把扫描件挑出来，**这一段本身就是工作量**，而且它决定了后面所有事的质量。
- **行业变体**：律所合同库、公司制度库、客服知识库、研究资料库、产品手册库，各自的坑和提示词补充条款在教材第 7 卷第 11 到 15 章。**同一台机器、同一套流程，换一个行业就是另一个客户。**
- **语义搜索改造**：客户只要搜得准、不要生成回答的，用教材第 7 卷第 16 章那两个脚本，接进他已有的系统。**这一项能拆出来单卖。**
- **季度体检**：每季度跑一次体检脚本加那张评测表，出一页对照上一次的差异。**库会漂**——有人加了两百份文件、有人换了模型、有人把旧版本又传回去了（教材第 7 卷第 10 章）。

**上面这些是可以准备的方向，不是已经验证过的成交路径。** 公开渠道里，这个方向有需求证据和定价参照，**没有可核验的成交案例**。价钱怎么报在教材第 11 卷。

## 常见问题

### 第 1 项说没有 embedding 模型

```bash
ollama pull bge-m3
ollama list
```

名字变了的话去 `ollama.com/library` 上看当天有哪些 embedding 类的模型（教材第 6 卷第 12 章）。用别的模型就指定一下：

```bash
CHECK_EMBED_MODEL=你的模型名 ./scripts/check-rag.sh
```

### 第 3 项说找不到数据目录

脚本默认查两个地方：`$HOME/ai/projects/open-webui/data`，以及叫 `open-webui` 的那个 Docker 数据卷。都不是就指定一下：

```bash
CHECK_DATA_DIR=/你的路径 ./scripts/check-rag.sh
```

数据卷的挂载点通常只有 root 读得了，**这一项报“跳过”是正常的**，加 `sudo` 再跑一次就能看到。

### 第 4 项说接口没有返回向量

三种常见原因，按顺序试：

1. 模型名不对。`ollama list` 照抄，或者用 `CHECK_EMBED_MODEL=` 指定。
2. 填的是对话模型。**对话模型和 embedding 模型是两类东西**，它会报“不支持 embeddings”（教材第 6 卷第 12 章）。
3. 接口没通。回案例 01 第 5 步，`ss -tln | grep 11434` 看是不是 `0.0.0.0`。

### 第 5 项说容器环境变量里有指向外网的地址

**把脚本打出来的那几行念一遍**，每一个地址你都要说得出它是干什么的。连的是本机、内网或者 `host.docker.internal` 都正常；**是一个公网域名，就要弄清楚断网之后它会不会挂住。**

### 断网之后它答不出来了

按教材第 7 卷第 9 章那四个翻车点查，**最常见的是第三个**：向量模型还是那个要联网下载的默认模型，第 4 步没做或者没保存。

### 回答不带引用

回教材第 7 卷第 4 章那一节。最常见的两条：问的时候没挂上知识库；用的不是第 6 步那个绑了库的自定义模型。

### 它还在瞎编

回教材第 7 卷第 5 章“改完不生效的两种常见情况”：模型选择框里选的还是原来那个基础模型；老对话带着旧设置，**新建一个对话再测**。

### 回答不准，但不瞎编

那是另一件事，教材第 7 卷第 6 章。**先按那三种情况分类，再一次只动一个旋钮**，改完把整张评测表重跑一遍。

其余的按教材第 15 卷的症状表走。

## 停止和恢复

这个案例没有新起任何服务，**停和恢复都是案例 01 那一套**。

删掉一个知识库：工作区 → 知识库 → 删掉那一个。**上传的原件和索引一起没**，原始文件还在你的 `ready/` 里。

换 embedding 模型之后：**整个库要重建索引**，对话里直接传过的文件不会跟着更新（教材第 6 卷第 12 章、第 7 卷第 10 章）。

把数据整个备份走：

```bash
docker stop open-webui
tar -czf "kb-backup-$(date +%F).tar.gz" -C "$HOME/ai/projects/open-webui" data
docker start open-webui
```

**停容器再打包**，正在写的时候打包可能拿到半份。

体检脚本本身不用停也不用恢复，它只读，删掉就是了。

## 隐私边界

- **库里装的是客户的真实文件。** 这个目录、这个数据卷、这份备份，全部按内部资料对待（教材第 2 卷第 12 章）。
- **`ready/`、`need-ocr/`、`archived/` 这几个目录不进 Git**，交付完按约定删掉并且给客户一个书面确认。
- **`excluded/` 里那些是有理由被挡在门外的**——工资表、个人信息、空白表单。**别因为“反正也搜不出来”就顺手传进去**（教材第 7 卷第 2 章）。
- **`eval-questions.md` 里会有客户的真实问题和真实答案**，它本身就是客户资料。**模板文件 `eval-questions.example.md` 里的题全是虚构的**，可以公开；填过的那一份不要。
- **体检脚本的输出里有内网地址、容器名、模型名和数据目录路径。** 往外发之前逐行看一遍（教材第 0 卷第 8 章）。
- 脚本不读知识库内容、不读对话记录、不读任何密钥、不发送任何数据到外部。它调用的是系统自带的查询命令，加上向本机 embedding 接口发的一句话。
- 交付客户机器时，管理员账号交给客户自己改密码，你自己的账号从里面删掉。

## 当前范围

这个案例只做**一个库、一台机器、一个界面**。

**没有做**：扫描件的处理（教材第 8 卷）、按部门分库和按人分权限（教材第 7 卷第 8 章，那一章的做法是同一套界面上的事）、定时更新和自动重建（教材第 9 卷）、给接口加认证（教材第 10 卷）、多台机器一起管（教材第 14 卷）。

**下一步可以接三样**：把 `need-ocr/` 那一堆按教材第 8 卷处理完再灌进来；按教材第 7 卷第 8 章把库拆成几个、按用户组控制谁能看哪个；按教材第 7 卷第 16 章加一个只搜不答的入口，接进客户已有的系统。
