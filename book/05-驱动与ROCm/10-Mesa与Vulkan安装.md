# 10　Mesa 与 Vulkan 安装

## 完成结果

Vulkan 那条路上要装的东西装完了。你确认过 Mesa 已经在位、用的是 Ubuntu 仓库自带的那一版，Vulkan 的实现登记文件在，检查工具包装上了。你也知道为什么本教材不为了追新版 Mesa 去加第三方软件源、加了会怎样、万一已经加了怎么退回去。

**本章不换 Mesa 版本，不加任何第三方软件源。** 装的只有一个检查用的工具包。

## 开始前需要准备什么

- **第 9 章的五条已经全部成立**：四个 `.txt` 清单在、`etc-backup/` 在、备份复制到了机器之外、恢复 U 盘能启动、整盘镜像的日期确认过。第 9 章末尾说过第 10 章可以跳着做，但本章末尾那一节讲的是软件源，**出错的影响面比装一个包大**，所以还是先把备份做完；
- 读过第 3 章（Mesa 是什么）、第 4 章（Vulkan 是什么）、第 8 章（本教材的基准组合）。**本章不重讲这三章的原理，只做操作**；
- 这台机器能连上网。本章从 Ubuntu 官方软件源下载，不需要访问别的地方；
- 大约 15 到 30 分钟，其中大部分是下载时间。下载量通常几十 MB，**精确数值本项目未记录，以你机器上 `apt` 给出的提示为准**；
- 本章要装东西，**装的是检查工具，不是系统核心组件**。真正有风险的一步在本章最后一节，那一节讲的是不要做什么。

## 新词

**软件源**（repository，也叫仓库）：`apt` 去下载软件包的服务器地址清单。装完 Ubuntu 之后，系统里只有 Ubuntu 官方的那几个。地址写在 `/etc/apt/sources.list` 和 `/etc/apt/sources.list.d/` 里（第 9 章第五步备份过这两处）。

**第三方软件源**：不是 Ubuntu 官方维护的那些。加进来之后，这台机器后续**所有**软件更新都会同时看这个源，影响面比装一个包大得多。

**PPA**（Personal Package Archive）：Ubuntu 上一种常见的第三方软件源，由个人或团队维护，地址写成 `ppa:作者名/仓库名` 的样子。加它用的命令是 `add-apt-repository`。

**软件包、包管理器、依赖**：第 9 章新词已经解释过。一句话回顾：软件包是安装的最小单位，`apt` 是管它们的程序，一个包要能跑得先装上别的包就叫依赖。

**卸载**（remove）：把一个软件包的程序文件从系统里拆掉。`apt remove` 只拆程序文件、留下配置文件；`apt purge` 连配置文件一起删。本章用到的是前一种。

**工具包**：本章要装的 `vulkan-tools` 属于这一类——它自己不参与跑模型，只提供几条查状态的命令。装了不影响任何程序的运行，卸了也不影响。

## 这一章要做的两件事

| 做什么 | 装不装东西 | 有没有风险 |
| --- | --- | --- |
| 确认 Mesa 和 Vulkan 的实现已经在位 | 不装，只读 | 没有 |
| 装一个 Vulkan 检查工具包 | 装一个包 | 极小，卸掉就回去了 |

**要装的东西就这么多。** 第 4 章说过原因：Vulkan 的实现（RADV）已经在 Mesa 里，Ubuntu 默认装好了；这条路上唯一缺的是查状态用的命令。

真正跑模型要用的 llama.cpp，走的是官方的 Ubuntu Vulkan 预编译包，下载解压就能用，**那一步在第 17 章，不在本章**。

全部照第 8 章那两张表，本章不另立版本。

| 组件 | 本章按什么值走 | 依据 |
| --- | --- | --- |

## 第一步：确认 Mesa 已经装好

```bash
dpkg -l | grep -i mesa
```

- **作用**：列出系统上已装的软件包，只显示名字或描述里带 `mesa` 的那些。第 3 章讲过这条命令怎么读，本章只用它确认现状。这条命令只读，不装也不删任何东西；
- **正常输出**：若干行，每行开头是 `ii`（已正常安装），常见的名字有下面这些（**具体有哪些包、版本号是多少，随你的 Ubuntu 小版本变化，本项目未固定，需要核验**）：

```text
ii  libegl-mesa0:amd64        25.0.7-0ubuntu0.24.04.1  amd64  free implementation of the EGL API -- Mesa vendor library
ii  libgl1-mesa-dri:amd64     25.0.7-0ubuntu0.24.04.1  amd64  free implementation of the OpenGL API -- DRI modules
ii  mesa-libgallium:amd64     25.0.7-0ubuntu0.24.04.1  amd64  shared infrastructure for Mesa drivers
ii  mesa-vulkan-drivers:amd64 25.0.7-0ubuntu0.24.04.1  amd64  Mesa Vulkan graphics drivers
```

**要看的是带 `vulkan` 那一行在不在。** RADV 就装在 `mesa-vulkan-drivers` 里面（第 3 章）。它在，Vulkan 的实现就在位；

- **看到别的怎么办**：
  - **一行都没有** —— 极少见，因为你能进桌面就说明 Mesa 在工作。先换个词再查一次：`dpkg -l | grep -i libgl`。还是没有，说明这台机器的图形栈和 Ubuntu 默认装法不一样，**先不要装任何东西**，按第 12 章的流程把 GPU 识别那五项走一遍再回来；
  - **有 Mesa 的包，但没有 `mesa-vulkan-drivers`** —— 这一个包缺了。补装的命令在下面“缺什么补什么”那一节，**先把那一节的警告读完**；
  - **行首不是 `ii`** —— `rc` 表示包卸了但配置还在，`iU` 表示装到一半。这属于软件包状态问题，第 3 章已说明，处理在[第 2 卷](../02-Ubuntu/README.md)。**状态不干净的时候不要往上叠加安装**；
  - **同一批包版本号不一致** —— 之前有过部分升级或部分回退。同样先按[第 2 卷](../02-Ubuntu/README.md)把状态理清楚；
- **怎么停止或撤销**：只读命令，不需要撤销。输出太长按 `Ctrl+C` 中断，或者用 `dpkg -l | grep -i mesa | less` 分页看（按 `q` 退出）。

## 第二步：确认 Vulkan 的实现登记文件在位

```bash
ls /usr/share/vulkan/icd.d/
```

- **作用**：列出系统上注册了哪几份 Vulkan 实现。第 4 章讲过这条命令，本章只用它确认现状。这条命令只读；
- **正常输出**：一个文件名，形如

```text
radeon_icd.x86_64.json
```

名字里带 `radeon` 的那个就是 RADV 的登记文件。**只有一个文件是正常的**——本教材不装 AMDVLK（第 3 章）；

- **看到别的怎么办**：
  - **提示 `No such file or directory`** —— 这个目录不存在，说明 Vulkan 那一层的包没装齐。多半是 `libvulkan1` 或 `mesa-vulkan-drivers` 缺了，按下面“缺什么补什么”处理；
  - **目录在但是空的** —— 同上；
  - **出现两个以上和 AMD 相关的文件** —— 这台机器上装了不止一份 Vulkan 实现，程序运行时可能挑错。**先不要急着删文件**，第 13 章有确认当前实际用的是哪一份的方法，看完那里再决定；
- **怎么停止或撤销**：只读命令，不需要撤销。

## 缺什么补什么

前两步都正常的话，**跳过这一节，直接做第三步**。

只有在第一步查到 `mesa-vulkan-drivers` 缺了、或者第二步查到目录不存在的时候，才补装下面这两个包。

> **⚠️ 这两个包是桌面正在用的东西。** `mesa-vulkan-drivers` 属于图形栈，`libvulkan1` 是所有 Vulkan 程序都要载入的那一层。从 Ubuntu 官方源补装它们通常不会出事，但只要动到图形栈，就有登录之后黑屏、或者输完密码又弹回登录界面的可能（第 9 章记录过这个表现）。
>
> **动手之前先确认第 9 章的备份做完了**，尤其是 `02-软件包清单-可回读.txt`。
>
> **万一重启之后进不了桌面**：在登录界面按 `Ctrl+Alt+F3` 切到文字终端，用你的账户名和密码登录，跑 `sudo apt install --reinstall mesa-vulkan-drivers libvulkan1`，然后 `sudo reboot`。文字终端切不回图形界面的话按 `Ctrl+Alt+F1` 或 `Ctrl+Alt+F2`。这两步都不行，用第 9 章准备的恢复 U 盘进 Live 模式（[第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)）。

```bash
sudo apt install mesa-vulkan-drivers libvulkan1
```

- **作用**：从 Ubuntu 官方源装这两个包。`mesa-vulkan-drivers` 里装的是 RADV，也就是这台设备上 Vulkan 的实现；`libvulkan1` 是 Vulkan 的加载层，程序通过它去找该用哪一份实现（第 3 章讲的 ICD 机制）。`sudo` 的含义见[第 4 卷第 9 章](../04-Max395硬件/09-UMA设置.md)新词，**输密码时屏幕上不显示任何字符是正常的**；
- **正常输出**：先列出要装什么、要下载多少、装完占多少空间，然后问你 `Y/n`。这两个包在多数机器上已经装着，所以**最常见的输出是下面这一句**：

```text
mesa-vulkan-drivers is already the newest version (25.0.7-0ubuntu0.24.04.1).
libvulkan1 is already the newest version (1.3.275.0-1build1).
0 upgraded, 0 newly installed, 0 to remove and 0 not upgraded.
```

**看到 `already the newest version` 就是好事**，说明本来就在，什么都没动。版本号随你的机器变；

- **看到别的怎么办**：
  - **列出的要装的东西里出现一大堆和图形无关的包** —— 停下来，按 `n` 取消。这说明系统里的包状态有问题，先按[第 2 卷](../02-Ubuntu/README.md)理清楚；
  - **提示要卸载（`to remove`）别的包** —— **一定按 `n` 取消**。从官方源装这两个包不应该卸掉任何东西。出现这种提示说明这台机器上有第三方源在起作用，先看本章最后一节；
  - **提示 `Unable to locate package`** —— 软件源清单是旧的。先跑第三步的 `sudo apt update`，再回来；
  - **提示 `Could not get lock`** —— 另一个程序正在用 `apt`（多半是系统自动更新）。等几分钟再跑；
- **怎么停止或撤销**：在问 `Y/n` 那一步按 `n` 回车就取消了，什么都不会动。已经装完想退回去，用 `sudo apt remove mesa-vulkan-drivers`——**但这两个包是桌面在用的，正常情况下不要卸**。真的要退，先把上面那个警告块里的恢复办法读完。

## 第三步：刷新软件源清单

```bash
sudo apt update
```

- **作用**：去各个软件源问一遍“现在有哪些包、各是什么版本”，把清单更新到本地。**这一步不装任何东西，也不升级任何东西**，只更新清单。装东西之前跑一次，是为了拿到最新的版本信息；
- **正常输出**：几行 `Hit:`、`Get:`，最后一行汇总，形如

```text
Hit:1 http://cn.archive.ubuntu.com/ubuntu noble InRelease
Hit:2 http://cn.archive.ubuntu.com/ubuntu noble-updates InRelease
Hit:3 http://security.ubuntu.com/ubuntu noble-security InRelease
Reading package lists... Done
Building dependency tree... Done
All packages are up to date.
```

**要看的是有没有 `Err:` 或 `W:` 开头的行。** 没有就算过；

- **看到别的怎么办**：
  - **出现 `Err:` 加超时或者连不上** —— 网络问题，或者软件源地址不通。先确认这台机器能上网，再重跑一次；
  - **出现 `W: ... NO_PUBKEY`** —— 某个软件源的公钥缺了。这台机器上装完 Ubuntu 不该出现这一条，出现说明有人加过第三方源。跑 `ls /etc/apt/sources.list.d/` 看看有哪些，处理在本章最后一节；
  - **出现 `Repository ... changed its ... value`** —— 某个源改了配置，需要确认。**这一条出现在第三方源上时，先看清楚那个源是谁加的**；
  - **提示 `Could not get lock`** —— 同上一条，等系统自动更新跑完；
- **怎么停止或撤销**：跑到一半按 `Ctrl+C` 中断，没有副作用，重跑一次就行。**这条命令只更新清单，不改系统上任何已装的软件。**

## 第四步：先看要装什么，再装

**先看不装**：

```bash
sudo apt install --dry-run vulkan-tools
```

- **作用**：模拟一次安装，把“会装哪些包、会不会卸掉什么”打印出来，但**不真的动手**。`--dry-run` 就是模拟的意思。装任何东西之前先跑这一条，是本教材的习惯做法，第 11 章装 ROCm 时这一条尤其重要；
- **正常输出**：末尾几行列出要装的包，形如

```text
The following additional packages will be installed:
  libvulkan-dev
The following NEW packages will be installed:
  libvulkan-dev vulkan-tools
0 upgraded, 2 newly installed, 0 to remove and 0 not upgraded.
Inst vulkan-tools (1.3.275.0+dfsg1-1 Ubuntu:24.04/noble [amd64])
Conf vulkan-tools (1.3.275.0+dfsg1-1 Ubuntu:24.04/noble [amd64])
```

**要看两件事**：`to remove` 那个数字是不是 `0`；列出的新包名字是不是都和 Vulkan 有关。具体带进来几个包随你的机器变，**本项目未固定，需要核验**；

- **看到别的怎么办**：
  - **`to remove` 不是 0** —— 停下来，不要往下装。有东西要被卸掉，说明依赖关系有冲突，多半是第三方源引起的。先看本章最后一节；
  - **列出几十个包** —— 不正常。`vulkan-tools` 是个小工具包，不该带进来一大堆。同样先查软件源；
  - **提示 `Unable to locate package vulkan-tools`** —— 软件源清单没更新，回第三步；
- **怎么停止或撤销**：这条命令什么都不动，不需要撤销。

**确认没问题再真装**：

```bash
sudo apt install vulkan-tools
```

- **作用**：装 Vulkan 的检查工具包。装完之后你会多出两条命令：`vulkaninfo`（打印 Vulkan 那一层认到了什么）和 `vkcube`（弹一个转动的立方体，用来看 GPU 是不是真的在画东西）。**这两条命令是第 13 章的主要检查手段**；
- **正常输出**：列出要装什么、下载量和占用空间，问 `Y/n`，按回车（默认是 `Y`）之后开始下载安装，最后回到提示符。形如

```text
The following NEW packages will be installed:
  libvulkan-dev vulkan-tools
0 upgraded, 2 newly installed, 0 to remove and 0 not upgraded.
Need to get 1,234 kB of archives.
After this operation, 5,678 kB of additional disk space will be used.
Do you want to continue? [Y/n]
```

**下载量和占用空间以你机器上的这一行为准**，上面的数字是格式示意；

- **看到别的怎么办**：
  - **和上面 `--dry-run` 看到的不一样** —— 中间软件源清单变了。按 `n` 取消，重跑一次第三步再来；
  - **下载中途断了** —— 重跑同一条命令，`apt` 会接着下。反复断说明网络不稳，换个时间；
  - **报 `dpkg was interrupted`** —— 上一次装到一半被打断了。按提示跑 `sudo dpkg --configure -a`，跑完再回来；
  - **提示 `E: Sub-process /usr/bin/dpkg returned an error code`** —— 包依赖有问题。先跑 `sudo apt --fix-broken install`，还不行按[第 2 卷](../02-Ubuntu/README.md)处理；
- **怎么停止或撤销**：问 `Y/n` 时按 `n` 取消，什么都不动。已经装完要退回去：

```bash
sudo apt remove vulkan-tools
```

**这个包卸了不影响任何别的东西**——它只是几条查状态的命令，桌面和推理程序都不依赖它。这也是本章说它风险极小的原因。

## 第五步：确认装上了

```bash
which vulkaninfo
```

- **作用**：看 `vulkaninfo` 这条命令在不在、在哪儿。`which` 就是“它在哪”的意思。这条命令只读；
- **正常输出**：一行路径

```text
/usr/bin/vulkaninfo
```

- **看到别的怎么办**：
  - **什么都不输出** —— 包没装上。回第四步重跑一次，看那一步有没有报错；
  - **输出的路径不在 `/usr/bin` 下面** —— 这条命令来自别的地方（可能是手工装的或者某个第三方源装的）。抄下来记进[第 4 卷第 16 章](../04-Max395硬件/16-设备基线.md)的设备基线，第 13 章检查结果异常时这条信息用得上；
- **怎么停止或撤销**：只读命令，不需要撤销。

**再记一条到备份目录**（把日期换成你第 9 章建目录时用的那个）：

```bash
dpkg -l | grep -i -E "mesa|vulkan" > ~/minipc-backup/2026-08-14/04-Mesa与Vulkan包.txt
```

- **作用**：把 Mesa 和 Vulkan 相关的包和版本号存成文件，放进第 9 章建的那个备份目录。`-E` 表示后面的 `mesa|vulkan` 是“或”的关系，两个词命中任何一个都算。以后升级系统之后再跑一次对照，能看出这两块有没有跟着变；
- **正常输出**：**屏幕上什么都不显示**，输出全进文件了。用 `cat ~/minipc-backup/2026-08-14/04-Mesa与Vulkan包.txt` 看内容；
- **看到别的怎么办**：
  - **提示 `No such file or directory`** —— 第 9 章那个备份目录不在，或者日期写错了。跑 `ls ~/minipc-backup/` 看看实际是哪个日期；
  - **文件是空的** —— 前面的筛选一行都没命中，回第一步查；
- **怎么停止或撤销**：撤销就是删掉这个文件，`rm ~/minipc-backup/2026-08-14/04-Mesa与Vulkan包.txt`。这条命令只读系统状态、只写一个新文件，**不改动系统上任何东西**。

**把 Mesa 的版本号同时抄进[第 4 卷第 16 章](../04-Max395硬件/16-设备基线.md)的设备基线**，连同你抄写的日期。第 8 章说过，只改数字不改日期等于没记。

## 禁区：不要为了追新版 Mesa 加第三方软件源

这一节是本章唯一有实际风险的地方。**它讲的是不要做什么。**

网上关于 AMD 新硬件的教程里，很常见的一条建议是“加某个 PPA 装最新版 Mesa”。**本教材不做这件事**，理由四条。

**一、本项目给不出“新版 Mesa 更好”的带来源依据。**

第 3 章已经标注：本项目来源目录里**没有收录“某个 Mesa 版本对 gfx1151 的支持门槛”的条目**，事实状态是待核验。也就是说，“升到某一版就好了”这句话，本教材没有证据支持。**为一个没有依据的收益去动图形栈，不划算。**

**二、加第三方源改的不是一个包，是这台机器后续所有更新的来源。**

第 9 章第五步专门备份 `/etc/apt/sources.list.d/` 就是为了这件事。加进来之后，`apt` 每次都会同时看这个源；这个源里只要有一个包版本号更高，升级系统时就会被换成它的版本。**影响面比装一个包大得多。**

**三、Mesa 是桌面正在用的东西，换错版本的典型后果是进不了桌面。**

第 3 章和第 9 章都记录过这个表现：登录之后黑屏，或者输完密码又弹回登录界面。**麻烦在于它不是当场发生的**——你装的时候一切正常，重启之后才发现进不去。

**四、第三方源里的 Mesa 版本可能比 Ubuntu 官方的新得多，依赖也跟着换。**

它往往会连带换掉一批基础库。这类改动一旦要退，靠卸载单个包是退不干净的，得用下面那个专门的工具。

> **⚠️ 加第三方软件源装 Mesa，属于替换系统核心组件。**
>
> **本教材主线不做这件事。** 你确实要做的话，动手之前先确认第 9 章的备份全部做完（尤其是 `etc-backup/sources.list.d/` 和 `02-软件包清单-可回读.txt`），并且确认恢复 U 盘能启动。
>
> **万一重启之后进不了桌面**，按下面这个顺序来：
>
> 1. 在登录界面按 `Ctrl+Alt+F3` 切到文字终端，用账户名和密码登录（这一步不需要图形界面）；
> 2. 按下面“万一已经加了怎么退回去”那一节的命令把第三方源移掉；
> 3. `sudo reboot`；
> 4. 文字终端也进不去，用第 9 章准备的恢复 U 盘进 Live 模式（[第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)）；
> 5. 系统彻底起不来，整盘镜像写回（[第 1 卷第 10 章](../01-开箱与安装/10-恢复介质.md)）。

## 万一已经加了怎么退回去

先说清楚：**这一节适用于第三方软件源，不适用于 Ubuntu 官方源。** 官方源不要动。

**第一步：看这台机器上有哪些第三方源**

```bash
ls /etc/apt/sources.list.d/
```

- **作用**：列出 Ubuntu 官方源之外，还加了哪些软件源。每个文件对应一个源。这条命令只读；
- **正常输出**：**在本教材的基准状态下，这个目录应该是空的，或者只有 Ubuntu 自己放的几个文件**（文件名里带 `ubuntu` 字样）。形如

```text
ubuntu.sources
```

- **看到别的怎么办**：
  - **出现名字里带别人 ID 的文件**（形如 `作者名-ubuntu-仓库名-noble.sources` 或 `.list` 结尾） —— 那就是加过的 PPA。抄下文件名，往下走；
  - **出现名字里带 `rocm` 或 `amdgpu` 的文件** —— 那是 ROCm 的官方源，第 11 章会加。**这一节不要动它**；
  - **提示目录不存在** —— 极少见。说明这台机器上从来没加过第三方源，这一节不用做；
- **怎么停止或撤销**：只读命令，不需要撤销。

**第二步：把 PPA 连同它装的包一起退回去**

`apt remove` 只能卸包，退不回被它换掉的那批库。要连版本一起退回官方源的版本，用 `ppa-purge`。

```bash
sudo apt install ppa-purge
```

- **作用**：装 `ppa-purge` 这个工具。它做的事是：把某个 PPA 从软件源里去掉，同时把被这个 PPA 换过版本的所有包，**降回 Ubuntu 官方源里的那一版**。这一点是 `apt remove` 做不到的；
- **正常输出**：常规的安装输出，列出要装什么、问 `Y/n`、按回车装完；
- **看到别的怎么办**：
  - **提示 `Unable to locate package`** —— 先跑 `sudo apt update`。还是找不到，说明官方源里没有它，那就只能走下面的手工路线；
  - **提示要卸载一批东西** —— 按 `n` 取消，走手工路线；
- **怎么停止或撤销**：问 `Y/n` 时按 `n` 取消。装完想拆掉：`sudo apt remove ppa-purge`。

```bash
sudo ppa-purge ppa:作者名/仓库名
```

- **作用**：把指定的 PPA 移除，并把被它换过的包降回官方版本。**`作者名/仓库名` 换成你在第一步查到的那个**——文件名 `作者名-ubuntu-仓库名-noble.sources` 对应的写法就是 `ppa:作者名/仓库名`；
- **正常输出**：先打印它要降级哪些包，问你确认，然后开始下载官方版本、逐个降级，最后一行形如

```text
Updating packages lists
PPA purged successfully
```

**过程中屏幕上会滚一大批包名，这是正常的**——被换过版本的每一个都要降回去；

- **看到别的怎么办**：
  - **提示 `PPA not found` 或者名字对不上** —— 写法不对。回第一步核对文件名。文件名里的 `-ubuntu-` 是固定的一截，写命令时要去掉；
  - **降级过程中报依赖冲突** —— 中断了也不要重启。先跑 `sudo apt --fix-broken install`，再重跑一次 `ppa-purge`；
  - **跑完了但桌面还是不对** —— 跑 `sudo apt install --reinstall mesa-vulkan-drivers libvulkan1 libgl1-mesa-dri`，然后重启；
- **怎么停止或撤销**：**这条命令会动系统上的包，中途按 `Ctrl+C` 会留下一个降到一半的状态**，比不动更麻烦。跑之前确认第 9 章的备份在。真的中断了，跑 `sudo apt --fix-broken install` 补齐，再重跑一次。

**第三步：`ppa-purge` 用不了时的手工路线**

工具装不上、或者那个源不是 PPA 而是别的形式时，用第 9 章的备份直接覆盖回去：

```bash
sudo cp -a ~/minipc-backup/2026-08-14/etc-backup/sources.list.d/. /etc/apt/sources.list.d/
sudo cp -a ~/minipc-backup/2026-08-14/etc-backup/sources.list /etc/apt/
sudo apt update
```

- **作用**：三条。前两条把第 9 章备份的软件源配置原样复制回系统里，`-a` 表示连权限一起保留，第一条末尾那个 `.` 表示“这个目录里的内容”而不是目录本身；第三条刷新清单。**把日期换成你自己的**；
- **正常输出**：前两条什么都不显示（除了要密码那一行），第三条是常规的 `apt update` 输出，末尾应当没有 `Err:`；
- **看到别的怎么办**：
  - **提示 `No such file or directory`** —— 备份目录的日期写错了，或者第 9 章第五步没做。跑 `ls ~/minipc-backup/` 看看有哪些日期；
  - **覆盖之后 `apt update` 还是报那个第三方源的错** —— 说明这个源不是写在这两处，而是写在别的地方。跑 `grep -r "那个源的关键词" /etc/apt/` 找出来；
- **怎么停止或撤销**：**这几条会覆盖系统的软件源配置**。覆盖之前想留一手，先把当前状态再存一份：`sudo cp -a /etc/apt/sources.list.d ~/sources.list.d.覆盖前`。

**第四步：确认退干净了**

```bash
dpkg -l | grep -i mesa
```

和第一步存下来的那份对照（`~/minipc-backup/日期/00-版本组合.txt` 里的 `=== Mesa 包 ===` 那一段，第 9 章第三步存的）。**版本号回到官方源那一版、行首都是 `ii`，就算退干净了。** 四件事同第一步。

**退完之后重启一次，再做第 13 章的检查。**

## 什么情况才真的需要换 Mesa

上面说了一堆不要做，这里给一条正面的判断依据。

**同时满足下面三条，才考虑换 Mesa：**

1. 第 13 章的 Vulkan 检查过不去，而且第 12 章的 GPU 识别五项全部正常（问题确实在 Vulkan 这一层，不在下面那一层）；
2. 第 7 章那张已知问题表里对不上号（不是已知的 gfx1151 问题）；
3. 第 17 章的 llama.cpp Vulkan 后端也跑不起来，并且换过 llama.cpp 的版本还是不行。

**三条缺一条，都先别动 Mesa。** 第 3 章的原话是：换 Mesa 是靠后的手段，不是第一步。

真到了这一步，**先做备份（第 9 章），操作按上面那个警告块里的路线走，回退在第 22 章。** 并且要清楚一件事：本项目给不出“换到哪一版能解决”的答案，**这条路是你自己在试，不是照着一个已验证的结论走**。

## 看到不同结果怎么办

**你想装最新版 Mesa，觉得本章太保守**：本教材给不出“新版更好”的带来源依据（第 3 章标注需要核验）。判断标准是第 13 章的检查和第 17 章能不能跑模型，不是版本号。**先按仓库自带那一版往下走，真的卡住了，上面“什么情况才真的需要换 Mesa”那三条同时成立时再回来。**

**你已经加过 PPA 了，机器现在还正常**：不用急着退。做两件事——把加了哪个源、什么时候加的记进[第 4 卷第 16 章](../04-Max395硬件/16-设备基线.md)的设备基线；跑一次 `dpkg -l | grep -i mesa` 和第 9 章存的那份对照，看看被换掉了哪些包。**以后出问题时这两条记录能省掉大半排查时间。**

**你加过 PPA，重启之后进不了桌面**：按上面那个警告块，从 `Ctrl+Alt+F3` 切文字终端开始。

**`vulkaninfo` 装上了但跑起来报错**：本章不处理，那是第 13 章的事。第 13 章按报错分了几种情况。

**这台机器没有桌面（装的是 Server 版或者切成了无头模式）**：本章照做，`vulkan-tools` 照装。`vulkaninfo` 在文字终端下能跑，`vkcube` 不能（它要弹窗口），**第 13 章那一步跳过就行**。

**你只打算跑 PyTorch，不用 llama.cpp，在想本章能不能跳**：可以跳，但**建议做**。理由是本章装的检查工具很轻，而第 13 章的 Vulkan 检查是一个便宜的对照组——ROCm 那条路出问题时，Vulkan 这条路通不通能帮你判断问题在哪一层（两条路共用最底下的 AMDGPU，第 4 章）。

**你在给客户交付，想知道本章要不要写进交付流程**：要。装了哪些包、版本号是多少、有没有加第三方源，都是交付时要交代清楚的环境信息。相关要求在第 13 卷。

**你看到有教程让你设 `AMD_VULKAN_ICD=RADV`**：本教材默认不设（第 3 章）。这台机器上只装了 RADV 一份实现，本来就会用它。真出现挑错实现的情况，第 13 章有确认当前用的是哪一份的方法。
