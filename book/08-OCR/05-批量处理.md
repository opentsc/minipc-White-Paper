# 05　批量处理

## 这一章的任务

整个文件夹跑完，汇成一张 Excel 打得开的台账。

**做完这一章，第 1 章那条主线就通了**——一个文件夹的发票进去，一张台账出来。剩下的两章是让它不用你手动触发（第 6 章），和让它能交给别人用（第 7 章）。

这一章的脚本要做到五件事：

```text
1. 一个文件夹里的单据全找出来，子目录里的也算
2. 一份一份处理，屏幕上能看见跑到哪儿了
3. 一份失败不打断，记下来接着跑下一份
4. 结果汇成一张 CSV，Excel 双击能打开
5. 跑过的跳过，重跑不重复干活
```

**第三条和第五条是这一章和第 4 章的全部区别。** 一份一份手动跑也能跑完，但跑到第 87 份挂掉一次，前面 86 份白跑，这活就没法干了。

## 开始前

- [第 4 章](04-单张跑通.md)做完，`~/ai/scripts/ocr_one.py` 在，**而且你已经拿它至少对过 10 张**；
- [第 2 章](02-环境准备.md)那个 `ocr-vlm` 服务在跑；
- 要处理的单据都在 `~/ai/data/invoices-2026-08/` 下面（[第 4 章](04-单张跑通.md)那张目录图）；
- 90 分钟，其中大半是机器在跑、你在旁边看着。

## 新词

**CSV**（逗号分隔值，Comma-Separated Values）：**最简单的一种表格文件格式。** 一行是一条记录，一行里的各列用逗号隔开。**它本质上就是一个文本文件**，用记事本打得开，用 Excel 和 LibreOffice Calc 双击也打得开，打开看到的是一张表。

**表头**：CSV 的第一行，写的是每一列叫什么名字。**下面每一行按同样的顺序排。**

**批处理**：一次处理一批，中间不需要人插手。**这一卷的价值全在这个词上**——一份一份手动跑，机器再准也省不了多少事。

**`utf-8-sig`**：存 CSV 的时候在文件最开头加一个看不见的小记号，**告诉 Excel 这个文件里的中文是 UTF-8 编码的**。Ubuntu 上的 LibreOffice Calc 不加也认得出来，**但这张台账多半要发给用 Windows 和 Excel 的人**，不加那个记号他们打开是一屏乱码。加上不吃亏。

## 完整脚本

新建文件 `~/ai/scripts/ocr_batch.py`，**下面这一整段照抄进去**：

```python
#!/usr/bin/env python3
# ocr_batch.py —— 一个文件夹的单据，跑成一张台账
# 用法：python3 ~/ai/scripts/ocr_batch.py ~/ai/data/invoices-2026-08 ~/ai/projects/invoice-ocr
# 前提：ocr_one.py 和这个脚本放在同一个目录里

import argparse
import csv
import json
import shutil
import sys
import time
import urllib.error
from pathlib import Path

from ocr_one import API_BASE, SCHEMA_FILE, IMAGE_SUFFIXES, detect_model, load_schema, read_one

DOC_SUFFIXES = IMAGE_SUFFIXES | {".pdf"}


def list_docs(indir):
    """把这个目录（含子目录）里的单据全列出来，按文件名排好序。"""
    found = [
        path for path in indir.rglob("*")
        if path.is_file() and path.suffix.lower() in DOC_SUFFIXES
    ]
    return sorted(found)


def field_names(schema):
    """台账的列，就是 schema 里字段的顺序。"""
    return list(schema.get("properties", {}).keys())


def write_ledger(json_dir, fields, ledger_path):
    """把 out/ 里所有 JSON 汇成一张 CSV。每次都重头汇一遍，重跑不会记两次账。"""
    header = ["文件名"] + fields + ["处理时间"]
    rows = []
    for path in sorted(json_dir.glob("*.json")):
        record = json.loads(path.read_text(encoding="utf-8"))
        rows.append([record.get(name, "") for name in header])
    with ledger_path.open("w", newline="", encoding="utf-8-sig") as handle:
        writer = csv.writer(handle)
        writer.writerow(header)
        writer.writerows(rows)
    return len(rows)


def note_failure(src, error, fail_dir):
    """失败的单据复制一份到 failed/，并把原因记一行。"""
    shutil.copy2(src, fail_dir / src.name)
    line = "%s\t%s\t%s\n" % (
        time.strftime("%Y-%m-%d %H:%M:%S"), src.name, error,
    )
    with (fail_dir / "failures.log").open("a", encoding="utf-8") as handle:
        handle.write(line)


def main():
    parser = argparse.ArgumentParser(description="一个文件夹的单据跑成一张台账")
    parser.add_argument("indir", help="放单据原件的目录")
    parser.add_argument("outdir", help="放结果的目录")
    parser.add_argument("--api", default=API_BASE, help="第 2 章那个服务的地址")
    parser.add_argument("--model", default=None, help="模型名，不填就问服务要")
    parser.add_argument("--schema", default=str(SCHEMA_FILE), help="第 3 章那份 schema")
    parser.add_argument("--dpi", type=int, default=200, help="PDF 转图片的清晰度")
    parser.add_argument("--max-pages", type=int, default=2, help="每份最多读前几页")
    parser.add_argument("--timeout", type=int, default=600, help="每份最多等多少秒")
    parser.add_argument("--limit", type=int, default=0, help="只跑前几份，用来计时，0 是全跑")
    args = parser.parse_args()

    indir = Path(args.indir).expanduser()
    outdir = Path(args.outdir).expanduser()
    if not indir.is_dir():
        sys.exit("找不到这个目录：" + str(indir))

    schema_path = Path(args.schema).expanduser()
    if not schema_path.is_file():
        sys.exit("找不到 schema 文件：" + str(schema_path) + "，先做完第 3 章")
    schema = load_schema(schema_path)
    fields = field_names(schema)

    json_dir = outdir / "out"
    fail_dir = outdir / "failed"
    json_dir.mkdir(parents=True, exist_ok=True)
    fail_dir.mkdir(parents=True, exist_ok=True)

    docs = list_docs(indir)
    if args.limit > 0:
        docs = docs[:args.limit]
    if not docs:
        sys.exit("这个目录里没有找到 PDF 或者图片：" + str(indir))

    try:
        model = args.model or detect_model(args.api)
    except urllib.error.URLError as error:
        sys.exit("连不上服务（" + args.api + "）：" + str(error.reason))

    total = len(docs)
    done = 0
    skipped = 0
    failed = 0
    started = time.time()

    for index, src in enumerate(docs, start=1):
        target = json_dir / (src.stem + ".json")
        if target.exists():
            skipped += 1
            print("[%d/%d] %s 跳过，已经跑过了" % (index, total, src.name), flush=True)
            continue
        print("[%d/%d] %s" % (index, total, src.name), end=" ", flush=True)
        one_started = time.time()
        try:
            record = read_one(
                src, schema, args.api, model,
                dpi=args.dpi, max_pages=args.max_pages, timeout=args.timeout,
            )
        except Exception as error:
            failed += 1
            print("失败：%s" % error, flush=True)
            note_failure(src, error, fail_dir)
            continue
        record["文件名"] = src.name
        record["处理时间"] = time.strftime("%Y-%m-%d %H:%M:%S")
        target.write_text(
            json.dumps(record, ensure_ascii=False, indent=2), encoding="utf-8",
        )
        done += 1
        print("好了，%.1f 秒" % (time.time() - one_started), flush=True)

    ledger_path = outdir / "ledger.csv"
    rows = write_ledger(json_dir, fields, ledger_path)

    print("---")
    print("这一轮：成功 %d，跳过 %d，失败 %d，一共 %.1f 分钟"
          % (done, skipped, failed, (time.time() - started) / 60))
    print("台账 %d 行：%s" % (rows, ledger_path))
    if failed:
        print("失败的复制在 %s，原因看 %s"
              % (fail_dir, fail_dir / "failures.log"))


if __name__ == "__main__":
    main()
```

**这个脚本必须和 `ocr_one.py` 放在同一个目录里**，两个都在 `~/ai/scripts/` 下面。第 14 行那句 `from ocr_one import ...` 就是从旁边那个文件里把东西拿过来用。

## 这个脚本在干什么

### 一、它没有重写第 4 章的东西

```python
from ocr_one import API_BASE, SCHEMA_FILE, IMAGE_SUFFIXES, detect_model, load_schema, read_one
```

**这一行是这个脚本最省事的地方。** 读一份单据的全部逻辑——PDF 转图、拼请求、发出去、解析——第 4 章已经写在 `read_one` 里了，**这里直接拿来用，一个字不重写**。

**好处不只是省字。** 以后改提示词、改请求参数，只改 `ocr_one.py` 一个地方，**两个脚本一起变**。抄成两份的话，改一处漏一处是迟早的事。

### 二、`list_docs`：找出所有单据

```python
path for path in indir.rglob("*")
if path.is_file() and path.suffix.lower() in DOC_SUFFIXES
```

- **`rglob("*")`** —— 这个目录和它所有子目录里的东西全列一遍。**按部门、按月份分了子目录也不用管**；
- **`path.is_file()`** —— 只要文件，目录本身不算；
- **`suffix.lower() in DOC_SUFFIXES`** —— 只要 PDF 和图片。**混在里面的 `.txt`、`.docx`、`.xlsx` 自动跳过**，不会让整批跑挂；
- **`sorted(...)`** —— 按文件名排序。**顺序固定的好处是重跑一次进度条对得上**，你能看出上次跑到哪儿了。

### 三、进度显示

```python
print("[%d/%d] %s" % (index, total, src.name), end=" ", flush=True)
```

- **`[3/128]`** —— 第几份，一共几份。**这一项是长时间批处理的必需品**，没有它你不知道该等五分钟还是两小时；
- **`end=" "`** —— 这一行先不换行，**留在那儿等结果**。跑完在同一行后面接上用时或者失败原因；
- **`flush=True`** —— 立刻显示，不要攒着。**[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)讲流式的时候说过同一件事**，少了它屏幕会一动不动攒半天再一次吐出来。

### 四、失败了不打断

```python
except Exception as error:
    failed += 1
    print("失败：%s" % error, flush=True)
    note_failure(src, error, fail_dir)
    continue
```

**这四行是这个脚本和第 4 章那个最重要的区别。**

第 4 章那个脚本，一份读不出来就整个停掉——一份一份手动跑，这样是对的。**批量跑不行**：一百份里有两份是坏文件，不能让这两份把另外九十八份也毁掉。

`continue` 的意思就是**这一份不管了，接着下一份**。

`note_failure` 做两件事：

- **把原件复制一份到 `failed/`**。是复制，**原件在 `data/` 里一动不动**（[第 4 章](04-单张跑通.md)那三条规矩的第一条）；
- **往 `failed/failures.log` 里追加一行**，写清什么时候、哪份、错在哪。

> **`except Exception` 这种写法在别处通常不好**，因为它把所有毛病都吞了。**在这里是对的**——批处理的目标就是不管遇上什么都别停，而且每一次都被记了一行，没有一个错误是悄悄消失的。

### 五、跑过的跳过

```python
target = json_dir / (src.stem + ".json")
if target.exists():
    skipped += 1
```

**每份单据的结果单独存一个 JSON，文件名跟着原件走。** `票据-0731-018.pdf` 跑完，`out/` 里就多一个 `票据-0731-018.json`。

**下次再跑，看到这个 JSON 已经在了，就跳过。**

这一条带来三件事，都是批处理离不开的：

- **中途断了，接着跑就行。** 跑到一半按了 `Ctrl+C`，或者机器重启了，重新跑一遍，已经跑完的几十份秒过；
- **新单据丢进去，只跑新的。** 这一条就是第 6 章那个自动处理的基础；
- **想重跑某一份，把它的 JSON 删掉就行。** 改了提示词想重做一批，`rm ~/ai/projects/invoice-ocr/out/*.json` 全删，然后重跑。

**失败的那些不会被跳过**——它们本来就没生成 JSON，所以每次重跑都会自动再试一次。**文件修好了、服务修好了，直接重跑就补上了。**

### 六、汇成台账

```python
header = ["文件名"] + fields + ["处理时间"]
```

**表头 = 文件名，加 schema 里那八个字段，加处理时间。**

`fields` 是从第 3 章那份 schema 里读出来的，**顺序照抄 schema 里 `properties` 的顺序**。所以你想调台账的列顺序，去改 schema，不用改这个脚本。

- **`文件名`放第一列** —— **这一列是回溯的钥匙**。台账上哪一行看着不对，照这一列去 `data/` 里翻原件。**没有这一列的台账没法核对，等于废的**；
- **`处理时间`放最后一列** —— 什么时候跑的。跑了两轮之后，这一列能告诉你哪几行是新补的。

```python
for path in sorted(json_dir.glob("*.json")):
```

**注意它是从 `out/` 里重头汇一遍，不是往台账后面追加。**

**这是这个脚本里一个刻意的设计**：不管你跑了几轮、中间断过几次、补跑过几次，**台账永远是 `out/` 里全部 JSON 的当前样子**，不会出现同一份单据记了两行的事。

```python
with ledger_path.open("w", newline="", encoding="utf-8-sig") as handle:
```

- **`encoding="utf-8-sig"`** —— 上面新词里那个记号，**Excel 打开不乱码全靠它**；
- **`newline=""`** —— 写 CSV 的固定写法，不写的话每行之间会多出一个空行。

## 全跑要多久

**这一节给的是估法，不是数字。** 你那台机器、你那批图、你选的 DPI，跑出来的数只能你自己测。

### 先数一共有多少份

```bash
find ~/ai/data/invoices-2026-08 -type f \( -name '*.pdf' -o -name '*.png' -o -name '*.jpg' \) | wc -l
```

作用：数一遍这个目录和它子目录里有多少份 PDF 和图片。**输出是一个数字**，记下来。[第 7 卷第 2 章](../07-RAG/02-收集与整理文档.md)数过一次文件，是同一个套路。

### 再跑 10 份计时

```bash
python3 ~/ai/scripts/ocr_batch.py ~/ai/data/invoices-2026-08 ~/ai/projects/invoice-ocr --limit 10
```

**最后那一行写着这一轮用了多少分钟。** 拿它除以这一轮实际跑的份数，得到一份的平均时间，再乘上面数出来的总数。

```text
一份平均用时 = 这一轮的分钟数 ÷ 这一轮实际跑成功的份数
全跑要多久   = 一份平均用时 × 总份数
```

**这个估法有三处会偏，心里有数就行：**

- **第一份可能特别慢。** 服务刚起来的话，第一份要等模型加载完（[第 6 卷第 7 章](../06-本地模型/07-多模型切换.md)那件事）。**算平均的时候把第一份剔掉更准**；
- **页数多的更慢。** 一页的和三页的差着一倍以上；
- **DPI 调高了更慢。** 300 比 200 慢，图大了视觉 token 就多。

> **不要把这个估算当承诺写进合同。** 要给客户一个数，按第 13 章那套办法在你自己的机器上、拿客户自己那批材料测，**带日期、带模型名、带量化档**（[第 13 卷](../13-项目交付/README.md)）。

## 全跑

```bash
python3 ~/ai/scripts/ocr_batch.py ~/ai/data/invoices-2026-08 ~/ai/projects/invoice-ocr
```

**不带 `--limit` 就是全跑。** 上面跑过的那 10 份会显示跳过，秒过。

跑完最后几行是这样（**格式示意，数值不是实测**）：

```text
---
这一轮：成功 118，跳过 10，失败 4，一共 32.5 分钟
台账 128 行：/home/你的账户名/ai/projects/invoice-ocr/ledger.csv

```

**三个数各看一眼**：

- **成功加跳过加失败，等不等于你数出来的总份数。** 对不上说明有文件没被找到，**多半是后缀不在那张表里**（比如 `.PDF` 大写是认的，`.tiff` 也认，`.heic` 不认）；
- **失败几份**，下面那一节处理；
- **台账多少行**，这个数应该等于成功加跳过。

### 存成真正的 xlsx

CSV 是文本文件，**它存不了公式、格式、多个工作表**。要交出去的话通常还是存成 `.xlsx`：

**最省事的做法**：用 LibreOffice Calc 打开 `ledger.csv`，点“文件”→“另存为”，**文件类型选 Excel 2007-365（.xlsx）**，存一份。

**要让脚本直接写 xlsx** 的话，Python 那边装一个 `openpyxl` 就能写，**这属于第 11 章“对接”的内容，本章不展开**。多数场合 CSV 已经够用——它能直接导进 Excel、导进数据库、导进大部分业务系统。

## 失败的那几份

`failed/` 目录里现在有两样东西：**失败单据的副本**，和一个 `failures.log`。

```bash
cat ~/ai/projects/invoice-ocr/failed/failures.log
```

每一行是**时间、文件名、错在哪**。常见的就三类：

- **文件本身坏了**。`pdftoppm` 那一行会说读不出来。**去 `data/` 里双击打开看一眼，打不开就是原件的问题**，要重新扫；
- **不是 PDF 也不是图片**。脚本会说认不了这个格式。**改后缀没用，要真的转换过**；
- **服务中途断了**。表现是连着好几份一起失败。跑 `systemctl status ocr-vlm --no-pager` 看它在不在。

**修好之后直接重跑就行**，失败的没有生成 JSON，会被自动再试一次。

> **`failed/` 里的东西和第 7 章那个“可疑件”不是一回事。** 这里放的是**根本没读出来**的，摆在明面上，你一眼看得见；第 7 章要处理的是**读出来了、形状也对、但内容可疑**的那些——**那一类不主动去挑，它就混在台账里发出去了。**
