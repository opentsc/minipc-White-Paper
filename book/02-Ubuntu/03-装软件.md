# 03　装软件

## 这一章的任务

一次把本教材后面要用的基础工具装齐。

做完之后，这台机器上多出十来个命令行工具，后面各卷用到的时候不用再回头装。你也会知道装软件有哪几条路、什么时候走哪条、装错了怎么卸干净。

## 开始前

- 网络已连通；
- 系统更新已经做过一次，国内网络下软件源镜像已经换好（[第 1 卷第 9 章](../01-开箱与安装/09-系统更新.md)）。没做过的先回去做完再来，源没换的话这一章会卡在下载上；
- 账户密码，`sudo` 要用；
- 20 分钟。

## 新词

软件包、软件源、软件包清单、镜像站这几个词在[第 1 卷第 9 章](../01-开箱与安装/09-系统更新.md)解释过。这一章多 3 个。

**依赖**（Dependency）：一个软件运行时需要的另一个软件。装 A 必须先有 B，B 就是 A 的依赖。`apt` 会自动把依赖一起装上，这是它和手动下载安装包最大的区别。

**.deb 包**：Ubuntu 的软件安装包文件，相当于 Windows 的 `.exe` 安装程序。从软件源装软件，系统在背后取的就是 `.deb` 文件。有些软件不进软件源，只在官网提供 `.deb` 给你下载。

**snap**：Ubuntu 自己做的另一套打包格式。一个 snap 包里把程序和它的依赖全带齐，装上就能跑，不依赖系统里已有的库。

## 一条命令装齐

先刷新一次软件包清单，装任何东西之前都该先来这一条：

```bash
sudo apt update
```

然后一次装完：

```bash
sudo apt install vim curl wget git htop tree unzip ca-certificates gnupg python3-pip python3-venv
```

一条 `apt install` 后面可以跟多个包名，用空格隔开。

每个是干什么的：

- **`vim`**：终端里的文本编辑器，改配置文件用（第 11 章）。Ubuntu 自带一个更好上手的 `nano`，两个都留着，按顺手的用；
- **`curl`**：在命令行里访问一个网址。第 6 卷验证本地模型服务通不通，用的就是它；
- **`wget`**：下载文件。下大文件、断了要续传，用它顺手；
- **`git`**：版本管理工具，从 GitHub 取代码要用（第 9 卷）；
- **`htop`**：看进程和资源占用的界面程序，比系统自带的 `top` 好读，第 6 章要用；
- **`tree`**：把目录结构画成树形图；
- **`unzip`**：解压 `.zip` 文件；
- **`ca-certificates`**：一组根证书。系统靠它判断一个 https 网站是不是冒充的，下载和调接口都要用到；
- **`gnupg`**：校验软件包签名的工具。第 9 章装 Docker 时要用；
- **`python3-pip`**：装 Python 库的工具。第 7、8 卷的程序要用；
- **`python3-venv`**：给 Python 程序建一个独立的运行环境，各个项目的库互不干扰，第 7 卷会用到。

执行后的正常过程：命令先算出这些包各自还需要哪些依赖，把完整清单列出来，然后问一句：

```
需要下载 42.6 MB 的归档。
解压缩后会消耗 178 MB 的额外空间。
您希望继续执行吗？ [Y/n]
```

输入 `Y` 回车继续。数字和你看到的不一样很正常，取决于系统里已经有哪些包了。之后是一屏下载和解包的滚动输出，结束后回到提示符。

其中一部分包系统里可能已经有了，输出里会显示 `已经是最新版`，这不是错误，那个包会被跳过。

## 验证装好了

挑几个试一下：

```bash
git --version
```

输出一行版本号，例如 `git version 2.43.0`。

```bash
tree ~/ai
```

输出是第 1 章那张目录结构图，这回是机器自己画的：

```
/home/roland/ai
├── backup
├── data
│   └── product-manuals
├── models
├── projects
└── scripts
```

命令找不到的话，输出会是 `command not found`，说明这个包没装上，回上一步看安装输出里有没有报错。

## `apt` 平时怎么用

**找一个包叫什么名字**

```bash
apt search 关键词
```

按关键词搜软件源里的包，输出是包名加一行简介。这条命令不需要 `sudo`，也不改动系统。搜出来的结果通常很多，用管道过滤一下更好读，例如 `apt search pdf | grep -i ocr`。

**看某个包是什么**

```bash
apt show 包名
```

显示这个包的版本、大小、依赖和详细说明。装一个不认识的包之前，先用它看一眼。

**看某个包装没装**

```bash
apt list --installed | grep git
```

列出已安装的包，再从中筛出名字含 `git` 的行。

**更新和升级**用 `sudo apt update` 和 `sudo apt upgrade`，区别和顺序在[第 1 卷第 9 章](../01-开箱与安装/09-系统更新.md)讲过，这里不重复。

## 图形界面的“Ubuntu 软件”

Ubuntu 桌面自带一个应用商店，按 `Super` 键搜“Ubuntu 软件”或 “App Center” 就能打开。里面按分类列出程序，点“安装”，输密码，等进度条走完。

它和 `apt` 装的是不是同一个东西，要看情况：

- 商店里的一部分程序来自软件源，装的和 `apt install` 是同一个 `.deb`；
- 另一部分是 snap 版本，来自 Ubuntu 的 snap 商店，和 `apt` 装的是两套东西。同一个程序有时两边都有，商店页面上会写着来源；
- 有些命令行工具在商店里根本搜不到，例如 `tree`、`htop`，这类只能用 `apt`。

本教材的做法：**正文里给了 `apt` 命令的，就照命令装**，这样版本和路径可控，出问题好查。浏览器、看图工具、办公软件这类日常程序，用商店点装更省事。

## snap 是怎么回事

snap 包把程序和依赖打包在一起，装上就能跑，也会自动更新。代价是启动比 `.deb` 版慢一点、占的磁盘空间多一点，而且它默认被限制在自己的沙箱里，访问家目录之外的位置需要额外授权。

看看这台机器上装了哪些 snap：

```bash
snap list
```

Ubuntu 桌面版出厂就带几个 snap，例如 Firefox。这一章不需要动它们。本教材后面的步骤都不依赖 snap，遇到某个软件同时有 `apt` 和 snap 两个版本，一律按正文给的命令走。

## 装一个从官网下载的 `.deb`

有些软件不进 Ubuntu 软件源，只在自己官网提供 `.deb` 文件下载，例如 Google Chrome、VS Code。下载下来的文件默认落在 `~/Downloads`。

```bash
cd ~/Downloads
sudo apt install ./google-chrome-stable_current_amd64.deb
```

- 文件名换成你实际下载到的那个；
- **前面的 `./` 不能省**。带 `./` 表示“当前目录下的这个文件”，不带的话 `apt` 会以为你在说一个软件源里的包名，然后报找不到；
- 用 `apt` 装 `.deb` 的好处是缺的依赖它会自动从软件源补上。老教程里的 `sudo dpkg -i 文件名` 也能装，但依赖不补，装完可能起不来，还要再执行一次 `sudo apt install -f` 收拾。

**`.deb` 只从软件官网下载。** 装一个 `.deb` 等于让它以管理员权限在你的系统里执行安装脚本，来路不明的包能做的事没有边界。搜索结果里的第三方下载站、别人发来的安装包，一律不装。

## 卸载

```bash
sudo apt remove 包名
```

卸掉程序本身，保留它的配置文件。以后想装回来，设置还在。

```bash
sudo apt purge 包名
```

连配置文件一起删。

```bash
sudo apt autoremove
```

清理那些当初作为依赖被自动装上、现在没有任何程序需要的包。

**执行前先看清楚它列出的“将会删除”清单。** 三条命令都会先把要删的包列出来，等你输入 `Y` 才动手。清单里如果出现你不认识的、和当前要卸的软件看不出关系的包，尤其是 `ubuntu-desktop`、`gnome-shell` 这类名字，输入 `n` 取消，不要确认——删掉桌面组件会导致开机后进不了图形界面。真的删错了，恢复方法见[第 0 卷第 9 章](../00-使用说明/09-停止与恢复.md)。

有哪一步做不出来，到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。

- `tree ~/ai` 画出来的树，和第 1 章建的目录结构一致吗？
