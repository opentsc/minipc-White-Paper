# 案例 01　全家或全公司的 ChatGPT

这份文档用于一台装好 Ubuntu、驱动正常的 Mini PC。完成以后，家里或者公司里任何一台手机、平板、笔记本，连上同一个网就能打开浏览器和这台机器上的模型对话，不花一分钱，数据不出门。同时留一个接口给程序用，后面几卷的知识库、单据处理、自动化全部接在它上面。附带一个体检脚本，一条命令逐项检查，每项当场给通过或者不通过，不通过的写清回教材哪一章。

对应教材[第 6 卷第 3 章](../../../book/06-本地模型/03-Ollama.md)、[第 4 章](../../../book/06-本地模型/04-Open-WebUI.md)、[第 5 章](../../../book/06-本地模型/05-局域网与手机访问.md)和[第 8 章](../../../book/06-本地模型/08-局域网API.md)。并发那一档在[第 15 章](../../../book/06-本地模型/15-并发与多人同用.md)。

体检脚本只读，不改任何配置，在没配置过的机器上跑也不会出事——查不到的项目它报“跳过”，不报错。它唯一会“动”的地方是向模型发一句话，那会让模型被加载进内存，那是模型服务本来就要做的事。

## 完成结果

- 模型在跑：Ollama 是一个开机自启的服务，至少装了一个模型。
- 跑在 GPU 上：`ollama ps` 显示 `100% GPU`，不是 CPU，也不是混合值。
- 有个门给人进：Open WebUI 在容器里跑着，重启策略是自己回来那一种，浏览器里能对话。
- 有个门给程序进：Ollama 的 OpenAI 兼容接口开在局域网上，一段代码改两行地址就能连过来。
- 手机上能用：连同一个 Wi-Fi，浏览器里输地址就能问。
- 门有人守：`ufw` 那张表上，3080 和 11434 每一行都说得出是给谁开的。
- `check-family-chatgpt.sh` 一条命令跑完全部检查，通过与否有明确的退出码。

## 准备条件

- 一台装了 Ubuntu 24.04 的 Mini PC，显卡驱动正常，能开终端。
- 教材第 4 卷第 9 章的 UMA 和内核参数已经设好。**没设的话模型可能被判显存不足，直接掉到 CPU 上。**
- 教材第 5 卷第 12 章、第 13 章通过，系统认得出这块 GPU。
- 教材第 2 卷第 9 章做完，Docker 装了，当前账户在 `docker` 组里。
- 教材第 3 卷第 3 章做完，这台机器的地址固定下来了。下面一律写成 `192.168.1.50`，**换成你自己那个**。
- 教材第 3 卷第 9 章做完，`ufw` 开着，你会看那张规则表。
- 硬盘上有几十 GB 空间，网络能下模型。
- 一部手机，和这台机器连同一个网。**它是最后的验收工具。**

检查环境。

```bash
bash --version | head -1
docker --version
free -h
df -h /
```

## 文件

```text
README.md                          就是这份
ollama-override.conf.example       Ollama 的 systemd 覆盖文件，照抄
open-webui.run.example             Open WebUI 的启动命令，照抄
ufw.rules.example                  两条防火墙规则，照抄
scripts/check-family-chatgpt.sh    体检脚本，只读
```

三个 `.example` 文件本身不会被执行，它们是给你照抄的清单，每条命令上面都写了作用。

## 操作步骤

### 1　复制到固定位置

```bash
mkdir -p "$HOME/apps"
cp -R labs/level-50/01-family-chatgpt "$HOME/apps/family-chatgpt"
cd "$HOME/apps/family-chatgpt"
chmod 755 scripts/check-family-chatgpt.sh
```

只下载了这个案例，就把案例目录放到 `$HOME/apps/family-chatgpt`。

### 2　先跑一次体检，看现在差哪几项

**动手改之前先跑一次**，把不通过的那几项抄下来，改完再跑一次对照。

```bash
./scripts/check-family-chatgpt.sh
```

什么都没装的机器上，六项全是“跳过”，退出码是 0。**那是对的**——这个脚本不负责替你判断该不该装。

### 3　装 Ollama，拉一个模型

```bash
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen3:4b
```

**先用一个小模型把流程跑通**，几 GB，几分钟就能说上话。大模型后面再换（教材第 6 卷第 2 章、第 7 章）。

模型名和标签会变，动手当天去 `ollama.com/library` 上看当前有什么。

### 4　确认它真的在 GPU 上

**这一步不是可选项。** 模型跑在 CPU 上照样能对话，只是慢好几倍，而且不报任何错。

一个窗口进对话，让它保持加载状态：

```bash
ollama run qwen3:4b
```

另一个窗口看：

```bash
ollama ps
radeontop
```

**`PROCESSOR` 那一列是 `100% GPU` 才算过关**，`radeontop` 里生成时 `Graphics pipe` 明显往上走。两个都对上才算数，排查顺序在教材第 6 卷第 3 章。

### 5　按清单写 Ollama 的配置

`ollama-override.conf.example` 里是要抄进覆盖文件的那几行。

```bash
grep -n '' ollama-override.conf.example
```

**三个变量写在同一个 `[Service]` 段下面，一行一个。** 分成三段是最常见的写错法。

抄完之后：

```bash
sudo systemctl daemon-reload
sudo systemctl restart ollama
ss -tln | grep 11434
```

**`Local Address` 那一列是 `0.0.0.0:11434` 就对了。** 还是 `127.0.0.1` 说明那几行没生效。

### 6　按清单起 Open WebUI

`open-webui.run.example` 里是另一组命令。

```bash
grep -n '' open-webui.run.example
```

**`--restart unless-stopped` 那一项不能少**，它是这个实验的验收点之一——没有它，机器一重启这套东西就没了。

起来之后在这台机器自己的浏览器里打开 `http://localhost:3080`，注册第一个账号。**第一个注册的是管理员**，家里人的账号由你在后台加。

### 7　按清单放行防火墙

`ufw.rules.example` 里是两条规则。

```bash
grep -n '' ufw.rules.example
sudo ufw status verbose
```

**表里每一行你都要说得出这个口是给谁开的。** 说不出的那一行，要么弄清楚，要么删掉。

### 8　拿手机验一次

**这一步才是这个案例真正的完成标志。**

手机连上同一个 Wi-Fi，浏览器地址栏里输：

```text
http://192.168.1.50:3080
```

**开头是 `http` 不是 `https`；端口不能少；要在地址栏里输，不是搜索框。**

用你在第 6 步注册的账号登录，问一句话。**它答出来了，这台机器就是你家的 ChatGPT 了。**

### 9　再跑一次体检

```bash
./scripts/check-family-chatgpt.sh
echo $?
```

六项应该全部通过，退出码是 0。

### 10　把这次结果存一份

```bash
./scripts/check-family-chatgpt.sh > "check-$(date +%F).txt" 2>&1
```

交付给客户的机器，这份输出就是验收单的附件。往外发之前按教材[第 0 卷第 8 章](../../../book/00-使用说明/08-文件保护.md)看一遍里面有没有不该外传的内容——输出里会带内网地址和模型名。

还没配的机器上，不通过的那几项后面会带着回哪一章，比如：

```text

  不通过　ollama ps 里出现了 CPU，模型没有全部跑在 GPU 上（教材第 6 卷第 3 章那一节的排查顺序）
```

没装某样东西的项目报“跳过”，不算不通过。没装 Docker 的机器上第 4 项就是跳过，退出码仍然是 0。

## 验收标准

七条全部满足才算通过。

1. `./scripts/check-family-chatgpt.sh` 输出“体检通过”，退出码是 0（`echo $?` 查）。
2. `ollama ps` 的 `PROCESSOR` 那一列是 `100% GPU`，同时 `radeontop` 里生成时 GPU 占用明显往上走。
3. 手机连同一个 Wi-Fi，浏览器打开 `http://192.168.1.50:3080` 能登录、能对话。
4. 局域网里另一台电脑上，教材第 6 卷第 8 章那段 Python 跑得通，打印出模型说的话和 token 统计。
5. `sudo ufw status verbose` 输出里，3080 和 11434 那几行你逐行说得出是给谁开的。
6. `sudo reboot` 之后**不做任何操作**，两分钟内手机上重新打开那个地址还能对话。
7. 拔掉显示器、键盘、鼠标，只留电源线和网线，上面六条重跑一遍结果不变。

第 6 条是这套东西和“在电脑上开个窗口聊天”的分界线。**过不了这一条，交付出去的机器每次重启都要人上门。**

## 可以出售的结果

- **私有 ChatGPT 交付**：给客户配好一台机器，全公司在浏览器里就能用，数据不出内网。交付时当场跑一次体检脚本，把输出存成文件放进验收单。客户拿到的是“我们自己的 ChatGPT，账号我发”，不是几条命令。做律所、诊所、会计事务所这类不敢把资料贴进云端的客户，卖点就是这一条。
- **承载能力评估**：用教材第 6 卷第 15 章那个并发脚本，在客户实际要用的模型和上下文长度下测一遍，出一页说明，写清几个人同时用是什么表现、几个人开始排队。**这一项能防住交付之后最常见的那场争执**——客户觉得慢，你拿得出交付前测过的数。
- **模型选型服务**：按客户的活（中文写作、看代码、读扫描件）各测三五个模型，用教材第 6 卷第 16 章那张表出一份对照，连体验评价一起给。多数客户自己分不清 20B 和 70B 对他们有没有差别。
- **接口对接**：把这台机器的接口接进客户已有的系统。教材第 6 卷第 8 章那两行地址是全部技术含量，但客户不知道，而且他们那套系统你要读一遍。
- **季度体检**：每季度远程跑一次体检脚本，出一页对照上一次的差异。配置会漂——有人重装了容器忘了加重启策略、有人升级完 Ollama 模型掉到 CPU 上了。这项服务卖的是定期确认。

## 常见问题

### 第 3 项说模型跑在 CPU 上

按教材第 6 卷第 3 章那一节的顺序查，别跳步：

```bash
journalctl -u ollama -e --no-pager | grep -iE "gfx|rocm|vulkan|amdgpu|no compatible"
```

1. 日志里没有任何 GPU 字样，或者写着 `no compatible GPUs` —— 驱动那一层的问题，回教材第 5 卷第 12 章。
2. 认出了 GPU 但报显存不足 —— 先把 Ollama 升到最新版（把安装命令再跑一遍），再确认教材第 4 卷第 9 章的内核参数生效了。
3. 手动装的那条路 —— 确认 AMD GPU 那个组件包也解开了，`groups ollama` 里有 `render` 和 `video`。

**别设 `HSA_OVERRIDE_GFX_VERSION`。** 网上那些教程是旧版本的补救办法，教材第 4 卷第 18 章已经把它列进禁区。

### 第 4 项说没有叫 open-webui 的容器

容器名不一样的话指定一下：

```bash
CHECK_WEBUI_CONTAINER=你的容器名 ./scripts/check-family-chatgpt.sh
```

`docker ps -a` 里真的没有，回第 6 步起一个。

### 第 4 项说连不上 Docker 服务

```bash
systemctl status docker
groups | grep docker
```

两种原因：Docker 服务没起来，或者当前账户不在 `docker` 组里（教材第 2 卷第 9 章）。加了组要注销重新登录才生效。也可以直接 `sudo` 跑一次体检。

### 第 5 项说 11434 只对本机开着

覆盖文件没生效。看一眼合并之后是什么样：

```bash
systemctl cat ollama --no-pager
```

后半段看不到你写的那几行 `Environment=`，十有八九是写在了注释外面，或者 `[Service]` 那一行漏了。改完记得 `daemon-reload` 加 `restart`。

### 第 6 项一直不通过，说没有返回可用的回答

三种常见原因，按顺序试：

1. 模型名不对。`ollama list` 照抄，或者用 `CHECK_MODEL=模型名` 指定。
2. 第一次加载超时了。大模型加载要几分钟，把等待时间放宽：`CHECK_TIMEOUT=900 ./scripts/check-family-chatgpt.sh`。
3. 接口没开或者防火墙挡着。回第 5 步和第 7 步。

其余的按教材第 15 卷的症状表走。

### 手机上打不开那个地址

按教材第 6 卷第 5 章那一节查，最常见的是这三条：地址输进了搜索框而不是地址栏；手机连的是手机流量不是家里的 Wi-Fi；路由器开了 AP 隔离，无线设备之间互相不通。

### 想让它跑大一点的模型

先算内存，再换（教材第 6 卷第 1 章那条 90 GB 的权重预算）。换完重跑一次体检，重点看第 3 项还是不是 `100% GPU`。

### 想改脚本查哪几个端口

```bash
CHECK_WEBUI_PORT=3000 ./scripts/check-family-chatgpt.sh
CHECK_OLLAMA_PORT=11434 CHECK_OLLAMA_HOST=192.168.1.50 ./scripts/check-family-chatgpt.sh
```

六个环境变量都写在脚本开头的注释里。

## 停止和恢复

停掉网页界面，保留数据：

```bash
docker stop open-webui
```

再起来就是 `docker start open-webui`。

让它不再自己启动：

```bash
docker update --restart no open-webui
```

停掉模型服务：

```bash
sudo systemctl stop ollama
```

把模型从内存里放出来，文件还在盘上：

```bash
ollama stop 模型名
```

关掉两个口：

```bash
sudo ufw delete allow from 192.168.1.0/24 to any port 3080 proto tcp
sudo ufw delete allow from 192.168.1.0/24 to any port 11434 proto tcp
```

**注意 Docker 发布的端口不受 ufw 约束**，要真正关掉 3080，得停容器或者按 `open-webui.run.example` 第 6 步把它绑到指定地址上。

回到只有本机能用的状态：把 `ollama-override.conf.example` 里 `OLLAMA_HOST` 那一行改成 `127.0.0.1:11434`，`daemon-reload` 加 `restart`。

体检脚本本身不用停也不用恢复，它只读，删掉就是了。

## 隐私边界

- 文档和示例里的地址一律是 `192.168.1.x` 这种示例地址，不含真实主机名、真实网段、账号和密码。
- **这两个口都没有认证。** Ollama 那个接口的 api_key 官方写明“要求填但不校验”，说白了就是：任何能连到 11434 的设备，不要账号不要密码就能用你的模型，而且能做的事不止提问。**只在局域网里开，不要在路由器上做端口转发**，出门要用走 Tailscale（教材第 3 卷第 6 章）。
- **Open WebUI 里存着全家人的对话记录。** 那个数据目录按内部资料对待，备份也按内部资料对待（教材第 2 卷第 12 章）。
- **体检脚本的输出里有内网地址、模型名、容器名。** 这是教材[第 0 卷第 8 章](../../../book/00-使用说明/08-文件保护.md)点名的内网信息，往外发之前逐行看一遍。
- 脚本不读任何密钥、不读对话记录、不发送任何数据到外部。它调用的是系统自带的查询命令，加上向本机模型发的那一句“用一句话说你在”。
- 交付客户机器时，管理员账号要交给客户自己改密码，你自己的账号从里面删掉。

## 当前范围

这个案例只做单机的本地模型服务和局域网访问，**没有做认证网关、没有做用量统计、没有做多机负载分担、也没有做出门访问**。

出门访问接教材第 3 卷第 6 章的 Tailscale，改的只是地址。给接口加认证要在它前面放一层网关，属于第 10 卷。用量统计、按人限流、排队提示这些也在第 10 卷。多台机器一起管属于第 14 卷。

下一步可以接三样：把体检脚本挂进定时任务每天跑一次、不通过时发一条通知（第 9 卷）；按教材第 6 卷第 15 章测一遍这台机器的承载能力，出一页可以给客户看的说明；按第 16 章把模型实测记录并进设备基线，作为交付文档的一部分。
