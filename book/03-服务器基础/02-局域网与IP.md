# 02　局域网与 IP

## 这一章的任务

查到这台机器在局域网里的地址，然后在笔记本或者手机上，确认能找到它。

这一章拿到的那个地址，后面每一章都要用：第 4 章连远程终端要用它，第 5 章传文件要用它，第 7 章连共享文件夹也要用它。**这一步不通，后面的章节全部做不下去。**

## 开始前

- Mini PC 和你的笔记本（或者手机）连在同一个路由器上，一个插网线一个连 Wi-Fi 也算；
- Mini PC 上能打开终端（第 2 卷[第 2 章](../02-Ubuntu/02-终端.md)）；
- 做过第 2 卷[第 9 章](../02-Ubuntu/09-Docker.md)的那个监控面板容器最好，没做也不影响，那部分可以跳过；
- 20 分钟。

## 新词

**局域网**（LAN）：连在同一个路由器下面的这一批设备，构成一个局域网。家里的电脑、手机、电视、打印机通常都在同一个局域网里，它们之间可以直接互相访问，不用经过互联网。

**IP 地址**：每台设备在网络里的门牌号，形如 `192.168.1.23`，四段数字用点隔开。别的设备靠这个号码找到它。

**内网地址**：只在局域网里有效的 IP 地址。出了这个路由器就没有意义，互联网上的机器无法直接用它找到你。家里设备拿到的都是这种地址。

**端口**（Port）：同一台机器上可以同时跑好几个服务，端口是用来区分它们的编号。IP 地址找到是哪台机器，端口决定进哪个服务。第 2 卷[第 9 章](../02-Ubuntu/09-Docker.md)那个监控面板用的 `3001` 就是端口。

**ping**：一条测试命令。往指定地址发几个很小的包，看对方回不回、来回花多久。它是判断“两台机器之间通不通”最直接的办法。

**网络接口**：机器上的一个网卡对应一个接口，有自己的名字。Ubuntu 上有线网口的名字通常以 `enp` 开头，无线网卡以 `wl` 开头。

## 局域网是什么

家里的路由器做两件事：一边连着运营商的线通向互联网，另一边把家里的设备连成一张小网。这张小网就是局域网。

局域网里的设备互相访问，数据只在路由器里面转一圈，**不出家门，也不占用你的宽带流量**。所以从笔记本访问这台 Mini PC，速度取决于你家网线和 Wi-Fi 的质量，跟你买的宽带是多少兆没有关系。

判断两台设备在不在同一个局域网，最实用的办法是看它们的 IP 地址前三段一不一样。`192.168.1.23` 和 `192.168.1.7` 是一个网，`192.168.1.23` 和 `192.168.0.5` 不是。这条规则下面排查故障时要反复用。

## 查这台机器的地址

在 Mini PC 上打开终端：

```bash
ip a
```

作用：列出这台机器上所有网络接口和各自的地址。`a` 是 `address` 的缩写，这条命令只读，不用 `sudo`。

正常输出类似这样：

```
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
    inet 127.0.0.1/8 scope host lo
       valid_lft forever preferred_lft forever
2: enp2s0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000
    link/ether a1:b2:c3:d4:e5:f6 brd ff:ff:ff:ff:ff:ff
    inet 192.168.1.23/24 brd 192.168.1.255 scope global dynamic noprefixroute enp2s0
       valid_lft 84521sec preferred_lft 84521sec
3: wlp3s0: <BROADCAST,MULTICAST> mtu 1500 qdisc noop state DOWN group default qlen 1000
    link/ether a1:b2:c3:d4:e5:f7 brd ff:ff:ff:ff:ff:ff
```

一段一段读：

- **`lo`** 是回环接口，地址永远是 `127.0.0.1`，指的就是机器自己。第 2 卷第 9 章在浏览器里输的 `localhost` 就是它。这个地址在别的机器上输入没有意义，那边的 `127.0.0.1` 是那边自己；
- **`enp2s0`** 是有线网口。名字里的数字随主板而变，你机器上可能叫 `enp1s0` 或者别的，认 `enp` 开头就行；
- **`inet 192.168.1.23/24`** 这一行才是你要的东西。`inet` 后面那个 `192.168.1.23` 就是这台机器的地址，记下来；
- 尖括号里的 **`UP,LOWER_UP`** 表示这个网口通着。`wlp3s0` 那行是 `state DOWN`，说明无线网卡没连——这台机器插着网线，正常；
- **`valid_lft 84521sec`** 是这个地址还能用多久，单位是秒。到期之前会去续，续不上就换一个。地址会变的根子在这里，第 3 章处理它。

只想要地址，不想看这一屏：

```bash
hostname -I
```

作用：只打印这台机器的 IP 地址，多个地址用空格隔开。注意是大写的 `I`。

**同时插了网线又连着 Wi-Fi 的机器会有两个地址**，两个都能用。做服务器建议只插网线，把 Wi-Fi 关掉，省得记两个。

`ip a` 的输出里如果还有一行 `docker0`，地址是 `172.17.0.1`，那是第 2 卷第 9 章装 Docker 时它自己建的一个内部网络，跟局域网没关系，不用管。

## 内网地址长什么样

内网地址只有三段范围，认前面几位就够：

- **`192.168.` 开头**：家用路由器最常发的，绝大多数人看到的是这种；
- **`10.` 开头**：公司和学校的网络常用；
- **`172.16.` 到 `172.31.` 开头**：少见，Docker 用的 `172.17.` 就在这个范围里。

这几段地址是留给内网用的，全世界的家庭和公司都在重复使用同一批号码。所以**内网地址出了这个路由器就没有意义**：你把 `192.168.1.23` 发给外地的朋友，他打开只会连到他自己家的某台设备上，或者什么也连不到。人在外面要访问这台机器，走的是第 6 章的办法。

看到 `169.254.` 开头的地址是另一回事：那是机器没从路由器拿到地址，自己随便编了一个。这种情况先检查网线插没插好，网口不亮灯的排查见[第 1 卷第 12 章](../01-开箱与安装/12-硬件问题处理.md)。

## 端口是什么

IP 地址找到是哪台机器，端口决定进这台机器上的哪个服务。

一台机器上可以同时开着一堆服务：一个网页面板、一个远程登录、一个文件共享。它们共用同一个 IP 地址，靠端口号分开。写在一起是这个样子：

```
192.168.1.23:3001
```

冒号前面是机器，后面是端口。第 2 卷第 9 章那条 `docker run` 里的 `-p 3001:3001`，做的就是在这台机器上开了 3001 这个口，通到容器里面去。

看看这台机器现在开着哪些端口：

```bash
ss -tln
```

作用：列出所有正在等着别人来连的 TCP 端口。`-t` 是只看 TCP，`-l` 是只看在等连接的，`-n` 是直接显示数字不去查名字。这条命令只读。

正常输出类似：

```
State    Recv-Q   Send-Q     Local Address:Port      Peer Address:Port
LISTEN   0        4096       127.0.0.53%lo:53             0.0.0.0:*
LISTEN   0        4096             0.0.0.0:3001           0.0.0.0:*
LISTEN   0        4096                [::]:3001              [::]:*
```

要看的是 `Local Address:Port` 这一列，冒号后面是端口号，冒号前面是**这个端口对谁开着**：

- **`0.0.0.0:3001`**：对所有地址开着，局域网里任何一台机器都能连进来。上面那个监控面板就是这样；
- **`127.0.0.53:53`**：`127.` 开头，只有这台机器自己能连，别的机器连不上。

这个区别在第 9 章讲防火墙时还要用。

几个后面会反复见到的端口号：`22` 是远程登录（第 4 章要开的就是它），`80` 和 `443` 是网页，`3001` 是那个监控面板。1024 以下的端口是留给系统服务的，普通程序开不了。

## 从另一台电脑找到它

现在换到你的笔记本上操作。

**macOS**：打开“终端”（在“应用程序 → 实用工具”里，或者按 `Command + 空格` 搜 terminal），输入：

```bash
ping -c 4 192.168.1.23
```

地址换成你刚才记下来的那个。`-c 4` 表示发 4 个包就停。不加 `-c` 它会一直发下去，按 `Ctrl+C` 停。

**Windows**：按 `Win + R`，输入 `cmd` 回车，或者在开始菜单搜“终端”，然后输入：

```
ping 192.168.1.23
```

Windows 的 `ping` 默认发 4 个包就自己停了，不用加参数。

通了的话，输出是这样：

```
PING 192.168.1.23 (192.168.1.23): 56 data bytes
64 bytes from 192.168.1.23: icmp_seq=0 ttl=64 time=0.412 ms
64 bytes from 192.168.1.23: icmp_seq=1 ttl=64 time=0.385 ms
64 bytes from 192.168.1.23: icmp_seq=2 ttl=64 time=0.401 ms
64 bytes from 192.168.1.23: icmp_seq=3 ttl=64 time=0.398 ms

--- 192.168.1.23 ping statistics ---
4 packets transmitted, 4 packets received, 0.0% packet loss
```

要看的就两处：**每一行都有回复**，**最后一行的丢包是 0.0%**。

`time=` 后面是一来一回花的毫秒数。有线连接通常是零点几毫秒，Wi-Fi 上几毫秒到几十毫秒都正常。数字大不大不重要，有回复就说明两台机器之间通了。

**看到这个输出，这一章的目标就达到了。** 你的笔记本现在能找到这台机器。

## 顺手验证一下服务

做过第 2 卷第 9 章那个监控面板的话，在笔记本的浏览器里输入：

```
http://192.168.1.23:3001
```

那台机器上的页面出现在你笔记本的浏览器里了。第 2 卷是在机器本地用 `localhost:3001` 打开的，现在换成局域网地址，从别的机器一样能开。

**这就是服务器的第一个实际效果**：服务在那台机器上跑，你在这台机器上用。

手机也一样。手机连着家里的 Wi-Fi，浏览器里输同一个地址，页面照样出来。手机上装 `ping` 工具比较麻烦，用浏览器打开这个页面，验证的效果是一样的。

## ping 通了，但页面打不开

这两件事分得很清楚，遇到问题先分清是哪一层：

- **ping 不通**：两台机器之间就没连上，看下一节；
- **ping 通了、页面打不开**：机器找到了，那个服务没在等你。回到 Mini PC 上执行 `docker ps` 看容器还在不在跑，或者 `ss -tln` 看 3001 这个口开没开。

## ping 不通的两种常见原因

**第一种，两台设备不在同一个局域网。** 这是最常见的。在笔记本上查一下自己的地址：macOS 上执行 `ipconfig getifaddr en0`，Windows 上执行 `ipconfig` 看“IPv4 地址”那一行。拿它和 Mini PC 的地址比前三段：

- 前三段一样（都是 `192.168.1.`）：在同一个网里，问题在别处；
- 前三段不一样：不在同一个网里，ping 不通是必然的。常见原因是笔记本连了访客 Wi-Fi、连了手机热点、或者家里有两个路由器串在一起，你俩挂在不同那个上面。把笔记本连到和 Mini PC 同一个路由器上，再试一次。

**第二种，地址抄错了或者已经变了。** 回到 Mini PC 上再执行一次 `hostname -I`，对一遍。地址真的变了的话，那正是第 3 章要解决的事。

还有一种情况不是故障：**从 Ubuntu 这边 ping 你的 Windows 笔记本，多半不通。** Windows 防火墙默认不回这种包，跟你的网络没关系。所以本章的方向是从笔记本 ping Mini PC，别反过来。

有哪一步做不出来，到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。

## 完成检查

- `ip a` 的输出里，哪一行是这台机器的局域网地址？`lo` 那个 `127.0.0.1` 为什么不能用？
- 你记下来的地址是 `192.168.` 开头还是 `10.` 开头？
- 把这个地址发给外地的朋友，他能打开你的机器吗？为什么？
- 从笔记本 `ping` 这个地址，最后一行的丢包率是多少？
- `192.168.1.23:3001` 里，哪部分是机器，哪部分是服务？
- `ss -tln` 输出里的 `0.0.0.0:3001` 和 `127.0.0.53:53`，这两个端口的开放范围差在哪？
- ping 通了但浏览器打不开页面，该去查什么？
