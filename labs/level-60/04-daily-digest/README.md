# 案例 04　信息抓取日报

**等级 60。分类：自动化与交付。**

这份文档用于一台已经装好 n8n、并且能连上本地 Ollama 的 Mini PC。完成以后，这台机器上有一条自己会跑的流程：每天到点去抓一个公开订阅源，把新出来的内容交给本地模型摘成中文，按日期存成一份日报文件。你早上打开那个目录，昨天的东西已经在那儿了。附带一个体检脚本，一条命令逐项检查这条流程的地基还在不在，不通过的写清回教材哪一章。

对应教材[第 9 卷第 2 章](../../../book/09-Agent与RPA/02-n8n装起来.md)、[第 3 章](../../../book/09-Agent与RPA/03-第一个工作流.md)、[第 4 章](../../../book/09-Agent与RPA/04-案例一-抓网页.md)、[第 5 章](../../../book/09-Agent与RPA/05-案例一-模型摘要.md)、[第 6 章](../../../book/09-Agent与RPA/06-案例一-每日推送.md)和[第 11 章](../../../book/09-Agent与RPA/11-日志与重试.md)。本地模型那一层在[第 6 卷](../../../book/06-本地模型/README.md)。

体检脚本只读，不改任何配置，不新建、不删除、不重启任何容器，也不动任何工作流。在没配置过的机器上跑也不会出事——查不到的项目它报“跳过”，不报错。它唯一会“动”的地方是在 n8n 容器里向 Ollama 的模型列表接口发一次请求，**那只是问一句“你在不在”，不加载模型、不做推理**。它不打开任何日报文件，也不读工作流内容。

## 完成结果

- **容器还在，而且断电会自己回来**：`n8n` 这个容器在跑，重启策略是 `unless-stopped`。
- **端口有人在听**：宿主机 5678 上有进程占着。
- **容器里够得着模型**：在容器内问 Ollama 的模型列表接口有返回。
- **两个卷都挂对了**：容器里的 `/home/node/.n8n` 和 `/data` 各自挂在宿主机的目录上，删掉容器工作流不会丢。
- **一条能跑的工作流**：七个节点，从定时触发到把文件写到硬盘上，手动点一次执行，日报目录里多出一份 `.md`。
- **日报读得下去**：条数和抓到的对得上，每条一句话，链接还在，没有出现原文里没有的东西。
- **它自己会跑**：工作流是发布状态，第二天到点自己跑了一次，执行记录里有那一行。
- `check-n8n.sh` 一条命令跑完全部检查，通过与否有明确的退出码。

## 准备条件

- 教材[第 9 卷第 2 章](../../../book/09-Agent与RPA/02-n8n装起来.md)做完，`n8n` 容器在跑，浏览器进得去，**那条 `docker run` 里的两个 `-v` 和 `--add-host` 都在**。
- 教材[第 6 卷](../../../book/06-本地模型/README.md)做完，Ollama 在跑，`ollama list` 里至少有一个能对话的模型，**而且它设成了对外监听**（不然容器里够不着）。
- 教材[第 9 卷第 3 章](../../../book/09-Agent与RPA/03-第一个工作流.md)做完，**加节点、连线、执行、看每个节点的输入输出，你都做过**。
- **一个你自己关心的公开订阅源。** 找它的三个办法在教材[第 4 章](../../../book/09-Agent与RPA/04-案例一-抓网页.md)。**动手之前打开那个站的 `robots.txt` 看一眼**，抓东西那六条规矩在那一章。
- 硬盘上留几百 MB。日报是纯文本，很小；占地方的是 n8n 自己的执行记录（教材[第 11 章](../../../book/09-Agent与RPA/11-日志与重试.md)第二节）。
- 一个半小时。**导入顺利的话四十分钟，卡在模型名或者字段名上就要一个半小时。**

检查环境。

```bash
docker ps
ss -tln | grep :5678
ollama list
ls -ld ~/ai/data/daily
```

## 文件

```text
README.md                  就是这份
workflow.example.json      七个节点的工作流样例，照它导入，三处占位要换
scripts/check-n8n.sh       体检脚本，只读
.gitignore                 真实的工作流导出和日报输出不进 Git
```

那个 `.example` 文件本身不会被执行，**它是给你导入和照改的**。**导进去之后另存成你自己那一份，别改这个原件**——下次换一台机器还要照它来。

## 操作步骤

### 1　复制到固定位置

```bash
mkdir -p "$HOME/apps"
cp -R labs/level-60/04-daily-digest "$HOME/apps/daily-digest"
cd "$HOME/apps/daily-digest"
chmod 755 scripts/check-n8n.sh
```

只下载了这个案例，就把案例目录放到 `$HOME/apps/daily-digest`。

### 2　先跑一次体检，看现在差哪几项

**动手之前先跑一次**，把不通过的那几项抄下来，做完再跑一次对照。

```bash
./scripts/check-n8n.sh
```

刚做完教材第 2 章的机器上，**多半是第 1 到第 4 项通过，第 5 项跳过**——日报目录在，但里面一份都没有，**那是对的**。

第 1 到第 4 项里有不通过的，**先把它修好再往下走**。**地基不在的时候导入工作流没有意义。**

### 3　把工作流导进去

浏览器打开 `http://localhost:5678`，新建一条工作流，**从界面上那个导入的入口把 `workflow.example.json` 导进去**。

**这个入口叫什么、在哪一个菜单里，随版本变化，需要核验**——一般在工作流右上角那个菜单里，措辞是导入之类的字样，可以从文件导入，也可以粘贴 JSON。

> **导不进去、或者导进去之后有节点是红的，不要在这上面耗。**
>
> **这份样例的节点参数名与版本号本项目没有在真实的 n8n 上导入验证过，需要核验。** 版本对不上是很正常的事。
>
> **退路是照教材[第 4 章](../../../book/09-Agent与RPA/04-案例一-抓网页.md)到[第 6 章](../../../book/09-Agent与RPA/06-案例一-每日推送.md)手动加这七个节点**，参数那三章写得比这份 JSON 全。**手动搭出来的结果和导入的完全一样**，只是多花二十分钟。**这份样例的用处是省那二十分钟，不是取代那三章。**

导进去之后画布上应该是这七个，从左到右连成一条线：

```text
每天早上 → 抓订阅源 → 整理素材 → 问模型 → 拼日报 → 转成文本文件 → 写到硬盘
```

### 4　三处占位换成你自己的

**样例里有三处是占位，不换它跑不起来。**

**一、订阅源地址。**

点开“抓订阅源”那个节点，**URL 那一格现在是 `https://请换成你自己的订阅源地址/feed`**，换成你自己那个。

**二、模型名。**

点开“问模型”那个节点，请求体里 `"model"` 那一行现在是 `"请换成你 ollama list 里的模型名"`，**换成 `ollama list` 里真实的那个名字，一个字都不能差。**

```bash
ollama list
```

**三、字段名——这一处最容易被跳过，也最容易出事。**

点开“整理素材”那个 Code 节点，里面取的是 `title`、`link`、`contentSnippet`。**这几个名字是常见写法，各站点的 RSS 写法有出入，需要核验。**

**做法是先执行一次“抓订阅源”那个节点，把它输出面板上真实的字段名抄下来，再回来改这几行。** 教材[第 4 章](../../../book/09-Agent与RPA/04-案例一-抓网页.md)那一步说的就是它。

**这一处不改的表现是：日报里每条只有标题和链接，正文那一段全是空的。**

### 5　一个节点一个节点跑通

**别一上来就整条执行。** 按教材[第 3 章](../../../book/09-Agent与RPA/03-第一个工作流.md)那套，一个一个点开看。

**四个要看的地方：**

```text
抓订阅源     ——  条目数和你在浏览器里数到的差不多
整理素材     ——  “用户内容”那一格里是编好号的几条，标题、链接、摘录都在
问模型       ——  choices[0].message.content 里是一段干净的中文
拼日报       ——  “正文”那一格从 # 日报 开头，读得下去
```

**问模型那一步返回空的、或者报错**，三种常见：模型名不对、Ollama 没设成对外监听、这台机器上 `host.docker.internal` 不通。**第三种的退路是换成本机的固定地址**（教材[第 3 卷第 3 章](../../../book/03-服务器基础/03-固定IP.md)）。

**整条执行一次，然后去硬盘上看：**

```bash
ls -lh ~/ai/data/daily/
cat ~/ai/data/daily/日报-$(date +%F).md
```

**写不进去、节点报权限相关的错**，是教材第 2 章那件事：

```bash
sudo chown -R 1000:1000 ~/ai/data/daily
```

### 6　保存并发布

**这一步最容易漏，漏了的表现是第二天什么都没发生。**

保存，**然后把工作流切到发布状态**（措辞随版本变化，认那个开关）。

**“每天早上”那个触发器默认是早上 7 点。** 想改时间点就点开它改。

> **验证它真的会自己跑，用教材[第 6 章](../../../book/09-Agent与RPA/06-案例一-每日推送.md)那一招**：把触发时间改到两三分钟以后，保存，确认还是发布状态，等着。到点之后执行记录里应该多一行，日报目录里应该多一份。**验完把时间改回去，保存，再确认一次还是发布状态。**

### 7　接上“送到手上”（可选）

日报现在是一份躺在硬盘上的文件。**要它自己送到你邮箱，在“写到硬盘”后面再接一个 Send Email**，凭据和参数在教材[第 6 章](../../../book/09-Agent与RPA/06-案例一-每日推送.md)，这份样例里不带它——**因为它要一套 SMTP 凭据，而凭据不该出现在一个能公开发出去的样例里。**

**要它失败了来通知你，做教材[第 11 章](../../../book/09-Agent与RPA/11-日志与重试.md)那条报警工作流，挂到这一条上。** 一条报警工作流可以给好几条流程共用。

### 8　再跑一次体检，存一份

```bash
./scripts/check-n8n.sh
echo $?
./scripts/check-n8n.sh > "check-$(date +%F).txt" 2>&1
```

交付给客户的机器，这份输出是验收单的附件之一。**往外发之前按教材[第 0 卷第 8 章](../../../book/00-使用说明/08-文件保护.md)看一遍**——输出里带容器名、端口、挂载路径和目录属主。

## 正常结果

一台配好的机器上，`./scripts/check-n8n.sh` 的输出（容器名、端口、路径会换成你自己的，**份数是格式示意**）：

```text
信息抓取日报体检
  时间          2026-08-15 07:05:11
  容器名        n8n
  宿主机端口    5678
  日报目录      /home/你的账户/ai/data/daily

第 1 项　n8n 容器在不在跑，重启策略对不对
  通过　n8n 在跑
  通过　重启策略是 unless-stopped，断电来电之后它会自己回来

第 2 项　端口有没有人在听
  通过　5678 上有人在听
  说明　这一项只证明有进程占着这个口，不证明占着它的就是 n8n。

第 3 项　容器里连不连得上 Ollama
  通过　容器里用 wget 问到了 http://host.docker.internal:11434/v1/models，有返回
  说明　这一项只证明这条路通，不证明模型跑得动，也不证明模型名填对了。

第 4 项　两个数据卷挂对了没有
  通过　/home/node/.n8n 挂着，来自 /home/你的账户/ai/projects/n8n
  通过　/data 挂着，来自 /home/你的账户/ai/data/daily
  说明　这一项只看挂没挂，不看里面有什么，也不判断属主对不对。

第 5 项　日报目录里有没有东西
  通过　日报目录 /home/你的账户/ai/data/daily 在

  说明　最后一份的文件名是 日报-2026-08-15.md
  说明　这一项只看文件名和份数，不打开任何一份，也不判断里面写得对不对。
  说明　目录属主是 xxx:xxx。容器里以 uid 1000 跑，写不进去看教材第 9 卷第 2 章。

结果　通过 6 项，不通过 0 项，跳过 0 项
体检通过。真正的验收是明天早上你邮箱或者日报目录里真的多出一份，而且读得下去。
```

还没配的机器上，不通过的那几项后面会带着回哪一章，比如：

```text
第 1 项　n8n 容器在不在跑，重启策略对不对
  通过　n8n 在跑
  不通过　重启策略是“不重启”（教材第 2 卷第 9 章、第 9 卷第 2 章）
  说明　服务类容器要 --restart unless-stopped。改这一项要停掉删掉重建，不是 restart。
```

**没装某样东西的项目报“跳过”，不算不通过。** 这台机器上没有 `ss` 的话第 2 项就是跳过，**退出码仍然是 0**。容器里既没有 `wget` 也没有 `curl` 的话第 3 项跳过，**换个办法是在 n8n 里跑一次 HTTP Request 节点，效果一样。**

## 验收标准

**七条全部满足才算通过。**

1. `./scripts/check-n8n.sh` 输出“体检通过”，退出码是 0（`echo $?` 查）。
2. **手动执行一次，日报目录里多出一份 `.md`**，文件名带今天的日期。
3. **打开那份日报，条数和“抓订阅源”那个节点的输出条数对得上。**
4. **随便挑三条，点进链接看原文**，日报里那一句说的是不是这篇文章讲的事。**说的不是同一件事，回教材[第 5 章](../../../book/09-Agent与RPA/05-案例一-模型摘要.md)改提示词，一次改一条。**
5. **日报里没有出现原文里没有的东西**——多出来的数字、多出来的公司名、多出来的结论。**这一条比第 4 条更硬。**
6. **工作流是发布状态，而且第二天到点它自己跑了一次**，执行记录里有那一行，日报目录里有第二份。
7. **故意让它失败一次，你知道去哪儿看。** 把“问模型”那个节点的地址改错一个字母，执行一次，**在执行记录里点开那个红掉的节点，看得到错在哪儿**（教材[第 11 章](../../../book/09-Agent与RPA/11-日志与重试.md)第一节）。**改回来，保存。**

**第 5 条是这个案例和“把几条新闻粘进对话框问一句”的分界线。** 过不了这一条，你交出去的是一份你自己都不敢照着做决定的东西。

**第 6 条管的是“它到底自动没自动”。** 手动点一次能跑，跟每天自己跑，中间隔着一个发布状态——**这一条是本卷从第 6 章起说过三遍的那一条。**

## 可以出售的结果

- **每日信息简报（轻交付）**：客户给你几个他关心的公开来源，你把这条流程配好，**每天早上一份中文简报送到他邮箱**。客户不用买机器、不用装环境。
- **整机预装 + 一条日报流程**：机器加系统加这条流程，装在客户自己那儿。**卖点是这些内容不经过任何外部服务**——抓下来、摘出来、存下来，全在这一台机器上。
- **换一个来源就是另一个客户**：行业公告、竞品动态、政策发布、招投标信息。**同一条流程、同一套节点，换一个订阅源地址就是另一单**（教材[第 17 章](../../../book/09-Agent与RPA/17-这个能力怎么卖.md)那张复杂度分档表里，这一条属于中等档）。
- **接到别的地方**：不发邮件，改成写进客户的群、写进一张表格、进他们自己的系统。**这一项必须单独报价**——教材[第 17 章](../../../book/09-Agent与RPA/17-这个能力怎么卖.md)那条“每对接一个第三方系统单独列一行”。
- **加一层监测**：某个页面变了就通知，不是每天都发。**这是这条流程的一个变体，做法在教材[第 4 章](../../../book/09-Agent与RPA/04-案例一-抓网页.md)和[第 11 章](../../../book/09-Agent与RPA/11-日志与重试.md)。**
- **配套的运维**：执行记录巡检、失败报警、来源失效之后的适配。**这一项按月收**，教材[第 17 章](../../../book/09-Agent与RPA/17-这个能力怎么卖.md)那条“月费是这门生意唯一会自己回来的钱”。

**上面这些是可以准备的方向，不是已经验证过的成交路径。** 公开渠道里，这个方向**有需求证据、有定价参照，没有可核验的成交案例**。成本怎么算、四种计价方式各配什么场合，在教材[第 17 章](../../../book/09-Agent与RPA/17-这个能力怎么卖.md)；报价单和合同在教材第 11 卷和第 13 卷。

**还有两条硬的：**

- **不承诺摘要的质量。** 能承诺的是“每天到点它会去抓、抓到的东西会摘一遍、失败了会通知你”，**不是“摘得准”**。
- **来源不是你的。** 对方站点改地址、改字段、停掉那个源，这条流程就要重新适配。**这一条要写进报价单**（教材[第 17 章](../../../book/09-Agent与RPA/17-这个能力怎么卖.md)第三条边界）。

## 常见问题

### 第 1 项说找不到容器

```bash
docker ps -a
```

容器名不是 `n8n` 的话：

```bash
CHECK_N8N_NAME=你的容器名 ./scripts/check-n8n.sh
```

### 第 1 项说重启策略不对

**这一项不能用 `restart` 改。** 要停掉、删掉、按教材[第 9 卷第 2 章](../../../book/09-Agent与RPA/02-n8n装起来.md)那条 `docker run` 重建一次，**那一行里要有 `--restart unless-stopped`**。

**重建不会丢工作流**——它们在挂出来的那个数据目录里（第 4 项查的就是这个）。

### 第 3 项说容器里问不到 Ollama

先在宿主机上确认 Ollama 自己是好的：

```bash
curl -s http://127.0.0.1:11434/v1/models | head -c 200
```

宿主机上通、容器里不通，多半是两件事之一——**Ollama 没设成对外监听**（教材[第 6 卷](../../../book/06-本地模型/README.md)），或者**这台机器上 `host.docker.internal` 不通**（教材[第 9 卷第 2 章](../../../book/09-Agent与RPA/02-n8n装起来.md)最后一节，退路是换成本机的固定地址）。

### 第 4 项说 /data 没挂

**这一项不挂，“写到硬盘”那个节点会报找不到目录。** 修法和重启策略一样——停掉、删掉、重建，**那条命令里要有 `-v "$HOME/ai/data/daily:/data"`**。

### 日报出来了，但每条只有标题和链接

**是第 4 步第三处那件事**：Code 节点里取的字段名和这个订阅源实际的字段名对不上。**先执行一次“抓订阅源”，照输出面板上真实的名字改。**

### 日报里的话跟原文对不上

**回教材[第 5 章](../../../book/09-Agent与RPA/05-案例一-模型摘要.md)改提示词，一次改一条，改完执行一次。** 提示词在“问模型”那个节点的请求体里，`"role": "system"` 那一段。

**内容太长被截断的情况**，那一章也讲了——样例里已经把每条摘录截到 500 个字符、最多取 8 条，**这两个数是本教材挑的起点，不是实测出来的最优值，需要核验**，在“整理素材”那个节点里改。

### 手动点能跑，第二天什么都没有

**九成是没发布。** 保存不等于发布（教材[第 6 章](../../../book/09-Agent与RPA/06-案例一-每日推送.md)、[第 11 章](../../../book/09-Agent与RPA/11-日志与重试.md)那条排查顺序第一条）。

还要看两件事：**容器当时在不在跑**（`docker ps`，`STATUS` 是 `Up`），**机器当时是不是开着的**。**机器关着的时候错过的那一次会不会补跑，本项目未核实，需要核验——别赌它会补。**

### 执行记录把硬盘占满了

教材[第 11 章](../../../book/09-Agent与RPA/11-日志与重试.md)第二节，保留策略怎么看、怎么改，那一节写全了。

## 隐私与边界

- **抓东西那六条规矩，一条都不越**：只抓公开页面、先看 `robots.txt`、控制频率、看站点条款、抓下来的内容自己看可以原样公开转载不行、出问题先停（教材[第 4 章](../../../book/09-Agent与RPA/04-案例一-抓网页.md)）。**这份样例默认一天只跑一次，不要改成每五分钟一次。**
- **日报里保留原文链接。** 它是给你决定“要不要点开看”的，**不是拿来替代原文的**。
- **真实的工作流导出不进 Git。** 里面会带凭据编号、内网地址、你自己的订阅源和模型名，`.gitignore` 已经排除了常见的几个文件名。
- **日报输出不进 Git。** 里面是抓回来的正文和链接。
- **这个界面不要开到公网上。** 进得去就能改工作流、能看到你存的凭据。出门要用走 Tailscale（教材[第 3 卷第 6 章](../../../book/03-服务器基础/06-Tailscale.md)）。
- **体检脚本的输出带内网信息**，往外发之前按教材[第 0 卷第 8 章](../../../book/00-使用说明/08-文件保护.md)看一遍。
