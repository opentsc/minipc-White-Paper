# 09　断网演示

## 这一章的任务

当着客户的面把网断掉，让他自己出题，机器照答。

**这是本卷最能卖钱的一章。**

第 4 章那套引用解决的是“它答得对不对”，第 5 章解决的是“它会不会瞎编”。**都很重要，但都不是客户最先问的那个问题。** 客户最先问的是——

> “我的合同传到你们服务器上去了吗？”

这个问题你没法用话回答。**你说“不会”，他只能选择信或者不信。** 断网演示把它变成一件他自己能验证的事：网都断了，它还在答，那这些文件和这个模型只可能在这台机器里。

这一章接着第 4 章那套现场话术往下走。**第 4 章的现场五步不重抄**，这一章补的是五步之后的那一段，加上一份演示前的检查清单和几个容易翻车的地方。

## 开始前

- 第 3 章到第 8 章做完。**特别是第 3 章那一步——向量模型必须已经换成 `bge-m3`**，本章最后一节讲不换会当场出什么事；
- 第 4 章那套现场五步你自己走过一遍，引用点得开、能翻到原文；
- 第 5 章做完，问一个库里没有的它会说查不到。**第 4 章第五步要用它**；
- 手上有一个用客户自己的文件建的库（第 2、3 章）；
- 知道这台机器的网线插在哪、Wi-Fi 开关在哪；
- 装了 [第 3 卷第 6 章](../03-服务器基础/06-Tailscale.md)那个 Tailscale 的，知道怎么断开、怎么开回来。

## 新词

**冷启动**：模型有一段时间没被用过，会从内存里退出去。**这时候第一个问题要多等一会儿**，模型得先重新装进内存。演示前十分钟随便问一句，就是为了避开这一下。

## 这个演示为什么管用

三句话。

**一、客户怕的是数据出门，不是 AI 不准。**

律所、诊所、代理记账、做产品设计的——这几类客户手上的东西，泄出去是要出事的。他们不是没试过 AI，是不敢把自己那份合同粘进去。**你卖的东西恰好解决的就是这一条**，但这一条最难用嘴说清。

**二、断网是一个外行也能判断的证据。**

你讲模型在本地、讲向量库在容器里、讲请求没有出网——**客户听不懂，听懂了也不信**，因为那仍然是你在替机器打包票（第 4 章那句话在这里同样成立）。

网线拔下来放在桌上，这件事不需要任何解释。**他自己看得懂。**

**三、这个动作让他自己动手。**

演示里最有效的部分从来不是你演的那些，是他自己做的那一下（第 4 章第四步已经说过一次）。**这一章把那一下升级了**——上一次是他自己翻文件，这一次是他自己拔线、自己出题。

> **一句可以照念的：**
>
> “您刚才看到的那几个答案，是这台机器自己算的，还是传到外面算的？光我说没用。咱们把网断了，再问一遍。”

## 演示前的检查清单

**这份清单在到客户那儿之前跑完，一条都别跳。**

```text
□ 1. ollama list 里有对话模型，也有 bge-m3
□ 2. 管理员面板 → 设置 → 文档，向量模型确实是 bge-m3，不是默认那个
□ 3. 知识库建好，文件份数和第 2 章记的那个数对得上
□ 4. 自定义模型建好，第 5 章那段系统提示词已经粘进去
□ 5. 用客户自己的文件建的库，不是你的样例文件
□ 6. 自己完整走一遍，包括断网那一段，一步不落
□ 7. 断网状态下问过至少三道题，答案和引用都正常
□ 8. 客户那几份原始文件在旁边开着，待会儿要翻
□ 9. 演示前十分钟随便问一句，让模型热起来（避开冷启动那一等）
□ 10. 网线看得见摸得着，不是藏在机柜后面
□ 11. 装了 Tailscale 的，知道怎么断、怎么开回来
□ 12. 演示结束后怎么把网恢复，你自己心里有数
```

**第 6 条是这份清单的核心。** 第 4 章说过“别在客户面前第一次试”，到了断网这一步更是——**断网之后出的错，你当场没法查，因为查也要上网。**

**第 7 条不能只问一道。** 一道答对可能是刚好命中缓存或者刚好那一段还在内存里。**三道不同的题都正常，才算走通了。**

### 加一道保险（可选）

第 3 章把向量模型换成 `bge-m3` 之后，运行时联网下载这条路基本已经堵上了。**想再稳一点，可以让容器彻底进离线状态。**

Open WebUI 有两个和离线有关的环境变量（`OFFLINE_MODE` 和 `HF_HUB_OFFLINE`），加进 `docker run` 里，容器就不再尝试去外面下东西。做法是[第 6 卷第 4 章](../06-本地模型/04-Open-WebUI.md)那套“改了参数要停掉、删掉、重新 run”：

```bash
docker stop open-webui
docker rm open-webui
```

然后在那一章那条 `docker run` 里多加两行 `-e`：

```bash
docker run -d \
  --name open-webui \
  --restart unless-stopped \
  -p 3080:8080 \
  --add-host=host.docker.internal:host-gateway \
  -e OLLAMA_BASE_URL=http://host.docker.internal:11434 \
  -e OFFLINE_MODE=True \
  -e HF_HUB_OFFLINE=1 \
  -v "$HOME/ai/projects/open-webui/data:/app/backend/data" \
  ghcr.io/open-webui/open-webui:main
```

**数据在 `-v` 那个目录里，删了容器重建不会丢**（[第 6 卷第 4 章](../06-本地模型/04-Open-WebUI.md)验证过），账户、库、模型都还在。

> **这两个变量的确切名称、大小写和当前是否仍然有效，本项目未核实，需要核验**，以你部署当天官方的环境变量文档为准。**加完照检查清单第 6、7 条重走一遍**——加保险的动作本身也可能把别的东西弄坏，走一遍才知道。
>
> **不想加也行。** 第 3 章那一步已经解决了主要的风险，这一条是锦上添花，不是必需。

## 拔哪根，两种拔法

**这一节要先想清楚，不然到现场会尴尬。**

要证的事只有一件：**这台机器出不了网。** 但“断网”这个动作有两种做法，效果和限制完全不同。

### 拔法一，断这台机器自己的全部网络（本卷推荐）

网线拔掉，Wi-Fi 关掉，Tailscale 断掉。**这台机器和外面、和局域网，全断。**

- **好处**：最硬。**连局域网都没了，它还答得出来**，客户没有任何解释空间。而且它不碰客户的任何网络设备，你到谁的办公室都能演。
- **限制**：演示只能在这台机器自己的屏幕上做（或者接一台显示器）。**手机、笔记本这时候都连不上它**——它们本来是靠局域网连过来的。

### 拔法二，断客户办公室的外网上联线

拔的是路由器那根出去的线。**Mini PC 和客户的手机还在同一个局域网里，手机上照样打得开 `192.168.1.x:3080`，但整个办公室出不了网。**

- **好处**：客户能在自己手机上操作，代入感更强。
- **限制**：你得碰客户的路由器，而且得说服他让你断掉整个办公室的网。**多数场合做不到**，尤其是第一次上门。

**本卷推荐拔法一**，理由是它不依赖客户的网络设备，而且更硬。下面的脚本按拔法一写。

> **这两件事别混起来说：** 断网证的是“**这台机器出不了网**”，不是“这台机器不能被访问”。客户可能会问“那我员工怎么用”——答案是平时它连着局域网，员工从局域网进来；**出网这条路本来就不需要**。这句话可以照念。

## 完整演示脚本

**前五步是第 4 章那套，照原样走，不重抄。** 走完那五步，客户已经看过一轮答案、点开过引用、自己翻过原文、也见过它说“资料里没有查到”。

**从第六步开始是这一章的内容。**

### 第六步，先说清楚要证什么

> “您刚才看到的那几个答案，是这台机器自己算的，还是传到外面算的？光我说没用。咱们把网断了，再问一遍。”

**这句话要在动手之前说。** 先立靶子，再射——客户知道你要证什么，后面那几分钟他才会盯着看。

### 第七步，当着他的面断网

**三样都要断，一样都不能少。**

**一、网线。** 拔下来，**放在桌上他看得见的地方**。

> “网线在这儿，您来拔。”

**把线交给他。** 这一下值得多花三秒钟——他自己拔的线，后面就没法说是你做了手脚。

**二、Wi-Fi。** 右上角状态菜单里关掉（[第 1 卷第 9 章](../01-开箱与安装/09-系统更新.md)连 Wi-Fi 用的就是这个菜单）。

**很多人会漏掉这一样。** 这台机器可能同时连着网线和 Wi-Fi，你拔了线它照样在网上，客户回去一想就明白了，这场演示白演。

**想一次断干净，用一条命令**：

```bash
sudo nmcli networking off
```

作用：把这台机器上所有网络接口一起关掉，有线无线都算。**比一样一样关稳**，也省得漏。

**三、Tailscale。** 装了[第 3 卷第 6 章](../03-服务器基础/06-Tailscale.md)那个的，多跑一句：

```bash
sudo tailscale down
```

作用：断开 Tailscale。**上面那条 `nmcli networking off` 其实已经把底下的网断了，Tailscale 自然也没了**，这一句是做给客户看的——让他知道那个能从外面连进来的通道也关了。

> **Tailscale 这件事要主动交代。** 你要是装了它却不说，客户后来自己发现有个“能从外面连进来的东西”，前面所有的信任一次清零。**主动说，然后当场断给他看**，这是加分不是减分。

**断完确认一次**：

```bash
nmcli device status
```

作用：列出这台机器上的网络接口和各自的状态（[第 1 卷第 11 章](../01-开箱与安装/11-收货验收.md)用过这条命令）。**每一行的状态都应该是断开的。**

### 第八步，让客户自己验证网真的断了

**这一步交给他做，你不要碰键盘。**

> “您打开个网页试试，随便哪个。”

**关键在“随便哪个”和“您来”。** 由他挑网址，由他敲，你站远一点。

**别用刚才打开过的那个网址**——那一页可能从缓存里出来，看起来像还连着，下一节专讲这件事。

不放心的话再跑一句他也看得懂的：

```bash
ping -c 4 www.baidu.com
```

作用：往一个外面的网站发四个包，看有没有回（[第 1 卷第 9 章](../01-开箱与安装/09-系统更新.md)用过）。**断网的时候它会直接报错或者一个包都收不到。**

> **一句可以照念的：** “您念一下这行字。”——让他自己念出屏幕上那句“连不上”，比你指着说效果好。

### 第九步，让他出一道新题

> “现在您再出一道，跟刚才那道不一样的。问什么都行。”

**必须是新题。** 重复刚才那道，客户会想是不是存下来了。

新建一个对话，模型选择框里挑那个自定义模型（第 3 章第七步那个），**把键盘交给他打，或者他说你打**。

答案出来。

### 第十步，再点一次引用，让他再翻一次原文

> “网是断的，答案照出来了。它这句话从哪儿来的，还在这儿。”

点开引用，**照着念一句原文**（第 4 章第三步那个动作），然后把客户那份原始文件推过去。

> “您再翻一次。”

**说完闭嘴。** 第 4 章那条规矩在这里还是那条——**这几秒钟是整场演示最有效的几秒**，别讲话。

### 第十一步，让他连出三道

> “您接着问，问几道都行。”

**这一步是主菜，别赶时间。**

前面十步都是你在带，这一步是他自己在用。**他连问三道之后，“这东西在本地跑”这件事就不再是你说的了，是他自己得出来的。**

这时候他多半会问出一道库里没有的。它说查不到，**这时候接一句**：

> “它查不到就说查不到，不硬答。这是设过的。”

（这一句归第 5 章管，**没做第 5 章那套设置就别说这句话**，它会当场编一段。）

### 第十二步，当着他的面把网插回去

**别留一台断网的机器给人家。**

网线插回去，然后：

```bash
sudo nmcli networking on
```

装了 Tailscale 的再来一句：

```bash
sudo tailscale up
```

> “网我插回去了。您什么时候想再验一次，自己拔就行——就这两下。”

**最后这句话很重要。** 它把“断网可用”从一场表演变成一个他随时可以自己重做的动作。**一个能反复自验的卖点，比一次漂亮的演示值钱。**

## 四个容易翻车的地方

### 一、浏览器缓存让人以为网还连着

断完网，你打开一个刚才看过的网站，它照样显示出来了。**客户当场就会说“这不是还有网吗”。**

原因是那一页存在浏览器本地，不需要重新联网就能显示。

**两个做法：**

- **用一个刚才没打开过的网址。** 最简单，也最自然；
- 或者在那一页上按 `Ctrl+Shift+R` 强制重新加载。**这一下会跳过缓存**，真的去连一次，连不上就报错。

**顺带一提，客户也可能反过来被缓存骗。** 有的客户会说“那你这个 AI 是不是也是缓存的”——**这时候让他出一道全新的题**，缓存里不可能有他现编的问题。这句反问用得好，比解释缓存原理有用。

### 二、演示放在手机上，一断网就全黑

这一条前面那一节已经埋过：**手机是靠局域网连到这台机器的。** 你按拔法一把这台机器的网全断了，手机上那个页面立刻就打不开。

**客户看到的是“一断网就用不了”，跟你要证的事正好相反。**

**做法：**

- **演示在这台机器自己的屏幕上做**，或者给它接一台显示器、一个大屏。这是本卷推荐的做法；
- 非要在手机上演，那就是拔法二——断路由器的外网上联线，让 Mini PC 和手机留在同一个局域网里。**这个要事先跟客户约好，别到现场才提。**

**别在现场临时换方案。** 两种拔法要说的话不一样，临时改你会说岔。

### 三、库还在用要联网的向量模型（最要命的一条）

**这一条会让演示当场死掉，而且死得很难看。**

第 3 章第一步做的事就是它——把向量模型从默认那个换成 `bge-m3`。**默认那个偏英文，而且第一次用的时候要联网下载。**

如果你跳了第 3 章那一步，或者交付的时候用了另一台机器上没改过的配置，会发生这个：**联网的时候一切正常，网一断，你一提问，检索这一步就卡住或者报错。** 客户面前，屏幕上转圈或者弹一个英文错误。

**这就是第 3 章那一步为什么排在建库之前。**

**演示前照检查清单第 1、2 条对一遍**：`ollama list` 里有 `bge-m3`，管理员面板那一页上填的也是它。**两处都对上才算过。**

同一个道理还有一处要留意：**第 6 卷第 12 章提过的 reranker，如果你装了要联网下载的那种，断网之后同样会出问题。** 没装的不用管——本卷主线一直没用它。

### 四、模型冷了，第一个问题等太久

断网之后客户出的第一道题，屏幕上半天不出字，**空气会变得很尴尬**，而且你没法解释——一解释就像在找借口。

原因多半是模型有一阵子没用过，从内存里退出去了（本章那个新词），第一次问要先把它装回来。

**做法就是检查清单第 9 条**：演示开始前十分钟随便问一句，让它热着。**这一下花不了十秒，能省掉现场那半分钟的沉默。**

## 客户会问的三句话

**这三句十有八九会碰上，先想好怎么答。**

**一、“那它要不要更新？更新不还是要联网？”**

> “模型和软件更新要联网，那是我这边的事，跟您的文件没关系。平时它可以一直断着用；要更新的时候连一下，更完再断上。”

**别把这件事说成不需要联网。** 说成“需要联网的是维护，不是您的数据”，这是实话，客户也听得懂。

**二、“那我怎么知道它平时没偷偷传？”**

> “今天这一下您已经验过一次了，而且您随时可以再验——拔线，问一道，就这两下。要更严的话，可以在您的网络设备上只放行必要的出网，这一层归网络管理，我们可以一起看。”

**别打包票说“我保证它不传”。** 你给的是一个他能反复自验的办法，这比保证有用。

**三、“断网了是不是就不能远程用了？”**

> “平时是连着的，员工从公司内网进来用，跟平常一样。今天断的是这台机器出网那条路，不影响内网。”

如果装了 Tailscale，这里顺便交代清楚：**它是一条能从外面连进来的通道，装不装由客户定，不装也能用。**

### 一条别越过的线

客户很可能顺口问一句“这样是不是就合规了”。

**能说的是架构事实**：数据的存储、检索和推理都在他自己的场所内完成，不往外部服务器传；断网可用，他随时可以自己验。

**不能说的是结果**：不说“用了就符合某某法规”，不说“绝对安全”“零风险”，不说“通过了某某认证”（除非真有证书）。

> 标准答法：“架构上数据不出您的场所，这一条您今天自己验过了。具体合规怎么认定，建议您问自己的法律顾问。”

**合规是客户的整体义务，不是买一台设备就达标。** 这句话记住，别在现场为了促单说过头。
