## 3.6 常驻 Agent 与多 Agent 工作节点

Mini PC 可以长期运行一个有固定入口和固定权限的 Agent。用户从聊天工具提交任务，Agent 在设备上调用允许使用的文件、模型和外部服务，再把结果送回原入口。

任务增加后，可以把一个 Agent 分成协调 Agent 和岗位 Agent。协调 Agent 接收自然语言，整理成结构化工单，再交给负责检索、内容、系统或数据的岗位 Agent。固定脚本继续处理抓取、索引、备份和健康检查，不需要全部改成对话 Agent。

多 Agent 节点可以组合对话入口、结构化工单、本地模型、浏览器任务和后台服务。每个岗位使用独立工作区和权限，多个岗位可以共享一套 Agent 运行时和模型服务。

可以先从这些候选任务中选择。

- 整理本地文件并生成文档草稿。
- 检索公开资料并生成报告。
- 用本地模型处理重复任务，遇到超出能力的任务再调用云端模型。
- 准备邮件、代码仓库事项或其他外部动作，等待人工确认后执行。
- 检查自己的服务状态、资源和日志。

这些是能力方向，不代表任意 Agent 已经完成部署。每项能力还要分别检查数据来源、工具权限、确认步骤和失败后的恢复办法。完整案例放在第 6 章。

## 3.7 怎样选择第一个项目

- 输入是否清楚。
- 结果是否看得见。
- 失败是否容易恢复。
- 是否需要公网。
- 是否涉及个人资料。
- 设备能否承担。
- Agent 能接触哪些文件和外部账户。
- 哪些动作必须由人确认。
