# 02　下载第一个模型

## 这一章的任务

把第一个模型文件下到 `~/ai/models`，并且确认它下全了。

这一章的难点不在命令，在国内网络。模型托管在 Hugging Face 上，那个站在国内多数网络下直连不通，一条命令跑半天没动静是常态。所以下面给三条路：**国内节点的 ModelScope、Hugging Face 官方、hf-mirror 镜像**。挑一条能通的走，三条路下下来的文件完全一样。

做完之后你手上有一个几十 GB 的 `.gguf` 文件，第 3 章开始用它。

## 开始前

- [第 2 卷第 1 章](../02-Ubuntu/01-桌面与文件.md)那套目录在，`~/ai/models` 已经建好；
- 硬盘有空间。先看一眼：`df -h ~/ai/models`，`Avail` 那一列要比你打算下的文件大出至少 10 GB。空间不够先看[第 4 卷第 13 章](../04-Max395硬件/13-SSD.md)；
- 第 1 章读完了，知道 `UD-Q4_K_M` 是什么意思；
- [第 2 卷第 11 章](../02-Ubuntu/11-环境变量与配置文件.md)看过，这一章要往 `~/.bashrc` 里写两行；
- 网络能上外网。下载几十 GB，挂着跑，别的事照做；
- 命令十几分钟，下载看网速，可能要一两个小时。

## 新词

**仓库**（repo）：模型托管站上的一个页面，一个模型一个仓库，名字形如 `发布者/模型名`。命令里填的就是这个完整名字，两段之间的斜杠不能少。

**转档仓库**：把原厂模型转成 GGUF 格式重新发布的仓库。`unsloth`、`ggml-org`、`bartowski` 这几家是常见的转档方。**跑 llama.cpp 和 Ollama 的人日常下的都是转档仓库。**

**镜像站**：把原站的内容同步一份放在别处的站点。`hf-mirror.com` 是 Hugging Face 的国内镜像。

**gated 模型**：设了访问门禁的模型，要先在官网申请、同意条款才能下。不申请直接下会报 401 或者 403。

**token**（这里指访问令牌）：一串代表你身份的字符串，用来向站点证明这个请求是你发的。和第 1 章那个作为文字单位的 token 不是一回事，同名不同物。

**断点续传**：下载中断之后，重新执行同一条命令，已经下好的部分不重下，接着往下。本章三个工具都支持。

**虚拟环境**（venv）：Python 的一个独立小环境，装在里面的包和系统自带的 Python 互不干扰。Ubuntu 24.04 不允许往系统 Python 里装包，所以本章的下载工具装在虚拟环境里。

## 第一个下哪个

**`unsloth/Qwen3.6-35B-A3B-GGUF` 仓库里的 `Qwen3.6-35B-A3B-UD-Q4_K_M.gguf`，22.1 GB。**

挑它的理由：

- 第 1 章那张表里的主力区间，22 GB 权重加 128K 上下文也就三十几 GB，这台机器余量很大；
- MoE 结构，35B 总参数每个 token 只激活 3B，出字不慢；
- 中文能用，本卷主线是给家里人用的；
- 同一个仓库里有一个 `mmproj-F16.gguf`（0.9 GB），是看图要用的投影文件，顺手一起下，第 11 章用得上。

**下载之前先去仓库页面看一眼。** 浏览器打开 `https://hf-mirror.com/unsloth/Qwen3.6-35B-A3B-GGUF/tree/main`，页面上是这个仓库的文件列表，每个文件后面标着大小。**你要下的那个文件名和大小，从这个页面上抄，不要凭本章的文字**——仓库会更新，本章的核验日期是 2026-08-14。

> **网速实在慢、或者只想先把流程跑通**，可以先下一个更小的。同样在第 1 章那张表的第一档里，`ggml-org/gpt-oss-20b-GGUF` 的 `gpt-oss-20b-MXFP4.gguf` 约 12 GB。**这个仓库和文件大小本项目未逐个核实，需要核验**，下之前先在页面上确认。流程完全一样。

## 先建目录

```bash
mkdir -p ~/ai/models/qwen3.6-35b-a3b
```

作用：在 `~/ai/models` 下面建一个子目录。**一个模型一个子目录**，目录名用小写。没有输出就是建好了。

一个模型的文件常常不止一个（权重加投影文件，大模型还会分片），全堆在 `~/ai/models` 根上，过两个月就分不清哪个跟哪个。

## 装下载工具

三条路里有两条要用 Python 的包，先把环境备好。

**第一步，装 Python 的虚拟环境工具：**

```bash
sudo apt install python3-venv python3-pip aria2
```

作用：装三样。前两个是 Python 的环境和包管理工具，`aria2` 是一个多线程下载器，本章最后那条备用路线要用。输出是一串安装进度，已经装过的会提示 `is already the newest version`。

**第二步，建一个虚拟环境：**

```bash
python3 -m venv ~/ai/scripts/dl-tools
```

作用：在 `~/ai/scripts/dl-tools` 下面建一个独立的 Python 环境。没有输出。

按[第 2 卷第 1 章](../02-Ubuntu/01-桌面与文件.md)的约定，工具类的东西放 `ai/scripts`，不往家目录根上散。

> **不要直接 `pip install`。** Ubuntu 24.04 禁止往系统自带的 Python 里装包，硬装会报 `error: externally-managed-environment`。网上有教程让你加 `--break-system-packages` 绕过去，**那个参数会把系统的 Python 弄乱**，本教材不用。

**第三步，把两个下载工具装进去：**

```bash
~/ai/scripts/dl-tools/bin/pip install -U pip huggingface_hub modelscope -i https://pypi.tuna.tsinghua.edu.cn/simple
```

作用：装 Hugging Face 的 `huggingface_hub`（`hf` 命令随包附带）和 ModelScope 的客户端。`-i` 后面那个地址是清华的 PyPI 镜像，国内直连可用；能连通国外的话去掉这一段也行。

输出是一串下载和安装信息，最后一行 `Successfully installed ...` 加一串包名。

**第四步，让这两个命令能直接敲：**

```bash
echo 'export PATH="$HOME/ai/scripts/dl-tools/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

作用：把刚才那个环境的命令目录加进 `PATH`，以后开终端直接敲 `hf` 和 `modelscope` 就行，不用每次写全路径。第一条往 `~/.bashrc` 末尾追加一行，第二条让它当场生效。两条都没有输出。

**注意是 `>>` 不是 `>`。** 一个大于号会把 `~/.bashrc` 整个覆盖掉，这是这一节唯一会闯祸的地方。

确认：

```bash
hf version
```

输出形如 `huggingface_hub version: 1.x.x`，就装好了。提示 `command not found` 的话，`PATH` 那一行没生效，重开一个终端窗口再试。

## 路线一、ModelScope：国内节点，最省事

ModelScope（魔搭）是阿里的模型托管站，服务器在国内，不用镜像不用代理。主流开源模型大多同步上架，仓库名和 Hugging Face 一致。

**先看有没有这个仓库。** 浏览器打开 `modelscope.cn`，搜 `Qwen3.6-35B-A3B-GGUF`。有就走这条路，最省事。

```bash
modelscope download --model unsloth/Qwen3.6-35B-A3B-GGUF Qwen3.6-35B-A3B-UD-Q4_K_M.gguf mmproj-F16.gguf --local_dir ~/ai/models/qwen3.6-35b-a3b
```

作用：从 ModelScope 下这两个文件，落到指定目录。`--model` 后面是仓库名，再后面挨个写文件名，`--local_dir` 是落地目录。

**这条命令的参数写法和下一节的 `hf` 不一样，两处容易抄混：** 这里是 `--model`，那里没有这一项；这里是下划线的 `--local_dir`，那里是连字符的 `--local-dir`。

正常输出是一串进度条，跑完回到提示符。

个别仓库要求登录才能下。那就去 `modelscope.cn` 注册一个账号，在个人中心里生成访问令牌，然后执行一次 `modelscope login --token 你的令牌`，以后不用再登。

## 路线二、Hugging Face 官方

网络能直连 `huggingface.co` 的话，直接用官方命令。

**下之前先问一句要下多大：**

```bash
hf download unsloth/Qwen3.6-35B-A3B-GGUF Qwen3.6-35B-A3B-UD-Q4_K_M.gguf mmproj-F16.gguf --dry-run
```

作用：只算不下。输出形如：

```text
[dry-run] Will download 2 files (out of 46) totalling 23.0G.
```

**几十 GB 的东西，下之前跑一次这个。** 数字和你预期差得远，多半是文件名写错了，或者漏了文件名——不写文件名它会把整个仓库拉下来，一个 GGUF 仓库把所有量化档加起来常常好几百 GB。

数字对了，去掉 `--dry-run`，加上落地目录：

```bash
hf download unsloth/Qwen3.6-35B-A3B-GGUF Qwen3.6-35B-A3B-UD-Q4_K_M.gguf mmproj-F16.gguf --local-dir ~/ai/models/qwen3.6-35b-a3b
```

作用：把这两个文件下到指定目录。正常输出是每个文件一个进度条，下完最后打印落地路径。

**`--local-dir` 不能省。** 不写的话文件进 `~/.cache/huggingface/` 里一层很深的目录，文件名还被改成一串哈希，后面各章的命令全都找不到它。

`hf download` 还有一个按通配符筛的写法，大模型分成好几片的时候用：

```bash
hf download unsloth/某个大模型-GGUF --include "*UD-Q4_K_XL*" --local-dir ~/ai/models/某个大模型
```

**下载中断了，把同一条命令原样再跑一遍**，已经下好的部分不会重下。这条命令本身就是修复手段。

> 网上 2025 年以前的教程写的是 `huggingface-cli download`。**那个命令名已经不存在了**，官方在 2025 年 7 月把它改名成 `hf`，命令结构变成资源加动作。照抄老教程会报命令不存在。把开头换成 `hf` 就行，参数基本同义。

## 路线三、hf-mirror 镜像：`huggingface.co` 连不上时走这条

`hf` 命令读一个叫 `HF_ENDPOINT` 的环境变量决定去哪个站点取文件。把它指到镜像站，命令一个字都不用改。

```bash
echo 'export HF_ENDPOINT=https://hf-mirror.com' >> ~/.bashrc
source ~/.bashrc
```

作用：往 `~/.bashrc` 里再追加一行，把这个变量长期设上，然后当场生效。同样注意是 `>>`。

确认设上了：

```bash
echo $HF_ENDPOINT
```

输出 `https://hf-mirror.com` 就对了。

**先用一个小文件试通路**，别一上来就下 22 GB：

```bash
hf download unsloth/Qwen3.6-35B-A3B-GGUF README.md --local-dir /tmp/hftest && ls -l /tmp/hftest/README.md
```

作用：下一个几 KB 的说明文件，然后列出来看看。几秒钟内下完并且列出了文件，说明镜像通了。这条只是测试，`/tmp` 下的东西重启就没了，不用管。

通了之后，路线二那两条 `hf download` 命令原样执行，走的就是镜像。

### 镜像也慢的时候：`hfd`

`hfd.sh` 是镜像站自己提供的下载脚本，底下调 `aria2` 多线程，断流自动重连，适合几十 GB 的大文件和不稳的网络。

```bash
wget https://hf-mirror.com/hfd/hfd.sh
chmod a+x hfd.sh
sudo mv hfd.sh /usr/local/bin/hfd
```

作用：三条，下脚本、给它执行权限、挪到系统的命令目录里去。挪完之后在任何目录敲 `hfd` 都能用。

确认：

```bash
hfd --help 2>&1 | head -5
```

能打印出用法说明就可用。

下载：

```bash
hfd unsloth/Qwen3.6-35B-A3B-GGUF --include "*UD-Q4_K_M*" "mmproj-F16.gguf" --local-dir ~/ai/models/qwen3.6-35b-a3b -x 4
```

作用：按通配符筛文件下载，`-x 4` 是每个文件开 4 个线程，这个值可以填 1 到 10。

**aria2 正在下的文件旁边会有一个同名的 `.aria2` 文件**，下完自动消失。看见 `.aria2` 还在，就是没下完，把同一条命令再跑一遍续传。

## 三条路怎么选

1. **先查 ModelScope 有没有这个仓库**，有就用它，全程国内节点；
2. ModelScope 上没有的，用 `hf download` 配 `HF_ENDPOINT` 镜像；
3. 镜像也断流、速度掉到几百 KB 每秒的，换 `hfd`，或者换个时段——白天早上通常比晚高峰快。

**三个工具下下来的文件完全一样，混着用没问题。** 这条路下一半换另一条接着下也行。

## gated 模型要多走两步

Hugging Face 上一部分模型设了访问门禁，页面上会写一句要你同意共享联系信息才能访问。不申请直接下会报 401 或者 403。

**四步：**

1. **在能打开 `huggingface.co` 的网络环境里注册账号**，打开那个模型页面，点同意并访问，或者填一张表提交。**这一步只能在官网做，镜像站代替不了。** 有的模型是人工审核，几分钟到几天不等；
2. **生成访问令牌。** 官网右上角头像里进设置，找到访问令牌，新建一个，类型选只读，复制生成的那串 `hf_` 开头的字符串。**它只显示一次，当场存进密码管理器**（[第 0 卷第 8 章](../00-使用说明/08-文件保护.md)）；
3. **在这台机器上登录一次：**

```bash
hf auth login --token hf_你的令牌
```

正常输出里有 `Login successful`。确认用 `hf auth whoami`，输出你的用户名。

4. **然后照常下。** 走镜像也行，镜像会带着你的令牌去官方源取。**先拿一个小文件验证权限通了**，比如下那个仓库的 `config.json`，能下下来就说明门禁过了，报 403 就是审核还没通过。

> **令牌等同于你的账号，不要贴进截图、日志、Git 仓库。** 判断标准和保管办法见[第 0 卷第 8 章](../00-使用说明/08-文件保护.md)。

**一个能省事的事实：门禁基本都设在原厂权重仓库上，社区转档的 GGUF 仓库绝大多数不设门禁。** 本卷主线用的这个仓库不是 gated，上面这四步现在用不上，撞上再回来看。

## 确认它下全了

大文件最常见的坏法是中途断掉，文件在，但是不完整。llama.cpp 和 Ollama 加载残缺文件会直接报错退出，不会给你一个错答案——**所以验证的意义是省下排查的时间，不是防止出错。**

**第一层，看字节数。** 这一层秒出结果，每次下完都做：

```bash
ls -l ~/ai/models/qwen3.6-35b-a3b/
```

作用：列出目录里的文件和精确字节数。`-l` 是长格式，第五列就是字节数。

拿这个数字和仓库页面文件列表上标的对。2026-08-13 从仓库文件树取到的参考值是：

```text
Qwen3.6-35B-A3B-UD-Q4_K_M.gguf   22,134,528,992 字节
mmproj-F16.gguf                     899,283,680 字节
```

**一个字节不差就是完整的。**

> **别被单位吓到。** 页面上写的 22.1 GB 是按 1 GB 等于 10 亿字节折算的，`ls -lh` 显示的是 20.6G，那是 GiB。**两个数不一样是正常的**，对比的时候看 `ls -l` 的精确字节数，不看 `ls -lh`。

**第二层，算一次 sha256。** 几分钟，重要的文件做一次：

```bash
sha256sum ~/ai/models/qwen3.6-35b-a3b/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf
```

作用：算出这个文件的指纹。22 GB 的文件在本机的固态硬盘上一两分钟出结果。

在镜像站上打开那个文件的页面，上面有一行 `SHA256:` 开头的 64 位十六进制值，和你算出来的对，完全一致就是完整的。

**第三层，真加载一次。** 这一层第 3 章会做——模型在 Ollama 里能说出话来，就说明文件没问题。

## 常见的几种情况

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `error: externally-managed-environment` | 往系统 Python 里装包了 | 回上面那一节用虚拟环境，**不要加 `--break-system-packages`** |
| `huggingface-cli: command not found` | 照的是 2025 年以前的教程 | 命令开头换成 `hf` |
| 下载卡住不动，也不报错 | 经镜像传输不稳 | 先 `export HF_HUB_DISABLE_XET=1` 再重跑。这是排障手段，平时不用设 |
| `401` 或者 `403` | gated 模型没申请或者没登录 | 走上面 gated 那一节；已经申请了还报 403，就是审核没通过，等 |
| `Repository Not Found` | 仓库名拼错，或者模型改名下架了 | 去 `hf-mirror.com` 或者 `modelscope.cn` 搜一下当前的仓库名 |
| 速度只有几百 KB 每秒 | 晚高峰，或者单线程 | 换 `hfd` 开多线程，换个时段，或者换 ModelScope |
| `No space left on device` | 盘满了 | `df -h ~/ai/models` 看剩多少。多半是没写文件名，把整个仓库拉下来了 |

其余的到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。
