# 06　案例一：每日推送

## 这一章的任务

**让这条流程每天早上自己跑，结果送到你手上。做完这一章，案例一就完整了。**

三件事：

- **把手动触发换成定时触发**，每天早上 7 点自己跑；
- **把五段摘要拼成一份日报**；
- **送出来。** 给两条路——**存成一个按日期命名的文件**（不需要任何外部服务，先做它），和**发到你邮箱**。

最后一节是案例一的完整回顾，**从零到收到第一份日报的全部步骤，列成一张清单。**

## 开始前

- [第 5 章](05-案例一-模型摘要.md)做完，那条“日报-案例一”的工作流点一下执行，输出面板上是几条带 `标题`、`摘要`、`链接` 的数据；
- [第 2 卷第 8 章](../02-Ubuntu/08-定时任务.md)读过。**这一章会拿 cron 和 n8n 的定时对比一节**；
- [第 2 章](02-n8n装起来.md)那两个时区变量填对了。**没填的话这一章做完会在半夜收到日报**，回那一章重建容器；
- [第 2 章](02-n8n装起来.md)那行 `-v "$HOME/ai/data/daily:/data"` 在。跑一句 `docker inspect n8n | grep daily` 能看到就是在；
- 走发邮件那条路的话，**手边要有一个邮箱，而且知道去哪儿开应用专用密码**（下面那节说）；
- 60 分钟。

## 新词

**SMTP**（简单邮件传输协议，Simple Mail Transfer Protocol）：**程序发邮件走的那条路。** 你在手机上用邮件 App 发信，底下走的就是它。程序要发信，得知道四样东西——服务器地址、端口、账号、密码。

**应用专用密码**：邮箱服务商单独发给某一个程序用的一串密码，**和你登录邮箱那个密码是两回事**。下面单说一节。

**发布**（publish）：把一条工作流从“我在编辑器里试”变成“它自己在跑”。**不做这一步，定时触发不会起作用。** 界面上的措辞可能是发布，也可能是激活（Active），**需要核验，以你看到的为准**。

**执行记录**（executions）：[第 3 章](03-第一个工作流.md)那一节。**这一章它从调试工具变成了验收工具。**

## 第一步：换上定时触发

### 把手动触发换掉

在画布上选中那个手动触发的节点，删掉。

然后点加号，搜 `schedule`，选 **Schedule Trigger**，把它连到 RSS Read 上（原来手动触发连的那条线）。

> **删掉手动触发之后还能不能手动跑？能。** 右上角那个执行按钮照样把整条流程从头跑一遍，**调试完全不受影响**。所以不用留着两个触发器。

### 配置

这个节点的参数是一层套一层的，**先选大单位，再填细节**：

- **Trigger Interval** 选 **Days**（按天）；
- **Days Between Triggers** 填 `1`（每天）；
- **Trigger at Hour** 选 `7`（早上 7 点）；
- **Trigger at Minute** 填 `0`。

**参数名以你面板上看到的为准，需要核验。** 官方文档列出的间隔选项有 Seconds、Minutes、Hours、Days、Weeks、Months，还有一项 Custom (Cron)——**那一项就是让你直接写[第 2 卷第 8 章](../02-Ubuntu/08-定时任务.md)那五个字段**。会写 cron 的人可以直接填 `0 7 * * *`，和上面四项选出来的是同一件事。

### 时区那一条，这里第二次说

[第 2 章](02-n8n装起来.md)讲过：**官方文档写明，自托管的 n8n 实例默认时区是 America/New York。**

这里就是它咬人的地方。**你在这个节点里选了 7 点，它按哪个 7 点算，取决于时区。** 时区没设对，这条流程会在你这边的下午或者晚上跑，**而且不报任何错**。

[第 2 章](02-n8n装起来.md)那条 `docker run` 里的 `-e GENERIC_TIMEZONE="Asia/Shanghai"` 管的就是这件事。**做到这一步发现没填**，把容器停掉删掉、加上那两行重新 `run`（[第 2 卷第 10 章](../02-Ubuntu/10-Docker-Compose.md)那条规矩——改参数不是 `restart`）。**数据在 `~/ai/projects/n8n` 那个目录里，删了重建不丢**，工作流还在。

### 和 cron 比一句

[第 2 卷第 8 章](../02-Ubuntu/08-定时任务.md)那套 cron，你已经会了。**同一件事这里换了个地方做，值得比一句：**

| | cron | n8n 的 Schedule Trigger |
| --- | --- | --- |
| 定时写在哪儿 | `crontab` 里一行 | 流程的第一个节点 |
| 要写全路径吗 | **要**，不写全就跑不起来 | 不用，没有路径这回事 |
| 输出去哪儿 | **你自己 `>>` 到一个文件**，还要加 `2>&1` | 自动进执行记录 |
| 跑了什么怎么看 | `cat` 那个日志文件，加 `journalctl -u cron` | 点开执行记录，一个节点一个节点看 |
| 改时间 | `crontab -e` | 改那个节点的参数 |
| 依赖什么 | **什么都不依赖**，系统自带 | 依赖 n8n 这个容器在跑 |

**在 n8n 里做的好处只有一条，但它很实在——整条流程连着定时一起，在一个地方看得见。** 半年后你想知道这份日报是几点跑的、抓的哪个源、用的哪个模型，**打开这条工作流看一眼就全有了**；换成 cron 加脚本，你得先找到那行 crontab，再顺着路径去翻脚本。

**cron 也没被淘汰。** [第 8 卷第 6 章](../08-OCR/06-文件夹监测.md)那条单据流水线走的就是 cron，理由是那一条本来就是一个 shell 脚本叫另一个脚本干活，**中间没有 n8n 什么事，硬套进来反而多一层依赖。** 两条路各有各的场合。

> **有一条两边一样**：[第 2 卷第 8 章](../02-Ubuntu/08-定时任务.md)说过，机器关着的时候 cron 不补跑。**n8n 在这件事上怎么表现，本项目未核实，需要核验。** 所以定时点挑一个你确定开着机的时段，**别赌它会补。**

## 第二步：把五段摘要拼成一份日报

现在流转的是五条数据。**要送出去的是一份东西，不是五份**，所以中间要合成一条。

从[第 5 章](05-案例一-模型摘要.md)最后那个 Edit Fields 拖一条线出去，加一个 **Code** 节点，**改名叫“拼日报”**。

- **Mode** 选“跑一次，处理全部数据”那一项（措辞可能是 Run Once for All Items，**以实际界面为准**）。**这一项要选对**——另一项是每条各跑一次，那就又变成五份了；
- **语言**选 JavaScript；
- 代码照抄：

```javascript
// 把上一步的每一条拼成一段，合成一份日报
const d = new Date();
const 日期 = `${d.getFullYear()}-${String(d.getMonth() + 1).padStart(2, '0')}-${String(d.getDate()).padStart(2, '0')}`;

const items = $input.all();
const 段落 = items.map((it, i) =>
  `## ${i + 1}. ${it.json.标题}\n\n${it.json.摘要}\n\n原文：${it.json.链接}\n`
);

return [{
  json: {
    日期: 日期,
    正文: `# 每日摘要 ${日期}\n\n共 ${items.length} 条。\n\n${段落.join('\n')}`,
  },
}];
```

**逐段说：**

- **头两行算今天的日期**，拼成 `2026-08-15` 这种样子。`padStart(2, '0')` 是把 8 月的 `8` 补成 `08`，**不补的话文件名排序会乱**；
- **`$input.all()` 是拿到上一步的全部数据**，五条就是五条。`.map(...)` 是对每一条做同一件事，这里是拼成一段带标题、摘要和原文链接的文字；
- **`return [{ json: {...} }]` 是这个节点吐出去的东西。** 外面那对方括号表示“只吐一条”，**这就是五合一那一下**；
- **`\n` 是换行**，`##` 和 `#` 是 Markdown 的标题标记，**存成 `.md` 文件之后用支持 Markdown 的编辑器打开就是排好版的。**

**日期那两行要说一句为什么写得这么啰嗦。** 网上常见的写法是 `new Date().toISOString().slice(0, 10)`，**那一种给的是世界时的日期**——早上 7 点在东八区跑，世界时还是前一天晚上 11 点，**文件名会写成昨天。** 上面这种写法用的是本地时间，**而本地时间是[第 2 章](02-n8n装起来.md)那个 `TZ` 变量定的**，填对了这里才对。

执行一次，点开这个节点的输出。**应该只有一条，里面两个字段——`日期` 和 `正文`。** 把 `正文` 那一大段读一遍，**这就是你明天早上要收到的东西。**

**读着不顺就回[第 5 章](05-案例一-模型摘要.md)改提示词**，别在这儿修修补补。

## 路线一：存成文件

**这条最省事，不需要任何外部服务，先做它。**

### 两个节点

**第一个，Convert to File。** 从“拼日报”拖一条线出去，搜 `convert`，选 **Convert to File**：

- **Operation** 选 **Convert to Text File**；
- **Text Input Field** 填 `正文`（就是上一步那个字段名）；
- 选项里的字符编码保持默认，**默认是 UTF-8，中文要的就是它。**

这个节点把一段文字变成一个文件，**文件放在这条数据的二进制那一块里**，字段名默认常是 `data`，**以你面板上显示的为准**。

**第二个，Read/Write Files from Disk。** 再拖一条线出去，搜 `file`，选它：

- **Operation** 选 **Write File to Disk**；
- **File Path and Name** 填（切到表达式那一边）：

```text
/data/日报-{{ $json.日期 }}.md
```

- **Input Binary Field** 填上一步那个字段名（默认常是 `data`）。

### 这个路径为什么是 `/data`

**[第 2 章](02-n8n装起来.md)那件事，这里第一次真的用上。**

n8n 官方文档写明：**在 Docker 里跑的时候，节点里填的路径指的是容器内部的文件系统。** [第 2 章](02-n8n装起来.md)那条 `docker run` 里有一行：

```text
-v "$HOME/ai/data/daily:/data"
```

它把宿主机的 `~/ai/data/daily` 接到了容器里的 `/data`。**所以节点里写 `/data/日报-2026-08-15.md`，文件真正落在你硬盘上的 `~/ai/data/daily/日报-2026-08-15.md`。**

**这里填 `/home/你的账户名/ai/data/daily/...` 是不行的**，容器里没有那个路径，节点会报找不到目录。

> **按[第 2 卷第 1 章](../02-Ubuntu/01-桌面与文件.md)的约定，`ai/data` 放的是原始资料，处理结果该放 `ai/projects`。** 日报放这儿的理由是它每天新增一份、跟着[第 2 卷第 12 章](../02-Ubuntu/12-日常备份.md)那套备份一起走最省事。**你想按项目归置**，在宿主机上换个目录（比如 `~/ai/projects/daily-digest`），把 `docker run` 里挂载那一行跟着改，**容器里那个 `/data` 不用动。**

### 跑一次，去硬盘上看

点执行。跑完回终端：

```bash
ls -lh ~/ai/data/daily/
```

**多出一个 `日报-2026-08-15.md` 就成了。** 打开看一眼：

```bash
cat ~/ai/data/daily/日报-2026-08-15.md
```

**写不进去**——节点报权限相关的错，是[第 2 章](02-n8n装起来.md)那件事：容器里的程序不是以你的身份跑的。

```bash
sudo chown -R 1000:1000 ~/ai/data/daily
```

改完再执行一次。**`1000` 这个数字需要核验**，以 `docker logs n8n` 里报出来的为准。

## 路线二：发到邮箱

**先说密码这件事，它比节点怎么配重要。**

### 用应用专用密码，不要用你登录邮箱那个密码

多数邮箱服务商现在都提供一种“应用专用密码”或者叫“授权码”的东西——**你在邮箱的设置里生成一串，专门给某一个程序用。**

**两条理由，都很硬：**

**一、多数服务商本来就不允许第三方程序用登录密码。** 你填登录密码进去，多半是直接被拒，表现是节点报认证失败，**而你会以为是密码打错了，反复试**。

**二、这串密码要存在这台机器上。** 存的是应用专用密码的话，**万一泄露，去邮箱设置里把那一串作废掉就完了，你的邮箱账号本身不受影响**；存的是登录密码，那就是把整个账号交出去了。

**怎么生成**：各家路径不一样，一般在邮箱的设置里找“账户安全”“客户端授权”“应用专用密码”这类字样。**具体在哪儿、叫什么，以你那家服务商当时的说明为准，本教材不写死。**

> **生成出来的那一串同样是密码。** [第 0 卷第 8 章](../00-使用说明/08-文件保护.md)那些规矩全都适用——不进 Git、不贴进聊天工具、不写进截图。**在 n8n 里它存在凭据里，不写在节点上，也不会跟着工作流被导出**，这是[第 2 章](02-n8n装起来.md)新词里说凭据要单独存的原因。

### 建 SMTP 凭据

从“拼日报”**再拖一条线出去**（一个节点可以引出多条分支，和上面那条去存文件的线并排），搜 `email`，选 **Send Email**。

这个节点要一个 SMTP 凭据。在节点里点新建凭据，要填的一般是这几样：

- **服务器地址**（Host）——形如 `smtp.你的服务商.com`；
- **端口**（Port）——常见的是 465 或者 587；
- **账号**（User）——多数就是你的邮箱地址；
- **密码**（Password）——上面那串应用专用密码；
- **加密方式**——SSL／TLS 的开关，和端口是配套的。

**这五项各家的填法都不一样，官方文档也没有列死，需要核验**——**去你邮箱服务商自己的帮助页面上找“SMTP 设置”那一页，照它写的填。** 填完凭据页面上一般有一个测试按钮，**测通了再往下走。**

### 配节点

- **From Email** 填发信的那个邮箱，可以写成 `Mini PC 日报 <mini-pc@example.com>` 这种带名字的形式；
- **To Email** 填收信的那个，多个用逗号隔开，例如 `me@example.com`；
- **Subject** 切到表达式，填：

```text
每日摘要 {{ $json.日期 }}
```

- **Email Format** 选 **Text**；
- **正文**那一格切到表达式，填 `{{ $json.正文 }}`。

**上面那两个邮箱地址是编的，换成你自己的。**

**Email Format 选 Text 而不是 HTML**，理由是“拼日报”那个节点吐出来的正文是 Markdown 写的，**当纯文本发出去，在任何邮件客户端里都读得下去**；当 HTML 发的话，那些 `#` 和 `##` 会原样显示成井号。**想要排好版的邮件，得先把 Markdown 转成 HTML，多一个节点，本卷不做。**

执行一次，**去收件箱里看**。

**收不到先看三处**：节点有没有报红（报红就点开看错在哪儿）、垃圾邮件文件夹、发信那个邮箱的“已发送”。**三处都没有的话，多半是 SMTP 那几项没填对**，回凭据页面重测。

## 第三步：让它真的每天自己跑

**到这一步为止，全部是你点一下它跑一次。** 要它自己跑，还差一个动作。

**点右上角保存，然后把那条工作流发布出去**——那个开关或者按钮的措辞可能是发布（Publish），也可能是激活（Active），**位置在右上角，需要核验。**

**官方文档写得很明白：以 Schedule Trigger 为入口的工作流，要保存并发布之后才会按点执行。** 不做这一步，你明天早上什么也收不到，**而且不会有任何报错**——它就是没跑。

## 第四步：确认它明天真的会跑

**这一步不能省，理由和[第 2 卷第 8 章](../02-Ubuntu/08-定时任务.md)那一节一模一样——写完不等于跑得起来。**

### 最直接的办法：把时间挪到几分钟以后

**这一招[第 2 卷第 8 章](../02-Ubuntu/08-定时任务.md)用过，原样照搬。**

1. 看一眼现在几点几分；
2. 把 Schedule Trigger 里的小时和分钟改成两三分钟以后；
3. **保存，重新发布一次**（改了内容要重新存，发布状态别忘了确认还开着）；
4. 什么也不做，等着。

到点之后看两个地方：

**一看执行记录。** 左侧菜单进执行记录，**列表最上面应该多出一行**，时间就是刚才那个点，状态是成功。**点开它，从左往右每个节点都能看到当时的输入输出**——这一次跑的时候抓到了哪五篇、模型答了什么，全在里面。

**二看结果。** 存文件那条路，去 `ls ~/ai/data/daily/` 看有没有多一个文件；发邮件那条路，去收件箱看。

**两处都对上，这条流程就成了。** 把时间改回 7 点 0 分，保存，确认还是发布状态。

### 失败了会怎样

**执行记录里那一次会标成失败，而且能点开看断在哪个节点。** 这是本卷从[第 3 章](03-第一个工作流.md)起一直在用的那件事。

**但有一条现在就要知道：没有人会通知你。** 它安安静静地失败在那儿，**你只会在第二天早上发现今天没收到日报。**

**这件事第 11 章整章处理**——失败了自动再试一次、试几次还不行就发一条消息告诉你、执行记录留多久。**那一章是客户问“出错了怎么办”时你的答案**，也是这条流程从“我自己玩”变成“能交出去”的分界线。

**在做到第 11 章之前，这条流程的验收标准就一条**：每隔几天点开执行记录扫一眼，看有没有红的。

## 案例一完整回顾

**从零到收到第一份日报，全部步骤。** 换一台机器重做一遍，照这张单子走。

**准备（第 2 章）：**

1. `ss -tln | grep :5678` 确认端口空着；
2. `mkdir -p ~/ai/projects/n8n ~/ai/data/daily` 建两个目录；
3. 一条 `docker run` 起容器，**时区那两个变量、`--add-host` 那一行、两个 `-v` 都不能少**；
4. `docker ps` 和 `docker logs n8n` 确认它起来了；
5. 浏览器打开 `http://localhost:5678`，建账户；
6. `docker exec` 进容器，确认连得到 `http://host.docker.internal:11434`。

**基本功（第 3 章）：**

7. 搭一条三节点的流程，手动触发加 HTTP Request 加 Edit Fields，**确认能问通模型**。这一条严格说不属于案例一，**但它不通，下面每一步都白搭。**

**抓（第 4 章）：**

8. 找到目标站的 RSS 地址，**打开它的 `robots.txt` 看一眼**；
9. 新建工作流“日报-案例一”，加手动触发加 RSS Read；
10. 执行一次，**把输出面板上的字段名抄下来**。

**摘（第 5 章）：**

11. 加 Limit 节点，只留 5 条；
