# 02　环境准备

## 这一章的任务

把一个能读图的服务起起来，做成开机自己回来的常驻服务。

**这一章不下载任何模型。** [第 6 卷第 2 章](../06-本地模型/02-下载第一个模型.md)下的那两个文件就是这一卷要用的全部东西——一个 22 GB 的主模型，一个 0.9 GB 的 `mmproj-F16.gguf`。**你已经具备条件了，这一章只是把它们摆成一个服务。**

做完之后，这台机器上多一个端口 8090，发一张图给它，它告诉你图上写了什么。**第 4 章和第 5 章的脚本连的就是这个端口。**

## 开始前

- [第 5 卷第 17 章](../05-驱动与ROCm/17-llama.cpp-Vulkan.md)做完，`~/llama` 目录在，`./llama-cli --list-devices` 能看到 Vulkan 设备。**本章不重讲怎么装 llama.cpp**；
- [第 6 卷第 2 章](../06-本地模型/02-下载第一个模型.md)下的两个文件都在。**除了那个 22 GB 的权重，还要有那个 0.9 GB 的 `mmproj-F16.gguf`**；
- [第 6 卷第 11 章](../06-本地模型/11-视觉模型.md)做完，你知道 `mmproj` 是干什么的，也知道漏掉它的表现是什么；
- [第 6 卷第 13 章](../06-本地模型/13-llama.cpp直接用.md)做完，你起过一次 `llama-server`，知道 `-m`、`-c`、`-ngl`、`--host`、`--port` 分别是什么。**本章只讲多出来的那一项**；
- [第 2 卷第 6 章](../02-Ubuntu/06-进程与服务.md)会看服务状态、会用 `systemctl`。**本章不重讲怎么写单元文件**；
- 手上有一张单据的图片，PNG 或者 JPG 都行，内容你自己清楚的那种；
- 60 分钟，其中大半是等模型加载。

## 新词

**base64**：**把任意一个文件变成一串只有字母、数字和几个符号的文本。** 图片是二进制的，没法直接写进 JSON；先变成这么一串，就能当普通文字塞进去了。变完体积会涨大约三分之一，**所以一张图发出去比它本身大一点**。

**data URI**：一种把内容直接写在地址位置上的写法，形如 `data:image/png;base64,iVBORw0KGgo...`。**这一卷所有发图的动作用的都是它**——不是给一个文件路径让服务自己去读，是把整张图的内容一起发过去。

**图文一起发**：[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)里 `messages` 每一条的 `content` 是一段文字。**发图的时候 `content` 变成一个列表**，列表里既有图也有文字，模型同时读这两样。这是本卷所有请求的形状。

**`--mmproj`**：[第 6 卷第 11 章](../06-本地模型/11-视觉模型.md)讲过的那个参数，把视觉编码器接上去。**这一章的服务和第 6 卷第 13 章那个服务，命令上的差别主要就是它。**

## 手起一次

**先手敲一遍看它能不能跑，跑通了再做成服务。** 顺序反过来的话，出问题你分不清是命令写错了还是单元文件写错了。

```bash
cd ~/llama && ./llama-server \
  -m ~/ai/models/qwen3.6-35b-a3b/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf \
  --mmproj ~/ai/models/qwen3.6-35b-a3b/mmproj-F16.gguf \
  -c 16384 \
  -ngl 99 \
  --host 127.0.0.1 \
  --port 8090
```

整段复制粘贴，最后回车。**路径换成你自己那两个。**

和[第 6 卷第 13 章](../06-本地模型/13-llama.cpp直接用.md)那条比，改动只有四处：

- **`--mmproj`** —— **这一项是这一章的全部新东西**。少了它，下面发图那一步会失败，或者更糟——它不失败，它编；
- **`-c 16384`** —— 上下文给到 16384。**图占的 token 比文字多得多**（[第 6 卷第 11 章](../06-本地模型/11-视觉模型.md)那条“视觉 token”），一张 200 DPI 的发票就能吃掉几千个，第 4 章还会一次发两页。第 6 卷第 13 章那个 8192 在这里不够用；
- **`--host 127.0.0.1`** —— **只有这台机器上的程序连得到它**。第 4、5 章的脚本就跑在这台机器上，不需要开给局域网。这一条比第 6 卷第 13 章那个 `0.0.0.0` 紧，是有意的；
- **`--port 8090`** —— 上面挑的那个号。

**`-m` 和 `-ngl 99` 和第 6 卷第 13 章一样，不重讲。**

**正常输出**：几十行加载信息，中间能看到层放到了 GPU 上、KV cache 占了多少，**加载 `mmproj` 的时候会多出几行关于视觉编码器的信息**，最后停在一行监听提示：

```text
main: server is listening on http://127.0.0.1:8090 - starting the main loop
```

**看到这一行，终端就不动了，这是对的。** 别按 `Ctrl+C`，另开一个终端窗口做下面几节。

> **具体的行文和字段随 llama.cpp 版本变化，本项目未固定，需要核验。** 要确认的只有三件事：**层放到了 GPU 上、加载信息里出现了那个投影文件、最后停在监听那一行。**

## 验证二：用 curl 发一张图

**上一节证明模型看得见图，这一节证明程序也能把图送进去。** 第 4 章那个脚本干的就是这件事，只是用 Python 写。

### 先拿到模型名

```bash
curl -s http://127.0.0.1:8090/v1/models | python3 -m json.tool
```

**返回里 `"id"` 那个字段就是模型名**，照抄下来。[第 6 卷第 13 章](../06-本地模型/13-llama.cpp直接用.md)讲过这一步，**这个名字一般从文件名来，和 Ollama 里那个不一样**。

### 再把图发过去

三条命令，一条一条来。第一条把两个会变的东西记下来：

```bash
MODEL="上一步 id 那一栏照抄过来"
IMG=~/ai/data/invoices-2026-08/样票.png
```

作用：给模型名和图片路径各起一个短名字，下面两条命令直接用。**路径换成你自己那张图。**

第二条把请求拼好，写进一个临时文件：

```bash
printf '{"model":"%s","messages":[{"role":"user","content":[{"type":"image_url","image_url":{"url":"data:image/png;base64,%s"}},{"type":"text","text":"这张图里写了什么？一行一行念出来，不要解释。"}]}]}' "$MODEL" "$(base64 -w 0 "$IMG")" > /tmp/req.json
```

**为什么要写进文件，不像[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)那样直接写在 `-d` 后面**：一张图转成 base64 之后是很长的一串，直接写在命令行上容易被截断。逐段说：

- **`printf '...' A B`** —— 按前面那个模板拼字符串，两个 `%s` 依次换成后面那两样；
- **`base64 -w 0 "$IMG"`** —— 把图片转成上面新词里说的那一串。`-w 0` 是不换行，**不加它转出来的东西是分成一行行的，塞进 JSON 会坏**；
- **`"data:image/png;base64,"` 前缀** —— 就是新词里那个 data URI。**图是 JPG 的话，把这里的 `image/png` 改成 `image/jpeg`**；
- **`> /tmp/req.json`** —— 存成一个临时文件，用完不用管。

第三条发出去：

```bash
curl -s http://127.0.0.1:8090/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d @/tmp/req.json | python3 -m json.tool
```

**`-d @文件名`** 的意思是要发的内容在那个文件里。其余和[第 6 卷第 8 章](../06-本地模型/08-局域网API.md)那条一模一样。

**正常输出**是一段 JSON，`choices[0].message.content` 里是它念出来的票面文字，`usage` 里能看到这次吃了多少 token。**顺手看一眼 `prompt_tokens`**——那个数就是这张图在这个模型里占多大，第 13 章估速度要用到它。

**到这里，这条路就通了。** 第 4 章的脚本做的是同一件事，多的只是把 PDF 先转成图、以及给模型加一份 schema 约束。

## 做成开机自启的服务

上面那条命令关掉终端就没了。**做成 systemd 服务，让它跟 Ollama 一样常驻、开机自己回来。**

**写单元文件的机制、每个字段什么意思、`daemon-reload` 和 `enable` 分别干什么，[第 2 卷第 6 章](../02-Ubuntu/06-进程与服务.md)已经讲透，[第 6 卷第 13 章](../06-本地模型/13-llama.cpp直接用.md)照着写过一份，这里不重讲。** 只给这个服务该写成什么样。

```bash
sudo nano /etc/systemd/system/ocr-vlm.service
```

内容（**路径和账户名换成你自己的**，不确定跑一句 `whoami`）：

```ini
[Unit]
Description=llama.cpp OCR server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=你的账户名
WorkingDirectory=/home/你的账户名/llama
ExecStart=/home/你的账户名/llama/llama-server \
  -m /home/你的账户名/ai/models/qwen3.6-35b-a3b/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf \
  --mmproj /home/你的账户名/ai/models/qwen3.6-35b-a3b/mmproj-F16.gguf \
  -c 16384 \
  -ngl 99 \
  --host 127.0.0.1 \
  --port 8090
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

和[第 6 卷第 13 章](../06-本地模型/13-llama.cpp直接用.md)那一份比，**只有 `Description`、多出来的 `--mmproj` 那一行、`-c` 的数和端口号不同**。那一章说过的三条在这里照样成立：

- **`WorkingDirectory` 必须是 `~/llama` 那个目录**，库文件在旁边；
- **`ExecStart` 里的路径必须写完整**，`~` 在这里不认；
- **`User` 那个账户要在 `render` 和 `video` 组里**才用得了 GPU，跑一句 `groups` 看一眼。

保存退出（`Ctrl+O` 回车，`Ctrl+X`），然后：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ocr-vlm
systemctl status ocr-vlm --no-pager
```

**`Active` 那行是绿色的 `active (running)`、`Loaded` 那行末尾是 `enabled`，就对了。**

模型加载要花几十秒到几分钟，**这期间服务显示在跑但接口还没通是正常的**。看它加载到哪儿了：

```bash
journalctl -u ocr-vlm -f
```

**加载信息会一行行出来，最后停在监听那一行。** 按 `Ctrl+C` 退出查看，**这只是停止看日志，不会停掉服务**。

服务起来之后，把上一节那两条 curl 再跑一次，确认接口通了。**从这一步起，第 4、5 章的脚本随时能连上它。**
