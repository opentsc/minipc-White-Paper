# 13　llama.cpp 直接用

## 这一章的任务

不经过 Ollama，直接用 llama.cpp 起一个常驻的模型服务，参数由你自己定。

**这一章不装东西。** [第 5 卷第 17 章](../05-驱动与ROCm/17-llama.cpp-Vulkan.md)已经把 llama.cpp 下好解压好、跑通过一个模型了，`~/llama` 那个目录还在。**那一章讲的是怎么装、怎么跑一次就退出；这一章讲的是怎么让它一直跑着，并且开一个接口出来。**

## 什么时候才需要绕开 Ollama

**日常不需要。** 前面十二章一路用 Ollama，够用，而且省事。

**下面三种情况绕不开：**

**一、要精细控制上下文长度。** Ollama 把上下文这类参数包在自己那一层里，改起来要写 Modelfile 或者传参数，改完还不容易确认到底生效没有。**llama.cpp 是命令行上写一个 `-c` 就完了**，而且启动日志会直接把 KV cache 占了多少打出来。这一章后半段专门讲这件事。

**二、要用 Ollama 库里没有的 GGUF。** 第 3 章那张两条路的对照表里已经写过：库里没有的模型、想挑特定量化档的，得自己下 `.gguf` 再导入。**导入这一步本身也可以省掉**——llama.cpp 直接读那个文件。第 3 章末尾那句“原文件先别删”，为的就是这一章。

**三、要一个只对外提供接口、不带别的东西的常驻服务。** Ollama 是一整套（模型库、自动加载卸载、多模型管理），这些在多数场合是优点。**但要把一个固定模型、固定参数的服务交付出去**，越少的活动部件越好——llama.cpp 起一个进程，参数全写在一行里，交付文档抄那一行就行。

**两条路可以并存。** 第 3 章说过一次，这里再说一遍：Ollama 在 11434 上跑着，llama.cpp 在另一个端口上跑着，互不干扰。**它们底下是同一个引擎，读的是同一种文件。**

## 开始前

- [第 5 卷第 17 章](../05-驱动与ROCm/17-llama.cpp-Vulkan.md)做完，`~/llama` 里有解压好的 llama.cpp，`./llama-cli --list-devices` 能看到 Vulkan 设备。**没做完的先回去做，本章跑不通**；
- 第 2 章下的那个 `.gguf` 文件还在 `~/ai/models` 里（第 3 章说过别删）；
- 第 1 章那两条估内存的公式看过，**这一章要拿它算上下文**；
- 第 8 章做完，你知道 OpenAI 兼容接口是怎么回事。**这一章开的是同一套接口**；
- [第 2 卷第 6 章](../02-Ubuntu/06-进程与服务.md)会看服务状态、会用 `systemctl`；
- [第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)那张 ufw 规则表你会看；
- 60 分钟。

## 新词

**`llama-server`**：llama.cpp 那一堆可执行文件里的一个。**它启动之后不退出，一直守在一个端口上等请求。** 第 5 卷用的是 `llama-cli`，问一句答一句然后退出；这一章用的是它。

**常驻**（daemon）：程序起来之后一直在后台跑着，你退出终端它也不停。**第 3 章那个 Ollama 服务就是常驻的**，这一章要把 llama.cpp 也做成这样。

**单元文件**（unit file）：systemd 用来描述一个服务的那个文本文件。**里面写清用哪个账户、执行哪条命令、挂了要不要自己重启。** 写法在[第 2 卷第 6 章](../02-Ubuntu/06-进程与服务.md)。

**KV cache 精度**：第 1 章讲过 KV cache 是模型把读进去的内容算成的中间状态，按 F16 精度存。**这一章有一个参数能把它改成 8 位存**，占用直接减半。

## 起一个 llama-server

先看一眼端口有没有被占：

```bash
ss -tln | grep :8080
```

作用：看 8080 这个口现在有没有人在用。**没有任何输出就是空着的**，可以用。

> **`8080` 这个端口号是本教材挑的，不是必须的。** 第 4 章那个 Open WebUI 容器在宿主机上用的是 3080，Ollama 用 11434，**三个不能撞**。被占了就换一个，下面所有命令里的端口号跟着改。

起服务：

```bash
cd ~/llama && ./llama-server \
  -m ~/ai/models/qwen3.6-35b-a3b/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf \
  -c 8192 \
  -ngl 99 \
  --host 0.0.0.0 \
  --port 8080
```

整段复制粘贴，最后回车。**模型路径换成你自己那个**，不确定的话先 `ls ~/ai/models/` 看一眼。

逐项说清楚：

- **`-m`** —— 模型文件的完整路径。**这里指的就是第 2 章下的那个原文件**，不是 Ollama 目录里那一份；
- **`-c 8192`** —— 上下文长度，8192 个 token。**这一项是这一章的重点**，下面单独一节讲怎么定；
- **`-ngl 99`** —— 把模型的层尽量放到 GPU 上算。**这一项不能省**，第 5 卷第 17 章讲过，不加的话多数版本默认在 CPU 上跑；
- **`--host 0.0.0.0`** —— 在这台机器的全部地址上监听，包括局域网那个。**含义和第 8 章 `OLLAMA_HOST` 那一行完全一样**。只想给本机用就写 `127.0.0.1`；
- **`--port 8080`** —— 开在哪个端口上。

**正常输出**：先是几十行加载信息（模型元数据、层数、量化档、Vulkan 设备），中间有一行写着把多少层放到了 GPU 上，**再往下有一行写着 KV cache 占了多少**，最后停在一行提示服务已经在监听，形如：

```text
main: server is listening on http://0.0.0.0:8080 - starting the main loop
```

**看到这一行，终端就不动了。** 这是对的——它在等请求。**别按 `Ctrl+C`**，另开一个终端窗口做下面几节。

> **具体的行文、字段和顺序随 llama.cpp 版本变化，本项目未固定，需要核验。** 要确认的只有三件事：**层放到了 GPU 上、KV cache 那一行出现了、最后停在监听那一行。**

**这个窗口关掉服务就停了。** 想让它一直跑，往下看最后那一节做成 systemd 服务。

## 它自带一个网页界面

浏览器打开：

```text
http://192.168.1.50:8080
```

**地址换成你这台机器的固定地址**（[第 3 卷第 3 章](../03-服务器基础/03-固定IP.md)），本机上用 `http://localhost:8080`。

打开是一个很简单的对话页，能打字、能看它一个字一个字往外吐。**够用，但也就是够用**——它没有账号、没有对话历史管理、不能上传文件、不能多人分开用。第 4 章那个 Open WebUI 干的那些事它都不干。

**它的用处是验证，不是日常。** 起完服务打开看一眼能不能说话，确认这条路通了，就可以关掉网页去写程序了。**给家里人用的入口仍然是 Open WebUI。**

> **这个页面和 Ollama 那个接口一样，没有认证。** 第 8 章那一节的三条在这里全部成立：只在局域网里开，不要做端口转发，出门走 [Tailscale](../03-服务器基础/06-Tailscale.md)。

## 防火墙放行

和第 8 章放行 11434 是同一个动作，只换端口号：

```bash
sudo ufw allow from 192.168.1.0/24 to any port 8080 proto tcp
```

作用：允许从你家这个网段来的连接访问 8080。**地址段换成你自己的**（[第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)拆过这四段的含义）。

```bash
sudo ufw status verbose
```

**规则表上现在多了 8080 那一行。** [第 3 卷第 9 章](../03-服务器基础/09-防火墙与密钥.md)那句规矩继续生效：每一行你都该说得出这个口是给谁开的。**8080 这一行是给直连 llama.cpp 的程序开的。**

## 它开的是同一套接口

**这一节是这一章最省事的地方：你不用学新东西。**

`llama-server` 也提供 OpenAI 兼容接口，端点和第 8 章那些同名。**第 8 章写的那些代码，改一行地址就跑在这上面。**

先问它有什么模型：

```bash
curl -s http://localhost:8080/v1/models | python3 -m json.tool
```

**返回里 `"id"` 那个字段就是模型名。** llama-server 一次只加载一个模型，所以列表里通常只有一条。**这个名字要照抄到下一步**，它一般是从文件名来的，和 Ollama 里那个名字不一样。

再发一句话：

```bash
curl -s http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "你上一步看到的那个名字",
    "messages": [
      {"role": "user", "content": "用一句话介绍你自己"}
    ]
  }' | python3 -m json.tool
```

**返回的形状和第 8 章那一段一模一样**——`choices[0].message.content` 是它说的话，`usage` 是 token 统计，`finish_reason` 是它为什么停。**第 8 章“看懂返回”那一节在这里原样成立，不重讲。**

Python 那边同样只改两处。把第 8 章那个 `ask_openai.py` 拿过来：

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://192.168.1.50:8080/v1",
    api_key="llamacpp",
)

completion = client.chat.completions.create(
    model="你上一步看到的那个名字",
    messages=[
        {"role": "user", "content": "用一句话介绍你自己"}
    ],
)

print(completion.choices[0].message.content)
```

**和第 8 章那一份比，只有 `base_url` 的端口和 `model` 的名字不一样。** `api_key` 照样是填什么都行。

**这就是第 8 章说“这两行最值钱”的意思在这一章的延续**：换掉底下跑的是什么，上面的程序一个字不用改。**以后从 Ollama 换成 llama.cpp、或者反过来，第 7 卷到第 9 卷那些应用都不用动。**

> **llama-server 具体开了哪些端点、各自支持哪些参数，随版本变化，本项目未逐个核实，需要核验**，以 llama.cpp 官方文档和 `./llama-server --help` 的输出为准。**能确定的是 `/v1/chat/completions` 这一个**，本章只用它。

## 上下文长度怎么定

**这一节是绕开 Ollama 最主要的理由。**

`-c` 这个参数写多少，直接决定两件事：**一次对话能塞进去多少内容，以及要多吃多少内存。**

### 先回第 1 章算一遍

第 1 章那条公式：

```text
每 token 字节数 = 2 × 层数 × KV 头数 × 每头维度 × 2
KV cache 总量 = 每 token 字节数 × 上下文长度
```

层数、KV 头数、每头维度在模型仓库页面的 `config.json` 里查得到。第 1 章拿 `Qwen3.6-35B-A3B` 算过一遍（40 层、2 个 KV 头、每头 256 维），结论是每 token 80 KiB：

```text
  8K 上下文 →  0.7 GB
 32K 上下文 →  2.7 GB
128K 上下文 → 10.7 GB
256K 上下文 → 21.5 GB
```

**同一张表在 `Llama-3.3-70B` 上完全不是这个量级**——第 1 章算出来它每 token 320 KiB，是前者的 4 倍。**所以“开多长的上下文”这个问题，换个模型就要重算。**

### 再看启动日志里的实测

**估算是估算，启动日志里那一行是实测。**

llama.cpp 加载的时候会打印一行 KV cache 的实际大小，第 1 章说过：**估算和实测对不上，以那一行为准。**

**做法是把 `-c` 从小往大调，每调一次看一眼那一行。** 比如先 `-c 8192` 起一次，记下那个数；再 `-c 32768` 起一次，看它涨了多少。**涨的倍数应该和上下文的倍数对得上。**

### 预算从哪来

第 1 章那条规则在这里落地：

```text
权重 + KV cache + 1 到 3 GB 计算缓冲 ≤ 120 GiB
权重本身控制在 90 GB 以内
```

主线那个模型走 UD-Q4_K_M 是 22.1 GB。**剩下将近 100 GB 都能给 KV cache 和缓冲**，所以这台机器上把上下文开到 128K 都不紧张。

**换成 GLM-4.5-Air 那种 67.7 GB 的权重，情况就完全不同**——剩下五十几 GB，还要扣掉缓冲，能开多长得算过才知道。

> **第 1 章那句话在这里重复一次：顶着上限装模型，表现不是报错退出，而是上下文开不大。** 权重塞进去了，KV cache 没地方放，对话稍微长一点就崩。**先算再开，别一上来把 `-c` 拉满。**

### 把 KV cache 压掉一半

第 1 章提过一句、说“第 13 章展开”的就是这两个参数：

```bash
cd ~/llama && ./llama-server \
  -m ~/ai/models/qwen3.6-35b-a3b/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf \
  -c 32768 \
  --cache-type-k q8_0 \
  --cache-type-v q8_0 \
  -ngl 99 \
  --host 0.0.0.0 \
  --port 8080
```

- **`--cache-type-k q8_0`** —— 把 KV cache 里的 K 那一半按 8 位存，不用默认的 16 位；
- **`--cache-type-v q8_0`** —— V 那一半同理。

**两个一起加，KV cache 的占用大约减半。** 加载信息里那一行会直接反映出来——同样的 `-c`，那个数比不加时小一半左右。

**代价是有一点质量损失，通常很小。** 什么时候值得加：**想开更长的上下文，但内存不够**的时候。内存富余就别加，没必要。

> **这两个参数的效果和质量影响是素材记录，本项目未在这台设备上复现，需要核验。** 加不加的判据是你自己那台机器上的实际内存占用和实际输出质量，不是这一段文字。

### 长上下文出问题的时候

[第 5 卷第 17 章](../05-驱动与ROCm/17-llama.cpp-Vulkan.md)有一节讲这件事，本章不重抄：**上下文开大之后报内存不足、或者跑到一半设备丢失**，那一章的处理办法是加 `-ub 512` 把微批压小。同一个参数在 `llama-server` 上一样能用。

**大模型加载卡死用 `--no-mmap`**，也在那一章，同样原样适用。

**这两条都是素材记录，本项目未复现过，那一章已经标注清楚。**

## 做成开机自启的服务

上面那条命令关掉终端就没了。**要让它跟 Ollama 一样常驻、开机自己回来，写一个 systemd 单元文件。**

**写单元文件的机制、每个字段什么意思、`daemon-reload` 和 `enable` 分别干什么，[第 2 卷第 6 章](../02-Ubuntu/06-进程与服务.md)已经讲透了，这一章不重讲。** 这里只给这个服务该写成什么样。

新建文件：

```bash
sudo nano /etc/systemd/system/llama-server.service
```

内容（**路径和账户名换成你自己的**，不确定跑一句 `whoami`）：

```ini
[Unit]
Description=llama.cpp server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=你的账户名
WorkingDirectory=/home/你的账户名/llama
ExecStart=/home/你的账户名/llama/llama-server \
  -m /home/你的账户名/ai/models/qwen3.6-35b-a3b/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf \
  -c 32768 \
  -ngl 99 \
  --host 0.0.0.0 \
  --port 8080
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

这一份里跟本章有关的几行：

- **`WorkingDirectory`** —— 必须是 `~/llama` 那个目录。**第 5 卷第 17 章说过，那些 `.so` 库文件就在旁边，不在这个目录里跑会报找不到库**；
- **`ExecStart`** —— 就是上面手敲的那条命令，**路径必须写完整，`~` 在这里不认**；
- **`User`** —— 用你自己的账户跑。**这个账户要在 `render` 和 `video` 组里才用得了 GPU**（[第 5 卷第 12 章](../05-驱动与ROCm/12-GPU识别.md)讲过，跑 `groups` 看一眼）；
- **`Restart=on-failure`** —— 挂了自己重启。

保存退出（`Ctrl+O` 回车，`Ctrl+X`），然后按[第 2 卷第 6 章](../02-Ubuntu/06-进程与服务.md)那套动作让它生效：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now llama-server
systemctl status llama-server --no-pager
```

**`Active` 那行是绿色的 `active (running)`、`Loaded` 那行末尾是 `enabled`，就对了。** 读法和第 3 章看 Ollama 服务那次一样。

加载要花几十秒到几分钟（模型大就久），**这期间 `status` 显示在跑但接口还没通是正常的**。看它加载到哪儿了：

```bash
journalctl -u llama-server -f
```

`-f` 是跟着往下滚，**加载信息会一行行出来，最后停在监听那一行**。按 `Ctrl+C` 退出查看（**这只是停止看日志，不会停掉服务**）。

要停掉或者不让它开机自启：

```bash
sudo systemctl stop llama-server
sudo systemctl disable llama-server
```

## 和 Ollama 的分工

两条路都在跑着的时候，谁干什么：

| | Ollama（11434） | llama-server（8080） |
| --- | --- | --- |
| 换模型 | `ollama run 另一个名字`，它自己加载卸载 | **换不了**，要改参数重启服务 |
| 同时放几个模型 | 可以，第 7 章那个上限 | **一个进程一个模型** |
| 上下文长度 | 包在里面，改起来绕 | **命令行上一个 `-c`** |
| 模型从哪来 | 官方模型库，或者导入 | **任何 `.gguf` 文件，直接指路径** |
| KV cache 精度 | 不方便调 | `--cache-type-k` / `--cache-type-v` |
| 网页界面 | 接 Open WebUI（第 4 章） | 自带一个很简单的 |
| 接口 | OpenAI 兼容（第 8 章） | **OpenAI 兼容，同一套** |
| 适合什么 | 日常、家里人用、要换着模型试 | **参数定死的常驻服务、要交付的那一台** |

**日常仍然走 Ollama。** 这一章这条路留给两种场合：**要精确控制参数的时候，和要把一台机器交付出去的时候。**

> **交付给客户的那一台，这条路有一个明确的好处**：完整的启动命令就是一行字，写进交付文档，客户或者接手的人照着看就知道跑的是什么模型、多长的上下文、放了多少层到 GPU 上。**Ollama 那边这些信息散在几个地方。** [第 5 卷第 17 章](../05-驱动与ROCm/17-llama.cpp-Vulkan.md)末尾说过同一件事：只写“用 llama.cpp 跑”不算交付。
