# 07　共享文件夹

## 这一章的任务

在这台机器上开一个文件夹，家里人或者组里几个人，在各自的 Windows、macOS、手机上都能打开它，往里放文件、从里面取文件，像用本地目录一样。

**先和第 2 卷[第 12 章](../02-Ubuntu/12-日常备份.md)分清楚。** 那一章做的是备份：机器自己定时把资料复制一份出去，人不参与，备份目录是给机器写的，谁都不该去动它。这一章做的是共用：一个几个人天天往里放东西、改东西、取东西的活动目录。

两件事不冲突，而且**共享文件夹里的东西照样要备份**——它是几个人天天在改的目录，误删的概率比别的地方都高。本章最后一节会把它加进第 12 章那个备份脚本。

## 开始前

- 第 3 章做完，这台机器的地址已经固定；
- 第 4 章做完，能远程登录，本章的命令都在远程终端里做；
- 有 `sudo` 权限；
- 家里或者组里另一台电脑，Windows 或者 macOS，用来验证；
- 40 分钟。

## 新词

**共享协议**：两台电脑之间约定好的一套“怎么把文件夹给对方看”的规则。不同系统之间能互相打开文件夹，靠的是双方说同一种协议。

**SMB**：Windows 用了几十年的那种共享协议，现在 macOS、Android、iOS 也都认它。局域网里做文件共享，选它兼容性最好。

**Samba**：在 Linux 上实现 SMB 的软件。装上它，这台 Ubuntu 机器就能被 Windows 的“网上邻居”和 macOS 的访达认出来。

**共享名**（Share Name）：一个共享文件夹对外的名字。别人连过来看到的是这个名字，不是它在硬盘上的真实路径。一台机器可以同时开好几个共享，各有各的名字和权限。

**Samba 账户**：Samba 自己的一套账户密码，和系统登录密码是两回事。**同一个用户名可以有两个不同的密码**，一个用来登录系统，一个用来连共享。

**只读和读写**：一个共享可以设成别人只能看、只能复制走，改不了也删不掉（只读）；也可以设成别人能往里写、能删（读写）。同一个目录可以同时开两个共享名，一个只读一个读写，给不同的人用。

**用户组**：一组账户的集合。给目录设权限时，按组设比按人设省事——以后加人只要把人加进组，目录本身不用动。第 2 卷[第 4 章](../02-Ubuntu/04-账户与权限.md)讲过。

## 为什么另开一个目录，不直接共享 `~/ai`

有四条理由，任何一条单独拿出来都足够。

**第一，家目录里有不能给别人看的东西。** `~/.ssh` 里是第 4 章那把私钥，`~/.env` 这类文件里可能有 API 密钥（[第 0 卷第 8 章](../00-使用说明/08-文件保护.md)）。共享一个目录，别人能看到的不只是你想给的那部分，权限一放松，边界就说不清了。

**第二，`~/ai/projects` 是机器干活用的。** 里面是第 2 卷第 9 章那些容器的数据目录、配置文件。别人手一滑删掉一个 `compose.yaml`，服务当场起不来。

**第三，`~/ai/models` 动辄几十 GB。** 共享出去之后，别人在文件管理器里点一下就可能整个目录拷贝走，把网络和硬盘一起占满。

**第四，`~/ai/data` 是备份脚本的源。** 几个人往里放临时文件，每周的备份跟着一起膨胀，很快就装不下了。

所以另开一个 `/srv/share`。`/srv` 是 Linux 约定用来放“对外提供服务的数据”的地方，正好是这件事。它和你的家目录完全分开，权限单独设，出问题也波及不到别的。

## 一、装 Samba

```bash
sudo apt install samba
```

装完它自己会起来。确认一下：

```bash
systemctl status smbd
```

第 2 卷[第 6 章](../02-Ubuntu/06-进程与服务.md)的读法：`Active` 那行是 `active (running)`，`Loaded` 那行末尾是 `enabled`，就对了。

它用的端口是 `445`。看一眼：

```bash
ss -tln | grep :445
```

有输出就是在等连接了。**这个端口现在对局域网开着**，第 9 章会用防火墙把它限制成只对局域网开、不对别的地方开。

## 二、建目录，设好组和权限

先建一个用户组，以后所有能用这个共享的人都进这个组：

```bash
sudo groupadd sharegroup
```

把你自己加进去：

```bash
sudo usermod -aG sharegroup $USER
```

`-aG` 里的 `a` 不能漏，漏了会把你原来所在的组全部顶掉，第 2 卷第 4 章说过。

建目录：

```bash
sudo mkdir -p /srv/share
sudo chgrp sharegroup /srv/share
sudo chmod 2775 /srv/share
```

三条依次是：建目录、把目录的属组改成 `sharegroup`、设权限。

`2775` 这四位数字，后面三位 `775` 是第 2 卷第 4 章讲的读写执行权限，意思是属主能读写、组内成员能读写、其他人只能读和进入。**前面那个 `2` 是这一章的关键**：它让这个目录里新建出来的文件和子目录，自动继承 `sharegroup` 这个组。没有它的话，A 建的文件属组是 A 自己的组，B 就改不了，几天之后目录里的权限会乱成一团。

确认一下：

```bash
ls -ld /srv/share
```

正常输出：

```
drwxrwsr-x 2 root sharegroup 4096 Aug 14 15:02 /srv/share
```

要看两处：属组那一列是 `sharegroup`，权限那一串里有一个 **`s`**（在组权限的位置上），那就是 `2` 起的作用。

## 三、写共享配置

Samba 的配置文件是 `/etc/samba/smb.conf`。**先备份一份**：

```bash
sudo cp /etc/samba/smb.conf /etc/samba/smb.conf.bak
```

打开它：

```bash
sudo nano /etc/samba/smb.conf
```

文件很长，前面是全局设置，不用管。**按 `Ctrl+End` 跳到最末尾**，在最后加上这一段：

```ini
[share]
   comment = 共用文件夹
   path = /srv/share
   browseable = yes
   read only = no
   guest ok = no
   valid users = @sharegroup
   create mask = 0664
   directory mask = 2775
   force group = sharegroup
```

一行一行说：

- **`[share]`** 是共享名，别人连过来输的就是它。想叫别的就改这里，中文名也能用，但英文名少很多麻烦；
- **`path`** 是它在硬盘上的真实位置；
- **`browseable = yes`** 表示这个共享会出现在别人的网络浏览列表里。设成 `no` 的话它还在，只是要手动输名字才能连到，算是一层很薄的遮挡；
- **`read only = no`** 表示可读可写。这是本章要的；
- **`guest ok = no`** 表示不允许匿名访问，**必须填这个**。设成 `yes` 的话，同一个网络里的任何人不用密码就能进来；
- **`valid users = @sharegroup`** 表示只有这个组里的人能连。`@` 开头表示后面是组名，不是用户名；
- **`create mask` 和 `directory mask`** 决定别人新建的文件和目录是什么权限。`0664` 是文件“组内可写”，`2775` 是目录“组内可写并继承属组”，和上一节 `chmod` 设的是同一个意思；
- **`force group = sharegroup`** 兜底：不管是谁写进来的文件，属组一律记成 `sharegroup`。

按 `Ctrl+O` 回车保存，`Ctrl+X` 退出。

检查语法：

```bash
testparm
```

作用：把配置文件读一遍，有错就指出来。**正常输出里有一行 `Loaded services file OK.`**，然后停下来等你按回车，回车之后它会把完整配置打印一遍，看不看都行。

让配置生效：

```bash
sudo systemctl restart smbd
```

## 四、设一个 Samba 密码

Samba 认的账户必须先是系统上已有的账户，但密码是另一套。给你自己设一个：

```bash
sudo smbpasswd -a 你的账户名
```

`-a` 是添加。它会让你输两遍新密码，屏幕上不显示，和第 4 章输密码时一样。

**这个密码可以和系统登录密码不一样，建议就设成不一样的。** 共享密码要告诉家里人或者同事，系统密码不该给任何人。

设完之后确认这个账户是启用的：

```bash
sudo smbpasswd -e 你的账户名
```

输出 `Enabled user 你的账户名.`。

看看现在有哪些 Samba 账户：

```bash
sudo pdbedit -L
```

一行一个。

## 五、从 Windows 连

在同一个局域网的 Windows 电脑上：

1. 打开“文件资源管理器”；
2. 在最上面的地址栏里输入下面这个，地址换成你的机器：

```
\\192.168.1.50\share
```

**是两个反斜杠开头**，Windows 用反斜杠，和 Linux 的正斜杠方向相反。

3. 回车。弹出一个登录框，用户名填 Mini PC 上的账户名，密码填**刚才用 `smbpasswd` 设的那个**，不是系统密码；
4. 勾上“记住我的凭据”，以后就不用再输；
5. 窗口里出现共享目录的内容。往里拖一个文件试试。

**想让它一直挂在“此电脑”下面**，在这个窗口里右键空白处选“映射网络驱动器”，或者在“此电脑”里点上方的“映射网络驱动器”：

- 驱动器盘符随便挑一个没用的，比如 `Z:`；
- 文件夹填 `\\192.168.1.50\share`；
- 勾上“登录时重新连接”。

确定之后，`Z:` 盘就一直在了，和插了一块硬盘差不多。

## 六、从 macOS 连

1. 在访达里按 `Command + K`，或者菜单栏选“前往 → 连接服务器”；
2. 输入：

```
smb://192.168.1.50/share
```

**macOS 这里用正斜杠**，和 Windows 的写法不同。

3. 点“连接”。弹出登录框，选“注册用户”，用户名填 Mini PC 上的账户名，密码填 Samba 密码；
4. 勾上“在我的钥匙串中记住此密码”；
5. 共享目录挂载出来，出现在访达侧栏和桌面上。

**想让它开机自动连上**：打开“系统设置 → 通用 → 登录项”，点加号，选中挂载出来的那个共享，加进去。以后开机它自己就挂上了。

用完要断开的话，点侧栏里它旁边的弹出图标。

## 七、从手机连

**iPhone**：打开自带的“文件”应用，点右上角的三个点，选“连接服务器”，输入 `smb://192.168.1.50`，选“注册用户”，填账户名和 Samba 密码。共享出现在“文件”的侧栏里，能直接看照片、存文件。

**Android**：系统自带的文件管理器不一定支持 SMB，装一个支持 SMB 的文件管理应用，在里面添加一个 SMB 连接，地址填 `192.168.1.50`，共享名填 `share`，账户和密码同上。

手机上连的时候，**手机要和这台机器在同一个 Wi-Fi 下**。在外面想连，先按第 6 章打开 Tailscale，然后把地址换成那个 `100.` 开头的。

## 八、再开一个只读的共享

有些资料是要给人看、但不许改的——公司的模板、共用的资料库、做完的成品。给它单独开一个只读共享。

先建目录：

```bash
sudo mkdir -p /srv/readonly
sudo chgrp sharegroup /srv/readonly
sudo chmod 2755 /srv/readonly
```

和上面差一个数字：`2755` 里组的权限是 `5`，只能读和进入，不能写。

再在 `/etc/samba/smb.conf` 末尾加一段：

```ini
[readonly]
   comment = 只读资料
   path = /srv/readonly
   browseable = yes
   read only = yes
   guest ok = no
   valid users = @sharegroup
```

**和上面那段只差一行**：`read only = yes`。

```bash
testparm
sudo systemctl restart smbd
```

现在别人连过来能看到两个共享，`share` 能改，`readonly` 只能看。往只读那个里拖文件，对方的系统会提示没有权限，这是对的。

**往只读共享里放东西，是你在 Mini PC 上用命令行放**，比如从 `/srv/share` 里挑一份定稿移过去：

```bash
sudo mv /srv/share/定稿.pdf /srv/readonly/
```

### 同一个目录，有人能改有人只能看

不想开两个目录，想让同一个共享对不同的人权限不同，在那一段里加一行：

```ini
   read list = 某个账户名, 另一个账户名
```

写进 `read list` 的人只能读，别人照 `read only = no` 的规则可读可写。

**加人的做法**：先在 Mini PC 上给对方建一个系统账户（第 2 卷第 4 章），再 `sudo smbpasswd -a 对方账户名` 设 Samba 密码，最后 `sudo usermod -aG sharegroup 对方账户名` 把人加进组。三步都做完，对方才连得上。

## 九、把它加进备份

共享文件夹是几个人天天在改的目录，误删的概率比别的地方都高。第 2 卷第 12 章那个备份脚本，把它加进去。

打开脚本：

```bash
nano ~/ai/scripts/backup.sh
```

找到 `SOURCES=` 那一行，在末尾加上 `/srv/share`：

```bash
SOURCES=("$HOME/ai/data" "$HOME/ai/projects" "$HOME/ai/scripts" "/srv/share")
```

保存退出，手动跑一次看看：

```bash
~/ai/scripts/backup.sh
```

日志里应该多一行 `已同步 /srv/share`。跑完确认备份目录里多了一项：

```bash
ls ~/ai/backup/latest/
```

里面应该有 `share` 这个目录了。

**只读那个目录 `/srv/readonly` 里如果放的是定稿，一样加进去。** 判断标准还是第 12 章那一条：这个文件丢了，能不能不花钱不求人地弄回来。

顺带说一句权限：备份脚本是用你自己的账户跑的，`/srv/share` 里别人写进去的文件，属组是 `sharegroup`，你在组里，读得到，所以备份不会报权限不足。这就是前面 `force group` 那一行的用处。

## 连不上的两种常见情况

**Windows 上提示“找不到网络路径”**：先在 Windows 的命令行里 `ping 192.168.1.50` 一次。ping 不通是网络的问题，回第 2 章；ping 得通但连不上，回 Mini PC 上执行 `ss -tln | grep :445` 看服务在不在。

**提示用户名或密码错误**：多半是把系统密码当成 Samba 密码输了。重设一次 `sudo smbpasswd -a 你的账户名`，然后在 Windows 上打开“凭据管理器”把旧的那条删掉再连，macOS 上在“钥匙串访问”里删掉对应的那条。

有哪一步做不出来，到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。

## 事实来源和版本日期

- Samba 服务在 Ubuntu 上的单元名是 `smbd`，早期版本里另有一个 `nmbd` 负责局域网名称广播。以 `systemctl status smbd` 在你机器上的实际输出为准；
- Windows 的“映射网络驱动器”、macOS 的“登录项”、iPhone“文件”应用的“连接服务器”这几处菜单位置随系统版本变化，以你机器上实际看到的为准；
- SMB 使用 445 端口，早期版本另用 139 端口；
- 本章核验日期：2026-08-14。
