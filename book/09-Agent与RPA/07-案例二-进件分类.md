# 07　案例二：进件分类

## 这一章的任务

**案例二从这一章开始。**

做出来的东西是这样的——**有人往一个文件夹里丢文件，机器隔几分钟去看一眼，把新来的读一遍，判断这是合同、发票、简历还是报告，改个名字归到对应的目录里。**

丢文件的人只做一个动作，把文件拷进那个文件夹。别的什么也不用管，也不用叫你。

**这一章还要立一条本卷所有案例共用的规矩**：**判断不确定的，不要硬分，宁可让它进「待定」等人看。** 这条规矩下面有一整节。

案例二一共两章。这一章把分类和归档做通，[第 8 章](08-案例二-结果台账.md)给它加一张台账，案例二就完整了。

## 开始前

- [第 6 章](06-案例一-每日推送.md)做完，案例一那条流程每天自己在跑。**这一章要复用它的每一个动作，一个新界面操作都没有**；
- [第 3 章](03-第一个工作流.md)那三件事你在用——改一处执行一次、只跑一个节点、把节点改个名字。**这一章的流程有十个节点，不改名字你会分不清**；
- [第 5 章](05-案例一-模型摘要.md)那段提示词的六条规矩读过，`JSON.stringify(...)` 那个坑撞过一次。**这一章的请求体和那一章几乎一样，不重讲**；
- **[第 8 卷第 6 章](../08-OCR/06-文件夹监测.md)读过**。那一章已经论过一次轮询和实时监听的取舍，还给过一套目录流转。**这一章原样沿用那两条结论，不重新论证**；
- [第 2 卷第 10 章](../02-Ubuntu/10-Docker-Compose.md)那条规矩——**改了容器参数不是 `restart`，是删了重建**。这一章第一件事就要用它；
- 手边有几份用来试的文件。**纯文本（`.txt`、`.md`）和 PDF 各准备两三份**，内容分别像合同、像发票、像简历；
- 90 分钟。

## 新词

**收件箱**：**一个约定好的目录，交件的人往里丢，你的程序从里面取。** [第 8 卷第 6 章](../08-OCR/06-文件夹监测.md)的新词，这一章原样借用。

**待定**：**模型拿不准的时候，这份文件的去处。** 它不是一个失败状态，它是一个正常出口。这一章有一整节讲它。

**白名单**：**事先列好的、允许出现的值的清单。** 这一章的白名单是四个类别名。**模型答出清单以外的东西，一律不认。**

**二进制字段**（binary）：n8n 里流转的数据分两块，一块是 [第 3 章](03-第一个工作流.md)见过的 `$json`，另一块专门装文件本身，叫二进制那一块。**读进来一个 PDF，PDF 的内容就在这一块里**，字段名由你在节点里指定。

**Glob**：**一种用星号匹配一批文件名的写法**，`/intake/inbox/*` 的意思是这个目录下面的全部文件。

**轮询**、**幂等**：[第 8 卷第 6 章](../08-OCR/06-文件夹监测.md)的新词。**这一章会再用一次幂等，[第 8 章](08-案例二-结果台账.md)会把它讲透。**

## 这个案例做成什么

一句话——**收件箱进，分好类的目录出。**

```text
~/ai/projects/intake/
├── inbox/          收件箱：交件的人只往这里丢
├── 合同/
├── 发票/
├── 简历/
├── 报告/
├── 待定/           模型拿不准的，人来看
└── 失败/           读不出内容的
```

一份叫 `扫描件.pdf` 的文件丢进 `inbox/`，几分钟之后它不在那儿了，变成 `合同/2026-08-15-153042-合同-扫描件.pdf`。

**新名字里有四段**，每一段都有用：

- **日期**——按时间排序，也方便按月份归档；
- **时分秒**——防重名。[第 8 卷第 6 章](../08-OCR/06-文件夹监测.md)那一条：`mv` 覆盖同名文件不问一句，**两个人同一天各交一份 `扫描件.pdf` 过来，不加这一手，先来那份就没了**；
- **类别**——一眼看得出机器判成了什么；
- **原来的名字**——**这一段不能省，它是回溯的钥匙**。归档之后要能对回交件人手上那一份（[第 8 卷第 5 章](../08-OCR/05-批量处理.md)那条“文件名是回溯的钥匙”）。

**这个案例值钱的地方在于它对着的是一个岗位。** 任何一个每天要有人手工分拣、录入、归档的活，都是这个形状。

## 触发用轮询，不用实时监听

**这一节只有一句结论，理由不在这里论。**

**每 5 分钟去看一眼收件箱，不要用“文件出现的那一刻通知我”那种做法。**

[第 8 卷第 6 章](../08-OCR/06-文件夹监测.md)已经把理由写全了，三条：触发时机不好把握（文件出现不等于拷完）、监听程序自己得一直活着、**它停着的那段时间事件是补不回来的**。轮询没有这三个问题——**它每一轮都是重新数一遍目录，停了三天，起回来的第一轮就把攒下的全处理了。**

**n8n 自己也表了一次态。** 它有一个专门守着目录的触发器节点，而官方文档里那个屏蔽节点的环境变量，**默认值就把它挡在外面**（下面那一节会看到这个默认值）。本章不去打开它。

## 第一步：改容器，一次改两件事

**这一步要把[第 2 章](02-n8n装起来.md)那个容器删掉重建。** 两件事一起做，省一次重建。

### 要加的两样

**一、多挂一个目录。** 案例二那一套目录得让容器看得见：

```text
-v "$HOME/ai/projects/intake:/intake"
```

**二、把 Execute Command 这个节点放出来。**

n8n 有一个能在容器里跑命令的节点，叫 **Execute Command**。**这一章要靠它搬文件。**

官方文档写明，有一个环境变量 `NODES_EXCLUDE` 管哪些节点不加载，**它的默认值是**：

```text
["n8n-nodes-base.executeCommand", "n8n-nodes-base.localFileTrigger"]
```

**两个节点默认都不加载。** 第一个就是要用的那个；第二个是上面说的那个守着目录的触发器。

所以要写一行把第一个放出来、第二个留着：

```text
-e NODES_EXCLUDE='["n8n-nodes-base.localFileTrigger"]'
```

> **这一行是在放宽一道默认的安全设置，先想清楚再加。** 官方文档写得很直白——这个节点在有不受信任的使用者的环境里有明显的风险，所以 2.0 以后默认关掉。**放出来的意思是：任何能打开这个界面的人，都能在容器里跑任意命令。** [第 2 章](02-n8n装起来.md)那句“这个界面别开到公网上”，从这一行开始变成硬要求。**只在自己或者客户内网里跑的机器上这么做。**

### 建目录

```bash
mkdir -p ~/ai/projects/intake/{inbox,合同,发票,简历,报告,待定,失败}
```

看一眼建对了没有：

```bash
ls ~/ai/projects/intake/
```

属主对不上的话，[第 2 章](02-n8n装起来.md)那一条照办：

```bash
sudo chown -R 1000:1000 ~/ai/projects/intake
```

### 重建容器

**先停掉删掉**（[第 2 卷第 10 章](../02-Ubuntu/10-Docker-Compose.md)那条规矩）：

```bash
docker stop n8n
docker rm n8n
```

**工作流和凭据不会丢**，它们在 `~/ai/projects/n8n` 那个目录里（[第 2 章](02-n8n装起来.md)验证过这件事）。

然后用新的命令建回来。**和[第 2 章](02-n8n装起来.md)那条比，只多了两行**，其余一个字不动：

```bash
docker run -d \
  --name n8n \
  --restart unless-stopped \
  -p 5678:5678 \
  -e GENERIC_TIMEZONE="Asia/Shanghai" \
  -e TZ="Asia/Shanghai" \
  -e N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true \
  -e N8N_RUNNERS_ENABLED=true \
  -e NODES_EXCLUDE='["n8n-nodes-base.localFileTrigger"]' \
  --add-host=host.docker.internal:host-gateway \
  -v "$HOME/ai/projects/n8n:/home/node/.n8n" \
  -v "$HOME/ai/data/daily:/data" \
  -v "$HOME/ai/projects/intake:/intake" \
  docker.n8n.io/n8nio/n8n
```

### 确认这两样真的生效了

**别信上面这条命令，自己验一次。**

```bash
docker ps
```

`STATUS` 是 `Up` 就往下走。

进容器看那个目录在不在：

```bash
docker exec -it n8n sh
ls /intake
exit
```

**打印出那七个目录名就是挂对了。**

节点那一样在界面上验——打开 `http://localhost:5678`，随便新建一条工作流，点加号搜 `execute command`。**搜得到就是放出来了；搜不到，回去看那一行环境变量的引号有没有写全。**

> **案例一那条日报流程还在跑吗？** 去执行记录里看一眼最近有没有新的一行。**重建容器不影响它**，但确认一次比猜强。

## 第二步：新建工作流，前四个节点

新建一条工作流，起名叫“进件分类-案例二”。

**下面每一个界面动作[第 3 章](03-第一个工作流.md)到[第 6 章](06-案例一-每日推送.md)都做过**，这一章只说填什么。

### 一、Schedule Trigger

搜 `schedule`，加进来。

- **Trigger Interval** 选 **Minutes**；
- **Minutes Between Triggers** 填 `5`。

**参数名以你面板上看到的为准，需要核验。**

**5 分钟这个数是起点，不是最优值。** 交件的人能接受等多久，就填多久。[第 8 卷第 6 章](../08-OCR/06-文件夹监测.md)那条一样成立——**间隔看你能接受多久的延迟。**

### 二、Execute Command，改名叫“列新文件”

拖一条线出去，搜 `execute command`。**Command** 那一格填：

```bash
find /intake/inbox -maxdepth 1 -type f -mmin +1 -print
```

**这条命令在容器里跑**，所以路径写的是 `/intake/inbox`，不是你终端里那个 `~/ai/projects/intake/inbox`。**[第 2 章](02-n8n装起来.md)那件事，这里又撞上一次。**

四个参数，**`-mmin +1` 是这一步的正题**：

- **`-maxdepth 1`**——只看这一层，不进子目录；
- **`-type f`**——只要文件，不要目录；
- **`-mmin +1`**——**只挑一分钟以上没被动过的**；
- **`-print`**——把找到的路径一行一个打出来。

**`-mmin +1` 防的是什么，[第 8 卷第 6 章](../08-OCR/06-文件夹监测.md)那一节写透了**，这里只复述结论：**一份文件出现在目录里，不等于它已经拷完了。** 从网络盘拖一个大文件过来要几十秒，这段时间里文件已经在那儿了，但里面只有一半。这时候去读它，读到的是半份。**拷贝还在进行中的文件，修改时间一直在刷新，这一轮就轮不到它，等下一轮。**

**一分钟够不够，看你的文件从哪儿来。** 本地拷贝绰绰有余；从一条很慢的网络拷几百 MB，改成 `-mmin +5`。**这个数不是规范，是你自己那条路上量出来的。**

点一下右上角执行。**这个节点的输出面板上应该有一块 `stdout`**，里面是找到的路径，一行一个。收件箱是空的话，`stdout` 就是空的。

**这个节点吐出来的字段名（`stdout`、`stderr`、`exitCode`）需要核验**，以你面板上实际看到的为准，下一步的代码要用它。

> **先往 `inbox/` 里丢两三份文件，等过一分钟，再执行一次。** 这一步没有路径出来，后面全是空跑。

### 三、Code 节点，改名叫“拆成一条一份”

上一步给的是一大段文字，**里面夹着好几个路径**。这个节点把它拆成一条一份。

- **Mode** 选“跑一次，处理全部数据”那一项（[第 6 章](06-案例一-每日推送.md)那个“拼日报”选的是同一项，措辞以实际界面为准）；
- **语言**选 JavaScript；
- 代码照抄：

```javascript
// 拆成一条一份 —— 把上一步打印出来的那一堆路径，拆成一条数据一个文件
// 模式：跑一次，处理全部数据

const 输出 = $input.first().json.stdout || '';

const 路径们 = 输出
  .split('\n')
  .map((行) => 行.trim())
  .filter((行) => 行 !== '');

return 路径们.map((路径) => ({
  json: {
    路径: 路径,
    文件名: 路径.split('/').pop(),
  },
}));
```

**四处说明：**

- **`$input.first().json.stdout`**——上一步只吐一条数据，`.first()` 就是拿那一条，`stdout` 是它里面装命令输出的字段。**字段名跟上一步面板上看到的对齐**；
- **`|| ''`**——[第 5 章](05-案例一-模型摘要.md)那个写法，**那个字段不在的时候不至于整条炸掉**；
- **`.filter(...)` 那一行**——把空行扔掉。`find` 什么也没找到的时候，`split` 会给你一个只有空字符串的列表，**不滤掉的话下面会凭空多出一条什么都没有的数据**；
- **`.split('/').pop()`**——把路径按斜杠切开，取最后一段，就是文件名。

**收件箱是空的时候，这个节点返回一个空列表，后面的节点全都不跑。** 执行记录里那一次是成功的，后面几个节点是灰的。**这就是对的**——绝大多数轮次都长这样。**这个空列表的确切表现需要核验**，跑一次看执行记录就知道。

执行一次，点开这个节点的输出。**丢了三份文件就应该是三条**，每条两个字段。

### 四、Read/Write Files from Disk，改名叫“读进来”

[第 6 章](06-案例一-每日推送.md)用过这个节点写文件，**这次用它的另一个操作**。

- **Operation** 选 **Read File(s) From Disk**；
- **File(s) Selector** 切到表达式那一边，填 `{{ $json.路径 }}`；
- 选项里加一项 **Put Output File in Field**，填 `文件`。

**三处说明：**

- **File(s) Selector 支持 Glob**，官方文档写明可以用 `*`、`**`、`?` 这些。**这一章不用 Glob，因为上一步已经把路径一个一个算好了**——一条数据一个路径，节点逐条执行（[第 5 章](05-案例一-模型摘要.md)那个“逐条执行”），一次读一份；
- **Put Output File in Field 填的是二进制那一块的字段名。** 不填的话默认叫 `data`，**这一章起名叫 `文件`，是为了后面写表达式的时候一眼认得出**；
- **官方文档在这一页又写了一遍那件事**：在 Docker 里跑的时候，这里填的路径指的是容器内的文件系统。**所以是 `/intake/inbox/...`，不是宿主机那一串。**

执行一次。**点开输出面板，右边应该能看到文件本身**，PDF 会显示成一个附件，文本文件能看到内容。

## 第三步：把内容读出来

**纯文本和 PDF 要走两条不同的路**，所以中间要分个叉。

### 五、Switch 节点，改名叫“按后缀分路”

搜 `switch`，加进来。**这个节点按你定的条件，把数据分到不同的出口。**

配三条：

| 出口 | 条件 | 去哪儿 |
| --- | --- | --- |
| 出口一 | 文件名以 `.pdf` 结尾 | 读 PDF |
| 出口二 | 文件名以 `.txt` 或者 `.md` 结尾 | 读文本 |
| 兜底 | 上面都不是 | 读不了的 |

条件那一格用表达式，取上一步之前那个节点的文件名：

```text
{{ $('拆成一条一份').item.json.文件名.toLowerCase() }}
```

**`$('节点名').item` 是[第 5 章](05-案例一-模型摘要.md)那个写法**——去别的节点的数据里取，取的是和当前这条对得上的那一条。**到了这一步，流转的数据已经变成文件本身了，文件名不在里面，得回头找。**

**`.toLowerCase()` 是转成小写**，不然 `合同.PDF` 会漏掉。

**这个节点的参数名、条件怎么填、兜底那个出口叫什么，随版本变化，需要核验。** 认意思——就是那个“按条件分几个出口”的节点。

> **为什么不用 If 节点。** If 只有两个出口，这里要三个。**两个出口的场合[第 9 章](09-案例三-邮件草稿.md)会用到 If。**

### 六 A、Extract From File，改名叫“读 PDF”

从出口一拖出去，搜 `extract`，选 **Extract From File**。

- **Operation** 选 **Extract From PDF**；
- **Input Binary Field** 填 `文件`（上一步起的那个名字）。

**这个节点把 PDF 里的文字抽出来，放进 `$json` 那一块。** 官方文档列出的操作有十来个，PDF 是其中一个，别的还有 CSV、XLSX、HTML 这些。

**它抽出来放在哪个字段，官方文档这一页没写明，需要核验。** 执行一次，点开输出面板看一眼，**多半是一个叫 `text` 的字段**，下面那一步照你看到的那个名字填。

> **抽出来是空的怎么办。** 那多半是一份扫描件——**整页是一张图，里面一个字符都没有**，PDF 里只有图，没有文字层。这种走不了这一章的路，要走[第 8 卷](../08-OCR/README.md)那条读图的线。**这一章的处理是让它进「待定」**，下面那段提示词的第 3 条管这件事。

### 六 B、Extract From File，改名叫“读文本”

从出口二拖出去，同样是 **Extract From File**：

- **Operation** 选 **Extract From Text File**；
- **Input Binary Field** 填 `文件`；
- **Destination Output Field** 填 `text`。

**最后这一项是这一步的关键。** 这个操作可以指定抽出来的内容放进哪个字段，**填成和 PDF 那一路一样的名字**，两条路汇到下一个节点的时候，取值的写法就是同一句。

**PDF 那个操作没有这一项**（官方文档写明它只对 JSON、ICS、文本文件和 Base64 那几个操作生效），**所以是文本这一路去迁就 PDF 那一路，不是反过来。** 上一步你看到 PDF 抽出来叫什么，这里就填什么。

### 六 C、Code 节点，改名叫“读不了的”

从兜底那个出口拖出去，加一个 **Code** 节点。**Mode 选“每条各跑一次”那一项**（和上面那个“拆成一条一份”选的不是同一项，别弄混）。

```javascript
// 读不了的 —— 这个后缀本章的流程读不出文字，直接给它一个归宿
// 模式：每条各跑一次

const 文件名 = $('拆成一条一份').item.json.文件名;

return {
  json: {
    text: '',
    读不了: true,
    说明: `后缀不在本流程处理的范围里：${文件名}`,
  },
};
```

**把它连到下一个节点，和上面两条路汇到一起。** 一个节点可以有多条线进来（[第 6 章](06-案例一-每日推送.md)那个“拼日报”引出两条线，是同一件事反过来）。

**这一路吐出来的 `text` 是空的**，所以下面模型会按规矩判成「待定」，文件会进 `待定/`。**这是故意的**——`.docx`、`.jpg` 这类东西现在没人处理，**放着不管比猜一个类别强。**

## 第四步：让模型分类

### 七、Edit Fields，改名叫“整理素材”

三条路汇进来，加一个 **Edit Fields (Set)**，加三个字段。

**第一个，`文件名`，字符串，表达式**：

```text
{{ $('拆成一条一份').item.json.文件名 }}
```

**第二个，`系统提示`，字符串，固定值**——把下一节那段提示词整段贴进去。

**第三个，`用户内容`，字符串，表达式**：

```text
文件名：{{ $('拆成一条一份').item.json.文件名 }}

内容：
{{ ($json.text || "").slice(0, 3000) }}
```

**这一段的三处写法[第 5 章](05-案例一-模型摘要.md)全讲过**，一处也没新增——大括号外面的字原样保留、`||` 是前面没有就用后面的、`.slice(0, 3000)` 是只取前 3000 个字符。

**为什么分类只看前 3000 个字符就够。** 判断一份文件是合同还是发票，**开头那一段基本就定了**——抬头、标题、第一段话。这跟[第 5 章](05-案例一-模型摘要.md)做摘要那个理由不完全一样，那里截断是权衡，**这里截断几乎没有代价。**

**填完看输入框下面那块预览**，[第 5 章](05-案例一-模型摘要.md)那条：预览出得来就是取对了，这比执行一次再回头查快得多。

### 分类提示词

**下面这段整段抄进上面那个 `系统提示` 字段。**

```text
你是一个文件分类助手。你的全部工作是判断用户给你的这份文件属于哪一类。

可以选的类别只有下面这五个，一个字都不要改：
合同
发票
简历
报告
待定

规矩：
1. 只根据用户给出的文件名和内容判断，内容里没有的东西一个字都不要补；
2. 拿不准就选“待定”。宁可选“待定”，也不要在两个类别之间硬挑一个；
3. 内容是空的、看不出讲了什么、或者同时像两类，一律选“待定”；
4. 不要发明新的类别，不要输出上面五个词以外的任何类别名；
5. 按下面这个格式回答，一共两行，不要写别的，不要写开场白，不要用 Markdown 标记：

类别：（上面五个词里的一个）
理由：（一句话，20 个字以内，说你是根据哪一句判断的）
```

**五条规矩，一条一条说它防的是什么：**

**第 1 条防瞎编。** [第 5 章](05-案例一-模型摘要.md)那一条，原样成立，**在这里更要紧**——摘要写偏了你还看得出来，分类判错了文件就跑到别的目录里去了。

**第 2 条是本章的正题**，下面单开一节说。

**第 3 条给空内容一条明路。** 扫描件抽不出文字、`.docx` 走了兜底那一路，`text` 都是空的。**不给这一条，模型会对着空内容硬选一个。**

**第 4 条堵新类别。** 不写这一条，你会收到“劳动合同”“增值税发票”这种——**听着更准确，实际上目录里没有这两个名字，搬文件那一步会当场断掉。**

**第 5 条管格式。** 下面那个 Code 节点要按行去解析，**格式脏了解析不出来。** 不写“不要用 Markdown 标记”，它爱给你加上 `**类别**：合同`。

> **改提示词的时候一次只改一条，改完执行一次看效果。** [第 3 章](03-第一个工作流.md)那条“改一处执行一次”，[第 5 章](05-案例一-模型摘要.md)已经重复过一次，**这是本卷第三次说它。**

### 八、HTTP Request，改名叫“问模型”

**参数和[第 5 章](05-案例一-模型摘要.md)那次一模一样**，只有请求体最后一行不同：

- **Method** 选 **POST**；
- **URL** 填 `http://host.docker.internal:11434/v1/chat/completions`；
- **Send Body** 打开，**Body Content Type** 选 **JSON**，**Specify Body** 选用 JSON 写；
- **选项里的超时调大**。

请求体：

```json
{
  "model": "qwen3.6-35b",
  "messages": [
    {"role": "system", "content": {{ JSON.stringify($json.系统提示) }}},
    {"role": "user", "content": {{ JSON.stringify($json.用户内容) }}}
  ],
  "stream": false,
  "temperature": 0
}
```

**`model` 那一行换成你自己 `ollama list` 里的名字。**

**`JSON.stringify(...)` 不能省**，理由[第 5 章](05-案例一-模型摘要.md)讲透了：抓进来的文件正文里一定有双引号和换行，不转义会把这段 JSON 从中间截断。**它自己会带上外面那对引号，不要再加一对。**

**`temperature` 这次填 `0`，比[第 5 章](05-案例一-模型摘要.md)那个 `0.2` 还低。** 理由是分类和摘要要的东西不一样——**摘要要读着顺，分类要的是同一份文件每次给同一个答案。** 一份文件今天判成合同、明天判成报告，这条流水线就没法交付。**`0` 是本教材挑的起点，不是实测出来的最优值，需要核验。**

执行一次，点开这个节点的输出，翻到 `choices[0].message.content`。**应该是干干净净的两行：**

```text
类别：合同
理由：开头写着甲方乙方和签订日期
```

**（上面这两行是格式示意，不是任何一次实际运行的输出。）**

**多出开场白、多出 Markdown 标记、类别是五个词以外的东西**——回上一节改提示词，别在下一个节点里修修补补。

## 关键设计：拿不准就进「待定」

**这一节是本章、也是本卷所有案例的共同原则。整节读完再往下。**

### 规矩是什么

**分类不确定的，不要硬分。宁可进「待定」让人看。**

模型面对一份看不懂的文件，**默认行为是硬挑一个最像的**。它不会说“我不知道”，除非你明确允许它这么说。上面那段提示词的第 2 条和第 3 条就是在允许它。

### 为什么这条比准确率重要

**因为两种错的代价差着量级。**

- **判成「待定」而它其实是合同**——文件躺在 `待定/` 里，人看一眼挪过去。**成本是三十秒。**
- **判成「发票」而它其实是合同**——文件躺在 `发票/` 里，**看上去一切正常**。没有人会去 `发票/` 里找合同，**这份文件从此就丢了**，等到半年后要用的时候才发现。

**第二种错的可怕之处在于它不留痕迹。** [第 8 卷第 7 章](../08-OCR/07-错的怎么拦.md)那句话在这里同样成立——**它识别成了另一个合法的值**，一眼看不出来。

**所以这条流水线的承诺不是“分得准”，是“分不准的会被拦下来”。**

### 白名单要在代码里再拦一遍

**光靠提示词不够。**

提示词是请求，不是保证。模型答出“劳动合同”“其他”“无法判断”这类东西是完全可能的，**尤其是换一个模型之后。**

所以下一个 Code 节点里有这么一段——**类别不在那四个词里，一律改成「待定」**。

**这一层不能省。** 它的作用是：**不管模型怎么发挥，文件永远只会落进你建好的那七个目录之一。** 没有这一层，模型答一个 `其他`，`mv` 那一步就会试图往 `/intake/其他/` 里搬，**目录不存在，节点当场报错，这一份卡在收件箱里。**

> **一句话记住它**：**提示词管的是它答什么，白名单管的是你认什么。两件事，都要做。**

### 待定目录要有人看

**建了「待定」不等于解决了问题。** 它只是把问题从“看不见”变成了“看得见”。

**交付给客户的时候这句话要说出口**：“机器拿不准的会放在待定这个文件夹里，**这个文件夹要有人每天看一眼**。它空着说明昨天全判出来了；它开始堆东西，说明有一类文件是我们没考虑到的，告诉我们，我们加一个类别。”

**「待定」堆起来是有用的信息，不是故障。** 同一种文件在里面出现了五次，那不是复核的事，**那是回去加一个类别、改一段提示词的事**（[第 8 卷第 7 章](../08-OCR/07-错的怎么拦.md)那条“某一类特别多就回去改提示词”，一模一样）。

## 第五步：按分类结果搬文件

### 九、Code 节点，改名叫“定归宿”

**Mode 选“每条各跑一次”那一项。** 代码照抄：

```javascript
// 定归宿 —— 读模型的回答，判类别，算出这份文件该叫什么、该搬到哪儿
// 模式：每条各跑一次

// 一、允许的类别。要加一类就改这一行，同时去建那个目录
const 允许 = ['合同', '发票', '简历', '报告'];
const 兜底 = '待定';

// 二、把模型那两行拆开
const 回答 = ($json.choices && $json.choices[0].message.content) || '';
let 类别 = '';
let 理由 = '';
for (const 行 of 回答.split('\n')) {
  const 一行 = 行.trim();
  if (一行.startsWith('类别：')) 类别 = 一行.slice(3).trim();
  if (一行.startsWith('理由：')) 理由 = 一行.slice(3).trim();
}

// 三、白名单。不在清单里的一律进待定，模型说什么都不算数
if (!允许.includes(类别)) {
  理由 = `模型给的类别是“${类别 || '空'}”，不在允许的清单里。原理由：${理由}`;
  类别 = 兜底;
}

// 四、原来的路径和文件名，回上游那个节点取
const 源路径 = $('拆成一条一份').item.json.路径;
const 原名 = $('拆成一条一份').item.json.文件名;

const 点 = 原名.lastIndexOf('.');
const 主名 = 点 > 0 ? 原名.slice(0, 点) : 原名;
const 后缀 = 点 > 0 ? 原名.slice(点) : '';

// 五、拼新名字：日期-时分秒-类别-原来的主名.后缀
const d = new Date();
const 两位 = (n) => String(n).padStart(2, '0');
const 日期 = `${d.getFullYear()}-${两位(d.getMonth() + 1)}-${两位(d.getDate())}`;
const 时刻 = `${两位(d.getHours())}${两位(d.getMinutes())}${两位(d.getSeconds())}`;

const 干净主名 = 主名.replace(/[\/\\\r\n\t]/g, '_').slice(0, 60);
const 新名 = `${日期}-${时刻}-${类别}-${干净主名}${后缀}`;
const 目标路径 = `/intake/${类别}/${新名}`;

// 六、给命令行用的写法：整段用单引号包住，里面的单引号按规矩换掉
const 引起来 = (s) => `'${String(s).split("'").join(`'\\''`)}'`;

return {
  json: {
    文件名: 原名,
    类别: 类别,
    理由: 理由,
    新名: 新名,
    目标路径: 目标路径,
    命令: `mv -n -- ${引起来(源路径)} ${引起来(目标路径)}`,
  },
};
```

**六段，四处要单说：**

**一、第三段那个白名单，是上一节讲的那一层。** 它不是可选的。**要加一个类别，改第一行那个列表，同时去建那个目录**——两件事都做了才生效。

**二、第五段那个日期为什么写得这么啰嗦。** [第 6 章](06-案例一-每日推送.md)讲过：网上常见的 `toISOString()` 那种写法给的是世界时，**这边下午跑，文件名会写成前一天。** 上面这种用的是本地时间，**而本地时间是[第 2 章](02-n8n装起来.md)那个 `TZ` 变量定的。**

**三、`干净主名` 那一行，把斜杠、反斜杠和换行换成下划线。** 文件名里出现斜杠会被当成目录分隔，**换成下划线是为了不让一个奇怪的文件名把文件搬到别的地方去。** 后面那个 `.slice(0, 60)` 是截长度，防止名字长到系统不认。

**四、最后那个 `引起来`，是这一段代码里最要紧的一行。**

这一行干的事是：**把一个字符串整段用单引号包住，里面本来就有的单引号按命令行的规矩换成 `'\''`。**

**为什么必须做这件事**：下一步要把这串命令交给命令行去跑。**文件名不是你写的，是交件的人起的。** 名字里有空格、有引号、有 `$`、有分号的话，**这串命令的意思就变了**——轻则搬错地方，重则跑起一条你完全没打算跑的命令。

**包起来之后，命令行会把引号里的东西整段当成一个文件名，不再往里看。**

> **这一条是这一章唯一一处安全设计，别删。** 你自己试的时候文件名都很规矩，看不出它的用处；**交付出去之后，客户那边的文件名什么样都有。**

执行一次，点开输出。**每条应该有六个字段**，`命令` 那一格读一遍，**它就是下一步真的要跑的东西。**

### 十、Execute Command，改名叫“搬文件”

拖出去，加 **Execute Command**。**Command** 那一格切到表达式，填：

```text
{{ $json.命令 }}
```

**只填这一句。** 命令本身在上一步算好了，这个节点只负责执行。

**注意节点设置里那个“只跑一次”的开关要关着**（官方文档写明这个节点有一项 Execute Once，管它是整批跑一次还是每条各跑一次）。**开着的话十份文件只有第一份被搬。**

**`mv -n` 里那个 `-n` 是“目标已经存在就不覆盖”。** 名字里已经带了时分秒，撞名的机会很小，**这一手是白加的保险**。

执行一次，回终端看：

```bash
ls ~/ai/projects/intake/inbox/
ls ~/ai/projects/intake/合同/ ~/ai/projects/intake/待定/
```

**收件箱空了，文件出现在对应的目录里，带着新名字**——这一章就通了。

### 报错了看哪儿

- **节点报的是找不到命令或者节点搜不到**——`NODES_EXCLUDE` 那一行没生效，回第一步；
- **报的是没有这个目录**——多半是模型答了一个白名单以外的类别，而你的白名单那一层被改坏了。点开“定归宿”的输出，看 `类别` 那一格是什么；
- **报的是权限不够**——[第 2 章](02-n8n装起来.md)那件事，`sudo chown -R 1000:1000 ~/ai/projects/intake`；
- **命令跑了但文件没动**——点开这个节点的输出，看 `stderr` 和 `exitCode` 那两格写了什么。

其余的到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。
