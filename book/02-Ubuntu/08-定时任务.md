# 08　定时任务

## 这一章的任务

让机器每天凌晨自己整理一次下载文件夹。

`~/Downloads` 用几个月就会堆成一片，里面混着装完就没用的安装包、要留的资料、看完的 PDF。做完这一章，机器每天凌晨 3 点自己跑一遍：7 天没动过的文件，按类型分好放进 `~/ai/data/downloads`，刚下的不动。你手上多一个能跑的脚本，和一套“写脚本、先手动跑、再交给定时”的做法，第 12 章的自动备份直接套用。

## 开始前

- 第 1 章的 `~/ai/scripts` 目录已经建好；
- 第 2 章的 `cd`、`ls`、`mv` 会用了；
- 第 7 章的 `journalctl -u 服务名` 会用了；
- 30 分钟。

## 新词

**cron**：Linux 上负责定时执行命令的服务。它一直在后台跑，每分钟醒一次，看看有没有到点该干的活。

**crontab**：一张表，记着“什么时候执行什么命令”。每个账户有自己的一张，互不干扰。这个词也是编辑这张表的命令的名字。

**脚本**（Script）：把一串命令按顺序写进一个文本文件，执行这个文件就等于把这串命令依次跑一遍。文件名习惯以 `.sh` 结尾。

**执行权限**：第 4 章讲权限时的那个 `x`。一个文本文件要能当程序跑，必须先有它。

**重定向**：把命令的输出写进文件，而不是打在屏幕上。第 7 章存日志用的 `>` 就是重定向。

## 先确认 cron 在跑

```bash
systemctl status cron
```

`Active` 那行是 `active (running)` 就行，读法见第 6 章。Ubuntu 桌面版默认装好并且开着，没在跑的话：

```bash
sudo systemctl enable --now cron
```

## 第一步，写脚本

脚本放 `~/ai/scripts`，这是第 1 章定下的位置。所有定时任务的脚本都放这儿，好处是备份的时候一起备走（第 12 章），换机器的时候一起拷走。

建文件：

```bash
nano ~/ai/scripts/tidy-downloads.sh
```

`nano` 是终端里的文本编辑器，第 5 章改 `/etc/fstab` 时用过。把下面这些原样抄进去：

```bash
#!/usr/bin/env bash
# 整理下载文件夹：把放了一阵子没动的文件按类型收进 ~/ai/data/downloads
set -euo pipefail

SRC="$HOME/Downloads"
DEST="$HOME/ai/data/downloads/$(date +%Y-%m)"
DAYS=7

if [ ! -d "$SRC" ]; then
  echo "$(date '+%F %T') 找不到 $SRC，什么也没做"
  exit 0
fi

mkdir -p "$DEST/docs" "$DEST/images" "$DEST/archives" "$DEST/others"

moved=0
while IFS= read -r -d '' file; do
  name="$(basename "$file")"
  lower="$(printf '%s' "$name" | tr 'A-Z' 'a-z')"
  case "$lower" in
    *.pdf|*.doc|*.docx|*.xls|*.xlsx|*.ppt|*.pptx|*.txt|*.md) sub=docs ;;
    *.jpg|*.jpeg|*.png|*.gif|*.webp|*.heic|*.bmp)            sub=images ;;
    *.zip|*.tar|*.gz|*.tgz|*.xz|*.7z|*.rar|*.deb|*.appimage) sub=archives ;;
    *)                                                       sub=others ;;
  esac

  target="$DEST/$sub/$name"
  if [ -e "$target" ]; then
    target="$DEST/$sub/$(date +%H%M%S)-$name"
  fi

  mv "$file" "$target"
  echo "$(date '+%F %T') 移动 $name 到 $sub"
  moved=$((moved + 1))
done < <(find "$SRC" -maxdepth 1 -type f -mtime +$DAYS -print0)

echo "$(date '+%F %T') 整理完成，这次移动了 $moved 个文件"
```

按 `Ctrl+O` 回车保存，`Ctrl+X` 退出。

逐段说这个脚本在干什么：

- **第一行 `#!/usr/bin/env bash`** 告诉系统用 bash 来跑这个文件。这行不能省，cron 执行命令时用的是另一个更简单的 shell，脚本里的一些写法在那个 shell 里不认识；
- **`set -euo pipefail`** 是一道保险：任何一条命令出错就立刻停下来，不接着往下跑。整理文件这类会动到东西的脚本，错了要马上停，不要带着错误状态继续；
- **`SRC` 和 `DEST`** 是源目录和目标目录。`$(date +%Y-%m)` 会换成当前年月，所以每个月自动分一个新目录，例如 `2026-08`；
- **`DAYS=7`** 是“多久没动过才搬”。刚下载的文件你多半还在用，别去动它；
- **`find ... -mtime +7 -print0`** 找出 `~/Downloads` 里 7 天以上没改过的文件。`-maxdepth 1` 表示只找这一层，不进子目录——子目录里往往是解压出来的一整套东西，拆开搬会散架；
- **`while ... read`** 那一段逐个处理找到的文件。文件名带空格是常事，`-print0` 和 `read -d ''` 配合起来才不会把一个名字拆成两半；
- **`case`** 按扩展名归类。前一行的 `tr 'A-Z' 'a-z'` 先把文件名转成小写，这样 `.PDF` 和 `.pdf` 都能对上；
- **目标位置已经有同名文件时**，在名字前面加上时分秒，避免覆盖。`mv` 覆盖同名文件不问一句，这一点第 2 章讲过；
- **每搬一个就 `echo` 一行**，带时间。这些输出后面会写进日志文件，是你判断任务有没有跑、跑了什么的唯一凭据。

给它执行权限：

```bash
chmod 755 ~/ai/scripts/tidy-downloads.sh
```

`755` 的含义见第 4 章。没有这一步，脚本跑不起来，会报 `Permission denied`。

## 第二步，先手动跑一遍

**任何脚本都要先手动跑通，再交给定时任务。** 定时任务是在你不看着的时候跑的，脚本有问题你不会立刻知道，等发现的时候可能已经错了一个月。

先造几个测试文件，免得拿真资料试：

```bash
touch -d "30 days ago" ~/Downloads/测试文件.pdf ~/Downloads/测试图.png ~/Downloads/test.zip
```

`touch` 建空文件，`-d "30 days ago"` 把它们的修改时间设成 30 天前，这样脚本才会认为它们该搬了。

跑：

```bash
~/ai/scripts/tidy-downloads.sh
```

正常输出：

```
2026-08-14 15:42:03 移动 测试文件.pdf 到 docs
2026-08-14 15:42:03 移动 测试图.png 到 images
2026-08-14 15:42:03 移动 test.zip 到 archives
2026-08-14 15:42:03 整理完成，这次移动了 3 个文件
```

去看结果：

```bash
tree ~/ai/data/downloads
```

三个文件应该分别落在 `docs`、`images`、`archives` 里，`~/Downloads` 里那几个测试文件不见了。

再跑一次，输出应该是“这次移动了 0 个文件”——没有新的旧文件了。这说明脚本重复跑不会出乱子，定时任务天天跑的东西必须有这个性质。

## 第三步，读懂时间格式

```bash
crontab -e
```

作用：编辑当前账户的定时任务表。**不要加 `sudo`**，加了就是改 root 的表，跑出来的文件属主不是你。

第一次执行会问用哪个编辑器：

```
Select an editor.  To change later, run 'select-editor'.
  1. /bin/nano        <---- easiest
  2. /usr/bin/vim.basic
  3. /usr/bin/vim.tiny
  4. /bin/ed
Choose 1-4 [1]:
```

直接回车选 `nano`。

打开后是一个带注释的空表，注释里已经画好了格式。定时任务一行一个，前面 5 个字段是时间，第 6 段开始是要执行的命令：

```
分  时  日  月  周   命令
0   3   *   *   *    /home/roland/ai/scripts/tidy-downloads.sh
```

5 个字段依次是：

| 字段 | 取值范围 | 说明 |
| --- | --- | --- |
| 分 | 0-59 | 第几分钟 |
| 时 | 0-23 | 第几点，24 小时制 |
| 日 | 1-31 | 每月第几天 |
| 月 | 1-12 | 第几月 |
| 周 | 0-7 | 星期几，0 和 7 都是星期日 |

`*` 表示“每个都算”。上面那行读出来就是：每月每天每星期的 3 点 0 分执行。

再看几个例子，对着上面那张表读一遍：

- `30 2 * * *`——每天 2 点 30 分；
- `0 4 * * 0`——每星期日 4 点整（第 12 章的备份用这个）；
- `0 9 1 * *`——每月 1 号 9 点整；
- `*/10 * * * *`——每 10 分钟一次。`*/10` 的意思是这个字段每隔 10 个单位来一次；
- `0 3 * * 1-5`——周一到周五 3 点整，连着的几个用横杠。

**最容易读错的是前两个字段的顺序**，分在前、时在后，和平时说“三点半”的顺序相反。`30 3` 是 3 点 30 分，`3 30` 里的 30 超出了小时的范围，这行会被忽略。

## 第四步，写进定时表

在 `crontab -e` 打开的文件末尾，加上这一行：

```
0 3 * * * /home/你的账户名/ai/scripts/tidy-downloads.sh >> /home/你的账户名/ai/scripts/tidy-downloads.log 2>&1
```

`你的账户名` 换成你自己的，用 `whoami` 查。按 `Ctrl+O` 回车保存，`Ctrl+X` 退出。退出时会显示一行 `crontab: installing new crontab`，这行是安装成功的意思。

这一行里有三处是新手最常栽跟头的地方：

**第一，路径必须写全。** 从 `/home` 开始一路写到底，不要写 `~/ai/scripts/...`。cron 跑命令时的环境和你在终端里不一样，简写和缩写在这里靠不住，写全路径最省事。

**第二，`>> 文件` 把输出存起来。** 两个大于号是追加，每次跑的输出都续在文件末尾，不覆盖上一次。只写一个 `>` 就是每次都覆盖，只剩最后一次的记录。不写重定向的话，脚本打印的东西直接丢掉，你无从判断它跑没跑。

**第三，`2>&1` 把报错也一起收进去。** 命令的正常输出和报错走的是两条道，`>>` 只管正常那条。真正要看的往往是报错那条，所以这一段不能省，位置就在文件名后面。

看看现在表里有什么：

```bash
crontab -l
```

作用：列出当前账户的定时任务，不进编辑器。输出里应该有你刚加的那行。

## 第五步，验证它真的跑了

写完不等于跑得起来。凌晨 3 点还没到，用下面的办法当场验证。

**先把时间改成一两分钟以后。** 现在是 15 点 47 分，就把那行的前两个字段改成 `50 15`，保存退出，然后等到 15 点 50 分。

`date` 命令看当前时间：

```bash
date
```

到点之后，看三个地方。

**一看输出文件**：

```bash
cat ~/ai/scripts/tidy-downloads.log
```

有带时间的那几行，就是跑过了。

**二看 cron 自己的日志**（第 7 章的命令）：

```bash
journalctl -u cron --since "10 minutes ago"
```

正常会看到类似这样一行：

```
8月 14 15:50:01 minipc-01 CRON[23456]: (roland) CMD (/home/roland/ai/scripts/tidy-downloads.sh >> ...)
```

这行证明 cron 确实按点把命令发出去了。**它只证明发出去了，不证明脚本跑成功了**，脚本本身干得怎么样看上一步的输出文件。

**三看结果**：目标目录里有没有多出文件。

验证完，把 `crontab -e` 里的时间改回 `0 3`。

任务没跑起来的时候，按顺序查这三样：`crontab -l` 里那行在不在、脚本有没有执行权限（`ls -l ~/ai/scripts/`，看有没有 `x`）、路径是不是写全了。还查不出来，到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。

## 几个后面要用的小事

**日志会一直长。** 上面那个 `.log` 文件每天追加几行，一年下来也不大，不用管。将来某个任务输出很多，用 `tail -50 文件名` 只看最后一段。

**任务不要都堆在同一分钟。** 你有好几个定时任务时，错开几分钟，别都写 `0 3`。同一时刻一起跑会互相抢磁盘。

**机器关着的时候任务不会补跑。** cron 只在到点那一刻看机器开没开。夜里关机的话，把时间挪到你确定开着机的时段。

**systemd timer 是另一条路。** systemd 自己也能做定时，写两个配置文件，比 cron 麻烦一点，换来的是可以用 `systemctl` 和 `journalctl` 统一管理，还能设成“开机时补跑错过的任务”。第 3 卷做服务器上的定时任务时会用到它。这一章的场景 cron 就够了。

## 完成检查

- `~/ai/scripts/tidy-downloads.sh` 存在，`ls -l` 看得到 `x` 权限吗？
- 手动跑一遍，测试文件按类型进了 `~/ai/data/downloads` 下面的三个子目录吗？
- 连着跑第二次，输出是“移动了 0 个文件”吗？
- `crontab -l` 能列出你加的那一行吗？
- `0 3 * * *` 这五个字段分别是什么意思，你能一个个说出来吗？
- 把时间改到一两分钟后验证，`~/ai/scripts/tidy-downloads.log` 里出现新的一行了吗？
- `>>` 和 `2>&1` 各自是干什么的？
