# 11　视觉模型

## 这一章的任务

让模型看图说话——丢一张截图或者一张扫描件给它，问里面写了什么。

**第 6 章留了一个尾巴**：扫描件传进去，界面照样说上传成功，模型照样回答你，但它其实一个字都没读到，是照着你的问题编的。**这一章是那件事的第一条出路。**

**这一章只是打底。** 一两张图临时看一眼，本章够用；一沓单据成批处理、把结果落成一张表，那是[第 8 卷](../08-OCR/README.md)整卷的事。两者的分工在最后一节，**先做完再看那一节，会更明白为什么要分开。**

## 开始前

- 第 3 章做完，Ollama 跑着；
- 第 2 章下的那两个文件都在——**除了那个 22 GB 的权重，还有一个 0.9 GB 的 `mmproj-F16.gguf`**，这一章要用它；
- 想走 llama.cpp 那条路的话，[第 5 卷第 17 章](../05-驱动与ROCm/17-llama.cpp-Vulkan.md)做完，`~/llama` 目录在。**本章不重讲怎么装 llama.cpp**；
- 手上准备两张图：**一张屏幕截图，一张扫描件或者手机拍的纸质文件**。内容你自己完全清楚的那种；
- 40 分钟。

## 新词

**多模态**（multimodal）：一个模型同时能处理不止一种东西。**这一章说的就是同时能看文字和图片的那种。**

**视觉编码器**（vision encoder）：模型里专门看图的那一部分。它把一张图变成模型能理解的一串数，再交给管文字的那一部分去用。

**mmproj**（多模态投影文件）：**一个单独的文件**，名字通常以 `mmproj-` 开头。它做的是视觉编码器和文字模型之间的转接。

**这一条最要紧**：走 llama.cpp 或者自己下 GGUF 文件这条路，**看图要两个文件——主模型一个，`mmproj` 一个**。只下主模型的话，模型能对话，但你把图给它，它看不见。第 2 章顺手多下的那个 0.9 GB 的文件就是它。

**视觉 token**：一张图进到模型里，会被换算成若干个 token，和文字一样占上下文（第 1 章）。**图越大、越清楚，占的越多。**

## 视觉模型是什么

**不是“另外装一个看图的程序”，是模型本身就能看。**

普通模型只认文字。视觉模型多了一只眼睛：你把一张图和一句问话一起给它，它同时读这两样，然后用文字回答你。

**它能干的事**：描述一张图里有什么；把截图里的文字念出来；看懂一张图表并回答上面的数；读一张收据上的金额和日期；看一张界面截图说明哪个按钮在哪。

**它不擅长的事**（现在就该知道，省得后面失望）：

- **精确的数字**。金额、编号、日期这类东西，它会看错，而且**看错的时候语气一样肯定**；
- **密密麻麻的表格**。行列一多就串行，和第 6 章说 PDF 表格那一条是同一个毛病；
- **歪的、糊的、有折痕和印章的纸**。下面那一节专门试这个。

**一句话记住它的脾气：它不报错，它编。** 第 6 章那句话在这一章更要紧——**图它总能“看到”，问题是看没看对。**

## Ollama 里怎么用

**最省事的一条：命令行里把图片路径写进问话里。**

官方文档给的写法是这样的（Ollama CLI 文档，访问日期 2026-08-14）：

```bash
ollama run qwen3.6-35b "这张图里写了什么？ /home/你的账户名/图片/截图.png"
```

作用：加载模型，把这句话连同那张图一起送进去。

- **图片路径直接写在问话里**，用空格和前面的文字隔开；
- **路径要写完整。** `~` 在这里不一定认，账户名换成你自己的（不确定就跑一句 `whoami`）；
- 路径里有空格的话，把整个文件名改掉最省事——**中文文件名没问题，空格容易出事**。

**没反应、或者它说看不到图**，最常见的是三种：

1. **路径写错了**。先 `ls -l /你写的那个路径` 确认文件在；
2. **这个模型不带视觉能力**。`ollama pull` 拉下来的模型不是每个都能看图，下面那张清单里带视觉的才行；
3. **它当成一句普通的文字读了**。表现是它开始解释这个路径像个文件名。**换一个确认带视觉的模型试一次**，排除是模型的问题。

### 在 Open WebUI 里

更简单：**把图片直接拖进对话框**，或者点第 6 章那个加号选图片，然后打字提问。

**用的是同一件事**——界面把图传给 Ollama，Ollama 交给模型。第 6 章讲的传文件和这里传图片是同一个入口，**区别在于文件走的是解析成文字那条路，图片走的是视觉模型这条路**。

**左上角选的模型必须是带视觉的那个**，不然拖进去也白搭。

## llama.cpp 走多模态

不经 Ollama、直接用 llama.cpp 的场景有两个：**你自己下的 `.gguf` 文件想直接用**，或者**你要自己控制上下文长度这些参数**（第 13 章）。

**怎么装 llama.cpp、怎么确认它认得出 GPU、`-ngl 99` 是干什么的**，[第 5 卷第 17 章](../05-驱动与ROCm/17-llama.cpp-Vulkan.md)已经写全，**本章一个字不重抄**。这里只讲多出来的那一项。

### 多出来的就是 `--mmproj`

官方文档的写法是两个文件一起给（llama.cpp 多模态文档，访问日期 2026-08-14）：

```bash
cd ~/llama && ./llama-server \
  -m ~/ai/models/qwen3.6-35b-a3b/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf \
  --mmproj ~/ai/models/qwen3.6-35b-a3b/mmproj-F16.gguf \
  -ngl 99
```

- **`-m`** —— 主模型，第 5 卷第 17 章那个参数；
- **`--mmproj`** —— 那个投影文件。**这一项就是这一节的全部新东西**；
- **`-ngl 99`** —— 把层尽量放到 GPU 上，同第 5 卷第 17 章。

官方文档还写明**投影文件默认也会放到 GPU 上**，不想放就加 `--no-mmproj-offload`。

跑起来之后它会一直在前台跑着，屏幕上打印一段地址。**浏览器打开它自带的界面**：

```text
http://127.0.0.1:8080
```

聊天框里直接把图片拖进去，然后提问。**按 `Ctrl+C` 停掉整个服务。**

> **8080 这个端口被占了的话**，加一个 `--port 8081` 换一个。看端口占没占用 `ss -tln | grep :8080`（第 4 章讲过）。**Open WebUI 那个 3080 不冲突**，它映射的是宿主机的 3080。

文档里还有一个只看一次图就退出的命令行程序，名字形如 `llama-mtmd-cli`，用法和上面一样带 `-m` 和 `--mmproj`。**你解压出来的那个包里有没有它，随版本变化，需要核验**——`ls ~/llama` 看一眼就知道（第 5 卷第 17 章那一步）。

### 两条路的分工

| | Ollama（`ollama pull`） | llama.cpp（自己的两个文件） |
| --- | --- | --- |
| 要不要自己管 `mmproj` | **不用**，库里那些带视觉的模型自己带着 | **要**，两个文件都得下、都得写进命令 |
| 上下文长度 | 它自己定（第 10 章那一节） | `-c` 自己指定 |
| 家里人能不能用 | 能，走第 4 章那个界面 | 只有自己用，或者自己再配 |

**日常看图走 Ollama，要调参数走 llama.cpp。** 和第 3 章那张表是同一个思路。

> **把自己下的“主模型加 mmproj”这一对导进 Ollama** 该怎么写 Modelfile，**本项目未核实，需要核验**，以 Ollama 的导入文档为准。**在核实之前，本章的建议是不要绕**：走 Ollama 就直接 `ollama pull` 库里带视觉的那个，要用自己下的两个文件就走 llama.cpp 那条路。

## 拿两张图各试一次

**这一节动手做，二十分钟，做完你对这件事的判断就建立起来了。**

### 第一张：屏幕截图

随便截一张有文字的界面，比如一份表格、一个设置页面。

```bash
ollama run qwen3.6-35b "这张图里的文字，一行一行念出来，不要解释。 /home/你的账户名/图片/截图.png"
```

**再问一个具体的**：图里某个位置写的是什么、某个数是多少。

**通常结果不错。** 截图是屏幕直接渲染出来的字，边缘清楚、没有阴影、不歪、分辨率高——**对模型来说这是最好读的一类图。**

### 第二张：扫描件

拿一张纸质文件，扫描或者手机拍一张，同样两个问题问一遍。

**对着原件逐字核一遍它念出来的东西。** 重点看这几处：

- **数字**。金额、日期、编号——**最容易错的就是这些**，而且错了它不会告诉你；
- **相似的字**。手写体和小字号里，字形接近的容易认混；
- **有没有漏行**。折痕、装订孔、印章压住的地方最容易整行丢掉；
- **顺序**。多栏排版的纸，它可能把两栏串着念。

### 差别在哪

**两张图效果不一样，原因不在模型，在图本身。**

| | 屏幕截图 | 扫描件 |
| --- | --- | --- |
| 字是怎么来的 | 屏幕渲染出来的，边缘干净 | 印在纸上再拍下来，有噪点和阴影 |
| 正不正 | 天然是正的 | 常常歪一点，还可能有透视变形 |
| 有没有干扰 | 基本没有 | 折痕、污渍、印章、纸纹、订书钉 |
| 清楚不清楚 | 分辨率高，字号可控 | 看拍摄条件，小字容易糊 |
| 结果 | 通常念得准 | **看运气，而且看不出来准不准** |

**改善扫描件效果最有效的办法不是换模型，是把图拍好**：光线均匀、正对着拍、别用闪光灯、别隔着塑料膜、分辨率给足。**这一条比换一个更大的模型管用得多。**

> **本章不给任何准确率数字。** 效果取决于你的图、你的模型、你的问题，**没有一个通用的数**。要给客户承诺，只能拿你自己那批真实材料测出来的结果，带日期、带模型名和量化档（[第 13 卷](../13-项目交付/README.md)）。

### 关键数字必须回原件核

**这条不是建议，是纪律。**

第 6 章说过一遍：表格串行、金额抄错这类问题不报错，只能靠人看。**在图上这条更严重**——文字文件至少解析失败会明显不对劲，图它总能“看到点什么”，于是总能给你一个像模像样的答案。

**拿去给客户、给老板、录进系统之前，回原件对一次。**

## 这一章只是打底

**做完上面那些，你能干的事是：一次拿一两张图，手动丢进去，人看结果。**

**你很快会想干的是另一件事**：一个月两百张收据，自动读出金额、日期、抬头，落成一张表，错的能查出来。**那不是这一章的活。**

| | 本章：看一眼 | [第 8 卷](../08-OCR/README.md)：成批处理 |
| --- | --- | --- |
| 一次几张 | 一两张 | 几百上千张 |
| 怎么送进去 | 手动拖进对话框，或者命令行带路径 | 程序调第 8 章那个接口，批量跑 |
| 出来的是什么 | 一段话，人看 | **结构化的字段**，直接进表格或数据库 |
| 怎么保证对 | 人当场核 | 校验规则加人工抽检，**要有一套办法** |
| 歪的糊的怎么办 | 重拍一张 | **先做图像处理**，摆正、去噪、切边 |
| 要不要出处 | 不要求 | 要求能追回是哪一份、哪一页 |
| 建起来要多久 | 十分钟 | 一卷的篇幅 |

**分工一句话：临时看一张图用这一章，成批的单据处理去[第 8 卷](../08-OCR/README.md)。**

**这一章是那一卷的地基**——那一卷里模型这一层用的就是本章装好的东西，加的是前面的图像处理和后面的校验落表。**本章不重复那些，也不下那一卷的结论。**

> 第 6 章给扫描件留了两条路：**一是用能看图的模型（就是本章），二是先把图转成文字再走文档那条路（那是[第 8 卷](../08-OCR/README.md)的 OCR）。** 现在两条路你都知道在哪了。**一两页临时看看走第一条，成批的走第二条。**
