# 09　案例三：邮件草稿

## 这一章的任务

**案例三从这一章开始。**

做出来的东西是这样的——**有人给你写信，机器读一遍，按你给的口径拟一份回信，存下来等你看。**

**它不发出去。一封都不发。**

这条流程里没有任何一个往外发信的节点，[第 6 章](06-案例一-每日推送.md)那个 Send Email 在这一章一次都不出现。**你做完这一章，手上是一个装着草稿的文件夹，仅此而已。**

草稿怎么变成真的发出去，[第 10 章](10-案例三-人工确认.md)整章讲。**那一章才是案例三值钱的地方**，这一章是给它备料。

案例三一共两章。

## 开始前

- [第 8 章](08-案例二-结果台账.md)做完，案例二那条流程在跑，台账在长。**这一章要复用的每一个节点你都配过至少一次**；
- [第 5 章](05-案例一-模型摘要.md)那段提示词的六条规矩、`JSON.stringify(...)` 那个坑、`$('节点名').item.json.字段` 那个写法，**这一章全都原样再用一遍，不重讲**；
- [第 6 章](06-案例一-每日推送.md)那节应用专用密码读过，**而且你手上真的有一串**。那一章生成的是给发信用的，这一章要的是给收信用的，**多数服务商是同一串，但这一条需要核验**，以你那家的说明为准；
- **手边要有一个专门拿来试的邮箱**。别用你天天在收信的那个主邮箱——这一章要反复往里发测试信、反复标已读，**在一个安静的邮箱上做，你不会心疼**；
- [第 7 章](07-案例二-进件分类.md)那次容器重建之后，Execute Command 这个节点是放出来的。**这一章不用它，[第 11 章](11-日志与重试.md)要用**；
- 90 分钟。

## 新词

**IMAP**（互联网邮件访问协议，Internet Message Access Protocol）：**程序从邮箱里把信读出来走的那条路。** [第 6 章](06-案例一-每日推送.md)那个 SMTP 管往外发，IMAP 管往里读，**方向正好相反，各要一套服务器地址和端口**。你手机上的邮件 App 能看到服务器上的信，底下走的就是它。

**草稿**：**一封写好了但没发出去的信。** 这一章的全部产物。

**口径**：**你允许机器替你说的那些话的范围。** 报价说不说、时间承不承诺、赔偿谈不谈，都在这个范围里定。**这一章的提示词里有一整段专门写它。**

**回环**：**机器发出去的信又被自己收进来，再触发一次，再发一封，没完没了。** 这一章筛邮件那一节专门防它，**[第 10 章](10-案例三-人工确认.md)那条半自动的路上它更危险。**

**邮件 ID**：**每封邮件自带的一个不重样的标识**，发信的那一头生成，跟着这封信走。[第 11 章](11-日志与重试.md)拿它做去重。

## 这个案例做成什么

一句话——**来信进，草稿出，人来点头。**

```text
邮箱（未读的新信）
    ↓  Email Trigger (IMAP)
筛一道：这封要不要回
    ↓  要
按口径拟稿
    ↓
~/ai/data/daily/drafts/2026-08-15-153042-合作咨询.md
    ↓
人看（第 10 章）
```

草稿文件打开是这样（**下面全是虚构内容**）：

```text
# 待发草稿 2026-08-15 15:30

来信人：李明 <liming@example.net>
主题：合作咨询
收信时间：Fri, 15 Aug 2026 15:22:11 +0800
邮件ID：<a1b2c3@example.net>

## 来信原文

你好，我们是一家做仓储的公司，想了解一下你们这套东西能不能处理我们的入库单。
另外想问下大概多少钱，什么时候能上。

## 草稿（没发出去）

李先生：

您好。入库单这类单据我们处理过，需要先看一份您那边的样张才能判断。

报价要看具体的量和字段，【待确认：是否要在这封信里给一个区间】。

麻烦您回信附上一份样张，和每天大概多少份。

——某某
```

**注意草稿里那个 `【待确认：……】`。** 那不是模型出错，**那是它按规矩举手**——这件事下面提示词那一节是正题。

## 为什么这个案例的做法和前两个不一样

**前两个案例，机器做完就完了。**

案例一自己抓、自己摘、自己把日报发到你邮箱。案例二自己判、自己搬、自己记一行台账。**中间没有人。**

**案例三中间必须有人，而且这件事不是可选项。**

理由只有一条，但它足够硬——**前两个案例做错了能改回来，这一个做错了改不回来。**

- 日报摘歪了一条，你多点一次原文，**成本是十秒**；
- 文件分错了目录，从待定里挪出来，**成本是三十秒**（[第 7 章](07-案例二-进件分类.md)那一节）；
- **一封替你承诺了交期和价钱的信发到客户手里，你收不回来。** 对方已经看见了，对方已经存下来了，对方已经按它安排事情了。

**所以这一章的设计不是“先做出来再加个确认”，是从第一个节点开始就没打算让它发。**

## 第一步：先建草稿目录

```bash
mkdir -p ~/ai/data/daily/drafts
```

看一眼属主，对不上就改（[第 2 章](02-n8n装起来.md)那一条）：

```bash
ls -ld ~/ai/data/daily/drafts
sudo chown -R 1000:1000 ~/ai/data/daily/drafts
```

**这一章不重建容器。** `-v "$HOME/ai/data/daily:/data"` 这一行[第 2 章](02-n8n装起来.md)就挂着了，**草稿放在它下面的一个子目录里，容器里的路径就是 `/data/drafts/`，什么都不用改。**

> **名字上有点将就**，那个目录当初是给日报建的（[第 2 章](02-n8n装起来.md)）。**想给案例三一个专用目录**，比如 `~/ai/projects/mailbot`，那就得像[第 7 章](07-案例二-进件分类.md)那样多挂一个卷、把容器停掉删掉重建一次。**省一次重建还是要一个干净名字，你自己权衡**，做法两边都写过了。

## 第二步：收邮件

新建一条工作流，起名叫“邮件草稿-案例三”。

### 一、Email Trigger (IMAP)

点加号，搜 `email`，选 **Email Trigger (IMAP)**。**这是一个触发器节点**，它当这条流程的第一个节点，位置相当于案例一那个 Schedule Trigger。

它要一个 IMAP 凭据。点新建凭据，要填的一般是这几样：

- **服务器地址**（Host）——形如 `imap.你的服务商.com`，**注意开头是 imap 不是 smtp**；
- **端口**（Port）——常见的是 993；
- **账号**（User）——多数就是你的邮箱地址；
- **密码**（Password）——[第 6 章](06-案例一-每日推送.md)那串应用专用密码；
- **加密方式**——SSL／TLS 的开关，和端口是配套的。

**这几项各家填法都不一样，官方文档也没有列死，需要核验**——去你邮箱服务商自己的帮助页面找“IMAP 设置”那一页，照它写的填。**填完凭据页面上一般有测试按钮，测通了再往下走。**

> **[第 6 章](06-案例一-每日推送.md)那两条理由在这里一字不改地成立**：用应用专用密码，不要用登录邮箱那个密码。多数服务商本来就不让第三方程序用登录密码；而且这串密码要存在这台机器上，**存的是应用专用密码，泄露了去作废那一串就完事，账号本身不受影响。**

### 二、参数怎么填

官方文档列出的参数是这几项：

- **Mailbox Name**——从哪个邮箱文件夹里取信。**默认那个收件箱就行**，具体默认值是什么字样以你面板上的为准；
- **Action**——两个选项，**None 是取完仍然保持未读，Mark as Read 是取完标成已读**；
- **Download Attachments**——要不要连附件一起下下来。**这一章关着**，理由下面说；
- **Format**——输出格式，官方给的三项是 **RAW**（整封信，正文是一串编码过的字符）、**Resolved**（整封信，数据解开了，附件放进二进制那一块）、**Simple**（整封信，官方提示要用到内嵌附件的话别选它）。

**本章的填法和理由：**

**Action 选 Mark as Read。**

**这一项是这一节唯一需要想一下的。** 选 Mark as Read 的意思是——**这封信被这条流程取走的时候，顺手在邮箱那头标成已读了。** 好处是同一封信不会被拟稿两遍：下一轮它已经不是未读的了，取不到它。

**这是拿邮箱当那份“跑过的记录”**，和[第 8 章](08-案例二-结果台账.md)拿台账当记录是同一个路子。

**代价也很实在**：你自己去邮箱看的时候，**那封信已经是已读的了**，你会漏看。所以这一章后面把来信原文整段写进草稿文件里——**以草稿文件夹为准，不以邮箱里的未读标记为准。**

**另一条路是 Action 选 None**，信保持未读，你自己照常看。**代价是去重要你自己做**——[第 11 章](11-日志与重试.md)那一节讲怎么用邮件 ID 去重，做完之后这条路是通的。

> **这个触发器默认取的是不是只有未读的信、取过一次之后同一封会不会再取一次，官方这一页没有写死，需要核验。** 表现很好认：**同一封信在执行记录里出现了两次以上**，就是没去重。撞上了就走上面那条邮件 ID 的路。

**Download Attachments 关着。**

这一章的流程只读正文，**附件一个字都用不上**。官方文档专门提了一句——**打开它会增加处理负担**。要处理附件的话，那是[第 8 卷](../08-OCR/README.md)那条线的活，跟这一章不是一件事。

**Format 选 Simple 或者 Resolved 都能用**，这一章只要正文和几个头部字段。**这两项的实际输出差别本项目未核实，需要核验**——两个都试一次，看下面那个节点取不取得到东西。

**选项里还有两项**，官方列的是 **Custom Email Rules**（自己写取信的条件，文档指向的是 node-imap 那套搜索条件的写法）和 **Force Reconnect Every Minutes**（隔多少分钟强制重连一次）。**这一章两项都不填**，筛信的活下一节用一个 Code 节点做，理由那一节说。

### 三、在编辑器里怎么试这个触发器

**它和前面那些触发器不一样。** Schedule Trigger 你点一下执行它就跑；**这个要等一封真的信进来。**

界面上一般有一个让它去取一次测试数据的动作（措辞可能是 Fetch Test Event 或者类似的字样，**位置和措辞需要核验**）。做法是：

1. 点那个动作，让它开始等；
2. 换个地方给这个邮箱发一封信，主题随便写，正文写两句像客户来信的话；
3. 回来看节点的输出面板。

**输出面板上出现一条数据，就是通了。**

**这一步有一件事必须做**：**把输出面板上那些字段名一个一个抄下来。** 发件人在哪个字段、主题在哪个字段、正文在哪个字段、邮件 ID 在哪个字段。

**这几个名字官方这一页没有列出来，需要核验**，各家邮箱、各个版本还可能有出入。**下一步那段代码要照你抄下来的名字改。** [第 4 章](04-案例一-抓网页.md)抄 RSS 字段名那一步是同一件事，**这是本卷第二次让你抄字段名，也是最容易被跳过的一步。**

## 第三步：筛掉不该碰的信

**这一节是这一章最要紧的一节，比提示词还要紧。**

### 为什么必须筛

**不筛的表现是：邮箱里进来的每一封信，机器都拟一份稿。** 广告、系统通知、验证码、退订确认、你自己订阅的周报，**统统被读一遍、被问一次模型、在草稿文件夹里堆一份。**

四条理由，**从轻到重**：

**一、绝大多数邮件根本不需要回。** 一个正常邮箱里真正需要你回信的，占比很低。**每封都问一次模型，是拿机器时间换一堆你要一份份删掉的文件。**

**二、有几类信不该让机器碰。** 投诉、索赔、提到律师和法律的、催款的、谈合同条款的。**这几类[第 10 章](10-案例三-人工确认.md)会列成一张清单，写进交付文档。这一节是那张清单的第一道闸**——连草稿都不给它拟，人根本不会在草稿文件夹里看到它，也就不会顺手发出去。

**三、防回环。** **这一条是硬的。**

[第 10 章](10-案例三-人工确认.md)那条半自动的路，会往你自己邮箱里发一封带草稿的确认信。**如果这条流程收的是同一个邮箱，那封确认信会被它当成新来信，再拟一份稿，再发一封确认信……** 停不下来，而且每一轮都在调模型、都在发信。

**这种事发生的时候你多半在睡觉**，第二天早上邮箱里是几百封。

**四、交付的时候你要说得清它动了哪些信。** 客户问“这东西会碰我哪些邮件”，你的答案得是一句话能说完的——**“只有发件人在这张清单里、主题里不带这几个词的信，才会被拟稿。”** 答不上这句话，这条流程就不该装到别人的邮箱上。

### 三、Code 节点，改名叫“挑要回的”

从触发器拖一条线出去，加一个 **Code** 节点。

- **Mode** 选“每条各跑一次”那一项；
- **语言**选 JavaScript；
- 代码照抄：

```javascript
// 挑要回的 —— 判断这封信要不要拟稿，理由一起带出去
// 模式：每条各跑一次

// 一、下面四行是你要按自己情况改的 ——————————————

// 只回这几个人的信。写域名片段也行，写整个地址也行。整个列表留空表示不限
const 允许的发件人 = ['@example.com', 'liming@example.net'];

// 这台机器自己那个邮箱。防回环全靠它，不能留空
const 自己的地址 = 'mini-pc@example.com';

// 主题里出现这些词，一律不拟稿
const 主题不碰 = ['投诉', '索赔', '赔偿', '律师', '法律', '仲裁', '催款', '欠款', '退款', '发票', '验证码', '退订'];

// 发件人地址里出现这些词，一律不拟稿。这些是自动发信的地址
const 发件人不碰 = ['noreply', 'no-reply', 'donotreply', 'mailer-daemon', 'postmaster'];

// 二、把这封信的几样东西取出来 ——————————————
// 字段名一律以 Email Trigger 那个节点的输出面板为准，下面这些名字要照你抄下来的改

const 原始 = $json;
const 发件人原样 = String(原始.from || '');
const 发件人 = 发件人原样.toLowerCase();
const 主题 = String(原始.subject || '');
const 正文 = String(原始.text || 原始.textPlain || 原始.textHtml || '');
const 邮件ID = String(原始.messageId || '');
const 收信时间 = String(原始.date || '');

// 三、一条一条筛。先撞上哪条就算哪条，不再往下看 ——————————————

let 要拟稿 = true;
let 原因 = '';

if (自己的地址 && 发件人.includes(自己的地址.toLowerCase())) {
  要拟稿 = false;
  原因 = '这封信是这台机器自己发的，不处理，防回环';
} else if (发件人不碰.some((词) => 发件人.includes(词))) {
  要拟稿 = false;
  原因 = '发件人是一个自动发信的地址';
} else if (主题不碰.some((词) => 主题.includes(词))) {
  要拟稿 = false;
  原因 = '主题里有不该让机器碰的词';
} else if (允许的发件人.length > 0 &&
           !允许的发件人.some((片段) => 发件人.includes(片段.toLowerCase()))) {
  要拟稿 = false;
  原因 = '发件人不在允许的清单里';
} else if (正文.trim().length < 10) {
  要拟稿 = false;
  原因 = '正文太短，看不出对方要什么';
}

return {
  json: {
    要拟稿: 要拟稿,
    原因: 原因,
    发件人: 发件人原样,
    主题: 主题,
    正文: 正文,
    邮件ID: 邮件ID,
    收信时间: 收信时间,
  },
};
```

**四处要说明。**

**一、五条筛的顺序不是随便排的。**

**防回环那条排第一**，因为它最致命，而且它必须在任何别的判断之前生效——**万一你的邮箱地址正好在允许清单里（很可能，你自己给自己发过测试信），排后面就漏了。**

**主题黑名单排在允许清单前面**，意思是：**就算是名单里的熟客，来信说“我要投诉”，照样不碰。** 反过来排的话，熟客的投诉信会被拟稿。

**二、`.some((词) => 字符串.includes(词))` 这个写法**，意思是“这个列表里只要有一个词出现在这段文字里，就算命中”。**加词就往那个列表里加，不用改别的地方**，这跟[第 8 卷第 7 章](../08-OCR/07-错的怎么拦.md)那个“加一条规则只加一个函数”是同一个路子。

**三、`允许的发件人` 留空表示不限，这是给试的时候用的。** 你自己试的时候八成还没有清单，**留空能让流程跑通**。**但交付出去之前必须填上**，理由是上面第四条——你要说得清它动哪些信。

**四、`String(原始.text || 原始.textPlain || 原始.textHtml || '')` 那个 `||`，是[第 5 章](05-案例一-模型摘要.md)那一招。** 各家邮件的正文落在哪个字段有出入，**几个名字都试一遍，都没有就是空字符串，不至于整条炸掉。** **这几个名字换成你自己抄下来的那个。**

执行一次（或者让它取一封测试信），点开输出。**`要拟稿` 那一格是 `true` 还是 `false`，`原因` 那一格写了什么，一眼看得见。**

> **调这一节的办法**：给这个测试邮箱发五封信——一封正常的咨询、一封主题带“投诉”、一封从 `noreply` 之类的地址来的、一封只写两个字的、一封你自己发给自己的。**五封的判断都对了，这一道闸就成了。**

### 四、If 节点，改名叫“要拟稿吗”

搜 `if`，加进来。**这个节点只有两个出口**，[第 7 章](07-案例二-进件分类.md)那个 Switch 是三个出口以上才用，**两个出口的场合用它。**

条件那一格用表达式，填：

```text
{{ $json.要拟稿 }}
```

**判断类型选布尔那一档，条件选“为真”**（措辞随版本变化，**需要核验**，认意思——就是那个判断真假的选项）。

**真那一路接下面的拟稿流程。**

**假那一路什么都不用接。** 那封信到这儿就停了，**执行记录里点开“挑要回的”这个节点，`原因` 那一格写着为什么停的**，够查了。

> **想给不拟稿的也留一行记录**，做法和[第 8 章](08-案例二-结果台账.md)那张台账一模一样——Code 拼一行、Convert to File、Read/Write Files 追加写进一个 `跳过记录.csv`。**转义那两条规矩照搬，不重讲。** 这一章不做，是因为草稿文件夹本身已经是记录，**跳过的那些多数是广告，留着也不看。**

## 第四步：提示词

### 五、Edit Fields，改名叫“整理素材”

从 If 那个真出口拖出去，加一个 **Edit Fields (Set)**，加两个字段。**这一步[第 5 章](05-案例一-模型摘要.md)和[第 7 章](07-案例二-进件分类.md)各做过一次，参数不重讲。**

**第一个字段，`系统提示`，字符串，固定值**——把下一节那段整段贴进去。

**第二个字段，`用户内容`，字符串，表达式**：

```text
来信人：{{ $json.发件人 }}
主题：{{ $json.主题 }}

正文：
{{ ($json.正文 || "").slice(0, 3000) }}
```

**这一段的写法[第 5 章](05-案例一-模型摘要.md)全讲过**，一处也没新增。**填完看输入框下面那块预览**，预览里那段文字就是模型要收到的东西。

### 那段提示词

**下面这段整段抄进 `系统提示` 那一格，然后按你自己的情况改中间那一块。**

```text
你是一个替人拟回信草稿的助手。你写出来的东西不会直接发出去，会有人看过之后再决定发不发。

先记住三件事：
1. 只根据来信内容和下面这份口径写。两边都没有的信息，一个字都不要补；
2. 时间、金额、数量、任何承诺，只能照口径里已经写好的说法抄。口径里没有的，不要自己给一个；
3. 你拿不准的地方，原样留一个标记【待确认：这里要填什么】，写清楚要确认什么。不要绕过去，也不要写一个看着合理的值填上。

口径（只能用这里面的说法，这一段是你要改的）：
- 我们做的是（写你的行业和主要业务）；
- 工作日一般当天回复。具体几点、几天内完成，一律不承诺；
- 报价要看具体需求，邮件里不给任何数字；
- 需要对方提供的资料是（写清单，一条一行）；
- 折扣、退款、赔偿、合同条款，一概不谈。

语气：
- 中文，客气，平铺直叙；
- 不用感叹号，不用“非常感谢您的来信”这类套话；
- 开头直接称呼对方，称呼从来信人那里取；
- 全文不超过 200 字。

格式：
- 只输出邮件正文本身，从称呼开始，到落款为止；
- 不要写主题行，不要写“以下是草稿”这类开场白，不要用 Markdown 标记；
- 落款写成：（写你的落款）。

遇到下面任何一种情况，正文只写一行【这封信不适合自动拟稿】，别的什么都不要写：
- 来信在投诉、在要赔偿、在提律师或者法律；
- 来信在催款，或者在谈合同条款的修改；
- 来信内容看不懂，或者根本不是发给我们的。
```

**四块，一块一块说它防的是什么。**

**开头那三条，第 3 条是这一章的正题。**

第 1 条防瞎编，[第 5 章](05-案例一-模型摘要.md)和[第 7 章](07-案例二-进件分类.md)都写过，**在这里最要紧**——摘要瞎编你自己看得见，分类判错文件还在，**拟稿瞎编的那句话是要发给客户的。**

第 2 条管住数字和承诺。**模型面对“大概多少钱”“什么时候能上”这种问题，默认行为是给一个听着合理的答案**——“三到五个工作日”“一般在两万元左右”。**这两句话它张口就来，而你要为它们负责。**

**第 3 条那个 `【待确认：……】` 标记，是这一章的设计核心。**

它把模型的一个坏毛病改造成了一个有用的信号。**模型不喜欢留白**，你不给它别的选择，它就会把空的地方填满。**给了这个标记，它就有地方安放“我不知道”。**

**这跟[第 7 章](07-案例二-进件分类.md)那个“待定”是同一件事的两种写法**——那里是整份文件进一个目录，这里是一句话留一个标记。**都是在给不确定一个正常出口。**

**你打开草稿看见这个标记，说明这封信要你亲自想一下再回。看不见，说明模型觉得这封信照口径就能答完。**

**口径那一块是你要改的，也是这段提示词里唯一有你自己业务的地方。**

**写它的时候只写“能说什么”，不要写“不能说什么”的长清单。** 正面的口径是封闭的，模型只能在里面挑；反面的清单是开不完的，你永远漏得掉一条。

**语气那一块看着琐碎，实际决定草稿能不能直接用。**

不写“不用感叹号”，它会给你写出三个感叹号；不写“不用套话”，每封信开头都是一段感谢。**这些东西你改起来比自己写还费劲**——因为要一句句删。

**最后那一块是这段提示词的保险丝。**

上一节那道筛已经拦掉了主题里带这些词的信。**但主题写得不明显的呢**——主题写“关于上次的事”，正文里在索赔。**筛拦不住，这一条能。**

**两层都在，才算这一类信真的不会被拟稿。** 提示词管的是它答什么，前面那个 Code 节点管的是你放什么进来，**两件事，都要做**（[第 7 章](07-案例二-进件分类.md)那句话，原样成立）。

> **改提示词一次只改一条，改完执行一次看效果。** [第 3 章](03-第一个工作流.md)定的规矩，[第 5 章](05-案例一-模型摘要.md)、[第 7 章](07-案例二-进件分类.md)各重复过一次，**这是本卷第四次说它。** 拟稿这件事尤其吃这条——**一口气改三条，你分不清是哪一条把语气改硬了。**

### 六、HTTP Request，改名叫“问模型”

**参数和[第 5 章](05-案例一-模型摘要.md)、[第 7 章](07-案例二-进件分类.md)那两次一模一样**，只有请求体最后一行不同：

- **Method** 选 **POST**；
- **URL** 填 `http://host.docker.internal:11434/v1/chat/completions`；
- **Send Body** 打开，**Body Content Type** 选 **JSON**，**Specify Body** 选用 JSON 写；
- **选项里的超时调大**。

请求体：

```json
{
  "model": "qwen3.6-35b",
  "messages": [
    {"role": "system", "content": {{ JSON.stringify($json.系统提示) }}},
    {"role": "user", "content": {{ JSON.stringify($json.用户内容) }}}
  ],
  "stream": false,
  "temperature": 0.3
}
```

**`model` 那一行换成你自己 `ollama list` 里的名字。** [第 6 卷第 7 章](../06-本地模型/07-多模型切换.md)那张常备表里，**日常对话那一档就够**——拟一封两百字的中文回信不难，**难的是它守不守规矩。**

**`JSON.stringify(...)` 不能省**，[第 5 章](05-案例一-模型摘要.md)讲透了。**邮件正文里一定有换行和引号**，不转义这段 JSON 会被从中间截断。

**`temperature` 这次填 `0.3`，是本卷三次里最高的一次。** [第 5 章](05-案例一-模型摘要.md)做摘要填 `0.2`，[第 7 章](07-案例二-进件分类.md)做分类填 `0`。**理由是这三件事要的东西不一样**——分类要的是同一份文件每次给同一个答案，摘要要的是稳，**写信要读着像人话，压得太死会写成一份填空模板。**

**`0.3` 是本教材挑的起点，不是实测出来的最优值，需要核验。** 觉得它开始自由发挥、开始编东西，就往下调；觉得每封信读着都像同一封，往上调一点。

执行一次，点开输出，翻到 `choices[0].message.content`。**应该是一段干干净净的中文正文，从称呼开始。**

**多出开场白、多出 Markdown 标记、多出主题行**——回上一节改提示词，**别在下一个节点里拿代码去删。**

## 第五步：草稿存到哪

**两条路，先讲取舍，再讲做法。**

### 两条路的对照

| | 存成文件（本案例走这条） | 存进邮箱草稿箱 |
| --- | --- | --- |
| 要不要额外凭据 | **不要**，现在这条流程就能写 | **要**，下面说 |
| 在哪儿改稿 | 文本编辑器 | 邮件客户端里 |
| 发出去要几步 | 复制粘贴进一封新邮件 | **点一下发送** |
| 看得到来信原文吗 | **能**，草稿文件里就带着 | 要回头去找那封来信 |
| 手滑直接发出去的风险 | 低 | **高，草稿箱里点一下就出去了** |
| 留不留痕 | **留**，文件在那儿，改没改、什么时候发的都能查 | 发完草稿就没了 |
| 适合什么场合 | 交付给客户、要留证据 | 自己用、量小、你就是那个要回信的人 |

**本案例走存文件这条，三条理由：**

**一、不需要任何额外凭据。** 这条流程到这儿为止只用了一个 IMAP 凭据。

**二、来信和草稿在同一个文件里。** 你看草稿的时候不用回邮箱找原信对着看，**这一条在量大的时候差别很大。**

**三、[第 10 章](10-案例三-人工确认.md)那三种确认做法，全都是从文件出发的。**

**最后那一行才是真正的理由。** 草稿箱里那份，离“发出去”只有一次点击——**而这一章整章都在把那次点击变难，不是变容易。**

### 路线一：存成文件

#### 七、Code 节点，改名叫“拼草稿”

**Mode 选“每条各跑一次”那一项。** 代码照抄：

```javascript
// 拼草稿 —— 把来信和模型写的稿子拼成一份能直接看的文件，顺便算出文件名
// 模式：每条各跑一次

const 来信 = $('挑要回的').item.json;
const 草稿 = (($json.choices && $json.choices[0].message.content) || '').trim();

// 一、算日期和时刻，写法和第 6 章、第 7 章一样，用的是本地时间
const 两位 = (n) => String(n).padStart(2, '0');
const d = new Date();
const 日期 = `${d.getFullYear()}-${两位(d.getMonth() + 1)}-${两位(d.getDate())}`;
const 时刻 = `${两位(d.getHours())}${两位(d.getMinutes())}${两位(d.getSeconds())}`;

// 二、主题要进文件名，先把不能进文件名的字符换掉
const 干净 = (s) =>
  String(s || '')
    .replace(/[\/\\\r\n\t:*?"<>|]/g, '_')
    .trim()
    .slice(0, 40);

const 主题片段 = 干净(来信.主题) || '无主题';
const 文件名 = `${日期}-${时刻}-${主题片段}.md`;

// 三、要不要人特别留意：模型举了手，或者它判定这封不该自动拟稿
const 要人看 = 草稿.includes('【待确认') || 草稿.includes('不适合自动拟稿');

// 四、文件正文：来信在上，草稿在下
const 正文 = [
  `# 待发草稿 ${日期} ${两位(d.getHours())}:${两位(d.getMinutes())}`,
  ``,
  `来信人：${来信.发件人}`,
  `主题：${来信.主题}`,
  `收信时间：${来信.收信时间}`,
  `邮件ID：${来信.邮件ID}`,
  `要人特别留意：${要人看 ? '是' : '否'}`,
  ``,
  `## 来信原文`,
  ``,
  String(来信.正文 || '').slice(0, 3000),
  ``,
  `## 草稿（没有发出去）`,
  ``,
  草稿,
  ``,
].join('\n');

return {
  json: {
    文件名: 文件名,
    路径: `/data/drafts/${文件名}`,
    正文: 正文,
    要人看: 要人看,
  },
};
```

**四处要说明。**

**一、文件名里那三段和[第 7 章](07-案例二-进件分类.md)那四段是同一个路子**——日期排序、时分秒防重名、主题片段让你一眼看出是哪封。**时分秒那一段不能省**，同一分钟内进来两封同主题的信，没有它后一份会盖掉前一份。

**二、`干净(...)` 那一行比[第 7 章](07-案例二-进件分类.md)那次多换了几个字符。** 多出来的 `*?"<>|` 和冒号，是因为**邮件主题是外人写的，什么字符都可能有**，而这些字符在某些系统上不能进文件名。[第 7 章](07-案例二-进件分类.md)那句话在这里更成立——**你自己试的时候主题都很规矩，交付出去之后什么样都有。**

**三、`邮件ID` 那一行写进文件里，是给[第 11 章](11-日志与重试.md)留的。** 那一章要拿它做去重——**同一封信的草稿已经在了就不再拟一份。** 现在写进去，那一章直接用。

**四、`要人特别留意` 那一格，是把提示词第 3 条那个标记提到了文件头上。** 你不用把整份草稿读完才知道这封要不要多想一下，**看头几行就够。** [第 10 章](10-案例三-人工确认.md)那三种做法里，有两种直接用这一格。

#### 八、Convert to File

拖出去，加 **Convert to File**（[第 6 章](06-案例一-每日推送.md)、[第 8 章](08-案例二-结果台账.md)各用过一次）：

- **Operation** 选 **Convert to Text File**；
- **Text Input Field** 填 `正文`；
- 字符编码保持默认，**默认是 UTF-8。**

#### 九、Read/Write Files from Disk

再拖出去：

- **Operation** 选 **Write File to Disk**；
- **File Path and Name** 切到表达式那一边，填：

```text
{{ $('拼草稿').item.json.路径 }}
```

- **Input Binary Field** 填上一步那个字段名（默认常是 `data`，**以面板上显示的为准**）；
- **Append 那一项不要打开。** 这里是一封信一个文件，**不是往一个文件末尾接**（[第 8 章](08-案例二-结果台账.md)那张台账才要打开它）。

**路径这里为什么回头去“拼草稿”取，不直接写 `$json.路径`。**

[第 6 章](06-案例一-每日推送.md)那次是直接写的 `$json.日期`。**中间那个转文件的节点会不会把 `$json` 原样带过来，本项目未核实，需要核验**——**两种写法都填一次，看输入框下面那块预览出不出得来。** 出得来就用那种。**回头去取的这种写法更稳**，因为它不依赖中间那个节点做了什么（[第 5 章](05-案例一-模型摘要.md)那个 `$('节点名').item` 的用处）。

#### 跑一次，去硬盘上看

给测试邮箱发一封像客户咨询的信，等它取到，执行一次。回终端：

```bash
ls -lh ~/ai/data/daily/drafts/
```

**多出一个 `.md` 文件就成了。** 打开看：

```bash
cat ~/ai/data/daily/drafts/2026-08-15-153042-合作咨询.md
```

**从头读一遍。** 来信原文在不在、草稿读不读得下去、有没有承诺不该承诺的东西、`【待确认】` 那个标记出现在该出现的地方没有。

**读着不对，回提示词那一节改，一次改一条。**

**写不进去**——节点报权限相关的错，是[第 2 章](02-n8n装起来.md)那件事：

```bash
sudo chown -R 1000:1000 ~/ai/data/daily/drafts
```

### 路线二：存进邮箱草稿箱

**这条路本章只给做法和边界，不给逐步截图。**

**用 Gmail 的话有现成节点。** n8n 的 Gmail 节点有一个草稿资源，官方文档列的操作是新建草稿、删除草稿、取一份草稿、取多份草稿。**新建草稿那个操作，做的就是这条路要的事**——把拟好的正文塞进邮箱的草稿箱，**你在手机上、在网页上打开草稿箱就能看到它，改完点发送。**

**代价是它要一套 Google 凭据**，配起来比[第 6 章](06-案例一-每日推送.md)那个 SMTP 麻烦不少，**本教材不写它的配置步骤**，官方文档有专门一页讲怎么设。

**不是 Gmail 的邮箱**，本项目没有找到 n8n 里现成的“往 IMAP 草稿箱里塞一封”的节点，**需要核验**——你自己那家服务商有没有别的路子，以它的说明为准。

**没有的话两条退路：**

- **走上面那条存文件**；
- **把草稿发到你自己邮箱**——那正好是[第 10 章](10-案例三-人工确认.md)三种做法里的第二种，**那一章有完整做法。**

> **走草稿箱这条路，有一句话现在就要说清。** 草稿箱里那封信离发出去只有一次点击，**而且它长得和一封你自己写的信一模一样**。手机上顺手一点就出去了。**这条路适合“你自己就是那个要回信的人、量也不大”的场合**；交付给客户、或者拟稿的人和发信的人不是同一个人，**走文件那条，让那次点击必须是一个明确的动作。**

## 第六步：先别发布

**到这一步为止，全是你点一下它跑一次。**

**这一章到此为止，先不要点发布。**

[第 6 章](06-案例一-每日推送.md)和[第 8 章](08-案例二-结果台账.md)最后那一步都是保存加发布，**这一章不是**。理由是这条流程现在只做了一半：**它会不停地把新来的信标成已读、不停地往草稿文件夹里堆文件，而你还没有一套看草稿的办法。**

**[第 10 章](10-案例三-人工确认.md)那三种做法挑一种做完，再回来发布。** 那时候你才知道草稿堆起来之后谁去看、多久看一次、看完怎么发。

**在那之前，用手动执行调这条流程就够。**
