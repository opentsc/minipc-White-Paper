## 新词

**序列号**（Serial Number，常缩写为 S/N）：厂商给每一台设备编的唯一号码，印在机身标签、外包装贴纸上，有的也能在 BIOS 里查到。同一个型号有成千上万台，序列号是区分具体哪一台的依据。报修、退换货、查保修期都要用它。

**验收**：对照订单和说明书，逐项确认收到的东西对不对、能不能用。做这件事有时间窗口，过了退换货期限，处理成本会高很多。

## 第二组：硬件规格是否与订单一致

第 4 章已经查过一遍。这一组是复核，补上内存的细节信息。

**内存总量**

```bash
free -h
```

`-h` 表示用 GB、MB 这种可读格式显示。看 `Mem:` 那一行的 `total` 列。

**存储容量和设备**

```bash
lsblk -d -o NAME,SIZE,MODEL
```

看容量和型号，确认盘的数量和订单一致（有的机型出厂装两块 SSD）。

**内存的详细信息**

这条要先装一个工具。`dmidecode` 读的是 BIOS 里记录的硬件信息表：

```bash
sudo apt install dmidecode
```

如果提示“无法定位软件包”，先执行 `sudo apt update`（见[第 9 章](09-系统更新.md)），再装一次。多数 Ubuntu 桌面版已经预装了这个工具，提示“已经是最新版”属于正常。

```bash
sudo dmidecode -t memory
```

`-t memory` 表示只看内存这一类信息。输出里关注四项：

- `Size`：每一片内存的容量，把所有片加起来应当等于标称总量；
- `Type`：内存类型，Max395 平台通常显示 `LPDDR5` 相关字样；
- `Speed` 或 `Configured Memory Speed`：内存频率；
- `Form Factor`：形态，板载内存常显示为 `Row Of Chips`。

两点说明：

**第一，`dmidecode` 读的是固件填写的表，不是直接测硬件。** 厂商填错或填得不全的情况存在。判断容量对不对，以 `free -h` 和实际能用的量为准，`dmidecode` 当参考。

**第二，输出里出现若干个“插槽”不代表内存可以更换。** 多数 Max395 机型的内存是焊在主板上的，固件仍然会用插槽的形式来描述。这台机器的内存能不能更换，以你的型号说明书为准（需要核验）。

### 为什么 `free -h` 显示的总量比标称少

这是验收时最容易误会的一项。128 GB 的机器，`free -h` 可能显示 `122Gi` 或 `125Gi`。这不是缺斤少两。

少掉的部分来自三处：

**第一，BIOS 给集成显卡预留的显存。** 第 7 章在 BIOS 里设过 UMA Frame Buffer，设成 512 MB 就少 0.5 GB 左右，设成 2 GB 就少 2 GB 左右。这块内存被划给了 GPU，系统那边就看不到了。

**第二，固件和硬件自己占用的保留区域。** 主板固件、微码、各种硬件映射都要占掉一小块，这部分不归操作系统管。

**第三，`free -h` 的 `total` 是内核可支配的量。** 内核自身镜像占的那一块不算在里面。

所以 128 GB 的机器显示 122 到 126 GiB 之间都算正常。要是显示的数字明显偏低——比如订单写 128 GB，实际只显示 60 GB 出头——才需要核查。

**内存和硬盘的单位不是一回事，别混着算。** 内存按 2 的幂标称，128 GB 就是 128 GiB，不存在单位换算的差额。硬盘不一样：厂商按 1 TB 等于 1000 的 4 次方字节标称，`lsblk` 按 1 TiB 等于 1024 的 4 次方字节显示，所以 1 TB 的 SSD 显示成 `931.5G`，2 TB 显示成 `1.8T`。这是换算方式不同，不是少给了容量。

## 第三组：系统能正常安装并启动

> **⚠️ 这一组要进 BIOS、要从 U 盘启动，两个动作都可能把系统弄坏。** 进 BIOS 只是看和翻菜单，不要改任何设置；不小心改了并保存，按[第 12 章](12-硬件问题处理.md)恢复 BIOS 默认值，再按第 7 章把 UMA Frame Buffer 设回最低值。从 U 盘启动后，出现选项时选**“试用 Ubuntu”**，不要选“安装 Ubuntu”——选错并往下走会清空硬盘上已经装好的系统和数据，清掉之后只能靠第 10 章的镜像恢复。

| 项目 | 检查动作 | 正常表现 |
| --- | --- | --- |
| 能进 BIOS | 开机按品牌对应的按键（见第 7 章的表） | 能进入 BIOS 界面，能翻菜单 |
| 能从 U 盘启动 | 插入第 10 章的恢复 U 盘，按启动菜单键 | 菜单里能看到 U 盘并能启动 |
| 系统已装好 | 正常开机 | 出现 Ubuntu 登录界面，输密码进桌面 |
| 反复开关机 | 正常关机再开机，连续做 3 次 | 3 次都能正常开、正常关，不卡在关机画面 |
| 系统更新能跑 | `sudo apt update` | 正常结束，无报错（见第 9 章） |
| 硬盘健康 | `sudo smartctl -a /dev/nvme0n1` | `Critical Warning` 为 `0x00`，`Percentage Used` 接近 0% |

最后一条要先装工具：`sudo apt install smartmontools`。新机器的已用寿命百分比应当很低，如果一台“全新”机器显示已用寿命 30% 或通电时间上千小时，把这段输出保存下来问卖方。

## 第四组：基本功能逐项测试

每一项给一条动作和对应的正常表现。看到不一样的，记下来，先不下结论，测完全部再一起判断。

### 有线网口

插上网线，另一端接路由器或交换机。

```bash
nmcli device status
```

正常表现：`ethernet` 那一行的 `STATE` 列显示 `connected`。网口上的指示灯亮起或闪烁。

再测通不通：

```bash
ping -c 4 223.5.5.5
```

`-c 4` 表示发 4 个包。正常表现：4 个包都有回复，`packet loss` 是 0%。

### Wi-Fi

```bash
nmcli device wifi list
```

正常表现：列出周围的 Wi-Fi 名称。连一个试试：点右上角状态菜单里的 Wi-Fi，选网络输密码，连上后拔掉网线再 `ping` 一次，仍然能通。

有的机型天线是单独包装的，要自己拧到机身背面的天线接口上。搜不到网络或信号很弱，先确认天线装了没有。

### 蓝牙

打开“设置”→“蓝牙”，把开关打开。

正常表现：开关能打开，下方开始列出附近的蓝牙设备。手边有蓝牙耳机或鼠标的话，配对一次，能连上。

命令方式确认：

```bash
bluetoothctl show
```

正常表现：输出里有 `Powered: yes`。

### USB 口

拿同一个 U 盘，逐个 USB 口插一遍。每插一次执行：

```bash
lsblk
```

正常表现：每个口插上后都能看到新出现的设备（通常是 `sda` 或 `sdb`）。

不接存储设备的口（比如只接鼠标的），用另一条命令对比插拔前后的列表：

```bash
lsusb
```

正常表现：插上设备后列表里多一行。

前面板和后面板的口要分开测，不要只测顺手的那两个。

### HDMI 和 DisplayPort 输出

有备用显示器：接上第二台显示器，打开“设置”→“显示器”。正常表现：出现第二个屏幕，能选“联合显示”或“镜像”，两台都出画面。

只有一台显示器：把视频线依次插到主机上的每一个视频口，每换一个口重启一次。正常表现：每个口都能出画面。

USB-C 口不一定支持视频输出，第 2 章已经说明。不支持视频的 USB-C 口接显示器没有画面，这是正常的，不算故障。

### 音频

打开“设置”→“声音”。

正常表现：“输出设备”里能看到设备；点“测试”按钮，左右声道分别有声音。插上耳机，输出设备自动切换成耳机，拔掉后切回去。

机身没有喇叭的机型（多数 Mini PC 都没有），只测耳机口和 HDMI 音频输出。HDMI 接的显示器带喇叭的话，输出设备列表里应当能看到显示器的名字。

### 电源

三项：

1. 正常关机后按开机键，能正常开机；
2. 拔掉电源适配器再插回去，机器不应当自己开机（部分机型 BIOS 里有“来电自启”选项，出厂默认设置不同，需要核验）；
3. 长按电源键 10 秒，能强制关机。

日常不要用第 3 项关机，这里只是确认这个功能在。

### 接口差异

不同品牌要额外测的东西不一样：

| 品牌 | 需要额外测的项目 |
| --- | --- |
| GMKtec EVO-X2 / EVO-X3 | 部分批次带 OCuLink 口（外接显卡用），本卷不测它的功能，但要确认接口存在且无变形；接口是否存在以订单和实物为准（需要核验） |
| Beelink GTR9 Pro | 两个网口都要各插一次网线单独测，不要只测其中一个 |
| Framework Desktop | 前面板接口由插上的扩展卡决定，每张卡都要插到底并单独测一次；把卡换到另一个槽再测一次 |
| HP ZBook Ultra G1a | 笔记本形态，除外接口外，键盘每个键、触控板、内置屏幕（看有无亮点暗点）、摄像头、麦克风和电池充放电都要一起验收 |
| 其他品牌 | 按订单页面和说明书列出的接口清单逐个测 |

## 退换货时间窗口和证据保存

### 时间窗口

退换货期限从**签收日期**开始算，不是下单日期。常见的是 7 天或 15 天，跨境购买、海外直邮、平台自营和第三方卖家的规则都不一样，具体以你的订单页面和平台规则为准（需要核验）。

第 5 章已经记过退货截止日期。现在做两件事：

1. 把这个日期写进手机日历，设成提前 2 天提醒；
2. 验收发现的任何问题，当天就联系卖方，不要拖到临近截止再说。

拖延的代价很直接：过了窗口，能退货的问题就变成只能保修，能换新的问题就变成只能维修。

### 证据清单

以下内容存在一个专门的文件夹里，同时备份一份到云盘或另一台设备：

- **开箱视频**：从快递面单还没拆开开始拍，一镜到底不剪辑，把外箱、面单、拆封、取出主机、机身标签都拍进去。缺件和运输损坏的争议，靠的就是这段；
- **外箱和快递面单照片**：面单上的收件信息和签收日期要拍清楚；
- **机身标签照片**：包含型号和序列号，拍到能看清每一位字符；
- **订单截图**：包含订单号、下单时间、规格描述、价格、卖家名称；
- **聊天记录**：优先用平台内的聊天，记录留在平台上。用微信或其他方式沟通的，另存截图，把对方昵称和时间戳一起截进去。不要删对话；
- **终端输出截图**：前面各章“联系卖方前需要保存的信息”里列的那些；
- **本章的验收表**：填好的那张。

包装箱和泡沫留到退换货窗口结束再处理。退货通常要求原包装。

## 哪些属于卖方责任，哪些属于自己操作

下面是常见的判断方向，用来帮你决定先找谁、怎么描述问题，**不是法律结论**。

**通常偏向卖方责任的情况**

- 开箱时外观已经有磕碰、划痕、进水痕迹或明显使用痕迹；
- 配件缺失，或与订单描述不符；
- 实际规格与订单描述不一致（内存、存储、CPU 型号、接口数量）；
- 在你做任何设置之前就完全不通电，或一开机就反复重启；
- 接口从一开始就不工作：网口不亮灯、USB 口全部不识别、所有视频口都无信号；
- 硬盘自检信息显示这台“全新”机器已有大量通电时间或较高的已用寿命。

**通常偏向自己操作导致的情况**

- 安装 Ubuntu 时清空了原来预装系统里的数据（第 7 章已经明确警告过）；
- 改了 BIOS 设置之后开不了机（多数能通过恢复 BIOS 默认值处理，见[第 12 章](12-硬件问题处理.md)）；
- 自己拆机、更换硬盘或内存之后出现的问题；
- 用了非原装电源适配器，或电压不匹配导致的损坏；
- 摔碰、挤压、进液；
- 装了第三方驱动或改了内核参数之后系统起不来（这属于系统问题，不是硬件故障，回退改动即可）。

**分不清的时候怎么做**

不要先自己拆机。按下面的顺序：

1. 把现象和时间线写清楚：什么时候收货、什么时候第一次出现、做了什么操作、出现过几次；
2. 按[第 12 章](12-硬件问题处理.md)做一遍最小排查（换线、换口、换显示器、减到最小配置），把每一步的结果记下来；
3. 带着验收表、证据和排查记录联系卖方，问他们的判断和处理方式；
4. 对方的回复留在平台聊天记录里。

最终以卖方的售后条款、销售平台的规则和你所在地区的消费者保护规定为准。这三者哪个更有利，不同地区不同平台不一样（需要核验）。

验收表二十项全部通过，退货截止日期已进日历，证据文件夹已建好并备份。

## 看到不同结果怎么办

**规格与订单不符**：立刻停止后续操作，联系卖方。附上订单截图和第 4 章、第二组的终端输出截图。规格不符属于退换货范围，不要自己想办法“凑合用”。

**配件缺失**：先确认不是漏在包装箱夹层或泡沫里。确认缺失后联系卖方补发，附开箱视频。

**某个 USB 口或视频口不工作，其他口正常**：先换设备、换线再测一次，排除是设备或线的问题。确认是接口本身的问题，记录是哪一个口（描述位置，比如“机身后面从左数第二个 USB-A 口”），拍照标出，联系卖方。

**Wi-Fi 搜不到网络**：先确认天线装了、`rfkill list` 里没有被屏蔽，处理方法见[第 12 章](12-硬件问题处理.md)。

**`free -h` 显示的内存比标称少几个 GB**：正常，原因见本章上面的说明。少一半以上才需要核查。

**硬盘显示已用寿命偏高或通电时间很长**：保存 `smartctl` 输出，联系卖方询问这台机器是否为退货翻新品。买的是全新品的话，这属于描述不符。

**退货窗口已经快到期，问题还没定性**：先在窗口内向卖方发起退换货申请，把申请记录留下来，再继续排查。申请发起的时间点通常比排查结论更要紧。

## 联系卖方前需要保存的信息

- 订单号、下单日期和签收日期；
- 品牌、型号、序列号；
- 填好的验收表；
- 不通过项目的具体描述：是哪一项、什么现象、能不能重复出现；
- 对应的终端输出截图（`free -h`、`lsblk`、`dmidecode`、`nmcli device status`、`smartctl`）；
- 开箱视频和机身标签照片；
- 已经排查过的步骤和结果。

## 完成检查

- 外观与配件这一组，每一行都填了吗？
- `free -h`、`lsblk`、`sudo dmidecode -t memory` 三条都跑过，结果记下来了吗？
- 你能说清楚为什么 `free -h` 的总量比标称少吗？
- 网口、Wi-Fi、蓝牙、每个 USB 口、每个视频口、音频、电源，都测过一遍了吗？
- 验收表二十项都有结论了吗？
- 退货截止日期进日历了吗，提醒设了吗？
- 开箱视频、序列号照片、聊天记录、订单截图，都存好并备份了吗？
