# 10　远程访问验收

## 这一章的任务

把显示器、键盘、鼠标从这台机器上拔下来，收进柜子。然后只靠笔记本和手机，把一天的活干完。

这是第 3 卷的收尾。前面九章各做了一件事，这一章把它们串起来验一遍——八条，每条写清用什么命令验、通过标准是什么、不过该回哪一章。

八条全过，这台机器就可以搬到角落里去了。

## 开始前

- 第 2 章到第 9 章做完。挑着做的那几章（第 6 章 Tailscale、第 7 章共享文件夹）没做的话，对应那一条跳过，不算不通过；
- 一台笔记本、一部手机；
- **验收全程在笔记本和手机上做**，不走到机器跟前；
- 显示器和键盘先别收远，第 7 条要用一次，出问题也要靠它；
- 两小时，其中有一段在等机器重启。

## 先把线拔了

验收从拔线开始，不是从命令开始。线还接着，你会不知不觉走过去解决问题，验收就白做了。

在机器跟前，拔掉三样：

- HDMI 或 DP 线；
- 键盘；
- 鼠标。

**留着的只有两根**：电源线，和网线（用 Wi-Fi 的话只有电源线一根）。

拔线不用关机，这三样都是热插拔的。

拔完回到你的笔记本前面。**接下来所有操作都在这里做。**

先看总表，再往下逐条做。

| 条目 | 验什么 | 通过标准 | 不过回哪 |
| --- | --- | --- | --- |
| 1 | 固定地址生效 | 地址是你设的那个，重启之后不变 | 第 3 章 |
| 2 | SSH 密钥登录可用 | `ssh minipc` 不问密码直接进 | 第 4 章 |
| 3 | 密码登录已关 | 用密码连被直接拒绝 | 第 4 章 |
| 4 | Tailscale 外网可达 | 手机只用流量能打开面板 | 第 6 章 |
| 5 | 共享文件夹可读写 | 从别的电脑能建文件也能删 | 第 7 章 |
| 6 | 防火墙已启用且规则正确 | `Status: active`，每条规则说得出给谁 | 第 9 章 |

| 8 | 备份定时任务仍在跑 | 任务行在，日志里有最近一次 | 第 2 卷第 12 章 |

**边做边在纸上打勾。** 八条不是一口气跑完的，第 7 条要等机器重启，中间容易忘了自己走到哪。

## 一、固定地址生效

在笔记本上：

```bash
ping -c 3 192.168.1.50
```

地址换成第 3 章固定下来的那个。

**通过标准**：三行都有回复，最后一行丢包 0.0%。

然后连进去，从机器自己这边确认一次：

```bash
ssh minipc
hostname -I
```

**通过标准**：打印出来的地址就是你设的那个。多打出来一个 `100.` 开头的，那是 Tailscale 的，正常。

这一条真正的考验在第 7 条——重启之后地址还是不是它。现在先记下来。

**不过的话**回[第 3 章](03-固定IP.md)。ping 不通先看机器开着没有、网线插着没有。

## 二、SSH 密钥登录可用

```bash
ssh minipc
```

**通过标准**：不问账户密码，直接出现 Mini PC 的提示符。设了密码短语的话，问的是密码短语，不是账户密码，这也算通过。

进去之后确认自己在哪台机器上：

```bash
hostname
```

**通过标准**：输出是 Mini PC 的主机名，不是你笔记本的。

**不过的话**回[第 4 章](04-SSH.md)那两节：公钥传给的是不是同一个账户，`~/.ssh` 和 `~/.ssh/authorized_keys` 的权限对不对。

## 三、密码登录已关

不用另找一台设备，在笔记本上用这条命令就能验：

```bash
ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password,keyboard-interactive 你的账户名@192.168.1.50
```

作用：**故意不用密钥**，只用密码去连。两个 `-o` 分别是“别用公钥”和“只走密码那条路”。

**通过标准**：立刻被拒绝，输出这一行：

```
Permission denied (publickey).
```

括号里的 `publickey` 是在说：这台机器只认公钥。**看到这行就是通过了**，这是好消息不是故障。

**跳出密码提示框就是没通过**——密码那条路还开着，谁都能来一个一个试。回[第 4 章](04-SSH.md)“关掉密码登录”那一节，六步重走一遍，重点是第三步那个配置文件写了没有、第五步的服务重启做了没有。

## 四、Tailscale 外网可达

没做第 6 章就跳过这一条。

先在笔记本上看设备都在不在线：

```bash
ssh minipc
tailscale status
```

**通过标准**：Mini PC、笔记本、手机三行都在，Mini PC 那行没有 `offline`。

真正的验收在手机上：

1. **把手机的 Wi-Fi 关掉**，只用流量；
2. 确认手机上 Tailscale 的开关是开的；
3. 浏览器里打开 `http://100.101.102.103:3001`，地址换成你的。

**通过标准**：监控面板出来了，数据是全的。

**注意手机一定要关 Wi-Fi。** 连着家里 Wi-Fi 打开的，走的可能还是局域网，验的不是外网这条路。

**不过的话**回[第 6 章](06-Tailscale.md)。先看手机上 Tailscale 的开关是不是被系统省电策略关掉了；再看第 9 章那条 `sudo ufw allow in on tailscale0` 加了没有——防火墙装完忘了给它放行，症状正是家里能开、外面打不开。

## 五、共享文件夹可读写

没做第 7 章就跳过这一条。

在另一台电脑上连过去，**Windows 和 macOS 的做法在第 7 章，两边都给了**。连上之后做三个动作：

1. 新建一个文本文件，随便写一句话，保存；
2. 关掉再打开，看内容在不在；
3. 删掉它。

**通过标准**：三个动作都成功，没有弹出“没有权限”。

再验一下备份那一头。连回 Mini PC：

```bash
ssh minipc
ls -l /srv/share
```

**通过标准**：刚才在另一台电脑上建的文件，属组是 `sharegroup`。第 7 章 `force group` 那一行管的就是它，属组不对的话，以后备份脚本可能读不了。

开了只读共享的，往 `readonly` 里拖一个文件试试，**被拒绝才是对的**。

**不过的话**回[第 7 章](07-共享文件夹.md)。连不上先看第 9 章有没有放行 445；能连上但建不了文件，看目录权限和 `read only` 那一行。

## 六、防火墙已启用且规则正确

```bash
ssh minipc
sudo ufw status verbose
```

**通过标准**三条，缺一不可：

1. 第一行是 `Status: active`；
2. `Default:` 那行是 `deny (incoming), allow (outgoing)`；
3. 下面表格里**每一行你都说得出这个口是给谁开的**。

第三条最容易糊弄过去。对着表逐行念一遍：22 是我自己远程登录的，3001 是那个面板、只对局域网开，445 是共享文件夹、只对局域网开，`tailscale0` 那条是给我自己的设备。念不出来的那一行，按第 9 章的做法删掉。

再看一眼实际在监听的端口，和规则表对照：

```bash
ss -tln
```

**通过标准**：出现的端口和你上面念得出的那几个对得上。多出来一个说不清的，去查是哪个程序开的。

**不过的话**回[第 9 章](09-防火墙与密钥.md)。`Status` 是 `inactive` 的话，注意先确认 `sudo ufw show added` 里有放行 SSH 那条，再 `sudo ufw enable`。

## 七、断电重启后服务自恢复

这一条是八条里分量最重的，也是唯一要动手到机器跟前的。做法在[第 8 章](08-自动启动与无人值守.md)最后一节，这里只列验收标准。

**先记下断电前的样子**：

```bash
ssh minipc
docker ps --format '{{.Names}}\t{{.Status}}'
systemctl is-active ssh smbd tailscaled
```

然后拔插座、等 30 秒、插回去、**不按电源键**、等两分钟。

回笔记本上，**六项逐条对**：

| 项 | 命令 | 通过标准 |
| --- | --- | --- |
| 机器自己开机了 | `ping -c 3 192.168.1.50` | 有回复 |
| 地址没变 | `ssh minipc` 后 `hostname -I` | 还是那个地址 |
| SSH 自己回来了 | `ssh minipc` | 直接进得去 |
| 容器自己回来了 | `docker ps` | 名单和断电前一样，`Status` 是 `Up 几分钟` |
| 服务自己回来了 | `systemctl is-active ssh smbd tailscaled` | 三行都是 `active` |
| 外网这条路还在 | 手机关 Wi-Fi 打开面板 | 页面出来 |

**六项全过才算这一条通过。**

**机器压根没开机**：回[第 8 章](08-自动启动与无人值守.md)那张分品牌线索表，BIOS 里那一项没设对。这一项确实找不到的话，接受它——以后停电要有人去按一下电源键，其余七条不受影响。

**机器开了但某个服务没回来**：`systemctl is-enabled 服务名` 看是不是 `enabled`；容器没回来看 `docker inspect` 里的重启策略是不是 `unless-stopped`。都在第 8 章。

## 八、备份定时任务仍在跑

前面九章改了不少东西，顺手确认第 2 卷那套备份没被碰坏。

```bash
ssh minipc
crontab -l
```

**通过标准**：第 2 卷[第 12 章](../02-Ubuntu/12-日常备份.md)那条每周备份的行还在，没有被注释掉（行首没有 `#`）。

```bash
tail -20 ~/ai/backup/backup.log
```

**通过标准**：最后一组带时间的行，日期是最近一次该跑的时间。看到 `开始备份` 和 `备份结束` 成对出现。

手动跑一次，看它现在还能不能跑通：

```bash
~/ai/scripts/backup.sh
```

**通过标准**：一路打到 `备份结束`，中间没有报错。第 7 章把 `/srv/share` 加进去了的话，日志里应该有 `已同步 /srv/share` 这一行。

**不过的话**回第 2 卷[第 12 章](../02-Ubuntu/12-日常备份.md)。日志里写“找不到……移动硬盘可能没插”，那不是故障，是硬盘没插，插上再跑一次。

## 真的过一天

八条打完勾，还剩最后一件事：**用一天。**

验收命令跑得通，和日常用得顺，是两回事。挑一个正常的工作日，只用笔记本和手机，把这些做一遍：

- 早上，浏览器打开面板，看一眼夜里有没有断过；
- 上午，往共享文件夹里放几个文件，让家里人或者同事从他们的电脑上取；
- 中午，用第 5 章的 `rsync` 把笔记本上一批资料同步到 `~/ai/data`；
- 下午出门，用手机流量打开面板确认服务还在；
- 晚上，`ssh minipc` 进去看一眼硬盘还剩多少（`df -h /`）、容器日志有没有异常（`docker logs --tail 20 uptime-kuma`）；
- 睡前，看一眼备份日志。

**一天下来一次都没走到机器跟前，这一卷就真的做完了。**

中间有哪一步让你想走过去，那就是还没做完的地方，回对应的章补上。

## 现在你手上有什么

第 2 卷结束时，这是一台放在桌上、要坐在跟前用的电脑。现在它是：

- **一台地址固定的机器。** 写进笔记、写进脚本、存成书签，重启多少次都是它；
- **一台只认钥匙不认密码的机器。** 密码那条路关着，别人试一万次也进不来；
- **一台在哪儿都能连的机器。** 家里用局域网地址，外面用 Tailscale 地址，两条路都不需要在路由器上开任何一个口；
- **一台几个人能共用的机器。** 共享文件夹在 Windows、macOS、手机上都能连，只读和读写分得清；
- **一台断电能自己回来的机器。** 来电自启、服务自启、容器自启、定时任务照跑，你不在也不影响；
- **一台门禁说得清的机器。** 防火墙的每一条规则，你都说得出是给谁开的；
- **一台资料有备份的机器。** 每周自动跑，删了能找回来，第 2 卷那一套原样还在。

用第 1 章的两条标准回头看：**它一直开着，它等着别人来用。** 它现在是一台服务器了。

## 可以搬到角落了

显示器、键盘、鼠标收进柜子。**别扔，也别收太远**——BIOS 要改（第 4 卷）、系统起不来要救（第 15 卷）、密钥丢了要本地登录（第 9 章），这三种情况下它们是唯一的路。

搬走之前，五件事：

**一、位置。** 进风口和出风口都要留出空间，别贴墙、别塞进密闭柜子、别在上面压东西。这台机器以后要长期满载跑模型（第 6 卷），散热不好会掉频，具体怎么看温度是[第 4 卷](../04-Max395硬件/README.md)的内容。

**二、电源。** 插排要牢靠，别和会突然大电流的电器（吸尘器、电暖器）共用一路。踢一脚就松的插头，等于随机断电。

**三、网线。** 有条件就走网线不走 Wi-Fi。理由第 5 章说过——传大文件时速度差好几倍，而且 Wi-Fi 断线重连的那几秒，正在传的东西会断。

**四、贴个标签。** 在机身上贴一张纸条，写三样：这台机器的固定地址、Tailscale 的地址、进 BIOS 按哪个键。**不要写账户密码、不要写共享密码**，理由见[第 0 卷第 8 章](../00-使用说明/08-文件保护.md)。

**五、记一笔。** 在你的笔记里存一份这台机器现在的状态：地址、开着哪几个端口分别给谁、共享文件夹的路径、备份跑在星期几、密钥备份在哪。半年之后你不会记得这些，而这些正是出问题时第一个要查的。

搬完插上电源和网线，回笔记本上 `ping` 一次、`ssh` 一次。通了，收工。

有哪一步做不出来，到[第 15 卷：故障排查](../15-故障排查/README.md)按症状查。
