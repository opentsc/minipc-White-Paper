## 开始前需要准备什么

如果你的设备已经安装好 Ubuntu，可以一边读一边在终端里对照练习，终端是什么下面就讲。如果还没有安装，先读完本章，安装好后再回来练习。

## 新词

**终端**（Terminal）：接受文字命令的程序界面，也叫“命令行”或“命令提示符界面”。Ubuntu 里的终端是一个应用程序，可以通过快捷键或应用菜单打开。它看起来像一个纯文字的黑色或深色窗口。

**命令**：发给操作系统的文字指令。命令区分大小写，`ls` 和 `LS` 是不同的命令。空格数量也影响结果，多余的空格可能导致命令出错。

**命令提示符**（Prompt）：终端里，你输入命令之前自动显示的一行文字。常见格式是 `用户名@主机名:当前目录$`，其中 `$` 表示普通用户，`#` 表示管理员（root）。

**sudo**：在命令前加上这个词，表示以管理员权限执行该命令。部分操作需要管理员权限才能运行。使用 sudo 时要格外注意命令会修改哪些内容，错误的 sudo 命令可能影响整个系统。

**目录**：文件系统中存放文件的位置，相当于 Windows 的“文件夹”。

**绝对路径**：从根目录开始的完整路径，例如 `/home/用户名/documents`。不管当前在哪个目录，绝对路径总是指向同一个位置。

**相对路径**：从当前所在目录出发的路径，例如 `../上一级目录/文件名`，`..` 表示上一级目录。路径结果随当前位置变化。

## 如何读教材中的命令

教材里的命令放在**代码块**里。代码块是一块和正文分开的灰底或深底区域，里面的字每个占同样宽度，方便你逐字核对。看到代码块，就是要你把里面的内容原样输入或复制到终端。

```bash
ls -la
```

上面的命令是 `ls -la`，作用是列出当前目录下的所有文件，包括隐藏文件，同时显示权限、大小和修改时间。

**不要复制提示符。** 如果代码块里有 `$` 开头，那是命令提示符，不是命令的一部分，不要复制。只复制 `$` 后面的内容。

例如，下面这个代码块：

```
$ ls -la
```

你只需要输入 `ls -la`，不需要输入 `$`。

**注意换行符号。** 如果一条命令太长，教材里可能用 `\` 换行继续写：

```bash
sudo apt-get install \
  package-name-a \
  package-name-b
```

这是一条命令，`\` 只是换行标记。复制时把整段一起复制，或者手动把换行去掉，写成一行。

**注意注释。** 命令里 `#` 后面的内容是注释，执行时会被忽略：

```bash
ls -la  # 列出所有文件
```

你可以复制整行，不影响结果。也可以只复制 `#` 前面的命令部分。

## 有风险的命令：作用、范围和停止方法

教材里涉及删除数据、格式化、批量写入或停止服务的命令，会单独说明它的作用范围和停止方法。

执行这类命令之前，先确认以下 3 件事：

**1. 这个命令会修改什么？** 例如，删除哪个目录，停止哪个服务，格式化哪块磁盘。

**2. 修改范围是整台设备还是某个特定目录？** 一个错误的路径可能让删除命令作用于整个根目录，而不是你预期的子目录。

**3. 如何停止？** 大多数长时间运行的命令可以用 `Ctrl+C` 中断。但涉及磁盘写入的操作，中断可能导致数据不完整。教材中有风险的命令会单独说明停止方法。

**示例：说明作用范围的命令**

```bash
# 删除当前目录下名为 test 的文件夹及其所有内容
rm -rf test/
```

- 作用：删除 `test/` 文件夹内的所有文件和子文件夹；
- 范围：只影响当前目录下的 `test/` 目录，不影响其他位置；
- 停止方法：`rm` 命令执行后无法中断已删除的文件，执行前先用 `ls test/` 确认内容再操作；
- 注意：如果路径写错（如写成 `rm -rf /`），影响范围会扩大到整个系统，执行前需要仔细核对路径。

## 如何读截图

教材中的截图用于展示正常结果。读截图时重点关注：

- **终端里的输出文字**：这是判断操作是否成功的主要依据；
- **用户名和路径**：确认你在正确的目录下操作，路径错误是操作失败的常见原因；
- **关键状态词**：如 `OK`、`Running`、`Failed`、`Active`、`Loaded`；
- **关键数字**：端口号、内存大小、文件数量，这些数字是验收的依据。端口号是一台设备上区分不同服务的编号，同一个网络地址加不同端口号指向不同的程序，后面装模型服务时会用到。

你看到的实际界面可能和截图有颜色差异或字体差异，这不影响结果判断。只要关键输出文字和截图一致，说明操作成功。

## 如何使用检查表

每章末尾的“完成检查”是一个可以逐条核对的清单。操作完成后，对照清单确认：

- 如果某条描述的状态你能实际看到或操作验证，说明该条通过；
- 如果某条看不到，返回对应步骤重新操作，或进入该章节的“看到不同结果怎么办”部分；
- 全部条目通过后，才算完成本章，可以进入下一章。

不要跳过检查表中的任何一条。即使你认为操作成功了，检查表可能会发现遗漏的步骤。

## 看到不同结果怎么办

**输入命令后提示 `command not found`**：这条命令对应的程序还没装，或者名字打错了。先逐字核对拼写和大小写，再看该章有没有要求先安装什么。

**提示 `Permission denied`**：当前账户没有权限。看该章的命令原文有没有 `sudo`，漏了就补上；原文没有 `sudo` 而你加了，先去掉再试。

**命令没有任何输出**：一部分命令成功时就是不输出内容，这属于正常。以该章“正常结果”写的为准，不要因为没有输出就重复执行。

**你的输出和教材截图不完全一样**：版本不同，输出的措辞、行数和颜色都可能不同。只对照该章点名要看的关键文字和数字，其余差异不影响判断。

**你不确定一条命令会改什么**：不要先执行。回到本章“有风险的命令”一节的 3 个问题，逐个回答得出来再执行。答不出来就跳过这一步，到[第 9 章](09-停止与恢复.md)按停止方法处理。
